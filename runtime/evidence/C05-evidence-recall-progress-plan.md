# C05 저장 근거 재조회의 준비 진전

new7의 CLI 두 실행은 수집 결과 채택 후 공개된 두 근거 ID로 core.evidence.get을 실행했고 둘 다 채택했다. 그러나 답변 모델 호출 전에 no_progress_limit으로 멈췄다. 도구·모델·재계획의 실행 한도는 남아 있었다. 현재 준비 진전 판정은 도구 카탈로그·guidance·게시판 요청에만 적용되므로, 계획 한 번과 저장 근거 조회 두 번이 연속 무진전 3회로 계산됐다.

기본 무진전 한도는 3으로 유지한다. 현재 허용된 근거의 정확한 provenance card를 찾거나 정확한 본문을 최초로 읽었을 때만 기존 준비 진전 키를 추가한다. 이는 새 관측·근거 생성이나 완료 판정이 아니다. 본문 get은 card와 body 키를 함께 남겨 get 후 같은 find가 진전을 늘리지 못하게 한다. find 후 최초 get은 본문을 읽은 별도 준비 진전이다.

키의 의미는 현재 evidence 진전 판정과 같은 tenant, scope, lineage, facts, coverage, 원문 해시로 정한다. 표시용 ID·위치·시각·state revision이나 조회 문구·크기 한도를 바꿔 같은 내용을 다시 읽어도 키는 늘지 않는다. 반환 카드/본문을 현재 허용된 정본과 먼저 대조한다. 채택·목표·범위·권한·재사용 검사는 유지하며 손상·외부 범위·거절·빈 결과는 진전으로 세지 않는다. find의 정상 부분 페이지는 검증된 카드만 준비 진전으로 인정하고, 너무 큰 본문이나 부분 get은 인정하지 않는다. 원문 raw 조회는 이번 확장에 포함하지 않는다.

기존 acceptedToolProgressKeys와 captureProgress를 재사용하며 저장 스키마나 기본 한도를 바꾸지 않는다. 준비 진전도 기존 근거 진전과 같이 원근거에 한정한다. 파생 복사본의 lineage나 wrapper 해시를 바꿔 반복 제한을 우회할 수 없게 하며, 파생 근거를 읽거나 답변에 사용하는 기능 자체는 바꾸지 않는다. 새 회귀는 실제 WorkResources 결과, find/get 순서, 내용 중복, 잘못된 결과 거부, 반복 중단을 확인한다. CLI 시험은 같은 좁은 창과 원문·MCP 무송신 조건을 유지한다. 최초 수렴 회귀 통과 및 new7의 117개 중 115개 통과·2개 실패는 기존 로그에 보존한다.
