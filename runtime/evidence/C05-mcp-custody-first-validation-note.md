# 전송 후 응답 보관: 첫 통합 검증

2026-09-07, macOS arm64, 전용 Node 24.20.0. 실제 모델/API는 호출하지 않았다.

현재 관측은 checkpoint311이다. 두 준비 fixture를 고친 뒤 `build3`와 `new2` 82/82가 통과했다. `related1`은 693개 중 685 통과·8 실패로 종료했으며, 실패는 모두 기존 `mcp-read-tools` 시험의 artifact 0 기대값이었다. 그 파일만 새 보관 계약으로 고친 뒤 `build4`와 `related-mcp2` 28/28이 통과했다. 실제 호출 차단·원 라벨·본문 미채택 검사와 원문/영수증·사용량 복구 검사를 유지했다. 제품 변경 없이 시험만 고쳤으므로 신규82와 전체693을 다시 실행하지 않았다. 각 소스 지문과 원실패를 보존하며 최종 소스의 전체 통과나 Linux 검증을 의미하지 않는다.

- `build1`: 종료 2. 기존 `evaluation-replay.test.ts`의 ContextRecovery 조립에 clock이 없어 타입 검사에서 중단했다. 해당 시험의 마지막 저장 시각을 반환하는 clock만 추가했다.
- `build2`, `core1`, `architecture1`: 종료 0. 각 단계의 소스 지문 불변과 직접 생성한 프로세스 그룹의 종료를 결과 JSON에 보존했다.
- `new1`: 신규 7개 파일의 82개 시험 중 80 통과, 2 실패, 취소/건너뜀 0. 원 로그와 결과 JSON은 보존한다.
- 실패 2개는 각각 유효하지 않은 명시 자료 세대 0, 컴퓨터 후속 작업에 필요한 준비 상태 누락으로 검증 대상 앞에서 거절됐다. 담당자가 시험 준비 경로를 교정 중이다. 이 기록은 교정 후 통과를 의미하지 않는다.
- 이번 소스의 관련 회귀·Linux 통합은 아직 실행하지 않았다. 선행 단위의 Linux 3423 통과를 이번 변경의 검증으로 사용하지 않는다.

## 후속 연결 검토

현재 실행 실패 뒤 사용량 복원과 직접 `recordStoredUsage` 호출은 연결돼 있다. 재시작 뒤 일반 입구의 자동 회복은 아직 연결되지 않았다. 원문 복원인 `restoreResult`와 사용량만 보완하는 기능의 권한 조건을 섞지 않는다.

후속 조립에서는 담당 저장소·tenant/principal·선택 업무/세션을 확인한 뒤 원 시도의 측정치만 보완한다. 상태 조회 GET/SSE와 CLI view는 읽기 전용으로 유지한다. 취소 상태와 기존 결과를 보존하고 새 모델·도구 호출 권한으로 해석하지 않는다. 명시 복구 명령의 추가 여부는 아직 확정하지 않았다.

현재 프로필을 다시 열면 provider discovery가 발생하므로 tools/call 재전송 0과 완전한 오프라인 복구는 다르다. 실제 강제 종료, 일반 CLI/Web 진입, 프로필 전체 종료 경합과 최종 Linux 검증은 별도 남은 인수다.
