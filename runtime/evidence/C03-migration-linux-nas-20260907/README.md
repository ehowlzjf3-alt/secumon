# C03 D3 native Linux verification preparation

Prepared scripts only. Creating these files did not connect to NAS, upload sources, start tests, install dependencies, or close SSH. Root will create `control-directory.txt` for a new private SSH control directory; this package does not store credentials.

Dedicated root: `/home/shaneee/secumon-linux-test.pCJ0bd`. Reuse only its Node `v24.20.0` and existing dependencies. `/usr/bin/node` must remain `v18.20.4`. D2 evidence and scripts remain unchanged.

The root operator selects two finished passing local result JSONs when preparing an upload. Their `sourceAndBuild` pins must both match the current `verifyEvaluationBuild()` result. The selected result bytes/hashes and exact pin are recorded per attempt and uploaded together. Old new2 passed 37 tests at build3, but related1 later failed 3 of 315; those historical results do not satisfy the new upload gate. No current/final pin or current test count is assumed by these prepared scripts.

Run from `runtime` with the pinned local Node, only when the root operator authorizes execution:

1. `preflight.mjs`: save real NAS environment, finished D2 result, and process visibility audit.
2. `prepare-upload.mjs 1 evidence/<new-result>.json evidence/<related-result>.json`: verify local pin; package only `src`, `scripts`, `fixtures`, package/lock and two tsconfig files; hash six uploads; check remote tar allowlist and unchanged dependency lock before moving old runtime entries into `before-migration-c03-attempt1`; extract and check source digest. No npm install or system change.
3. `start-native.mjs 1`: start the single D3 runner over the registered SSH control, with an empty inherited environment except fixed PATH/cache/TMPDIR values. An uncertain SSH exit is observer status, not proof of native completion.
4. `collect-attempt.mjs attempt-1` for a finished failure, or `collect-attempt.mjs final` for the finished passing run. Original result and every completed/failed step log are saved with hashes. Existing collection paths are never overwritten.
5. `close-native.mjs`: only after a collected exact-pin pass, save the fresh process audit, require observed owned processes zero/unexpected audit errors zero, close the control socket, and remove its now-empty directory. Inaccessible peers remain in the record.

The native runner executes eight steps: build; D3 new tests (5 files; count read from TAP); prior related tests (35 files); core typecheck; architecture; existing architecture CLI fixtures; all discovered test files; fixtures. `targeted-files.json` preserves the two exact local file lists. Actual Linux totals must be read from TAP, not copied from local observations. D2's diagnostic MCP preload is not enabled by default in this D3 run.

Each Node test has a 60-second timeout. The full-test stage keeps D2's 900-second limit, while other stages have 180 seconds each. A separate 1200-second allowance bounds the complete native run; a stage cannot exceed its remaining overall allowance. Timeout/error cleanup signals only the directly spawned detached process group: TERM, 5-second grace, KILL if still present, 5-second final observation, and up to 5 seconds for log flush. Cleanup can therefore finish after the execution allowance. A surviving/unobservable group is a failed result, not success. Descendants that create a different group are outside this signal guarantee.

Process audits inspect all comm names using same-UID `/proc/<pid>/exe` and `cwd`, excluding the audit process. EACCES/EPERM peers and unresolved scope remain separate from observed owned processes; other unexpected errors block progress. The record explicitly does not establish global process absence. The runner captures audits before and after native validation, and close takes a further fresh audit.

For another attempt, collect the failed attempt first. `prepare-upload.mjs 2 <new-result> <related-result>` requires its finished failure, archives the remote D3 evidence, and preserves another old runtime snapshot. Each upload/collection is named by attempt. No automatic retry, failed-log deletion, current-runtime rollback, or orphan-process mass termination is implemented.

Final proof needs the eight native step outcomes, actual new/related/full TAP totals and timeout counts, initial/final exact build pin, uploaded hashes, collected log hashes, observed group cleanup, final `/proc` limitations, default Node/root checks, and SSH closure. Preserve the historical new1 failure and the separate disconnect diagnosis; do not promote it into a product failure or erase it. Native Windows, live model/API calls, actual services, migration performance and power-loss durability remain outside this run.

After the root operator has run final collection and `close-native.mjs`, run `finalize-evidence.mjs` with the pinned local Node from `runtime`. It performs local checks only and creates `evidence/C03-migration-verification.json` once, using exclusive creation. It refuses an existing output, a changed current source/build pin, incomplete/failed steps, mismatched raw-log hashes or TAP summaries, missing local pass proofs, unresolved directly managed groups, unexpected process-audit errors, or a remaining SSH control directory/socket. Inaccessible peers remain qualified in the output instead of being converted into a global zero-process claim.

The finalizer needs the selected per-attempt validation inputs/upload records and original upload files; `final/result.json` plus its eight logs and collection hashes; completed run metadata and cleanup; the two selected local result/log/before triples; and the retained `new1`, `new2`, `related1` result/log/before triples plus both new1 diagnosis JSONs. It also hashes the original D2 verification, initialization diagnosis and MCP diagnosis JSONs without modifying them; later D3 success does not resolve their original unexplained observations. Windows runtime/file bindings and parts of the backup file lifecycle remain unimplemented/unconnected and unverified, not merely awaiting a test run. It reads observed TAP counts rather than assuming 37, 38, 315, or a full-suite total. Recovery-test names stay in the JSON but are omitted from the concise console summary. It does not connect to NAS, run a test, edit D2 evidence, or mark C03/the overall goal complete.
