# C05 컨텍스트 선택 수렴 교정 계획

new6에서 collection의 저장 결과 채택과 core.evidence.find의 실행·채택은 성공했지만, 그 다음 모델 입력의 근거·참조·도구 결과가 비었다. 이 관측만으로 어떤 선택이 창에 들어갈 수 있었는지는 확정하지 않는다. 별도 정적 검토에서 큰 byte 한도와 작은 token 한도가 함께 있을 때 선택기가 미사용 byte 예산을 줄이느라 같은 선택을 반복하는 경계를 찾았다.

먼저 실제 ContextCompiler의 inspect/materialize와 prepare를 각각 실행하는 회귀를 만든다. 같은 입력 추정기로 전체 선택은 초과하고 일부 optional 항목을 포함한 요청은 들어간다는 사실을 먼저 확인한다. 현재 구현의 불필요한 최소 선택과 실패를 보존한 뒤, 두 루프에서 다음 선택 예산을 계산할 때 실제 선택 비용을 상한으로 삼는 최소 교정을 적용한다. 반복 상한, 최종 입력 추정, 필수 문맥 보호, 현재성 확인은 유지한다.

교정은 최적 부분집합 탐색을 추가하는 작업이 아니다. 선택하지도 않은 여유 예산 때문에 같은 후보를 반복하는 현상만 줄인다. 새로운 공개 API, 저장 스키마, 모델 호출은 추가하지 않는다. 기존 필수 항목만 들어가는 사례, 무쓰기 inspect, 잘못된 추정 거부, memo의 보존·퇴출 규칙도 함께 검증한다.

CLI 인수 시험은 실제 compact, 원 수집 계보·영수증 보존, 저장 전용 소비의 추가 MCP 전송 0, 현재 원근거에 따른 답변을 공통 조건으로 유지한다. 입력에 원근거가 이미 있으면 바로 답하고, 빠졌을 때만 find/get을 사용한다. 따라서 교정으로 불필요한 조회가 사라졌다면 특정 get 횟수를 강제하지 않는다. 조회가 발생한 경우에는 바로 그 모델 입력에 공개된 ID만 사용했는지와 추가 호출의 정산을 계속 확인한다. 한 실행에서 지나지 않은 분기까지 검증했다고 주장하지 않는다.

검증 순서는 현재 dist의 무송신 반례 → 소규모 교정과 빌드 → 선택 회귀와 CLI 대상 시험 → 최종 source의 신규·관련 검사 → NAS/Linux 확인이다. 실제 모델/API 및 사내 연결 시험은 중단 상태를 유지한다. 원 staging과 new3~new6 실패 기록은 수정하지 않는다.
