## grounded 핵심 발견

- **F2 근본원인**: judge 가 증거 맹목 — assistant 산문만 보고 tool 결과/finding 을 안 봄.
  effort "low" 는 **의도**(high 면 hidden reasoning 이 JSON 예산 태워 파싱실패) → effort 조정
  대신 증거 digest 접지로 해결.
- **F3**: 마스킹이 egress 만 → 영속 3곳(finding.json/DB·audit·evidence 캐시)에서 평문 유출.
  쓰기 지점만 봉인, tool 반환은 미접촉(딥다이브 유효).
- **F5**: idle-reaper 는 web lifespan 만 배선 — 워커(신고 케이스)는 teardown 전무 +
  프로세스그룹 미격리로 SIGKILL 시 chromium 고아. 실전 검증(공유 머신의 타 사용자
  DrissionPage 누수 = 우리가 F5 로 고치는 그 패턴).

## codex 합심 (슬라이스별 diff 교차검증) — 잡아낸 실결함

- **A perf**: HTTP/2 + cap-break flow-control stall / 풀 Client cookie jar carryover.
- **C2-a**: 승인 후 입력 변조로 게이트 우회 / 정책의 코어 상태 변조 / iteration race →
  입력 deep copy·스칼라 read-only metadata·lock 스냅샷.
- **Front-D**: None passthrough 정확성 / warn<block 사다리 붕괴 / SSO 회로차단기 경계 누락 /
  **자율 Ralph(ChatSession) 배선 누락**(주 경로가 mid 로 샘) → client 파생 단일소스.
- **F2-B**(4 라운드): boundary miss / cache-before-persist / digest 예외 루프중단 / throttle
  곱셈 폭주 / 판정실패 후 cap 붕괴.
- **F2-E**(3 라운드): 재-pause 루프(fire-once) / flag·pause 비원자성.

## 정직한 경계 (문서화 잔여)

- **F2-B/F2-E throttle 한계**: judge 는 최신 assistant_text 만 본다 → 증거에 안 남고 한 번만
  산문으로 선언된 완료는 스킵/throttle 턴에서 소실 가능. **기존 %N 스로틀도 갖는 동일 절충**,
  cap+boundary 로 창 상한, 증거 접지 완료는 절대 미판정 안 됨.
- **전역 digest(G1)**: 단일 operator 전제. 무관 goal 의 finding 이 다른 goal 판정에 섞임 →
  goal-scoped finding(후속)으로 좁힘.
- **C2-a 신뢰 모델**: 정책은 신뢰된 in-process plugin — 악성 plugin 샌드박스 아님(불가능),
  선의 정책 실수에 대한 defense-in-depth. plugin 이 서브도구 `.execute()` 직접 호출 시 우회
  (기존 권한 게이트도 동일) → skill 측 invoke_tool 배선 위임.
- **F2-E**: review-surface 게이트(루프정지+GoalPaused+영속 감사 flag). 강제 human sign-off
  (flag 된 goal 자동 resume 금지)는 배포 정책.
