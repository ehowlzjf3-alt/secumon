# v3.81 — 도메인-프리 자율 엔진 방향 (확정 결정 + 로드맵)

2026-06-12 논의 산출물. v3.80 de-domain 추출(엔진 `9b23832` / skill repo `a8ca3ee`) 직후,
"완전무결한 자율형 보안 엔진"을 목표로 한 방향 합의. 사실 수집은 5-스카우트 워크플로우

## 0. 사용자가 던진 6포인트 → 3덩어리 + 1긴급결함

| 사용자 포인트 | 수렴 위치 |
|---|---|
| ① 의존성·주석까지 도메인 0, 엔진 개선 | 덩어리 A (도메인-0 경계선) |
| ② 루프/쿼리 속도·효율 (Slice2 subagent 포함) | 덩어리 B (자율 엔진 심장) |
| ③ dynamic workflow deep-dive + 모델 버전별 | 덩어리 B |
| ④ 도메인 0 수렴, 전부 skills / 공통툴 이식 / 보일러플레이트 | 덩어리 C (skills 플랫폼) |
| ⑤ 도메인별 가드레일을 경로로 함께 로드 | 덩어리 C |
| ⑥ goal/schedule 공통모듈로 재설계 | 덩어리 B (termination_gap) |

**긴급결함 (선행 수정):** generic `max_turns=0` goal 무한루프 가능.
`RalphController.run()` 은 `while True`, `max_turns=0` 이면 턴-캡 pause 비활성 →
긍정 종료는 judge(`goal_evaluate`)가 체크리스트 전부 terminal flip 할 때 하나뿐.
그런데 judge 실패 탈출구(`parse_fail_streak>=3`)가 default `SA_GOAL_JUDGE_EVERY=3` 에서
**영원히 발동 못 함** — 평가 턴 사이 게이트 턴 2개가 매번 streak 을 0으로 리셋
(`ralph_controller.py:234-240` → `state.goal_record_turn`). 도메인 batch driver 가
갖던 "claim None ∧ 활성 0 → 결정론 GoalDone" 이 추출로 사라진 자리를 아직 안 메움.
**자율 generic goal 이 바로 이 경로를 탄다 → 비용·정확성 리스크. Slice2 이전에 수정.**

## 1. 확정 결정 (AskUserQuestion + 후속 논의)

1. **착수 순서 = 엔진 자율성 먼저.** termination_gap 수정(선행) → AgentTool 을
   WorkerPool subprocess 로 교체(dynamic workflow) → 역할별/버전별 모델 라우팅.
   그 다음 skills 외부화, 마지막 위생/텍스트 정리.

2. **수직 슬라이스(state.py SMB 테이블 + web/routes/smb + web/services 8개 +
   ui/index.html 229건 + mcp/server.py + cli status + 테스트 ~20파일, 약 30파일)
   = 재부착 API 와 함께 이동.** 단 "코어 web UI 로 되살림"이 아니라 **외부 업로드
   sink 로 대체** 가능 — 재부착 부담이 오히려 줄어듦.

3. **코어 타입의 도메인 enum = plugin 완전 소유.** 코어는 string 만
   (`finding.task_type` 선례). `FindingCategory` 의 semiconductor_process/
   business_confidential, `schedule_tool._AGENT_TYPE` Literal, `findings.TaskType`
   전부 string + 등록형으로. **중요 정정:** "plugin 이 코어 web UI 에 라벨 주입"이
   아니다 — 코어 web UI 는 도메인을 렌더링하지 않는다.

4. **UI/DB 모델 = 코어는 generic finding 생산자, 도메인 표현은 코어 밖.**
   3계층:
   - **코어 엔진** = generic finding 생산자. string task_type, 중립 finding store.
     도메인 enum/테이블/대시보드 전부 없음. 코어 web UI 는 generic finding 만.
   - **도메인 skill** = 점검 플레이북 + "결과를 어디에 어떤 포맷으로 올려라"
     가이드(`api.md` 에 업무 시스템 엔드포인트/스키마). UI/DB 가 따로 필요하면
     그 별도 구현체도 skill 옆(skill repo/도메인 패키지)에, 코어가 아니라.
   - **도메인 표현/적재** = 코어 밖. 에이전트가 skill 가이드대로 실제 업무 시스템
     (티켓·SOC 포털·Confluence 등)에 업로드, 또는 별도 UI/DB 모듈이 수신.

5. **Delivery sink = (a)-done-right (도메인-프리하게 쪼갠 코어 추상화).**
   - **코어 소유** = 전달 *프로토콜*(`deliver(finding, sink_id, payload)`) +
     컨트랙트 레이어 *egress 게이트*(목적지 allowlist · 마스킹 검증). 도메인 무관.
   - **plugin/skill 소유** = sink 별 *어댑터*(MCP/HTTP/file/git/웹폼…)와 *포맷*.
     코어 하드코딩 금지, 등록형.
   - 근거 2건(사용자): ① "어차피 컨트랙트 레이어를 호출한다" → 모든 도구 호출이
     dispatch 의 `check_permission`/execution-contract 를 이미 통과하므로 egress
     규칙을 거기 박으면 그게 진짜 perimeter(별도 "모든 문 잠그기" 불필요, 컨트랙트
     레이어가 그 모든 문). ② "sink 가 MCP 로만 안 빠진다" → 이질적 transport 에선
     코어 정규화가 실재 가치(MCP 이중래핑 아님). **Slice2 어댑터 프로토콜과 같은
     패턴** — delivery 는 "claim 대신 deliver" 인 또 하나의 plugin 어댑터.
   - **Knox 정리:** Knox **메신저**(채팅) = `knox/client.py` 데몬 HTTP(127.0.0.1:8771).
     Knox **메일** = MCP(`SA_KNOX_MAIL_MCP_URL`, `owner_mail.py::call_knox_mail_tool`
     → `knox_send_email`, 현재는 사람이 web 버튼으로 트리거). 둘은 별개. Knox Mail 이
     첫 delivery sink(이미 MCP, KEEP 채널). `owner_mail.py` 의 수신자/제목/본문 검증이
     이미 (a)의 씨앗 — SMB 전용·사람 트리거를 generic·에이전트호출형으로 키우는 것.

6. **Outbound 정책 = dry-run 기본 + 자율 발송 opt-in.** 기본은 draft 생성·로그만,
   특정 sink/charter 에만 자율 발송 허용 (web default-credential opt-in 과 같은
   fail-safe 결). 완전자율(blast radius 최대)도, 항상-승인(자율성 양보)도 아닌 가운데.

## 2. 통일 원리

> **코어 = 프로토콜 + 게이트. 도메인 = 등록형 어댑터.**

v3.81 전체가 한 원리로 수렴한다. Slice2 fan-out 어댑터(claim_fn/spec_builder/
summary_fn), delivery sink 어댑터(transport_fn/format_fn), skill unlock·계약 로딩,
finding category·agent_type — 전부 "코어는 메커니즘과 안전 게이트만 소유, 도메인 데이터/
형상은 등록형으로 주입" 형태. 코어를 도메인 툴/타입/UI 로 다시 오염시키지 말 것.

## 3. 로드맵 (트랙 순서)

### 트랙 1 — 엔진 자율성 (먼저)
- **1a. termination_gap 수정 (긴급·선행).** generic 무진전 in-loop 안전 종료 추가
  (`_goal_evaluate_phase`/budget 블록: 연속 judge 턴 flips==0 ∧ new_items==[] ∧
  pending 불변 → N회 후 GoalPaused) + parse_fail_streak 탈출구 복구(게이트 턴이
  streak 리셋 안 하게). 결정론 종료(claim None ∧ 활성 0)는 어댑터 훅 자리에서
  (Slice2 와 합류).
- **1b. AgentTool 백엔드를 WorkerPool subprocess 로 교체.** 현재 `spawn_subagent`
  는 `asyncio.to_thread` thread 실행(kill 불가·병렬 없음). WorkerPool(이미 완비:
  취소·backstop·fail-closed 결과·고아정리) 소비로 교체 + 재귀 depth 제한(부재) +
  토큰 enforcement(보고만 됨) + 진행 가시화. = "dynamic workflow deep-dive"의 실체.
- **1c. 모델 버전별 라우팅.** 역할별 모델 분리 현재 없음(judge/summarizer 가 이미
  `client=` 받아 저비용 주입 가능). per-worker 는 `WorkerSpec.env SA_BEDROCK_MODEL`
  / `--profile-name` 으로 지금도 가능 — 단 `cli.py` 가 `SA_CHAT_PROFILE` 무시
  (미지정 시 YAML 첫 프로파일 o4-mini fallback) 버그 수정 필요. 진짜 턴단위는
  `LLMRequest.model` 필드 또는 ClientRouter.
- **1d. Slice2 (재정의) — 트랙 1 종착.** generic fan-out 헬퍼 + 어댑터 프로토콜
  (claim_fn/spec_builder/summary_fn, 재부착 plugin API 의 첫 조각) + Fake 어댑터 테스트.
  Slice1 WorkerPool 의 첫 호출부. **1a 의 결정론 종료(claim None ∧ 활성 0)를 여기서
  구조적으로 복원** (1a = judge 무관 임시 안전종료 / 1d = 진짜 claim 기반 종료).
  cf. 1b(AgentTool→WorkerPool)와 둘 다 WorkerPool 소비하나 모양 다름 — 1d=루프 레벨
  batch fan-out(자율 goal 이 타깃 분배), 1b=모델이 도구로 띄우는 dynamic subagent.

### 트랙 2 — Delivery sink + egress 게이트
- 코어 `deliver(finding, sink_id, payload)` 프로토콜 + 컨트랙트 레이어 egress 게이트
  (allowlist·마스킹). plugin/skill 등록형 sink 어댑터. Knox Mail 을 첫 sink 로 일반화
  (`owner_mail.py` 검증 로직 재사용, 에이전트호출형). dry-run 기본 + opt-in 자율발송.

### 트랙 3 — skills 플랫폼 (외부화 + 계약 + 보일러플레이트)
- **외부 skills dir 로드 (현재 불가 — 차단지점).** `ctx.metadata['skills_dir']` 훅은
  있으나 세팅 코드가 리포에 없음. `resolve_skills_dirs()` 추가(env `SA_SKILLS_DIRS`
  다중경로, 기본=모듈 상대) + 호출부 4곳 교체(`prompts/__init__.py:35`,
  `skill_tool.py:30·51`, `chat_session.py:59·144·167`). = 재부착 전제조건.
- **per-skill 계약 동반 로드.** trigger 매칭된 도메인의 `safety.md` 를 body 와 함께
  주입(`_auto_skill_context_for_turn`) — 무관 도메인 토큰 낭비 없음. (사용자 ⑤안 채택.)
- **공통툴 이식.** 대부분 이미 코어에 존재 — **새로 만들지 말 것**(셸/파일/python_exec/
  scan_text/todo/memory/skill/tool_search/schedule/session_search/browser/sandbox/
  agent_tool 다 있음). 진짜 빠진 것: **WebFetch/WebSearch**(기존 `url_safety` 재사용해
  연결, domain='core'). 이식 템플릿 = my_claude_code `Tool.ts` ≈ 코어 `BaseTool` 1:1.
  **도메인 툴 작성 지양** — 도메인은 skills 의 공통툴 사용 가이드로.
- **skill 보일러플레이트(scaffold).** 1순위 함정 = 디렉토리명 == frontmatter `name`
  불일치 시 silent skip. scaffold 가 자동생성 + lint 검증(frontmatter 파싱·name 일치·
  body 32KB cap·triggers 정규식 compile·trigger 충돌). resources 4종 stub(api/schema/
  snippets/safety) + unlock 매핑 안내.
