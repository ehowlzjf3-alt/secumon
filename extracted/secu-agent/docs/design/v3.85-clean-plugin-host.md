# v3.85 — 클린 플러그인 호스트

> **목표: 코어를 Claude Code / OpenCode 식 플러그인 호스트로 — "도메인 추가 시
> 코어 코드 0줄 수정".** 코어는 고정된 확장 지점(`register_*` 훅) + 안전 게이트만
> 소유하고, 특정 도메인의 존재를 알지 못한다. 새 도메인은 별도 레포에서 훅 등록만으로
> 붙는다.

## 배경 — 감사 (cleanliness 72%)

de-domain([[v3.84-de-domain-completion]]) 이후 코어를 "가상의 `dns` 스캐너가 별도
레포에서 코어 0줄 수정으로 등록 가능한가" 기준으로 20개 확장능력을 감사했다. 결과:
등록 표면(16 `register_*` 훅 + `SA_PLUGINS` 부트스트랩)은 이미 Claude Code 급이고,
8개 능력 + skills 디렉토리 auto-scan 은 이미 클린. 하지만 아직 도메인을 추가하려면
코어를 건드려야 하는 지점이 9개 남아 있었다(워커 도구셋·실행계약이 로드베어링).

## 통일 원리 (불변)

- **코어 = 프로토콜 + 안전 게이트 + `register_*` API.** 도메인 = 등록형 어댑터.
- **핵심 불변식: 코어 코드는 특정 플러그인을 위해 바뀌지 않는다.** 설치된 능력 집합은
  코드가 아니라 데이터(등록 호출)다. 코어에 `if domain == "smb"` 같은 분기가 있으면
  그것이 곧 위반이다.
- **코어 상주 기본값도 같은 공개 훅으로 등록.** operator/package_sandbox/
  finding_narrator 도구셋·실행계약, `'agent'→'operator'` 별칭은 코어가 부트스트랩에서
  일반 도메인과 똑같이 `register_*` 로 등록한다(특별 경로 없음).

## SAFETY-KEEP (전부 보존 확인)

- 읽기 전용 도구 · `url_safety` 하드블록 · `redact_secrets`/PII 마스킹
- **민감 PII(rrn/card/bank/account/phone/passport/주민/전화/계좌)는 등록 정책이
  "전부 제외"해도 절대 제외 안 됨** — 코어 가드가 먼저 실행
- **fresh-subprocess-per-spec 유지**: `register_task_contract` 는 이미-fresh 워커
  안에서 어느 계약이 도는지만 고른다 — 워커 웜풀 금지(SSO 서킷브레이커 = 프로세스
  종료로만 리셋)를 바꾸지 않는다
- web plugin 라우터는 `require_token` 의존성으로만 마운트 · evidence path-jail 코어 유지
- Knox delivery 는 `register_delivery_sink` 그대로

## 적대 리뷰 — 놓친 skill 깨짐 2건 (back-compat 복원)

5차원 리뷰 → 발견별 독립검증(9 에이전트)이 **skill-facing public 심볼 제거** 2건을
잡았다. 전체 스위트를 `SA_PLUGINS=""` 로 돌려 놓쳤으나, 실제 `.env` 는 skill 을 로드한다.

- **(HIGH) `state.ENTITY_TYPES` 제거** → skill `service/state_domain.py` 의 import
  깨짐 → `load_plugins()` 실패 → 모든 워커 rc 2 + web 기동 실패.
  **fix:** `ENTITY_TYPES = ("host","domain","url")` public alias 복원
  (`_CORE_ENTITY_TYPES = frozenset(ENTITY_TYPES)`, 내부는 등록형 유지).
- **(MED) `FindingSignal.pivot_exposed` → `enrichment_counts` 리네임** → skill
  `service_task_tools.py` 의 `FindingSignal(pivot_exposed=…)` TypeError.
  **fix:** `pivot_exposed` 필드 유지(리네임 되돌림), slot/followup_hint seam 은 유지.

추가로 자체 발견: **`'smb'`→`operator` 라우팅 완전 제거** 시 SMB 챗이 operator(34툴)→
generic(2툴) degrade → 코어에 back-compat 시드로 복원.

**실제 skill `load_plugins()` 로 세 fix 모두 재현·검증.** 교훈 = **de-domain 으로
코어 public 심볼을 제거/리네임할 때는 반드시 back-compat alias 를 두거나 skill 을
lockstep 마이그해야 한다**(skill 이 import/construct).
