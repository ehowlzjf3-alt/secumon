# v3.90 후속 — platform.devops_target `last_hunt_at → last_task_at` 리네임 (완주 블로커 ⑤, CORE-ASK)

> de-domain(hunt→task, v3.84) 어휘 리네임 시대에 **platform 소유** 테이블 하나가 코어
> 부트스트랩 마이그에서 누락됐다. 구 라이브 DB 의 `platform.devops_target` 은 `last_hunt_at`
> 잔존 → 스킬/코어 클레임 SQL 이 기대하는 `last_task_at` 부재 → github/confluence **SSO-task
> 워커가 claim 단계에서 즉사**(`UndefinedColumn`, 0 turn). additive·멱등·데이터보존.

## 증상 (라이브)
github SSO-task 워커 1타깃 실행 → `state_domain.devops_target_claim_next` 의 클레임 SQL 이
`... OR last_task_at < $5 ...` 에서 `psycopg.errors.UndefinedColumn: column "last_task_at"
does not exist` → 부모 fanout 예외 → PlanCompleted 없이 크래시. 전 devops_target 클레임 공통
(github SSO + confluence SSO 둘 다 이 테이블).

## 근본 원인 = 코어 platform 마이그 갭
- 코어 canonical DDL 은 이미 `last_task_at`(`state.py` `_PLATFORM_TABLES_DDL`) → **신규 DB 정상.**
- 코어 부트스트랩은 형제 리네임(`hunter→agent_type`, `finding_lifecycle.hunt_type→task_type`)은
  하지만 `devops_target.last_hunt_at → last_task_at` 은 안 했다 → 구 DB 영영 `last_hunt_at`.
- 스킬은 자기 소유 테이블만 수렴 리네임(`state_domain.py`: dev_web_target/web_target_domain).
  `devops_target` 은 **platform 소유라 스킬이 P2 W2 락스텝으로 의도적 제외** → 코어만이 할 수 있다.

## 설계 (도메인-프리, 멱등, 데이터보존)

| 조각 | 위치 | 내용 |
|---|---|---|
| 리네임 | `state.py` `_provision_platform_schema` | `_relocate_tables` **후**, executescript **전**. **조건부 introspection**: `last_hunt_at` 존재 ∧ `last_task_at` 부재일 때만 `ALTER ... RENAME`. |
| 안전망 | `_PLATFORM_MIGRATIONS_DDL` 첫 줄 | `ALTER TABLE devops_target ADD COLUMN IF NOT EXISTS last_task_at DOUBLE PRECISION` — 리네임 **후** 실행이라 old-only 는 데이터보존 리네임이 이기고, **둘 다 없던 초-구 shape** 도 컬럼 보장. |
| read-only 검증 | `_bootstrap_core_schema` `_txn_read_only` 브랜치 | shape-check 튜플에 `("devops_target","last_task_at")` 추가 — read-only 롤은 DDL 불가라 구 shape 를 fail-closed 로 잡아야(안 잡으면 ready 표시 후 첫 claim 사망). |

- **relocate 후 배치가 정답**: relocate 가 구 DB 의 `public.devops_target` 을 platform 으로 먼저
  옮긴 뒤라, 리네임 대상이 항상 platform 에 있음이 보장된다. (ASK 권고안 = relocate **전** 형제
  리네임 옆 qualified 배치는 public 잔류 테이블을 놓친다 → 채택 안 함.)
- **catalog 는 same-txn**: information_schema 는 같은 트랜잭션의 미커밋 SET SCHEMA 를 본다 → 스테일 없음.
- **post-condition 무조건**: RW provisioning 후 `last_task_at` 은 {old-only, both, neither,
  canonical, fresh} 전 상태에서 존재한다(리네임 또는 ADD).

## codex 적대검증 (2R) — 주요 수정
- **R1-1 (High, fail-open)**: 최초안은 `try/except: pass` savepoint 로 리네임을 감쌌다 → DuplicateColumn
  (양쪽존재)·lock timeout·손상 shape 를 **삼켜 미수렴 DB 를 ready** 로 만든다. → **조건부 introspection**
  으로 전환(예외 자체가 안 남 → savepoint 불필요, 예기치 못한 실패는 전파 fail-closed) + **neither-column
  안전망 ADD COLUMN**.
- **R1-2 (Med-high)**: read-only validate 브랜치가 `last_task_at` 을 안 봐서 구 shape 를 통과 → 튜플에 추가.
- **R1-3 (cosmetic)**: 주석 "public/core 잔류" → "public 잔류"(`_relocate_tables` 는 public 만 이관).
