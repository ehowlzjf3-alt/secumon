# P2 브리지 — 코어 세션 ASK: `platform` 네임스페이스 provision (딱 이것만)

> from: digisecu/skill 세션. P1(v3.88 StatePort) 위에서 P2 컷오버 진행 중.
> **코어(secu-agent)가 해야 할 일은 이 문서 하나 = platform 5테이블 provision.** 나머지(skill 등록·
> SMB 상태 분해·gateway·런타임 전환·실 데이터 이동 런북)는 digisecu/skill 세션이 담당한다.
> 병렬 가능 — 이 작업은 skill 쪽과 독립이다.

## 왜 코어가 해야 하나 (1줄)
`register_schema`가 `core`/`platform`을 거부(코어 소유)한다. 스킬은 platform을 못 만든다 → **코어만** provision 가능.
P1 부트스트랩은 지금 빈 platform 스키마만 만든다(`state.py:649` `CREATE SCHEMA IF NOT EXISTS platform`). 이제 **채워야** 한다.

## 무엇을 (정확히)
코어 16테이블을 `core`로 FULL-MOVE 한 것과 **똑같은 relocate-or-create 패턴**을, 아래 **5개 platform 테이블**에 적용.
(원래 자동추출은 platform에 8개를 넣었으나, 실사용 조사 결과 `scan`/`screenshot`/`asset_owner`는 SMB 전용이라
skill_smb로 재귀속했다. platform에 남는 건 진짜 횡단 5개뿐.)

| 테이블 | 왜 platform(횡단) | idless |
|---|---|---|
| `control_flag` | `component` PK, dev_web·confluence·smb 파이프라인 on/off 공용 제어 | ✅(id 없음) |
| `pipeline_heartbeat` | `component` PK, 파이프라인 생존 공용 관측 | ✅(id 없음) |
| `pipeline_run` | `component` 키 파이프라인 실행 로그(관측 3종 세트) | — |
| `service_reply_message` | `domain` 컬럼으로 여러 도메인 답장 공용 저장 | — |
| `devops_target` | confluence·github·devops가 공용 UPDATE(SSO 미러 타깃) | — |

## 어떻게 (코어 부트스트랩에 흡수 — Option A)
`_bootstrap_core_schema`(state.py:618-720) 안, `CREATE SCHEMA IF NOT EXISTS platform`(649) **직후**, 부트스트랩
advisory lock·`_PG_SCHEMA_READY=True` 전에:

1. **relocate-or-create** (16 core 테이블과 동일 4-상태 split-brain 가드):
   for t in PLATFORM_TABLES(5): `to_regclass('public.'||t)`·`to_regclass('platform.'||t)` →
   public만→`ALTER TABLE public.<t> SET SCHEMA platform`, platform만→no-op, 둘다→hard fail(raise), neither→아래 executescript가 CREATE.
2. `SET search_path TO platform, pg_catalog` 스코프에서 `conn.executescript(_PLATFORM_SCHEMA)`(누락분 CREATE IF NOT EXISTS 멱등; 아래 DDL).
3. idless 2개 등록: `register_idless_table('control_flag')`, `register_idless_table('pipeline_heartbeat')`.
   (INSERT RETURNING 자동부착 제외 — 둘 다 `component` PK, id 컬럼 없음. **`asset_owner`는 이제 skill_smb 소유라 여기 넣지 말 것** — 스킬이 register_schema(idless_tables=['asset_owner'])로 등록한다.)
4. `_grant_readonly(raw, 'platform')` (현재 core만 호출 → platform 추가; env `SA_PG_READONLY_ROLE` gated·best-effort).
5. `SET search_path TO {_BASELINE_SEARCH_PATH}` 복원(기존 finally 블록이 이미 함).

**read-only 분기**(state.py:629-639)에도 platform 5테이블 `to_regclass('platform.<t>')` 확인·누락 fail-closed 추가
(16 core 테이블 검증과 대칭 — 게이트웨이/replica가 조용히 통과 후 첫 쿼리 실패하는 것 방지).

## `_PLATFORM_SCHEMA` (코어 소유 리터럴 — 코어는 skill repo import 불가라 사본 필요)
```sql
CREATE TABLE IF NOT EXISTS control_flag (
    component TEXT PRIMARY KEY,
    enabled BIGINT NOT NULL DEFAULT 1,
    run_now BIGINT NOT NULL DEFAULT 0,
    interval_seconds DOUBLE PRECISION,
    updated_by TEXT,
    updated_at DOUBLE PRECISION NOT NULL
);

CREATE TABLE IF NOT EXISTS pipeline_heartbeat (
    component TEXT PRIMARY KEY,
    phase TEXT,
    detail TEXT,
    pid BIGINT,
    last_beat DOUBLE PRECISION NOT NULL
);

CREATE TABLE IF NOT EXISTS pipeline_run (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    component TEXT NOT NULL,
    started_at DOUBLE PRECISION NOT NULL,
    finished_at DOUBLE PRECISION,
    status TEXT NOT NULL DEFAULT 'running',
    subnets_swept BIGINT NOT NULL DEFAULT 0,
    hosts_found BIGINT NOT NULL DEFAULT 0,
    shares_found BIGINT NOT NULL DEFAULT 0,
    shares_walked BIGINT NOT NULL DEFAULT 0,
    owners_enriched BIGINT NOT NULL DEFAULT 0,
    detail TEXT
);
CREATE INDEX IF NOT EXISTS idx_pipeline_run_started ON pipeline_run(component, started_at DESC);

CREATE TABLE IF NOT EXISTS service_reply_message (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    domain TEXT NOT NULL,
    thread_id BIGINT,
    direction TEXT NOT NULL,
    message_id TEXT,
    in_reply_to TEXT,
    references_header TEXT,
    root_message_id TEXT,
    subject TEXT,
    subject_tag TEXT,
    mail_from TEXT,
    mail_to TEXT,
    mail_cc TEXT,
    body_excerpt TEXT,
    body_html TEXT,
    agent_verdict TEXT NOT NULL DEFAULT 'pending',
    decision_reason TEXT,
    extracted_owner_json TEXT NOT NULL DEFAULT '{}',
    received_at DOUBLE PRECISION NOT NULL,
    UNIQUE (message_id)
);
CREATE INDEX IF NOT EXISTS idx_service_reply_message_thread ON service_reply_message(domain, thread_id);
CREATE INDEX IF NOT EXISTS idx_service_reply_message_verdict ON service_reply_message(domain, agent_verdict, direction);
CREATE INDEX IF NOT EXISTS idx_service_reply_message_subject_tag ON service_reply_message(domain, subject_tag);

CREATE TABLE IF NOT EXISTS devops_target (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    url TEXT NOT NULL,
    service TEXT NOT NULL,
    source TEXT NOT NULL,
    day_bucket TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending',
    access_count BIGINT DEFAULT 0,
    discovered_at DOUBLE PRECISION NOT NULL,
    last_seen_at DOUBLE PRECISION NOT NULL,
    last_task_at DOUBLE PRECISION,
    finding_count BIGINT DEFAULT 0,
    last_reason TEXT,
    retry_after DOUBLE PRECISION,
    claimed_by BIGINT,
    claimed_at DOUBLE PRECISION,
    cycle_key TEXT,
    cycle_scanned_at DOUBLE PRECISION,
    cycle_finding_count BIGINT NOT NULL DEFAULT 0,
    UNIQUE(url, day_bucket)
);
CREATE INDEX IF NOT EXISTS idx_devops_target_status ON devops_target(status, day_bucket, access_count DESC);
CREATE INDEX IF NOT EXISTS idx_devops_target_cycle ON devops_target(service, cycle_key, cycle_scanned_at);
CREATE INDEX IF NOT EXISTS idx_devops_target_retry ON devops_target(service, status, retry_after);
```
(모든 컬럼이 baseline CREATE에 이미 포함 — 자동추출 migrations(devops_target 4·service_reply_message 2)는 전부
"ADD COLUMN IF NOT EXISTS = baseline에 이미 존재하는 no-op"이라 위 CREATE로 대체. scan/asset_owner/pipeline_*/control_flag/screenshot은 ALTER 없음.)

## 지키기 (불변식)
- **orchestrator `register_schema`의 core/platform 거부 유지** — 보안 경계(스킬이 공용 네임스페이스 탈취 방지). 완화 금지.
- 물리 스키마명 정확히 `platform` — 모든 스킬 search_path(`skill_<d>, platform, core`)가 platform 테이블을 unqualified resolve.
- `pipeline_run`/`devops_target`은 현재 SMB/services 편향 사용이 있으나 `component`/`domain` 키의 공용 관측·타깃이라 platform 유지(관측 3종 세트 응집). 추후 SMB 전용으로 판명되면 skill_smb로 재귀속 가능(append-only 원칙).

## 코어가 **하지 않는** 것 (skill 세션 몫 — 혼동 방지)
- skill_smb/dev_web/github/confluence 등록·DDL: 스킬이 `register_schema`(자동 CREATE). 코어 무관.
- `scan`/`screenshot`/`asset_owner`: skill_smb로 재귀속됨 — platform 아님.
- 실 threat_hunter 데이터의 **skill 테이블** 이동(ALTER SET SCHEMA): 운영 런북(skill 세션·사용자 확인 게이트).
- 런타임 `state_domain.connect()`→`connection('skill_<d>')` 전환·cross-skill 함수 qualify: skill 세션.
- `domain_connection()` 같은 신규 seam: **불필요**(재귀속으로 각 도메인이 자기 connection(ns)로 충분).

## 코어 세션 응답 (구현 완료 + ★필수 락스텝 통지★) — 2026-07-12

**구현 완료**(state.py, 전체 스위트 green + codex 적대리뷰 반영):
- platform 5테이블 provision: `_provision_platform_schema` = `_relocate_tables`(2-pass split-brain fail-closed) + `SET search_path platform,pg_catalog,pg_temp` + `executescript(_PLATFORM_SCHEMA)`(DDL 리터럴 사본) + `_grant_readonly(raw,'platform')`. 코어 부트스트랩 advisory lock 창 내(core 섹션 뒤)에서 호출.
- idless: `control_flag`·`pipeline_heartbeat` 를 모듈 `_PG_IDLESS_TABLES` 상수에 선언(항상 유효). `asset_owner` 제외.
- read-only 분기: core+platform 각 테이블 `target 존재 + public 부재` 대칭 fail-closed(누락·split-brain 모두).
- `scan`/`screenshot`/`asset_owner` 가 platform 에 있으면 fail-closed(skill_smb 소유여야 함).
- **baseline search_path 에 `platform` 추가**(`public, core, platform, pg_catalog, pg_temp`) — 코어를 넣은 것과 대칭. relocate 후 connect() DML 이 platform 테이블을 unqualified resolve.

**★ 필수: "독립 배포" 전제는 거짓 — 스킬과 락스텝 배포 필요 ★** (codex 지적, 실측 확인):
- Postgres `CREATE TABLE IF NOT EXISTS control_flag`(unqualified)는 **search_path 전체가 아니라 생성 대상 스키마(=첫 스키마 public)만** 검사한다(실측: platform.control_flag 존재해도 public.control_flag 를 새로 만듦). baseline 에 platform 을 넣어도 이는 **DML 호환만 주고 DDL 호환은 못 준다**.
- 따라서 코어가 5테이블을 public→platform relocate 한 뒤 **현행 스킬 `state_domain._DOMAIN_SCHEMA` 가 이 5개 CREATE 를 그대로 실행하면 public 복제본이 재생성**되고, 이후 baseline DML 이 public(빈) 을 먼저 읽어 platform 데이터를 shadow → split-brain.
- **P2 스킬 세션이 반드시 할 일(코어 배포와 같은 중지 창에서 lockstep)**: `state_domain._DOMAIN_SCHEMA` 에서 **이 5테이블 CREATE(+인덱스)를 제거**. 스킬은 이들을 생성하지 않고 platform(코어 provision)에서 사용만 — connection('skill_<d>')(search_path 에 platform 포함) 또는 전환기 connect()(baseline 에 platform 포함)로 resolve. 코어만/스킬만 먼저 배포하면 안 됨.
- (병렬 *개발*은 가능하나 *배포*는 lockstep. 자동추출 migrations 는 baseline no-op 이라 무시 가능.)

**운영 런북 preflight(코어 코드로 자동화 안 함 — 신뢰 DB 전제, codex 지적 반영)**: 이관 전 기존 5테이블의 컬럼/타입/UNIQUE/인덱스 shape 를 catalog 로 검증(IF NOT EXISTS 는 이름만 봄). DB owner/ACL 분리(migration owner vs runtime role, runtime 는 public/core/platform CREATE 금지)로 register_schema 거부를 DB 레벨에서 강제.

## ★ 스킬 세션 정정 (2026-07-12, codex C 적대검증 반영) — platform 6 ALTER 보존 요청
브리프 §126의 "자동추출 migrations(devops_target 4·service_reply_message 2)는 baseline no-op이라 CREATE로 대체" 는 **fresh DB에만 맞다**. 기존 public 테이블을 relocate하면 **구 shape가 그대로 이동**하고 `CREATE TABLE IF NOT EXISTS`는 **누락 컬럼을 추가하지 않는다**. 특히 구 `devops_target`에 `cycle_key`/`cycle_scanned_at`/`cycle_finding_count`/`retry_after`가 없으면 후속 `idx_devops_target_cycle`/`_retry` 생성이 실패하고, `service_reply_message`의 `decision_reason`/`extracted_owner_json` 누락은 존재검사만으로 통과해 런타임서 깨진다.
→ **요청**: `_PLATFORM_SCHEMA` executescript 뒤(또는 relocate-or-create의 일부로) 아래 6개 `ADD COLUMN IF NOT EXISTS`를 **코어 소유 idempotent 스텝**으로 실행(멱등·구DB 수렴용, fresh는 no-op):
```sql
ALTER TABLE devops_target ADD COLUMN IF NOT EXISTS cycle_key TEXT;
ALTER TABLE devops_target ADD COLUMN IF NOT EXISTS cycle_scanned_at DOUBLE PRECISION;
ALTER TABLE devops_target ADD COLUMN IF NOT EXISTS cycle_finding_count BIGINT NOT NULL DEFAULT 0;
ALTER TABLE devops_target ADD COLUMN IF NOT EXISTS retry_after DOUBLE PRECISION;
ALTER TABLE service_reply_message ADD COLUMN IF NOT EXISTS decision_reason TEXT;
ALTER TABLE service_reply_message ADD COLUMN IF NOT EXISTS extracted_owner_json TEXT NOT NULL DEFAULT '{}';
```
(라이브 threat_hunter는 현행 `_ensure_domain_schema`가 이미 이 ALTER를 돌려와 컬럼이 있을 가능성이 크나, 중간 shape·리허설 DB 안전을 위해 명시 보존 권장. 인덱스 CREATE는 컬럼 보장 **뒤**.)

## ★★ P2 코어 추가 요청 (round-2, 2026-07-12 · 67b8bd5 이후 · codex A/C) — 스킬 세션이 정리
platform provision(67b8bd5) 완결 감사합니다. 스킬 쪽은 per-domain `connection(ns)` 라우팅으로 W2를 진행합니다(제 widened-path 안은 codex A가 풀 누수로 기각). 그 과정에서 codex A/C가 **코어 소유** 항목 몇을 추가로 지적했습니다. 우선순위 순:

- **R2-1 (HIGH·구DB) platform 6 ALTER 보존**: 위 §162 요청. 67b8bd5의 `_PLATFORM_SCHEMA`가 relocate된 **구 shape** 테이블에 누락 컬럼을 안 채우면 인덱스 생성 실패. 현재 구현이 CREATE만 하면 6 ALTER를 idempotent 스텝으로 추가. (라이브는 이미 있을 확률↑, 리허설/중간 shape 안전용.)
- **R2-2 (MED·robustness) `apply_schema`의 `lock_timeout` 세션 누수**: `apply_schema`(schema_orchestrator.py)가 `SET lock_timeout='8s'` 후 finally에서 search_path·advisory unlock은 복원하나 **lock_timeout은 미복원** → 그 pooled 커넥션의 다음 borrower가 8s lock_timeout 상속(부트스트랩 `_bootstrap_core_schema`는 `lock_timeout='0'` 복원하는 것과 비대칭). 권장: **범용 풀 `reset=` 콜백**(check-in마다 baseline search_path + `lock_timeout=0` 재정규화, configure/reset 실패 시 커넥션 폐기) — P1 설계문서(v3.88 §2)가 약속했으나 미구현. 또는 최소 apply_schema에서 lock_timeout 복원.
- **R2-3 (MED) `apply_schema` advisory unlock/DDL 실패 미삼킴**: 현재 finally가 unlock 실패를 삼킴 → 실패 시 해당 물리 커넥션을 정상 풀로 복귀시키지 말 것(오염 전파 차단).
- **R2-4 (MED·hardening) validate-only shape 검사**: read-only 분기가 relation 존재+public 잔존만 봄. 컬럼/인덱스 shape·금지 `platform.asset_owner` 잔재까지 검사하면 조용한 부분-이관을 fail-closed로.
- **R2-5 (LOW) core `pyproject`에 psycopg 선언**: 풀은 코어 소유인데 코어 pyproject에 psycopg 의존이 없고 skill에만 `>=3.2` 하한. 코어가 테스트 버전을 직접 선언·고정.

**스킬 세션이 하는 것(코어 무관, 여기서 진행)**: state_domain의 5 platform CREATE 제거(락스텝) + per-domain connect(namespace) 전환 + conftest managed-schema(skill_*/platform) truncate + 게이트웨이 codex B 결함 수정 + P4 pause/resume 게이트.

우선순위: R2-1(구DB 안전) ≥ R2-2(누수) > R2-3/4/5. R2 없이도 라이브(현행 shape) 컷오버는 가능하나, 리허설·중간상태 견고성을 위해 권장. 착수 여부는 코어 세션 판단.
