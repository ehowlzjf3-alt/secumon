### U3. 8765 분리 — 코어 = 엔진 + 채팅 (결정 ②④⑦⑧ 집행)

**코어 유지(8765):** app factory+lifespan(scheduler loop·MCP bootstrap·browser reaper),
index, chat(WS+세션 CRUD), approvals, scheduler, evidence, health(**재작성**: db ok +
chat_session/schedule/finding 카운트 — smb 카운트 제거), generic findings CRUD

### U4. TUI — `secu-agent chat` (rich REPL, 결정 ⑨)

현재 터미널 대화 수단 부재(web+브라우저 또는 Knox 뿐). ChatSession 은 frontend-중립이라 신규 진입점만 필요.

- 이벤트 렌더러 추상화: TextChunk(스트리밍 마크다운)/ReasoningChunk/ToolCallStarted·Completed/LoopError/Goal* 를 rich 로 — worker CLI(agent/cli.py 의 raw stderr print)와 공유
- keystroke ApprovalResolver + `frontend_capabilities={'interactive_approval'}` (없으면 plan mode 등 게이트 도구 소실)
- 세션 list/resume/new (엔진의 session_id 복원 기능을 터미널에 노출), `/compact` 등 슬래시 명령 — WS 핸들러 안의 명령/턴제어 로직을 frontend-중립 레이어로 추출(web/knox/TUI 공유)
- 플래그: `--profile/--evidence-dir/-s(--skills)` + 시작 배너(해석된 프로파일·모델·skills dirs 출력)
- **`-s` 시맨틱(단일 resolver 원칙):**
  - `-s name1,name2` = 이름 필터 — load_skills_all 출력에 대해(first-wins dedup **후**), 미존재 이름 = fail-loud
  - `-s /path` = 추가 dir — **additive**(core-first 유지, 교체 금지 — v3.81 first-wins fail-safe 보존)
  - 선택은 세션 시작 시 고정(immutable), 3개 로드 경로(시스템프롬프트 인덱스 / trigger 자동주입 / skill 도구) **모두** 동일 selection 통과 — 한 경로라도 빠지면 deselect 된 skill 이 trigger 로 무음 재주입되거나 not_found 불일치 발생
  - skill_tool `ctx.metadata['skills_dir']` 의 "교체" 시맨틱 폐기(additive 로 교정 — 현재 코어 dir 보호 우회 구멍)
- `python -m secu_agent` __main__ 추가(cli.main 위임)
