# v3.90 후속 — terminal-tool 계약 게이트 (완주 블로커 #2, CORE-ASK)

> candidate ledger 침묵 게이트의 **형제**. 그건 "후보를 관찰하고도 제출·기각 없이
> 침묵(미정산)"을 지키고, 이건 "실질 작업은 다 했는데 완료 신호(종료 상태 도구)를
> tool_use 가 아니라 assistant **텍스트로 서술**하고 끝냄(미종료)"을 지킨다.
> 약한 모델(gauss/gpt-oss)의 실패모드 — tool call 을 산문/JSON 으로 적는 것 — 대상.

## 증상 (라이브)

confluence keyword_search 워커(gauss). 검색·triage·오검출 없는 판정까지 다 옳게
하고, turn 7 에서 `confluence_search_set_status(...)` 를 **tool_use 가 아니라 최종
텍스트로** 냄 → `saw_terminal=False` → `error_crash rc=1`. 전 도메인 공통(set_status
종료 워커 전부: confluence/github/smb).

## 설계 (도메인-프리, opt-in)

| 조각 | 위치 | 내용 |
|---|---|---|
| reminder | `agent/terminal_contract.py` | `build_terminal_tool_reminder(names)` 순수 함수(도메인 인자 스키마 하드코딩 안 함) + `REQUIRE_TERMINAL_TOOL_KEY`/`TERMINAL_INVOKED_KEY` |
| 게이트 | `engine.py` text-only 캐스케이드 | plan→finding→candidate_ledger→execution→**terminal**. 발동: `require_terminal_tool` & 플래그 미set & **광고된** 종료 도구 존재. 리마인더 캡2 → `contract_violation` |
| 플래그(invoked) | `tools/invoker.py` `_execute` | 종료 도구의 **실제 execute 진입 직전**(모든 실행경로 canonical choke point)에 원자 기록. require_terminal_tool opt-in |
| config | `engine.py` `QueryConfig` | `max_terminal_tool_reminders=2` |

- **opt-in**: 워커 cli 가 `metadata["require_terminal_tool"]=True`. chat/operator 미설정 → byte-for-byte 불변.
- **광고 판정**: deferred 종료 도구는 unlocked 여야 광고 → `registry.get(n) & (not deferred or n in unlocked)`.
  광고된 부분집합(`_advertised_terminals`)을 predicate·reminder·violation 에 동일 사용(잠긴 도구 요구 금지).

## codex 적대검증 (7R, gpt-5.6) — 주요 수정

- **R1-3**: notify/플래그 위치·`is`-레지스트리·CancelledError 격리(초기 설계 반복).
- **R4-6 핵심 = 플래그 시맨틱 수렴**: "종료 도구가 실제로 **실행**됐나"의 신뢰 신호를 어디서
  잡나. 최종 = **invoker `_execute` choke point**(execute 진입). task 생성/디스패치 시점
  (`_start_locked`)은 취소/검증/권한 실패로 execute 미도달한 도구를 오분류(R6-1). 성공-시
  `_record_tool_event` 기록은 yield 후라 consumer close 시 유실(R6-3). choke point 하나로 통일.
- **R6-2/R6-4**: 스트림·도구실행 단계 예외/조기close 시 실행기 취소(+`aclosing(_run_tool_calls)`
  으로 하위 태스크 동기 종료) → leak/지각 실행 감소. 잠긴 deferred 종료 도구를 reminder/violation
  에서 제외(광고 부분집합).
- **하네스 배선 버그(R6, 별건이지만 게이트 무력화 원인)**: `GuardedHarness.run()` 이
  `context.unlocked_tools`(스킬 `_unlock_all` 이 채운 화이트리스트)를 `run_query` 에 전달 안 해
  빈 set 으로 wipe → deferred 종료 도구 미광고 → 게이트 무력. `unlocked_tools=self.context.
  unlocked_tools` 전달로 수정(ToolContext 기본 빈 set 이라 non-skill 무변).

## 정직한 경계 (pre-existing, 이 ASK 범위 밖)

- **executor cleanup on abnormal consumer-close**: `run_query`(async gen)는 LlmCallMeasured/
  TextChunk 등 **개별 yield 마다** 실행기·`_run_tool_calls` 동시 태스크를 완전 취소하지
  않는다. consumer 가 그 지점에서 aclose/cancel 하면 도구가 반환 후 leak 실행될 수 있다
  (codex R7-1/R7-2). **이 게이트가 만든 문제가 아니라 코어 루프의 pre-existing async-gen
  cleanup 사안** — 부분 완화(스트림·도구실행 단계 except + aclosing)만 넣고, 전 턴을 감싸는
  executor-lifetime cleanup 은 별건으로 남긴다. **워커 사용경로엔 무영향**: 워커는 harness
  queue 로 전 이벤트 소비(mid-turn aclose 없음), abort 는 signal→abort monitor 가 취소.
