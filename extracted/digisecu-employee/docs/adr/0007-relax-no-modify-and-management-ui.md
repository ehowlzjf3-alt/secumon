# ADR 0007 — 무수정 완화 · 단일 관리 UI · 파드 순수 워커 · 조합형 섹션

- 상태: Accepted (M1)
- 관련: §1, §6, ADR 0005, ADR 0006
- 배경: 사용자 확인 — 세 저장소 모두 본인 소유, 운영 전(설계 단계)이라 수정 가능. SMB 외 도메인은 webapp 미구현.

## 결정
1. **무수정(§1·§6) 완화 → "신중한 수정 허용"**. 단 유지:
   - **안전 불변식은 성역**(read-only 점검·크리덴셜 기록만·POP3 DELE 금지·lockout·egress 허용목록·PII 마스킹). 변경 금지.
   - **엔진 코어의 plugin/attach 설계 유지** — 도메인프리 코어 + 등록형 도메인은 좋은 구조. 이유 없이 갈아엎지 않고, 수정은 주로 스킬/데이터 쪽.
2. **finding 관리 = 단일 제네릭 React 관리 UI**(우리 콘솔). 도메인별 webapp을 살리지 않음(SMB만 있었고 그것도 대체). 4개 도메인 균일·톤온톤.
3. **파드 = 순수 워커** — 엔진이 데이터만 생산(state_domain). **UI는 전부 우리 콘솔**. 파드 webapp/iframe/딥링크 불필요(이전 톤·인증 논쟁 소멸).
4. **데이터 이음새 단순화** — 관리 오버레이(트리아지·상태·담당·메모)를 `state_domain` 확장 또는 스킬의 콘솔용 read/write API로. 별도 미러 DB+조인 불요. (§3-3 "유일 접근 경로" 규율은 유지 — 이제 write도 그 경로로.)
5. **워크스페이스 = 조합형 섹션(열린 레지스트리)** — `finding>report` 고정 아님. 섹션 타입(metrics/findings/reports/…)을 등록하면 어떤 워크스페이스에도 붙음. 향후 SOC 분석·알림·케이스 등이 **섹션 등록만으로** 확장.

## 결과
- 갱신: §6 무수정(완화), ADR 0006(강화·webapp 완전 폐기), ADR 0005/§3-3(경계 단순화 가능·규율 유지), M4 게이트웨이(read-only → read/write).
- 불변: 안전 불변식, 코어 attach 아키텍처, "SMB 점검 로직 재구현 금지"(이미 잘 돎 — 수정 가능해도 재작성 안 함).
- 코드: `web/src/workspaces/` = 제네릭 뷰 + 섹션 레지스트리(`sections/`) + 도메인 디렉토리(섹션 조합) + finding 상세 드로어·트리아지.
