요청 저장

는 무엇을 끝내야 하는지, 는 어디까지 진행됐는지다. 은 검증할 생각, 는 그 생각을 지지하거나 반박할 관측이다. 는 확인할 일을 실행 순서로 연결한다.

항상 오래 생각해야 할까?

빠르게 fast

간단한 업무를 좁은 범위에서 처리한다. 제한에 닿았다고 목표 완료로 표시하지 않는다.

자동 auto

직접 처리로 시작하고 반증·복잡성이 있으면 허용 범위 안에서 조사 전략으로 확장한다.

깊게 deep

조사 전략으로 시작한다. 충분한 근거가 있으면 불필요한 추가 호출 없이 종료할 수 있다.

모드의 실행 규칙은 로컬 검증했다. 실제 모델의 최적 기본값·속도·정확도는 아직 측정하지 않았다.

04 / HOW WE WORK

만드는 방법과, 일하는 방법

개발 과정의 방법론과 완성될 에이전트가 업무를 수행하는 방법론을 구분해서 읽으면 이해가 쉽다.

우리가 코어를 개발해 온 순서

01개념

무엇을 해결하고 어떤 의미를 지킬지 정한다.

02계획·판정 기준

정상·실패·복구에서 기대할 결과를 구체화한다.

03작은 단위 구현

공통 계약을 유지하며 한 실행 경로를 연결한다.

04실행·검증

기능 시험과 기존 경로의 회귀 검사를 수행한다.

05결과·결정 저장

성공·실패·한계·다음 작업을 파일로 남긴다.

스킬을 형식적으로 호출하는 절차는 필수가 아니다. 필요한 지침만 사용한다. 현재는 사용자의 요청으로 구현 변경을 멈추고 수정 범위와 현황을 검토한다.

에이전트가 업무를 수행할 때의 방법

01

필요한 만큼 계획한다

간단한 일은 짧게, 불확실성이 크면 경쟁 가설과 판별 질문을 만든다. 모든 기능마다 별도 모델을 호출하지 않는다.

02

필요한 도구·기억·지침을 찾는다

후보 검색 → 정확한 형식 조회 → 현재 권한/버전 검사 → 호출. 사용한 결과가 유효하면 재사용한다.

03

근거가 바뀌면 판단을 갱신한다

새 증거와 반증을 기존 가설에 연결한다. 필요한 작업만 수정하고 끝난 일을 무조건 반복하지 않는다.

04

불명확하면 기록을 보존한다

확인되지 않은 효과나 사용량을 0 또는 성공으로 바꾸지 않는다. 응답이 저장돼 있으면 원본을 재사용해 복구한다.

05

완료와 전달까지 확인한다

명령 실행, 결과 채택, 목표 충족, 사용자 전달을 서로 다른 상태로 관리한다.

05 / ROADMAP

전체 계획과, 아직 남은 일

아래 31개 항목은 초기 P0~P6의 기능별 이력이다. 당시 상태를 보존하며, 현재 착수 순서나 완료율로 사용하지 않는다.

현재 구현 순서는 C01~C10이다.
C01 담당·설정 → C02 지속 대화·compact → C03 개인 기억 → C04 범용 대화·추론 → C05 도구·기억·스킬 효율 → C06 채널·업무 배치 → C07 게시판·아카이브 → C08 동료·반론·자원 → C09 에이전트 간 통신(A2A)·상시 임무 → C10 설치·운영.
같은 담당의 여러 항목 수집을 일반 CLI·Web에 연결했다. 저장된 원응답을 먼저 정산하고 필요한 대화 요약과 문맥 복원을 거친 뒤, 모델이 명시한 완전한 저장 결과의 후속 시도를 로컬에서 소비한다. 새 페이지가 필요하면 연결을 기다리고 명시 온라인 재열기에서 다음 페이지나 실패 항목만 요청한다. 문맥 선택은 실제 한도에 들어오는 선택 항목 일부를 유지하도록 수렴을 고쳤다. 현재 허용된 원근거의 최초 카드·본문 조회만 준비 진전으로 인정한다. 동일 내용·파생 복사본의 반복 조회는 기본 무진전 한도 3을 초기화하지 않으며 준비 진전은 새 사실이나 목표 완료가 아니다.
다음 필수 단위는 collection 페이지별 전송 후 원응답 보관·known usage 정산과 현재 본문 채택의 분리다. 기존 단순 읽기의 보관 인수와 구분하며 아직 별도 구현·검증이 필요하다. 원문 재검증·조회 비용 개선도 측정과 경합 검증을 거쳐 진행한다. C05 전체와 C01~C10 전체 goal은 미완료다. 실제 모델/API 시험은 중단 상태다. 실제 모델 의미 품질·사용량·취소·tokenizer 적합성, 사내 MCP·Knox·운영 배포는 미검증이며 native Windows runtime/file의 미구현·미연결 부분과 검증, PostgreSQL 구현·검증도 남아 있다.

06 / DESIGN REVIEW

이전 검토에서 확인한 기준

2026.09.06에 정리한 협업·자료·자원 연결부의 검토 기록이다. 이후 구현은 현재 C01~C10 계획에 연결하며, 아래 표 자체를 최신 구현 완료 목록으로 보지 않는다.

확인된 사용자 방향
범용 에이전트 · 고정 리드–워커 강제 없음 · 모든 역할의 사내 모델 사용 가능 · 과도하게 복잡한 게시판 흐름 재검토 · 수정 내용을 정리한 뒤 다음 구현.
항목유지할 기반수정·검토할 내용
역할 구조공통 runtime은 유지고정 리드–워커 대신 업무별 요청자·조사자·검토자. 조정자는 선택한다.
모델 배치모델 adapter와 호출 장부 유지모든 역할의 사내 모델 사용을 지원하고 역할과 모델 위치를 분리한다.
원문 접근현재 권한·출처 검사 유지리드/대화 담당이라는 이름만으로 원문을 차단하지 않는다. 업무 정책으로 결정한다.
게시판글·인용·요청·알림 기반 유지참여자가 읽는 공유 게시판을 기본 후보로 검토한다. 매 글 승인·가공은 강제하지 않는다.
응답 책임의무와 처리 위치 저장 유지관측글은 선택 반응, 질문·위임은 응답 상태 관리. 미응답 처리와 실행기를 연결한다.
자원 관계배정·정산·반환 장부 유지작업별 비용 장부와 에이전트 조직을 분리한다. 모든 질문을 자식 작업으로 만들지 않는다.
수락 판단무단 업무 실행 차단 유지수락 전 모델 전면 금지가 수락 판단 자체를 막는지 검토한다. 자체 자원 사용은 후보안이다.
사람 대화조용한 접수·결과 중심 채널 유지대화 담당을 모든 내부 협업이 경유하는 필수 상위 에이전트로 만들지 않는다.

네 가지 관계를 분리한다

  • 협업: 누가 누구에게 질문하고 답하는가
  • 자원: 어느 작업이 비용을 부담하는가
  • 권한: 누가 어떤 자료를 읽고 전달하는가
  • 모델: 어느 실행 환경에서 추론하는가

아직 열어 둔 선택

  • 게시판의 공유 범위와 원문 접근 정책
  • 강한 격리가 필요한 배치의 공개 절차
  • 수락 판단에 쓸 자원의 소유 방식
  • 조정자와 미응답 재배정의 최소 실행 정책
원래 설계도 고정 리드 계층을 강제하지 않았다. 이번에는 특정 요청의 지원/수행 관계가 모든 협업의 조직도나 자료 권한으로 굳어지지 않게 점검한다.

검토가 끝난 뒤의 작은 구현 순서

  1. 역할·모델·자료·자원의 관계와 기본 협업 사례를 정한다.
  2. 현재 코드에서 영향을 받는 연결부를 확인한다.
  3. 독립 역할의 요청·응답부터 작은 단위로 연결한다.
  4. 자원 조정·미응답 처리·선택 격리를 확장하고 회귀 검증한다.

코드 용어를 일의 언어로

이름과 변수는 일을 구분하기 위한 표지다. 영문 이름과 쉬운 설명, 구체적인 예시를 함께 읽어 보자. 본문의 초록색 점선 용어도 눌러 볼 수 있다.

93개 용어

목표

Goal / goal

업무가 끝났다고 판단할 목적·범위·완료 조건의 묶음.

예 · “현재 보존기간을 독립 근거 두 개로 확인한다.”

업무 상태

State / WorkState

지금까지의 계획·시도·근거·가설·의무·사용량을 보관한 업무 기록.

예 · “문서 한 개 확인, 다른 문서 응답 대기.”

실행 체계

Runtime

모델·도구·저장·복구를 연결해 실제 작업을 진행시키는 프로그램.

예 · 모델이 계획하면 runtime이 검사하고 도구를 실행한다.

계획 제안자

Planner

다음에 무엇을 확인하거나 실행할지 제안하는 구성요소. 모델이 맡을 수 있다.

예 · “문서 조회 후 개정 이력을 확인하자.”

계획 검사기

Plan validator

제안된 계획의 형식·도구·권한·순서·근거 연결을 검사하는 코드. 내용의 진실을 만능으로 보장하지 않는다.

예 · 없는 도구나 순환하는 선행 관계를 거절한다.

작업 선행 관계도

Task graph / DAG

작업별로 무엇을 먼저 끝내야 하는지 표현한 연결. 한 계획 안의 선행 관계는 순환하지 않게 제한한다.

예 · 자료 읽기 → 비교 → 결과 작성.

실행기

Executor

실행할 수 있는 작업을 골라 도구를 호출하고 결과를 기록하는 구성요소.

예 · 현재 계획에서 자료 조회 작업을 실제 실행한다.

검증할 가설

Hypothesis

맞는지 확인해야 하는 잠정 설명. 지지 근거와 반증 조건을 함께 관리한다.

예 · “문서 차이는 개정 시점 차이 때문일 것이다.”

반증 근거

Counterevidence

현재 가설과 맞지 않거나 가설이 틀렸음을 보여주는 자료.

예 · 90일 가설과 충돌하는 최신 30일 규정.

재계획 / 재계획 횟수

Replan / replans

새 근거나 제약 때문에 실행 계획을 바꾸는 것. 같은 계획을 유지하는 가설 평가와 구분한다.

예 · 개정 이력 조회 작업을 추가한다.

판단 근거

Evidence

출처·관측 시각·원본 참조·현재 유효성 등이 연결된 관측 자료.

예 · 어느 문서의 어떤 버전에서 30일을 확인했는지 기록한다.

원출처 계보

Lineage / provenance

자료가 어디에서 나와 어떤 복사·가공을 거쳤는지 나타내는 관계.

예 · 같은 문서를 두 에이전트가 인용해도 원출처는 하나다.

저장된 원본·산출물

Artifact

응답, 파일, 화면 등 실제 내용을 저장한 객체. 상태에는 그 객체의 참조를 남긴다.

예 · 원래 도구 응답 JSON이나 문서 파일.

이번 모델 입력 문맥

Context

모델이 이번 호출에서 볼 목표·업무 상태·대화 요약·최근 원문·근거·도구 설명·지침의 묶음.

예 · 저장된 전체 이력은 보존하고, 이번 호출에는 검증한 요약과 최근 발언을 담는다.

활성 문맥 정리

Compact

원문을 보존하면서 현재 입력을 줄이는 과정. 도구 설명을 선택해 내리는 일과, 대화 앞부분을 모델로 요약하는 일은 별도 경로다.

예 · 앞부분은 요약하고 최근 발언은 원문으로 이어 붙인다. 작업 완료나 compact가 대화 초기화를 뜻하지 않는다.

재개 기준점

Checkpoint

중단 뒤 어디부터 계속할지 알 수 있도록 저장한 상태와 참조.

예 · 수집 10개 중 6개 완료와 다음 조회 위치.

장기 기억

Memory / Knowledge

대화 이력이나 세션 요약과 별도로 보관하는 경험·사실·선호·절차. 사용할 때 담당·사용자 범위와 출처·현재성을 확인한다.

예 · 대화 요약은 자동으로 장기기억이 되지 않는다. C03은 발언을 지정해 저장하고 새 대화에서 선택·회상하는 흐름을 연결했다.

실행 도구

Tool

모델이 직접 할 수 없는 조회·입력·계산 등을 수행하는 함수나 외부 기능.

예 · 문서 읽기, 자료 검색, 화면 입력.

도구 목록·검색대

Tool catalog

사용 가능한 도구의 후보와 버전·용도를 찾는 목록.

예 · “문서 검색”에 맞는 도구를 찾는다.

데이터 형식 약속

Schema

필드 이름·자료형·필수 여부·허용 범위를 정한 규칙.

예 · maxPosts는 글을 최대 몇 개 읽을지 나타내는 숫자다.

도구 실행 중개기

Tool broker

현재 작업·권한·도구 버전을 확인한 뒤 실제 도구에 연결하는 구성요소.

예 · 허용됐던 도구라도 실행 직전 권한이 바뀌면 막는다.

이어 읽을 위치표

Cursor

큰 목록을 나눠 읽을 때 다음 구간을 식별하는 값. 대개 현재 목록 버전과 함께 사용한다.

예 · 첫 20개를 읽은 뒤 다음 20개를 읽는다.

묶음 호출 / 나눠 읽기

Batch / pagination

여러 요청을 묶거나 큰 결과를 페이지로 나눠 처리하는 방법.

예 · 8개 성공·2개 실패이면 실패한 2개만 재시도한다.

재사용 보관

Cache

이미 얻은 자료를 제한된 기간·용량 안에서 재사용하는 방식.

예 · 본문은 재사용하되 원본이 바뀌었는지 확인한다.

선택해서 읽는 업무 지침

Skill

업무 수행 방법을 설명한 자료. 필수 실행 엔진이나 권한 자체는 아니다.

예 · 문서 비교를 할 때 필요한 비교 지침.

지침 관리

Guidance

필요한 지침의 목록·본문·버전·선택 이유를 관리하는 공통 기능.

예 · 현재 업무에 필요한 지침 버전만 불러온다.

업무 방법론

Methodology

어떤 순서와 기준으로 문제를 풀지 정하는 방법.

예 · 경쟁 가설을 세우고 서로 구분할 증거를 찾는다.

업무 배치 묶음

Bundle

역할·도구·지침·정책·완료 기준·평가 사례를 한 업무용으로 구성한 묶음.

예 · 문서 비교용 배치와 관측 검토용 배치.

실행 방식 선택

Mode

빠르게·자동·깊게처럼 계획의 범위와 진행 전략을 고르는 값.

예 · 복잡한 반증이 생기면 자동 모드가 조사를 확장한다.

검증된 진척

Progress

새 근거·가설 평가·완료 조건 충족 등 실제로 앞으로 나아간 변화.

예 · 같은 자료를 새 ID로 다시 읽는 것은 새 진척이 아니다.

실행 자원 한도·장부

Budget

모델/도구 호출·토큰·재계획 등 사용할 수 있는 몫과 실제 사용량. 사용자 대화 턴 수나 금액만을 뜻하지 않는다.

예 · 도구 호출 20회 중 8회를 다른 작업에 배정한다.

예약된 몫

Reserved / reservation

아직 사용이 확정되지 않았지만 다른 작업이 중복 쓰지 못하게 확보해 둔 양.

예 · 응답을 잃은 모델 호출의 토큰 예약은 보류한다.

사용량 정산

Settlement

실제 사용한 양과 끝나지 않은 양을 확인해 장부에 반영하는 절차.

예 · 종료 확인 후 사용 3회는 남기고 미사용 5회 몫은 반환한다.

배정 식별값

grantId

특정 작업에 자원을 나눠준 기록을 구별하는 ID.

예 · 같은 grantId를 다시 정산해도 이중 반환하지 않는다.

도구 호출 횟수

toolCalls

도구 실행에 쓰는 논리적 사용량 항목. 실제 네트워크 왕복 수와 항상 같지는 않다.

예 · 한 묶음 도구 안에서 여러 원격 요청이 일어날 수 있다.

모델 호출 횟수

modelCalls

계획·평가 등에 모델을 호출하는 사용량 항목.

예 · 채팅 한 턴에서 모델이 여러 번 호출될 수도 있다.

모델 텍스트 처리 단위

tokens

모델이 입력과 출력을 나눠 처리하는 단위. 글자 수와 일치하지 않는다.

예 · 현재 추정값과 실제 모델 보고 사용량은 구별한다.

작업 마감 시각

deadlineAt

이 업무가 실행 가능한 마지막 시점을 저장한 값.

예 · 재시작했다고 원래 마감이 자동 연장되지는 않는다.

업무 식별값

workId

대화가 바뀌거나 실행기가 재시작돼도 같은 업무를 찾기 위한 ID.

예 · work-17이라는 업무를 새 채팅에서 이어본다.

대화 식별값

conversationId

사람과 주고받는 대화 묶음을 구별하는 ID. 하나의 대화에 여러 업무가 연결될 수 있다.

예 · 같은 채팅에서 문서 비교와 일정 확인을 별도 업무로 처리한다.

실행 시도 식별값

attemptId

어떤 작업의 한 번의 호출 시도를 구별하는 ID.

예 · 같은 작업 재시도라도 새 attemptId로 원래 결과와 구분한다.

개정 번호

revision

상태·목표·계획 등이 바뀐 순서를 구별하는 숫자. 각 대상의 번호는 별개다.

예 · goal.revision 2의 목표에 옛 목표의 결과를 무조건 적용하지 않는다.

내용 대조 지문

Digest / hash

내용이 같은지 또는 바뀌었는지 대조하기 위한 계산값. 권한이나 진실 자체를 증명하지 않는다.

예 · 도구 설명이 같은 버전 이름인데 내용이 바뀌었는지 확인한다.

남아 있는 책임

Obligation

답변·추가 확인·효과 대조·정산처럼 완료 전에 해결해야 하는 일.

예 · 자료 분석은 끝났지만 요청자에게 답변해야 한다.

아직 확인할 수 없음

Unknown

실제 결과나 사용량을 모르기 때문에 성공/실패 또는 0으로 단정하지 않는 상태.

예 · 입력 후 연결이 끊겨 저장됐는지 모른다.

처리 대기

Pending

아직 수행되거나 해결되지 않은 상태. unknown과는 다르다.

예 · 다음 문서 응답을 기다린다.

처리 영수증

Receipt

어떤 명령이나 입력이 저장·적용됐는지 다시 대조할 수 있는 기록. 목표 달성 증명과는 다르다.

예 · 저장 요청 적용 기록은 있지만 내용이 맞는지는 별도 확인한다.

중복 요청의 한 번 처리

Idempotency

같은 명령이 재전송돼도 같은 효과를 중복으로 만들지 않게 하는 성질.

예 · 접수 메시지가 두 번 와도 업무는 한 번 생성한다.

현재 버전 확인 후 저장

CAS

읽었던 상태가 아직 최신일 때만 변경을 저장하는 방식. 달라졌으면 다시 확인한다.

예 · 두 실행기가 동시에 같은 상태를 덮어쓰지 않게 한다.

외부 기능에 대한 약속

Port

저장·모델·도구가 제공해야 하는 기능을 정의한 경계. 여기서는 네트워크 포트 번호와 다른 뜻이다.

예 · 상태를 읽고 저장하는 함수 약속.

연결 구현체

Adapter

공통 약속을 특정 저장소·모델·도구 제품에 맞게 구현한 코드.

예 · SQLite adapter를 파일 저장 adapter로 바꾼다.

데이터베이스

Database / PostgreSQL / SQLite

구조화된 정보를 보관하고 조회하는 시스템. PostgreSQL과 SQLite는 서로 다른 구현 제품이다.

예 · 핵심 코드는 특정 DB의 SQL에 직접 묶이지 않는다.

파일 기반 변경 장부

File journal

작업의 변경과 영수증을 파일 기록으로 보존하는 저장 방식.

예 · 재시작 후 원래 기록을 확인해 진행을 복원한다.

실행 환경을 구성하는 쪽

Host

신원·역할·정책·모델·도구를 연결하는 프로그램/운영 환경. 반드시 상위 리드 에이전트를 뜻하지 않는다.

예 · 시험 코드가 허용된 두 역할 runtime을 등록한다.

업무상 역할

Agent role

에이전트가 맡는 목적과 담당 범위. 고정된 상하 계급을 뜻하지 않는다.

예 · 이번 업무에서는 요청자, 다른 업무에서는 검토자.

실제 작업을 수행하는 실행 주체

Worker

문맥에 따라 실행 프로세스 또는 요청 수행 역할을 뜻한다. 고정된 하위 에이전트 종류로 읽지 않는다.

예 · 일시적인 worker 프로세스가 지속되는 agent의 상태를 읽어 실행한다.

공유 게시판

Board

관측·가설·질문·근거 참조와 요청 상태를 공유하는 협업 공간.

예 · 다른 역할의 발견을 읽고 확인 작업을 요청한다.

재개 신호 / 구독

Wake / subscription

어떤 변화가 생기면 업무를 다시 확인해야 한다는 신호와 관심 대상 등록.

예 · 새 요청 도착 알림을 저장하고 담당 실행기가 처리한다.

실행 배정기

Dispatcher / scheduler

대기 중인 역할·작업 중 누구를 언제 실행할지 정하는 구성요소. 단일 작업 실행과 상시 역할 배정은 범위가 다르다.

예 · 여러 역할에 공정하게 실행 기회를 준다.

접근·실행 규칙

Policy

어떤 주체가 어떤 범위에서 자료·도구·목적지를 사용할 수 있는지 정한 규칙.

예 · 사내 문서를 읽을 수 있어도 외부 모델 전송은 금지할 수 있다.

권한 주체 식별값

principalId

자료 접근과 실행 권한의 주인이 누구인지 구별하는 ID.

예 · 두 역할이 같은 게시판에 있어도 접근 주체는 다를 수 있다.

조직 구역 식별값

tenantId

서로 다른 조직의 자료와 상태를 구별하는 ID.

예 · 다른 조직의 동일 이름 문서가 섞이지 않게 한다.

업무·자료의 허용 범위

Scope

어떤 대상이나 영역에 이 업무와 권한이 적용되는지 나타내는 값.

예 · 한 부서의 문서 검토 범위.

정보를 보여주거나 전달하기

Disclosure

자료를 어느 수신자·모델·채널에 제공하는 행위와 그 허용 정책.

예 · 내부에서 읽은 자료를 외부에 보내는 것은 별도 판단이다.

모델과 도구를 연결하는 공통 통신 규약

MCP

외부 도구 목록을 조회하고 호출·결과를 주고받는 약속. 업무 상태나 장기 추론 엔진 자체는 아니다.

예 · 이미 구현된 사내 자료 조회 MCP를 adapter로 연결한다.

에이전트 간 상호운용 규약

A2A

다른 시스템의 에이전트와 작업·상태·결과를 교환하기 위한 통신 방식.

예 · 사내 다른 agent 서비스에 검토 업무를 요청한다.

프로그램 호출 창구 / 주소

API / endpoint

다른 프로그램의 기능을 요청하는 약속과 그 요청을 받는 위치.

예 · 사내 모델에 추론 요청을 보내는 주소.

연결용 개발 도구 묶음

SDK

특정 통신이나 서비스를 쓰도록 제공되는 라이브러리.

예 · MCP SDK가 메시지 처리를 돕고 업무 복구는 우리 코어가 맡는다.

프로세스의 표준 입출력 통신

stdio

로컬 프로그램 사이에서 입력·출력 통로로 메시지를 주고받는 방식.

예 · 로컬 MCP 서버를 띄워 실제 규약을 시험했다.

문자 명령 인터페이스

CLI

터미널에 명령을 입력해 업무를 접수·조회·제어하는 방식.

예 · 명령으로 상태를 보거나 업무를 중지한다.

서버에서 화면으로 상태 보내기

SSE

서버가 연결된 웹 화면에 상태 변경을 이어서 전달하는 방식.

예 · 같은 작업 카드의 상태가 갱신된다.

보낼 메시지 장부

Outbox

준비된 답변의 대상·내용·전달 상태를 저장하는 기록.

예 · 분석은 끝났는데 메신저 전송이 실패하면 전송만 다시 처리한다.

컴퓨터 화면 조작

Computer use

화면을 보고 클릭·입력 등을 수행한 뒤 결과를 확인하는 기능.

예 · 폼을 채우고 저장됐는지 확인한다.

웹 화면의 구조화된 요소 정보

DOM

브라우저가 버튼·입력칸·문서 내용을 표현하는 구조. 운영체제 전체 화면 조작과는 다르다.

예 · 이름이 “저장”인 버튼을 찾아 클릭한다.

고정 시험 자료 / 모델 대역

Fixture / scripted model

같은 상황을 재현하도록 미리 정한 자료와 모델 응답. 실제 모델의 지능을 측정하지 않는다.

예 · 반증 문서를 주면 정해진 재계획을 반환하는 대역.

구현 약속 / 약속 준수

Contract / conformance

입력·출력·상태 변경·오류·복구의 의미를 정하고 지키는지 확인하는 것.

예 · 부분 수집을 전체 완료로 처리하지 않는지 시험한다.

실제 환경 배치

Deployment

코드를 실제 사용자·신원·서비스·운영 정책과 연결해 사용하게 하는 단계.

예 · 로컬 합성 시험과 사내 운영 도입은 다른 단계다.

변경 되돌리기

Rollback

새 버전이나 정책에 문제가 있을 때 이전의 정한 상태로 돌아가는 절차.

예 · 지침 변경 후 결과가 나빠지면 검증된 이전 버전으로 전환한다.

변수 / 데이터 항목

Variable / field

이름을 붙여 값을 담는 것. 객체 안의 이름 붙은 값은 필드라고 한다.

예 · workId에는 업무 ID, deadlineAt에는 마감 시각이 들어간다.

제품 언어 / 실행 환경 / 선택 언어

TypeScript / Node.js / Rust

현재 코어는 TypeScript로 작성해 Node.js에서 실행한다. Rust는 필요할 때 검토할 별도 언어다.

예 · Python 없이 새 제품의 필수 실행 경로를 구성했다.

문서에 저장한 개인 기억

Document memory

개인 기억을 버전별 Markdown 파일에 저장하는 선택 방식. 기본 SQLite와 함께 같은 기억 서비스 계약을 사용한다.

예 · 새 담당에서 documents를 선택해도 원문 대화와 업무 기억은 별도 저장한다.

게시 확인 기록

Publication witness

어떤 순서와 내용 지문으로 기억을 저장했는지 확인하는 작은 파일. 본문을 한 번 더 저장하는 기억 DB는 아니다.

예 · 마지막 기억 파일만 사라졌을 때 옛 버전을 현재 기억으로 돌려주지 않는다.

기억 편집 초안

Memory draft

기존 기억에서 복사해 편집하는 파일. 저장만으로 정본이나 대화 원문이 바뀌지 않는다.

예 · 파일 편집 뒤 명시 적용하면 그 내용을 고정하고 원문과 기억의 처리 기록을 각각 확인한다.

한 적용 요청의 식별값

Apply ID

중단 뒤에도 같은 편집 내용을 이어 처리하고 중복을 확인하는 ID. 재시도마다 새로 만들지 않는다.

예 · 이 요청의 반영 버전은 v2이고 지금 기억은 v3에서 잊힌 상태일 수 있다.

한 시점에 확인한 기록 묶음

Snapshot

이관할 기억과 영수증·색인 상태를 같은 시점으로 읽은 묶음. 지문으로 확인한 원본과 나중에 옮기는 내용이 같은지 대조한다.

예 · preview 뒤 기억이 바뀌면 확인했던 지문과 달라져 전환을 거절한다. 대화 요약이나 과거 본문 복원이라는 뜻은 아니다.

원본 개인 기억 사용 제한

Source fence

검증한 백업 이후 원본 SQLite 개인 기억의 사용을 막아 두 저장소가 각각 새 정본으로 바뀌는 일을 방지하는 기록.

예 · 이후 중단되면 같은 이관 ID로 재개한다. 업무 근거는 SQLite를 계속 사용하며 오래된 프로세스 자체가 자동 종료되는 것은 아니다.

현재 저장소로 최종 선택

Activation

문서 초기 기록과 영수증 검증을 마친 뒤 문서를 현재 개인 기억의 정본으로 선택하는 별도 기록.

예 · 문서 파일이 생긴 것만으로 완료가 아니다. status의 activated와 effectivePersonalMemory를 확인한다.

모델 한 번의 입력·출력 공간

Context window / contextWindowTokens

모델 호출 한 번이 처리할 수 있는 입력과 출력의 총 범위. 이번 답변을 작성할 공간을 빼고 입력 한도와 함께 비교한다. 업무에 배정한 소비 자원과 별개다.

예 · 총 공간 10,000단위에서 출력 2,000단위를 남기면 입력은 최대 8,000단위이고, 별도 입력 한도가 더 작으면 그 한도를 따른다.

입력 크기 추정기

Input estimator / inputEstimation

프롬프트·도구 설명·대화 등 실제 전송 형태의 크기를 보내기 전에 계산하는 방법과 버전. 정확한 모델 토큰 계산기 또는 보수적인 추정법일 수 있으며 실제 사용량 보고와 구분한다.

예 · 한국어 글자 수만 세지 않고 모델별 입력 포장까지 포함해 크기를 가늠한다. 합성 추정기의 통과가 실제 모델 정확도를 증명하지는 않는다.

게시 전 입력 크기 검사

Preview / inspect

아직 정상 문맥으로 게시하지 않은 재료로 입력 구성을 가늠하는 준비 단계. 여기서는 모델 호출·문맥 head 게시·업무 상태 변경을 하지 않으며 실제 사용 직전에 다시 확인한다.

예 · 필수 상태와 현재 지시가 들어가는지 먼저 본 뒤, 과거 대화를 얼마나 담을지 고른다.

입력 설정 변경 확인값

Profile digest / inputProfileDigest

모델·한도·추정기 버전을 묶어 계산한 지문. 예약한 호출을 보내기 전에 설정이 같은지 확인한다. 응답의 진실성을 판정하는 값은 아니다.

예 · 예약 뒤 추정기 버전이 바뀌면 새 설정으로 다시 준비한다. 이미 받은 응답은 이 변경만으로 버리지 않는다.

이름으로 모델 연결을 찾는 등록표

Model registry / AgentTurnHost.models

에이전트를 실행하는 프로그램인 호스트가 준비하는 이름과 모델 생성 함수의 목록. 담당 설정에는 이름만 저장하며 이 값으로 파일이나 모듈을 실행하지 않는다.

예 · local-contract-v1이라는 이름을 현재의 로컬 합성 연결에서 찾는다. 등록 이름이 없으면 거절한다.

모델 요청·응답 전송 담당

Model transport

구조화한 요청을 받아 응답을 돌려주는 연결 부분. 원문 조회·계획 검증·실행·요약 게시·정산은 기존 코어가 맡는다. 전송 부분을 등록했다는 사실만으로 실제 연결 성공을 증명하지 않는다.

예 · 현재 로컬 전송은 고정 합성 규칙을 실행한다. 실제 사내 모델 연결은 별도로 구현하고 검증해야 한다.
