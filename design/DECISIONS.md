- 2026-09-06 담당 배치/지속 세션: 공통 실행기를 담당 디렉터리 밖에 두고 디렉터리별 설정·스킬·개인 기억·세션을 사용한다. 같은 대화 문맥으로 여러 작업을 이어가며 필요할 때 compact하고, 작업 완료를 문맥 초기화 조건으로 삼지 않는다. 사용자가 기본값 선정을 위임하여 **담당별 SQLite 상태/기억 + 설정/스킬/큰 원문 파일**을 기본 설계로 정했다. PostgreSQL과 문서 기억은 선택 지원하며 PostgreSQL은 연결/역할 설정 뒤 사용한다. 경로는 담당 탐색 기준, 지속 ID는 디렉터리 안에 보존한다. [기본값·배치·구현 순서](/Users/seunghanee/Documents/secumon/design/chapters/workspace-agent-defaults.md). 이는 설계 결정이며 설치/제품 구현 완료를 뜻하지 않는다.

- Rust는 자원·성능 요구가 있는 구성요소에 선택 적용하며, Rust 중심 백엔드도 팀 역량·SDK 적합성·운영 비용으로 비교한다. 다언어 구성을 필수로 두지 않는다.
- ‘Python 없음’은 우선 새 제품의 필수 실행 의존성 범위다. 외부 MCP·빌드 도구·전사 서버의 언어는 별도로 확인하고 운영 비용을 누락하지 않는다.
- 대화 ID와 장기 업무 ID를 분리한다. 사람의 변경·취소를 업무 이벤트로 반영하며 대화가 끊겨도 업무는 유지한다.
- 보안·공개 문서 비교 두 업무군으로 범용성을 검증한다. 사람 대화 담당은 양쪽의 공통 역할이다.
- 실행 상태와 인식 상태(질문·가정·가설·지지/반증)를 구분하고 Planner가 판별 질문을 실제 작업으로 바꾼다.
- 계획 제안·검증·배정·결과 수락·상태 커밋·완료 검증을 분리한다. 유효 계획은 이어가고 변경이 필요한 부분만 재계획한다.
- 컨텍스트 정책은 모든 모델 호출에 적용하고 compact는 필요할 때 수행한다. 정본 커밋 → 버전 있는 패킷 생성 → 필수 구조/근거/권한 검증 → 활성 창 교체 순서를 사용한다.
- Tool Registry와 호출 장부로 선택·재사용·신선도·효과별 재시도를 관리하고, 메모리는 상태/근거 직접 조회와 필요한 경험 검색을 구분한다.
- skill은 필요한 지침의 버전 있는 활성화, 방법론은 업무 특성별 계획/검증 전략, 배치는 역할·capability·권한·지식·예산·평가를 연결하는 구성으로 둔다.
- 각 논리 단계마다 별도 LLM/서비스를 만들지 않는다. 단순 업무의 직접 처리와 복잡한 업무의 가설/반증 검토를 함께 지원한다.

v0.6 권고: 기본 대화는 접수·필요 질문·결과로 하고 Web/CLI의 현재 상태를 같은 위치에서 갱신한다. 공개 상태 투영·응답 정책·전달 장부를 코어와 채널 사이에 두며 내부 사건마다 LLM을 호출하지 않는다. 결과 준비와 전달 의무를 분리하고, 다중 업무/계정/방/답변 경로와 취소의 실제 상태를 명시한다. Knox는 텍스트부터 적용하고 실제 지원 기능만 추가한다. 이는 설계 권고이며 런타임 구현 결과가 아니다.

## P2-06 로컬 정보 공개 계약 (2026-09-06)

- 읽기 권한과 목적지별 공개 규칙을 분리했다. 새 공개 정책이 있는 업무는 과거 분류 상한을 보존하며 compact/자식/권한 축소로 낮추지 않는다. 미분류 legacy 업무의 자동 전환을 거부한다.
- 공개 뷰는 trusted rule의 유한 값 매핑과 명시된 출처/파생 메타데이터를 사용한다. 원본/기억/정책을 매 전송 전에 확인하고 공개 기록/누적 한도는 영속 보존한다.
- 공개 거부는 실행 상태/체크포인트와 함께 관리하고 미사용 예약을 정산한다. 분석 완료와 답변 전달을 구분한다.
- A/B/C의 운영 채택은 미결정이다. [합성 비교](/Users/seunghanee/Documents/secumon/design/chapters/P2-boundary-result.md)는 전송 계약 검증이며 실제 모델/조직 정책/격리 보장을 대신하지 않는다.
