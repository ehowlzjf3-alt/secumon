# 컨텍스트 수명과 미사용 내용 정리

2026-09-05 · v0.10 · 설계 제안, 구현 전

현재 추론에 필요한 내용을 활성 컨텍스트에 두고, 사용이 끝난 상세 내용은 정본에서 다시 찾을 수 있게 정리한다. 대상은 도구 명세, skill/방법 지침, 도구 결과, 읽은 문서, 화면, 대화와 중간 설명 모두다. [08의 compact 계약](/Users/seunghanee/Documents/secumon/design/08-core-framework.md)과 [13의 도구 카탈로그](/Users/seunghanee/Documents/secumon/design/13-tool-catalog.md)를 연결하는 정책이며 별도 추론 에이전트가 필수인 것은 아니다.

## 1. 저장된 업무와 다음 호출의 입력을 구분

| 구분 | 역할 | 정리의 의미 |
|---|---|---|
| 정본 | 목표·상태·계획·근거·호출 장부·원본, 버전과 접근 정책 | 별도 보존/정정/삭제 정책에 따라 관리 |
| 조회 계층 | 카탈로그·근거/문서 색인·참조와 파생 요약 | 현재 주체가 필요한 원본/명세를 다시 찾음 |
| 활성 컨텍스트 | 다음 모델 호출에 실제 보내는 지시·상태·근거·명세 | 관련성·의존성·예산에 맞춰 구성/축소 |

모든 과거 항목의 이름과 ID를 활성 창에 남기면 목록 자체가 다시 커진다. 현재 계획과 미해결 의무에 필요한 참조만 패킷에 두고, 나머지는 권한 있는 조회 계층에서 찾는다. 현재 컨텍스트에 없다는 것을 조직에 해당 도구나 증거가 없다는 뜻으로 해석하지 않는다.

활성 입력에서 빼는 것, 저장소에서 삭제하는 것, 모델 공급자의 보관 데이터 삭제는 각각 다른 처리다. 공급자 쪽 보관/삭제 보장은 별도 계약으로 확인해야 한다. 이번 정책은 다음 추론 입력을 관리한다.

## 2. 항목별 보존과 정리

| 항목 | 활성 창에 유지할 내용 | 상세 내용 정리 조건과 복원 |
|---|---|---|
| 사용자 목표·제약 | 최신 범위·완료 조건·변경/취소·출력 요구 | 과거 대화는 상태에 반영 후 정리. 유효한 제약을 단순 연령으로 제거하지 않음 |
| 진행 중 작업 | 현재 계획의 관련 부분, 미완료 의무·대기 조건·unknown 효과 | 전체 작업 그래프/장부는 저장. 다음 행동과 복구에 필요한 task/attempt만 노출 |
| 도구 명세 | 다음 행동에 필요한 정확한 schema·버전·제약 | 계획 의존성이 없고 한동안 사용하지 않은 명세를 내림. 다시 선택되면 권한/버전 검사 후 로딩 |
| skill/방법 | 현재 적용 범위·버전·필수 규칙 | 완료된 단계의 예시·긴 본문 정리. 다음 단계에 필요하면 원래 버전 재조회 |
| 도구 결과·문서 | 현재 판단에 필요한 발췌·범위·근거 위치·부분성 | 내구성 있는 원본 저장 뒤 큰 본문을 참조로 교체. 필요 부분을 정확히 재조회 |
| 화면·DOM·OCR | 다음 UI 행동에 유효한 관측과 대상 | 옛 화면은 이력/근거로 이동. 행동 전 현재 창·관측 버전을 확인하며 오래된 좌표를 그대로 재사용하지 않음 |
| 가설·반증 | 현재 경쟁 가설, 중요한 가정·반증·판별 질문 | 관련 없는 과거 가설은 이력으로 이동. 빈번히 인용된 지지 근거만 남기는 정책을 피함 |
| 중간 설명·진행 메시지 | 사용자 변경이나 결정에 영향을 준 내용 | 반복된 진행 문구/같은 설명을 축소. 공개 가능한 결정 요약과 근거는 상태에 연결 |

필수 유지 항목도 전체 원문을 영원히 고정하는 뜻은 아니다. 범위에 맞는 정확한 상태/제약/근거를 간결하게 유지한다. 사용자 변경으로 더 이상 유효하지 않은 제약은 이력에 남기고 현재 지시를 갱신한다. 신뢰되지 않은 도구 본문이 스스로 '필수 보존 지시'라고 주장해도 정책으로 승격하지 않는다.

## 3. 미사용 판단: 시간 하나로 결정하지 않음

후보 판단에 사용할 메타데이터는 항목 ID/종류, 출처와 revision, 적용 task/범위, 마지막으로 필요했던 단계, 실제 사용 시점, 토큰/이미지 비용 추정, 재조회 위치와 비용, 보호 사유, 신선도/권한 상태다. 모델 입력에 매번 포함하는 것과 내부 관리에 사용하는 것을 구분한다.

초기 정책은 설명 가능한 규칙으로 시작한다.

1. 현재 권한과 자료 목적지에 맞지 않는 항목은 다음 입력에서 배제한다. 과거 버전 고정이나 캐시보다 정책 변경이 우선한다.
2. 미완료 의무·진행 중 호출·현재 가설/판별 질문·유효한 제약과 연결된 내용은 먼저 보호한다.
3. 완료된 단계, 중복 결과, 교체된 명세, 관련 없는 긴 원문을 정리 후보로 둔다.
4. 최근 사용, 다음 계획과의 관련성, 다시 읽는 비용, 크기와 중요도를 함께 고려해 후보를 줄인다.
5. 예산을 맞춘 뒤 필요한 근거/명세를 다시 찾을 수 있는지 검증한다.

경과 시간은 신선도와 보조 우선순위에 사용한다. '며칠간 미사용'만으로 durable wait의 회신 조건이나 종료 전 정리 의무를 제거하지 않는다. 조회수·사용 횟수도 정답이 아니다. 한 번 등장한 결정적 반증은 자주 나온 요약보다 중요할 수 있다.

명세의 비활성화와 도구 등록 폐기는 다르다. 카탈로그에서 도구를 삭제하거나 실제 세션을 닫는 결정은 각각 등록 수명/자원 소유권 정책이 한다. 컨텍스트 정리만으로 실행 중 브라우저나 외부 작업을 종료하지 않는다.

## 4. 가벼운 정리와 compact의 순서

모델 호출 전 Context Builder 안의 수명 정책이 현재 상태와 입력 예산을 검사한다. 매번 별도의 정리 LLM을 호출하지 않는다. 다음 순서를 권고한다.

1. **중복 제거:** 같은 자료 revision의 중복 발췌·반복된 진행 문구·동일 명세를 합친다. 서로 다른 시점/범위/출처를 잘못 같은 증거로 합치지 않는다.
2. **선택적 축소:** 사용이 끝난 명세·지침·예시를 비활성화하고, 큰 결과를 필요한 발췌/참조로 바꾼다.
3. **조회 범위 조절:** 전체 자료 대신 현재 질문에 필요한 구간을 읽고 출력 예약과 도구 명세를 포함한 예산을 맞춘다.
4. **compact:** 앞 단계로 부족하거나 단계/역할 전환에 따라 입력 재구성이 필요하면 정본 snapshot에서 검증된 ContextPacket을 만든다.
5. **재조회:** 다음 단계에서 빠진 근거/명세가 필요하면 선택적으로 복원한다. 필수 판단 근거가 없는 상태를 기억만으로 채우지 않는다.

예산은 시스템 지시·사용자/업무 상태·근거/최근 대화·도구/지침·이미지 등 전체 입력과 공급자별 출력/추론 예약 의미를 함께 고려한다. 같은 비율을 모든 모델과 역할에 고정하지 않는다. 비용을 줄이려다 핵심 내용이 들어갈 수 없으면 업무 분할이나 허용 범위 내 처리 조정을 검토하고, 불가능하면 제한/미완료를 명시한다.

정리 시작 기준과 정리 후 여유 목표를 다르게 두고, 최소 유지 구간·최근 퇴거 기록을 활용해 같은 명세를 매 호출마다 내렸다 올리는 진동을 줄인다. 권한 철회·명세 폐기·목표 변경은 이 유예보다 우선한다. 기본 입력의 안정된 순서를 유지하되 prompt cache 적중을 위해 불필요하거나 금지된 내용을 남기지 않는다.

## 5. 안전한 전환과 재로딩

전환은 [08의 저장→snapshot→검증→게시 순서](/Users/seunghanee/Documents/secumon/design/08-core-framework.md)를 따른다. 큰 결과를 축소하기 전에 원본/참조 저장을 확인한다. 미저장된 유일한 결과를 지운 다음 다시 실행해서 복구하는 방식에 의존하지 않는다.

ContextManifest에는 기반 goal/state/plan/정책 revision, 사용한 항목/표현/버전, 생략·유지의 간단한 사유, 이력 cursor와 예상 입력 비용을 남긴다. 이는 진단용 정책 기록이며 모델 내부 사고 원문이 아니다. 새로운 사용자 변경·권한 철회·늦은 결과가 오면 새 packet을 게시하기 전에 관련 revision을 검사하고 필요한 변경을 반영한다.

도구 명세는 현재 사용 가능한 버전으로 다시 확인하고, 과거 호출 해석은 당시 버전을 참조한다. 증거는 '당시 상태를 재현'하는 조회와 '지금 상태를 확인'하는 조회를 구분한다. 유효하지 않은 자료를 다시 읽을 수 없으면 stale/unavailable 상태로 남기고 재수집이나 계획 변경을 판단한다. 문서/화면 안의 지시가 재조회 과정에서 사용자 지시로 승격되지 않게 출처를 유지한다.

Provider adapter는 활성 명세 목록과 실제 전송할 메시지/결과 본문을 함께 구성한다. 명세 목록에서만 제거하고 과거 검색 결과의 같은 긴 설명을 계속 보내면 정리 효과가 제한된다. 그렇다고 tool call/result 쌍이나 미응답 호출을 임의로 잘라 잘못된 history를 만들지 않는다. 명시적으로 허용된 입력 구성·재개 방식을 사용하고 공급자별 계약 fixture로 확인한다. 서버가 이전 history를 연결하는 방식이라면 로컬 배열을 줄였다는 이유만으로 실제 모델 입력이 줄었다고 판단하지 않는다.

상태 확인/취소/결과 조회처럼 후속 행동에 필요한 기능은 실행 관리자가 항상 찾을 수 있어야 한다. 전체 schema를 계속 프롬프트에 고정할지는 다음 모델 행동에 따라 결정한다. pending 참조와 의무는 남기되 모든 비동기 도구의 상세 명세를 영구 pin하지 않는다.

## 6. 짧은 업무, 긴 업무, 채팅과의 관계

자동/빠르게/깊게 모두 같은 권한·상태·원본 보존 계약을 쓴다. 빠른 업무는 작은 입력과 규칙 기반 정리만으로 끝날 수 있다. 긴 업무는 단계별 working set을 바꾸고 필요할 때 compact한다. 회신을 기다리는 동안 컨텍스트 정리를 위한 추론 호출을 주기적으로 돌릴 필요는 없다. 재개할 때 최신 상태와 권한으로 다시 구성한다.

사람 대화 담당·작업자·검토자는 같은 원자료 전체를 복제받지 않고 각 역할/단계에 필요한 packet을 받는다. 다른 작업의 문서·명세가 대화에 등장했다는 이유로 현재 작업의 활성 지침이 되지 않는다.

일반 채팅에는 내부 정리 이벤트를 새 말풍선으로 보여주지 않는다. 상세 진단에서는 입력 종류별 크기, 어떤 단계 때문에 유지/정리했는지, 재조회와 실패를 볼 수 있다. 정리 실패가 결과 품질이나 진행을 막을 때 필요한 설명만 사용자에게 전달한다.

## 7. 예시

문서 비교에 앞서 브라우저에서 필요한 자료를 수집했고 현재 단계는 저장된 두 문서의 차이를 판단하는 일이라고 가정한다.

- 수집 단계가 끝났다면 긴 브라우저 명세와 오래된 화면을 활성 창에서 내릴 수 있다. 원본 화면/자료와 출처는 보존 정책 안에서 유지한다.
- 현재 비교 기준, 두 문서의 관련 발췌, 서로 충돌하는 근거, 아직 확인하지 못한 항목은 유지한다.
- 며칠 전부터 기다리는 담당자의 회신 조건은 아직 미완료라면 유지한다.
- 원문 추가 확인이 필요하면 도구의 현재 권한/명세를 다시 불러오고 실제 페이지 상태를 확인한다.
- 최종 답변에는 비교 결과와 근거를 제시한다. 브라우저 명세를 언제 정리했는지는 실행 진단에 남긴다.

## 8. 구현 단계와 평가

P1에는 항목 참조/출처·필수 의무 보호, 완료된 단계의 명세 비활성화, 큰 결과의 저장 후 참조화, 최소 packet 복원, 유효한 tool-call 연결을 넣는다. P2에서 긴 합성 실행과 역할 전환, 반복 compact·재조회·예산 정책을 비교한다. 거대한 별도 Context Manager 서비스를 만들 필요는 없다.

| 평가 사례 | 확인할 결과 |
|---|---|
| 많은 도구를 순서대로 사용한 뒤 다른 업무 수행 | 상세 명세가 무한 누적되지 않으며 필요한 도구를 다시 발견 |
| 오래된 반증/회신 대기/unknown 효과 | 나이·빈도 때문에 사라지지 않고 이후 판단/재개에 반영 |
| 원본 저장 전 장애 또는 끊어진 참조 | 유일한 결과 유실 방지, 실패를 감춘 정리 성공 표시 없음 |
| 정리 중 목표/권한 변경·늦은 결과 | 기반 revision 검사, 최신 의무·허용 정보로 재구성 |
| 새 버전 도구 또는 stale 화면 재사용 | 현재 계약/대상 확인, 과거 응답과 새 실행 의미 구분 |
| 반복 축소와 재로딩 | 퇴거/재조회 빈도, 불필요한 왕복·지연·추가 모델 비용 측정 |
| 작은 단서를 한참 뒤에 요구 | 원문과 근거 연결을 찾아 답변, 검색 실패율·잘못된 완료 측정 |
| 공급자별 실제 요청 | 명세/메시지/이미지와 usage 확인, 호출/응답 쌍 유효성 검사 |

고정 입력 창 유지, 가벼운 정리, 정리+compact를 같은 모델·자료·완료 기준으로 비교한다. 활성 토큰 감소 외에 완료 품질·필수 사실 회수·반증 보존·재조회 비용·총 지연을 함께 본다. 아직 임계값이나 절감률은 확정/측정하지 않았다.

## 9. 참고 범위

필요한 시점의 자료 조회, structured notes, compaction은 [Anthropic의 context engineering 설명](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)에서도 다룬다. 이 문서의 보호 조건·수명 정책·manifest·revision 검사는 본 프로젝트의 설계 제안이다. 특정 공급자의 context editing 기능을 채택하거나 자동으로 같은 보존 성질을 얻었다는 뜻은 아니다.
