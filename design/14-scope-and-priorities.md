# 추가 범위와 첫 구현의 경계

2026-09-05 · v0.12 · 통합 구현 순서 연결 · 설계 제안, 구현 전

추가해야 할 것은 핵심 기능의 종류보다 **각 기능이 연결될 때의 실행 계약과 검증 방법**이다. 기존 설계에 이미 있는 내용을 새 기능처럼 다시 늘리지 않는다. [전체 단계](/Users/seunghanee/Documents/secumon/design/03-migration-plan.md)를 유지하며 아래 항목을 각 단계의 통과 조건에 연결한다.

v0.12의 단계 기준은 03이다. P3은 단일 에이전트의 도구/채널/컴퓨터 유즈, P4는 협업/A2A/상시 임무다. 범용성은 P0/P1부터 검증하고 정보 경계는 사내 자료 연결 전의 통과 조건으로 둔다. 전체 요구와 작업의 누락 검사는 implementation-backlog.json의 매핑을 사용한다.

## 2. 입력·산출물의 공통 계약

범용 에이전트는 질문 외에도 파일, 표, 링크, 화면, 시스템 기록을 받는다. 입력을 전부 문자열 한 덩어리로 바꾸면 문서 위치·표 구조·시간 범위·누락 여부가 사라진다.

원본 artifact와 읽기용 표현을 분리한다. 원본 버전/hash·출처·수집 시각·자료 등급을 유지하고 추출기/설정 버전, 페이지/행/좌표, 실패·잘림·관측 범위를 연결한다. hash는 바이트 식별 수단이며 출처의 진실성이나 독립된 증거라는 보장은 아니다.

같은 원본·추출 버전·설정·권한 범위의 변환 결과는 재사용할 수 있다. 필요한 부분만 읽고 요약에는 근거 위치를 붙인다. 지원하지 않는 형식이나 추출 실패를 '내용 없음'으로 바꾸지 않는다. 새 첨부가 오면 기존 근거와 관계를 정정/새 버전/독립 자료 중 무엇인지 기록한다.

도구 결과는 정상/부분/실패, 자료 범위·cursor, 근거 참조·artifact, 효과 상태를 공통 envelope로 표현하되 제공자 원래 오류를 참조 가능하게 보존한다. 출력 schema 검증과 내용의 정확성 검증은 구분한다. 모델이 생성한 주장은 evidence와 검증을 거쳐야 한다.

최종 산출물도 업무 ID·목표 버전·근거·미해결점·형식·생성 버전을 가진다. 채팅은 짧은 답변과 접근 가능한 결과 링크를 보여준다. 다운로드 권한은 링크 발급 시와 실제 조회 시 확인하며, 링크 하나를 공개했다고 원자료 전체를 열지 않는다. 초기 형식은 합성 텍스트/JSON으로 제한하고 OCR·Office·복잡한 표 처리는 필요한 업무에서 추가한다.

## 3. 모델 호출도 관리 대상

Model Gateway는 provider/model/version, 지원 capability, 요청 목적, 입력 manifest, 제한시간·예산·목적지 정책, 응답/usage를 기록한다. 도구 호출·structured output·이미지 입력·취소·effort 지원은 adapter의 명시적 capability로 표현한다. 같은 옵션명이 모든 모델에서 같은 동작을 보장한다고 가정하지 않는다.

Provider 응답을 공통 계약으로 변환하되 tool-call ID, 중간/최종 응답, 거절, truncation, usage 부재를 잃지 않는다. 잘린 출력이나 schema 오류를 정상 완료로 승인하지 않는다. 비용을 받지 못하면 0으로 기록하지 않고 미확정으로 남겨 대조한다.

대체 모델은 자료 목적지·capability·품질/예산 조건이 맞을 때만 선택하고 별도 attempt로 남긴다. 데이터가 허용되지 않은 외부 모델을 장애 대체 경로로 쓰지 않는다. 모델 변경 전후의 비교는 저장 입력/근거·설정과 버전을 함께 기록한다. 모든 호출 앞에 추가 라우팅 LLM을 붙이지 않는다. 초기 모델 하나와 fake model로 시작해도 이 계약은 유지한다.

추론 effort, 장기 업무의 실행 전략, 지출 한도, 사용자 알림은 [11의 구분](/Users/seunghanee/Documents/secumon/design/11-execution-modes.md)을 따른다. 비밀키는 업무 상태/프롬프트에 넣지 않고 인증된 실행 환경에서 credential handle로 해석한다.

## 4. 계속 생각해도 진전이 없을 때

진행은 모델이 말을 늘리거나 계획을 다시 쓰는 횟수가 아니다. 새 근거 확보, 미해결 질문 감소, 가설의 판별 가능한 변화, 완료 조건 충족, 외부 대기의 상태 변화 등으로 판단한다. 반증이나 실패 조건을 확인한 것도 이후 선택을 바꾸면 유용한 진전이다.

Controller는 같은 목표/계획 단계·입력·근거 revision에서 같은 호출·실패가 반복되는지 추적한다. 시간에 따라 변하는 자료의 정상 갱신과 새 관측 필요성을 고려하므로 같은 문자열 질의라는 이유만으로 일괄 차단하지 않는다. 변화 없는 중복은 호출 장부를 참조하고, 재계획에는 무엇이 바뀌어 결과가 달라질 수 있는지 짧은 근거를 요구한다.

| 상황 | 다음 처리 |
|---|---|
| 새 근거로 기존 계획이 여전히 유효 | continue |
| 반증·범위 변경·도구 폐기로 기존 단계가 부적절 | 필요한 부분만 replan |
| 일시 장애, 재시도해도 안전한 실행 | 공유 deadline/예산 안에서 backoff |
| 외부 답변/사건이 필요 | wake 조건을 저장하고 wait, 추론 호출 중지 |
| 권한·필수 입력·외부 상태 때문에 진행 불가 | 차단 사유와 재개 조건, 필요한 사용자 질문 |
| 같은 시도로 진전 없이 한도 소진 | 부분 결과·한계·후속 선택 제시, complete로 위장하지 않음 |
| 증거·산출물·필수 전달 조건 충족 | complete |

SDK·MCP adapter·executor·planner가 각각 여러 번 재시도해 비용이 곱절로 늘어나지 않도록 한 실행의 재시도 책임과 총 deadline을 정한다. 읽기 오류와 결과가 불명확한 외부 변경은 다른 정책을 쓴다.

부모/자식 작업 예산은 예약액·확정 사용액·미확정 사용액을 함께 추적한다. 같은 잔액을 여러 자식에게 중복 배정하지 않는다. 취소는 새 배정을 중지하고 진행 중 호출을 대조한다. 대기 업무가 작업 슬롯을 계속 점유하지 않도록 실행과 임무 수명을 분리한다. 사용자 취소·상태 확인 입력은 과부하 중에도 처리 여력을 둔다.

## 5. 재생 가능한 디버깅과 평가

각 실행은 목표/계획/상태 revision, 입력/근거 참조, 모델·prompt template·skill·방법·도구 카탈로그 버전, 실행 환경/코드 버전, 호출/효과·usage·지연을 묶는 manifest를 남긴다. 전체 민감 프롬프트를 무조건 일반 로그에 복사하지 않는다. 제한 저장소의 참조와 비식별 projection을 사용하고, 자료가 삭제되거나 사용권이 없어 재현할 수 없으면 그 한계를 기록한다.

세 가지 동작을 구분한다.

- **사건/결과 재생:** 저장 이벤트와 모델/도구 결과를 다시 읽어 상태·제어·화면 투영을 검사한다. 외부 효과를 재실행하지 않는다.
- **새 추론 비교:** 같은 허용된 입력 fixture로 새 모델/지침을 실행한다. 비결정성과 추가 비용이 있는 새 실행이며 원본을 덮지 않는다.
- **실제 연동 시험:** 격리된 대상과 정해진 범위에서 adapter를 시험한다. replay 통과를 연동 통과로 대신하지 않는다.

처음에는 CLI로 한 work ID의 단계·판단 요약·근거·실패·비용을 보는 것으로 충분하다. 내부 사고 원문 저장/노출을 전제로 하지 않는다. 일반 채팅의 조용한 접수·결과 정책은 유지한다.

평가는 계약/복구 시험과 추론 품질을 함께 본다. 단순/복잡한 업무, 늦은 반증, 오래된 명세, 부분 결과, 컨텍스트 교체, 취소, 외부 효과 불명확을 고정 fixture로 만든다. 변경 전후 완료율·잘못된 완료·재조회·비용·지연을 비교한다. 모델 평가자의 점수만으로 결과를 승인하지 않고 기계 판정 가능한 조건과 사람이 검토할 표본을 둔다.

## 6. 정정·삭제·권한 철회는 파생 기억까지

원본에서 추출·claim·요약·색인·캐시·최종 산출물로 이어지는 lineage를 기록한다. 원본 정정 시 관련 claim을 재검토 대상으로 만들고, 진행 중 계획과 답변이 최신 근거를 사용하도록 무효화/재구성한다. 같은 근거의 여러 요약을 독립된 사실로 세지 않는다.

삭제·접근 철회 시 원본만 숨기고 임베딩/요약/검색 카드가 계속 반환되지 않도록 파생물과 권한 view까지 전파한다. 이미 전송된 메시지·외부에 공개된 정보는 저장소 삭제만으로 회수할 수 없으므로 전달 장부에 범위를 남긴다. 한 번 공개된 정보를 기술적으로 완전히 되돌렸다고 주장하지 않는다.

내용 보존과 최소 감사 메타데이터의 보존 정책을 구분한다. 이벤트 로그를 영구 불변이라고 정해 개인정보/기밀 삭제 요구를 배제하지 않는다. 삭제/tombstone·보존 기간·백업 만료·복원 후 삭제 재적용을 설계하며 정확한 보존 기간은 조직 정책 결정 사항이다. 과거 재생의 완전성과 삭제 요구가 충돌하면 정책을 따르고 재생 제한을 표시한다.

## 7. 배치·변경·운영 수명

업무 모듈은 capability 요구, 입력/산출물·완료 기준, 역할/권한, skill·방법·모델 정책·도구 버전, 합성 평가 fixture를 가진 검토 가능한 bundle로 취급한다. '문서에 쓰인 지시'만으로 실행 권한이 늘어나지 않는다. 임의 다운로드 코드를 자동 등록하는 경로를 기본으로 만들지 않는다.

카탈로그/skill/방법 변경은 검증 → 제한 평가 → 승격 → 관측 → 필요 시 롤백으로 관리한다. 진행 중 업무는 사용 버전을 기록하고 명시적으로 이행한다. 긴급 권한 철회는 버전 고정보다 우선한다. 성공한 실행에서 재사용할 절차를 추출할 수 있지만, 한 번 성공한 절차를 검토 없이 조직 전체의 기본 규칙으로 승격하지 않는다.

운영 도입에는 저장 용량/보존, 백업·복원 시험, 큐 한도, 지출 상한, 자격증명 만료, 장애 담당·재개 절차가 필요하다. 메시지·게시판 구독의 fan-out과 중복 wake도 예산에 포함한다. 에이전트 수 증가만으로 처리량 개선을 가정하지 않는다. 다중 조직의 자료/권한 격리는 처음부터 계약에 두되 첫 시제품에서 여러 클러스터를 운영할 필요는 없다.

## 8. 첫 구현의 크기와 이후 확장 기준

첫 수직 경로는 **한 요청 → 접수 저장 → 목표/상태 → 필요한 지침·도구 선택 → 검증/실행 → 근거/상태 반영 → 재개 또는 결과 → 사용자 답변**이다. 한 TS 서비스, 격리된 저장소, 한 실제 모델 adapter + fake model, 작은 검토 도구 목록 + fake MCP, CLI + 가짜 채널 수신기로 시작하는 안을 권고한다. 정확한 프레임워크·버전·데이터 경계는 아직 미선택이다.

첫 경로에 포함할 것:

1. 단순 업무가 불필요한 가설/검토 호출 없이 끝나고, 복잡한 업무는 가설·반증·부분 계획을 유지하는 공통 상태 계약.
2. 작은 catalog의 직접 선택/발견/명세 로딩, 권한·버전 검사, 호출 장부, 근거 직접 조회.
3. 한 지침의 버전 있는 선택 로딩, 텍스트/JSON 입력과 출처 있는 산출물.
4. 프로세스 중단·재개, ContextPacket 교체, 늦은 결과·사용자 변경·취소, 한도 소진과 unknown 효과 처리.
5. 접수·최종 답변·필수 질문의 공개 이벤트와 전달 장부, 한 실행의 진단/replay.

최소 compact/재개 계약은 P1에 포함하고, 긴 실행·반복 compact·큰 카탈로그 최적화는 P2에서 확장한다. 업무 하나의 성공 사례만으로 통과하지 않고 [03의 실패/품질 조건](/Users/seunghanee/Documents/secumon/design/03-migration-plan.md)을 함께 확인한다.

그다음 기능은 다음 조건으로 추가한다.

| 나중에 추가할 항목 | 시작할 근거 |
|---|---|
| 의미 검색/reranker/전용 검색 저장소 | lexical 기준선의 도구/기억 회수 실패와 비용 비교 |
| 다중 에이전트 게시판·A2A·담당 조직 | 단일 업무 복구가 통과하고 서로 독립된 권한/지식·협업 가치가 있는 업무 |
| 여러 모델·독립 critic | 단일 경로의 품질 한계와 비용 대비 효과 |
| 네이티브 OS driver·Rust | 필요한 OS/앱·자원 격리·측정된 병목 또는 라이브러리 요구 |
| Knox 실제 연동·다양한 문서 형식 | 실제 MCP/형식 계약 확인과 격리된 fixture |
| 분산 서비스·대규모 스케줄러 | 용량·장애 격리·정보 경계가 단일 배치를 넘는 근거 |
| 자동 절차 개선·전역 학습 | 성공/실패 평가와 오염·회귀를 막는 검토/롤백 경로 |

이 문서는 범위 점검 목록이자 우선순위다. 모든 항목을 매 요청에 실행하거나 첫 릴리스에서 모두 구현하라는 뜻이 아니다. 신규 요구가 들어오면 해결하려는 실패, 현재 계약의 공백, 통과 조건, 도입 단계를 먼저 기록한다.
