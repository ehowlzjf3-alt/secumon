# 남은 확인 작업

2026-09-09 · checkpoint399 반영. **남은 작업은 아래 네 묶음이다.** checkpoint398의 잔여 목록에서 이번 완료 항목을 제외했다. 이미 통과한 개별 시험을 다시 나열하지 않고, 아직 끝까지 확인하지 못한 흐름과 필요한 환경만 정리했다.

**checkpoint399의 ‘상시 임무의 미확정 Web 명령을 새로고침 후 복원하고 실제 브라우저에서 조작하는 확인’은 완료되어 남은 목록에서 제외했다.** 이는 C06의 개인기억 업무 화면 검증까지 완료했다는 뜻은 아니다.

| 묶음 | 현재 로컬 환경에서 이어갈 일 | 외부 환경이 필요한 일 |
| --- | --- | --- |
| **C09 — 오래 실행하는 담당의 이력·문맥 비용** | 전체 세션의 문맥을 다시 가져오는 비용을 측정하고 필요한 개선을 확인한다. 같은 목표 안에서 사건이 오래 누적될 때의 중복 확인, 용량과 장기 보관을 마무리한다. | 해당 동작의 Linux·네이티브 Windows 확인은 C10 환경 확인과 함께 묶는다. 실제 외부 에이전트와의 통신은 최종 실환경 묶음에서 확인한다. |
| **C05/C06 — 권한 복구 후 완주·개인기억 대화** | **C05:** 권한을 다시 허용한 뒤 사용자가 명시적으로 재개하여, 이미 저장한 수집 자료로 원래 업무가 완료되는 CLI 흐름을 확인한다. **C06:** 개인기억을 사용하는 HTTP 업무의 완료 지연, 기억 저장에 필요한 권한·도구 등록의 사용성, 실제 브라우저 조작을 확인한다. 기다리는 시간을 늘리는 것만으로 속도가 개선됐다고 판정하지 않는다. | Linux·네이티브 Windows의 실행·설치 확인과 실제 Knox 연결은 아래 환경·통합 묶음에서 함께 다룬다. |
| **C10 — 초기 복원 중단·설치 구성** | 신뢰할 수 있는 복원 실행 기록이나 표식이 생기기 **전**에 중단되는 초기 구간을 확인한다. 원자료를 보존하며 관계없는 디렉터리를 복원본으로 자동 채택하지 않는 복구 처리를 마무리한다. 설치 묶음에서 필요한 네이티브 모듈이 실제로 제공·로딩되는지, 패키지 구성과 준비 비용이 적절한지 확인한다. | 현재 코드로 **Linux와 네이티브 Windows**의 실행·설치·복구를 확인한다. 실제 PostgreSQL 서버에서 복원·회복 흐름을 검증한다. macOS 실행이나 Windows 대상 컴파일, PostgreSQL 기록용 대역 시험으로 대신하지 않는다. |
| **최종 통합·실환경 — 실제 사용할 구성의 완주** | 기존 계획의 통합 흐름을 선택한 배치 구성으로 연결해 확인한다. 최종 변경으로 영향을 받는 관련 회귀와 원자료·세션·기억·외부 실행 기록의 연결을 확인하고, 발견된 실제 결함을 고친다. 유효한 기존 결과는 재사용한다. | 실제 사내 MCP, Knox, 외부 A2A 연결과 운영 시범·배포 인수를 수행한다. 사용할 주체·자료·전달 범위와 용량·복원 목표를 확정한 구성만 대상으로 한다. 운영 이관은 기존 계획대로 별도 선택이다. |

진행 순서는 **C09 이력·문맥 비용 → C05/C06 → C10 → 최종 통합**이다. 외부 환경이 필요한 항목은 로컬 확인과 별도로 남겨 두며, 실행하지 않은 환경을 통과로 표시하지 않는다.

각 묶음은 **기존에 이름 붙인 시나리오가 끝까지 성립하고, 그 과정에서 발견한 실제 결함을 수정해 필요한 회귀를 확인하며, 결과와 미실행 범위를 기록하면** 닫는다. 확인 중이라는 이유만으로 새로운 요구나 가상의 경계 사례를 계속 추가하지 않는다. 남은 시험 개수·완료율·소요 시간은 아직 확정하지 않는다.

**실제 모델/API 시험은 사용자의 중단 결정을 유지한다.** 따라서 실제 모델의 추론·대화 품질이나 실제 호출 비용은 이번 로컬 완료 판정에 포함하지 않으며, 이 문서가 해당 시험이나 사내 서비스 연결을 새로 시작하도록 지시하는 것은 아니다.
