# C09 상시 임무 제어 명령과 사용자 입구

2026-09-09 · checkpoint397 · 기준선 c741ffaa76cbae8cc334d3eaaf48255f88543de3. 이 단위 구현·로컬 검증 완료. 전체 C09/goal 진행 중.

직전 checkpoint396은 구현·고유143개 로컬 검증·커밋/푸시·원격 일치까지 완료한 progress다. 이번 시작 때 같은 커밋과 깨끗한 작업 트리를 재확인했다.

## 개념

상시 임무의 관측 제어와 이미 접수한 사건 업무의 제어는 별개다. 응답이 유실되어 같은 일시정지를 다시 보냈을 때 그 사이의 명시 재개나 새 관측을 다시 멈추면 안 된다. 명령 ID는 같은 의도를 식별하고, 예상 제어 번호는 사용자가 본 상태를 기준으로 새 명령을 적용하도록 한다. 반환값은 원 명령 적용 번호와 현재 관측 상태를 구분한다.

## 재사용·수정·추가

1. 기존 ResidentMissions, 지속 사용자 세션과 별도 peer controller, checkpoint 원문, StateRepository의 원자적 단일 commit/영수증, 기존 시작 revision 기반 취소를 재사용한다.
2. commandId/expectedControlRevision/kind(pause·resume·stop)를 가진 control API를 추가한다. 명령 checkpoint에 선택 publication 정보를 넣고 같은 한 번의 commit에 안정된 원 명령 영수증을 저장한다. 일반 관측 checkpoint는 기존 SHA 영수증을 유지한다. DB·새 보조 ledger나 두 번 쓰기 프로토콜을 추가하지 않는다.
3. 동일 ID/동일 명령은 원 영수증으로 재전달 처리하고 다른 내용은 충돌로 거절한다. 새 명령은 예상 제어 번호와 현재 번호가 같아야 한다. 이전 pause 재전달은 원 명령보다 뒤에서 시작한 poll에 영향을 주지 않는다. 저장 응답 불명은 원기록으로 확인하되 원 오류를 보존하고 명시 재전달로 회복한다.
4. 호스트 wrapper에 control과 선택 session 검사를 연결한다. 기존 trusted-host pause/resume/stop API는 유지한다. 새 CLI/Web은 사용자 sessionId와 실제 binding 전체를 검사하며 일반 업무의 세션 경계를 완화하지 않는다.
5. 설치 CLI에 mission status/pause/resume/stop, Web에 별도 status/commands API와 접이식 제어 패널을 연결한다. 조회/제어는 임무 등록·poll·workflow·모델 실행을 자동 시작하지 않는다. UI는 접수 안내·현재 결과만 간결하게 보여주고 응답 불명 재시도는 같은 ID를 보존한다.
6. 실제 임시 SQLite/file, 원 명령 재전달·경합·재개 후 보호·저장 응답 불명·재열기, 실제 CLI 자식 프로세스와 localhost HTTP의 session/담당/CSRF 경계를 확인한다. 변경에 맞는 기존 회귀와 빌드·코어·구조 검사를 실행하고 원 로그/최종 소스 대조를 저장한다.

## 검증 범위와 잔여

실제 모델/API 시험 중단·사내 서비스 연결 없음 유지. HTTP는 로컬 서버이고 모델은 호출하지 않거나 기존 결정적 대역으로만 구성한다. 실제 브라우저 렌더링 여부는 실제 수행한 경우만 표시한다. CLI 프로세스에서 발생한 제어의 즉시 다른 프로세스 poll 전달, Knox의 실제 UI/전송, Linux/native Windows/PG·배포/최종 통합과 C05/C06/C10 잔여를 유지한다. 로컬 제어가 구현되어도 전체 C09/goal 완료로 표시하지 않는다.

## 구현·검증 중간 기록

공통 코어, 호스트, CLI, Web HTTP와 접이식 패널 구현을 연결했다. active 표시는 실제 관측 실행으로 오해하지 않도록 ‘관측 허용’으로 정했다. core1의 nullable subscription과 build1의 반환값 nullable 추론을 명시적 검사와 never 함수 선언으로 교정했고 원 로그를 보존했다. core3/build3는 exit0이며 구조 검사202개/위반0이다.

build3 최초 신규 시험은 코어5/5, CLI/Web/UI10/11이다. 음수 CLI 값을 두 인자로 넘겨 Node의 옵션 파서가 먼저 거절하므로 수치 검사를 보려면 `--control-revision=-1`로 전달해야 한다. 기존 resident 시험20/21의 한 실패는 pause/resume 뒤 과거 상태와 현재 상태를 통째로 비교하던 기대값이다. status에 추가한 제어·상태 버전은 실제 제어 때 증가하므로 데이터 보존과 번호 증가를 별도로 검증하도록 보완한다. 제품 동작 변경 없이 해당 두 시험 파일만 수정할 예정이며 다른 시험이 종료되기 전에는 소스/빌드를 바꾸지 않는다. 별도 호스트 회귀는 진행 중이다.

사용자의 메인 프롬프트 질문에는 현재 소스를 다시 확인해 구현·모델 전송 경로 연결과 실제 모델 품질 미검증을 구분해 답했다. 프롬프트를 새로 만들거나 모델/API 시험을 재개하지 않았다.
