# P1 — 저장소 독립적인 최소 코어

2026-09-05 · 진행 중 · P0 계약에서 실행 의미로 연결

목표는 도구가 끝날 때마다 새 계획을 만드는 루프가 아니라, 검증된 현재 계획을 실행하고 변경이 필요할 때만 다시 계획하는 코어다. 실행 의도/결과/예산/근거를 저장하고 다음 실행이 이 상태에서 이어지게 한다.

| 순서 | 구현 단위 | 주요 확인 |
|---|---|---|
| P1-01 | 메모리 저장 대역, scripted planner/tool/clock/sink와 composition | DB/채널 SDK 없는 코어 시험, 두 fixture의 공통 타입 |
| P1-02 | 파일 artifact와 기존 SQLite 저장 통합/강화 | 해시·정책·원본 유실, 바이트 저장 후 commit 실패, 재시작/중복 |
| P1-03 | Plan Validator·배정·실행 의도/결과 수락·상태 제어 | 무효/낡은 계획, continue/replan/wait/blocked/complete·취소/예산·unknown 분리 |
| P1-04 | 작은 도구 목록, 호출 장부, 근거 조회, 지침 로딩 | 버전/권한/상한·정확한 ID, 실행 전 검증·재시도 의미 |
| P1-05 | CLI 접수·상태·변경/취소·응답 outbox | 접수 응답, 조용한 상태 표시, 결과 준비와 전달의 분리 |
| P1-06 | 모델 adapter와 가설/반증/계획 변경의 실제 통합 | 코드와 로컬 계약 검증 가능; 실제 모델은 연결 정보/새 시험 지시가 필요 |
| P1-07 | 전체 경로·최소 재개 packet·장애 구간 | 대역 전체 경로와 실제 모델 전체 경로의 검증을 구분 |

모델 연결 정보가 없어도 01~05와 후속 독립 구성요소를 구현한다. 06의 실제 모델 검증 및 이를 요구하는 단계 완료를 대역 성공으로 대체하지 않는다. 이전 API 키 실험 재개/검색은 하지 않는다.

P0의 fact 판정은 일반적인 원문 의미 판단 전체가 아니다. P1의 evidence intake는 인증된 tool/context가 출처·범위를 제공하게 하고, 모델의 제안을 곧바로 신뢰된 근거나 목표/권한 변경으로 저장하지 않는다.

실행 시작 전 의도와 예산을 기록하고 결과 수락은 별도 커밋으로 처리한다. 중간 종료 시 읽기는 계약/예산에 따라 재시도할 수 있고, 쓰기의 효과가 불명확하면 대조 의무로 남긴다. 커밋 뒤 응답 전 실패는 같은 결과/응답 의도를 복원한다. 큐가 비었다는 이유로 목표를 완료하지 않는다.

챕터를 진행하며 실제 코드/실행 예제·명령/결과·실패/미검증 항목을 기록하고 통과한 작업만 목록에서 갱신한다.
