## 구현한 흐름

현재 근거는 자신의 상태와 모든 부모 근거를 함께 검사한다. 부모가 철회되거나 접근이 막히면 그 부모에서 나온 내용도 현재 근거에서 제외한다. 정정본이 보이지 않는다는 이유로 이미 대체된 옛 근거를 다시 수락하지 않는다. 정정은 새 ID로 저장하며, 단순 철회 후 허용되는 역사 검토와 삭제·접근 제한을 구분한다.

공식 수명 변경은 인증된 업무 소유자, 예상 수명 세대, 명령 ID와 사유를 받아 상태 저장소에 커밋한다. 같은 요청의 재시도는 다시 적용하지 않으며, 같은 ID의 다른 내용이나 오래된 예상 세대는 거부한다. 삭제·접근 제한 후에는 과거 도구 결과, 모델 입력, 준비된 답변, 작업 파일의 접근도 차단한다. 늦게 돌아온 응답은 사용량·효과 불명 상태를 보존하면서 내용은 정리한다. 이미 발송됐을 수 있는 쓰기나 메시지를 취소 완료로 바꾸지 않는다.

기억은 개인 기록으로 시작한다. 공유하려면 검토 요청 후 다른 인증된 검토자가 해당 내용 버전을 확인해야 한다. 작성자·namespace·범위·자료 등급·관측/기록 시각·출처 버전·만료·파생 기억을 보존한다. 조회 권한은 도구 인자로 받지 않고 인증된 호출 맥락에서 얻는다. 기억의 직접 출처 등록과 검토된 공유 기억에서의 파생을 구분하며, 공유 카드 조회가 원본 업무 읽기 권한을 부여하지 않는다.

`core.memory.get`은 ID로 읽고, `core.memory.search`는 현재 목표 범위에서 기억을 찾는다. 관리 API는 유형·시각·범위 조건도 지원한다. 현재 검색은 한국어/영어 NFC 정규화와 부분 문자열 기준선이다. 의미 검색이나 reranker의 성능을 검증한 것은 아니다. 새 기록은 색인 전에 직접 읽을 수 있고, 검색은 색인 지연·오류·후보 상한·결과 잘림을 부분 결과로 표시한다. 캐시에는 후보 ID만 넣으며 반환할 본문은 정본과 출처를 다시 검사한다.

모델 입력에는 허용된 기억 결과를 최대 8개, 합계 16 KiB의 본문 예산 안에서 넣는다. 빠진 항목 수와 과거 관측이라는 의미를 표시하고 내부 권한·출처 관리 envelope는 노출하지 않는다. 이 제한은 최소한의 입력 구성이다. 오래된 도구 명세 퇴거, 호출 쌍 보존, 반복 compact와 선택 재로딩은 다음 P2-03 범위다.

## 조회 이후에도 출처를 따라가는 이유

독립 검토에서 다음 사례를 찾아 수정했다.

- 검색 중 앞서 확인한 출처가 바뀌면, 마지막 항목만 확인해서는 전체 결과를 믿을 수 없다. 묶음 전체의 권한·기억·부모·출처·색인 버전을 제한된 횟수로 비교한다.
- `core.calls.get`으로 기억 결과를 복사할 때 공개 본문에서 뺀 내부 출처 정보를 별도 envelope로 전달해야 한다. 저장된 복사본과 이후 도구 결과에도 이 참조를 이어 붙인다.
- 목표 변경이나 무관한 근거 철회가 시도의 `adopted` 상태를 바꿔도 파생 내용은 남을 수 있다. 그 상태 변화만으로 출처 검사 대상에서 제거하지 않는다.
- 관련 없는 상태 저장 때문에 증가한 `workRevision`은 읽기 일관성을 확인하는 값이다. 출처 내용이 바뀐 의미 버전으로 사용하지 않으며, 중복 의존성도 이 값만 다르다고 새 항목으로 늘리지 않는다.
- 채택 저장이나 원본·파일·모델 입력 I/O 중 출처가 바뀔 수 있다. 조회 이후, 채택 이후, 도구/모델 호출 전, 결과 준비와 발송 전, 재개 패킷 반환 전에 검사를 연결했다. 검증기가 빠진 재시작에서도 보호를 생략하지 않는다.

기억의 유효성이 사라지면 관련 검토 의무를 만들고 실행·답변을 중단한다. 기존 근거에는 기억의 필드별 출처 관계가 없으므로 현재 구현은 **해당 업무 전체의 현재 복사본을 보수적으로 격리**한다. 계획·가설·준비 답변을 비우고 근거 본문을 제한하며 과거 artifact를 차단한다. 격리된 현재 view가 더 이상 내용을 소비하지 않을 때만 현재 의존성 집합을 정리한다. 원래 결과 artifact에 들어 있는 참조는 역사 조회를 검사하기 위해 남는다. 정밀한 영향 범위 축소는 후속 개선이다.

## 작업 파일과 로컬 프로필

`WorkspaceCheckpoints`는 work/attempt별 파일을 격리한다. 논리 경로, 소유권, 자료 등급, 바이트·파일 수 상한을 검사한다. 기본 상한은 파일당 1 MiB, 시도당 128개·16 MiB다. 같은 경로의 같은 바이트는 중복 저장하지 않으며 내용이 다르면 충돌로 처리한다. 중요 파일은 불변 artifact로 승격해 업무 checkpoint로 저장하고 새 인스턴스에서 복원한다.

진행 중인 시도, 효과/전달 불명 상태, checkpoint가 없는 파일은 오래됐다는 이유로 정리하지 않는다. 정리 시 확인한 파일 목록과 실제 목록이 달라지면 뒤늦게 저장된 파일을 지우지 않는다. 접근 제한과 기억 유효성도 파일 I/O 전후에 검사한다. 로컬 잠금은 다른 프로세스가 소유한 잠금을 임의로 회수하지 않으므로 잠금을 남긴 비정상 종료에는 `workspace_busy` 복구 절차가 필요하다.

로컬 프로필은 `knowledge.sqlite`와 `workspaces/`를 함께 연다. 기본 신뢰 주체는 합성용 `synthetic/learner`, namespace는 `local`이며 공유 검토/게시 권한은 없다. 업무 상태 저장 방식은 SQLite 또는 FileJournal로 선택한다. 기억 서비스와 workspace는 작은 포트로 주입하고 domain/application에는 DB·파일 SDK를 추가하지 않았다. 두 업무 상태 구현을 확인한 것이 모든 저장 adapter가 이미 구현됐다는 뜻은 아니다.

## 보장 범위와 다음 단계

이 검증은 로컬 계약과 결정적인 모델 대역을 사용한다. 실제 모델의 기억 활용 능력·업무 성공률, 실제 MCP/Knox/컴퓨터 유즈, 운영 처리량·검색 회수율은 미검증이다. 서로 다른 저장소의 여러 읽기를 비교하는 것은 전역 트랜잭션이 아니다. 마지막 유효성 확인 뒤부터 외부 수신자의 실행까지 원자적으로 묶으려면 배포 환경의 공유 fence/lease 또는 수신측 조건부 실행 계약이 필요하다. 현재 검사로 그 수준의 보장을 주장하지 않는다.

논리 삭제와 물리 삭제도 다르다. SQLite 상태 영수증, FileJournal 과거 record, 색인·WAL·백업·이미 전달된 내용이 자동으로 모두 지워진 것은 아니다. 물리 제거는 `pending_retention_review`로 기록하며 P6 보존/백업/복원 검증과 연결한다. 실제 모델 시험 중단은 유지한다.

P2-02의 로컬 범위는 검증했지만 선행 실제 모델 조건이 남아 작업 전체 상태는 `in_progress`로 유지한다. 전체 검증 완료 작업은 9개다. 다음 독립 로컬 챕터는 **P2-03 컨텍스트 수명과 compact**다. 이번에 만든 저장·출처·조회 경계를 재사용해 컨텍스트를 줄이면서 목표·제약·반증·미확정 의무를 복원하는 과정을 검증한다. 전체 P0–P6 구현 목표와 실제 연동 조건은 유지한다.
