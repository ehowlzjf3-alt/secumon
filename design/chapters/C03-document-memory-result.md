SQLite 기본값을 유지하면서, 새 담당에서 `secumon-agent init --personal-memory documents`를 명시하면 개인 기억을 해당 담당의 `memory/documents`에 저장하도록 연결했다. 원문 대화·실행 상태·업무 근거 기억은 각각의 기존 저장 경로를 유지한다. 검색한 외부 자료가 자동으로 개인 기억이 되지는 않는다.

## 연결한 구성

- v2 설정과 최초 설정 기록에 개인 저장 방식·storeId를 먼저 저장한다. 중단된 설정을 재개할 때도 같은 선택을 유지하며, 복제에는 새 담당·저장소 ID를 발급한다.
- `.secumon/personal-memory-profile.json`은 최초 배정, `document-memory-ready.json`은 등록 완료 기록이다. 등록된 문서 저장소가 사라지면 빈 기억이나 다른 SQLite 저장소로 대체하지 않는다.
- 호스트가 정한 개인 범위는 문서 repository, 업무 기억은 SQLite repository로 보낸다. `KnowledgeService`, CLI/Web, `core.memory.get/search`, 실제 packet/frame은 이 같은 조합을 사용한다.
- 조직·담당·사용자의 논리 범위를 경로 지문과 파일 메타데이터에 대조한다. 같은 기억 ID를 가진 다른 사용자의 기록·영수증·검색 결과가 섞이지 않게 한다.
- 순차 Markdown 파일 한 개에 기억 버전과 명령 receipt를 함께 저장한다. receipt는 같은 요청이 이미 적용됐는지 확인하는 기록이다. 별도 확인 파일에는 게시 순서와 내용 지문만 두어 마지막 버전이나 전체 namespace 삭제를 대조한다.
- 완전한 Markdown 게시 뒤 확인 파일을 쓰기 전에 중단되면, 검증된 게시 기록의 빠진 확인 파일만 복구한다. 기존 서비스의 먼저 읽기·중복 확인 경로도 이 복구를 통과한다.

## 범위와 남은 작업

이 D1은 새 담당의 문서 저장 선택과 기존 기억 명령 연결이다. 편집기에서 고친 Markdown 초안의 명시 적용은 [D2](C03-document-draft-plan.md), 기존 SQLite 개인 데이터의 이관은 D3다. 현재 정본 파일을 직접 고쳐서 기억을 수정하는 방식은 지원하지 않는다.

본문과 확인 기록을 모두 일관되게 되돌리는 동일 OS 계정 변경은 별도 신뢰 기준 없이 탐지할 수 없다. 현재 파일 경계는 POSIX 경로 재검사이며 모든 접근을 디렉터리 핸들로 고정한 격리가 아니다. Windows 연결·네트워크 파일시스템·물리 삭제·대량 이력 정리·실제 모델 품질은 별도 잔여다. 장기기억 전체에 사용자 승인을 강제하는 설계가 아니며, 이후 자율 경험 기억은 별도 출처 유형으로 같은 저장 경로를 사용할 수 있다.
