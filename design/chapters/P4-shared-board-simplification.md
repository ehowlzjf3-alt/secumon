# P4 공유 게시판과 응답 책임 단순화

후속 사용자 지시에 따라 지금은 변경 내용을 먼저 정리한다. [P4 수정 범위 정리](/Users/seunghanee/Documents/secumon/design/chapters/P4-design-reconciliation.md)가 최신 요구·제안·미결정의 구분 기준이다. 아래의 역할별 원문 저장소/리드 접근 제한은 필요한 배치의 예시이며 모든 에이전트의 고정 구조로 채택하지 않는다.

## 바꾸려는 동작

게시판은 참여자들이 같은 내용을 읽고 협업하는 공간으로 사용한다. 참여자에게 읽을 수 없는 답변을 게시한 다음 확인을 기다리는 흐름은 기본 경로에서 없앤다. 원문 파일의 접근 권한과 게시판 글의 공유 범위를 구분한다. 모든 글에 별도 사람 승인·가공 작업을 붙이지 않는다.

기본값은 **게시판 단위의 공유 범위**다. 해당 게시판에 게시된 글은 현재 참여 권한이 있는 역할들이 읽고 답할 수 있어야 한다. 공유 범위가 다르면 별도 게시판을 사용한다. 글별 숨김/열람 신청/복잡한 권한 단계는 기본 협업 흐름에 넣지 않는다.

원문은 역할별 저장소에 남고, 게시판에는 관측·가설·질문·답변·상태와 근거 참조를 올린다. 원문을 열 수 없더라도 글은 읽고 관련 역할에 질문할 수 있다. 다른 역할의 말을 읽은 것은 독립 원본을 직접 검증한 것과 구별한다. 근거가 필요하면 원문 보유 역할에 검증 작업을 요청하거나 자기 접근 범위에서 다른 근거를 찾는다.

## 공유와 원문 보호의 정확한 의미

- 기본 배치에서는 지정된 게시판 참여자에게 업무상 관측과 답변을 공유하는 것을 허용한다. 공유 대상은 모든 사용자나 외부 채널이 아니다.
- 리드의 원문 파일 접근은 저장소/도구 권한으로 제한한다. 원문 파일을 못 연다는 조건이 요약된 내용도 전혀 알 수 없다는 조건을 자동으로 뜻하지 않는다.
- 게시 도구는 게시판 대상·현재 참여 권한·허용 자료 범위를 한 번의 게시 작업 안에서 검사한다. 부적합한 글은 게시 전에 명확히 실패하며, 다른 참여자에게 안 보이는 답변을 올려 놓고 수신 확인을 기다리지 않는다. 일반 글마다 사람 승인이나 별도 승인 담당 에이전트를 호출하지 않는다.
- 자연어 요약이 민감 정보를 절대로 포함하지 않는다는 보장을 파일 권한이나 모델 지시만으로 주장하지 않는다. 원문에서 나온 정보 자체의 엄격한 비공개가 필요한 배치는 공유 가능한 입력/출력 형태를 제한하거나 별도 공개 절차를 사용한다. 이 강한 격리 모드는 선택 배치로 두며 범용 게시판의 기본 경로에 강제하지 않는다.
- 기존 P2 공개 검증 구성요소는 강한 격리 배치에서 재사용할 수 있다. 기존의 보수적인 자료 등급 전파를 모든 게시판의 기본 협업 설계로 고정하지 않는다.

## 읽고 답하는 동작

관측글은 관련 역할이 선택적으로 반응할 수 있다. 모든 글에 모든 역할의 답변을 의무화하지 않는다. 질문·검증 요청·작업 위임에는 담당 역할과 명시적인 요청 상태를 둔다.

1. 글/요청을 저장하고 해당 역할의 영속 알림을 만든다. 대화 모델 컨텍스트에 전체 게시판을 계속 넣지 않는다.
2. 실행기가 관련 역할을 깨우고 새로운 요청을 조회한다. 수락 또는 거절·담당 부적합 상태를 남겨 요청자가 진행을 알 수 있게 한다.
3. 수락한 요청은 task graph의 의무가 된다. 답변, 추가 정보 요청, 근거 부족 보고, 취소 중 하나로 진행 상태를 명시한다.
4. 응답이 없으면 대기 기한과 무진전 기준에 따라 알림을 합치고, 실행 중인지 확인한 뒤 재배정하거나 원 요청자에게 막힌 상태를 돌려준다. 고정 간격으로 모든 에이전트가 모델을 호출하며 게시판을 순회하지 않는다.
5. 같은 원인/요청의 중복 알림과 답변은 묶는다. 답변이 새 조사 목표를 만들 때도 원 요청과 연결하고 무한 대화를 제한한다.

가시성은 게시판 계약으로, 응답 책임은 요청·의무·실행기로 해결한다. 게시판에 쓰는 것만으로 실행을 시작했다고 간주하지 않는다.

## 구현 순서와 통과 기준

현재 진행 중인 funding 검증은 현재 코드의 동작을 기록한다. 비공개 답변 거절 시험의 통과가 그 UX를 새 기본 설계로 채택했다는 뜻은 아니다. 전체 검증 중 제품 소스는 고정하고 이후 다음 순서로 전환한다.

1. 게시판 audience와 공유 가능한 글의 계약을 먼저 확정한다. 원문 저장소의 독립 권한을 유지하면서 글 본문과 근거 접근을 분리한다. 이미 보관된 비공개 글을 자동으로 공개하는 데이터 변경은 하지 않는다.
2. 요청자가 읽을 수 없는 최종 답변을 정상 게시/답변 상태로 만들지 않는 게시 경계를 구현한다. 기본 공유 흐름과 선택적인 엄격 격리 흐름을 시험에서 분리한다.
3. 현재 영속 알림·요청·의무·budget 기반을 재사용해 담당 역할 실행과 미응답 처리를 연결한다. 에이전트의 잔량 조회·배정/추가 요청/회수·재배정 도구는 같은 실행 흐름에 연결한다.
4. 두 역할×두 업무군×두 저장소에서 게시→읽기→수락→근거 조사→답변 또는 근거 부족/추가 질문→종결을 검증한다. 사람의 글별 승인 0회, 읽을 수 없는 정상 답변 0건, 원문 무권한 열람 0건, 재시작 시 미응답 요청 유실 0건을 기준으로 삼는다.

게시판의 공유 가능 범위와 엄격 격리 배치 여부는 조직의 데이터 정책에 따른다. 실제 사내 서비스 연결·모델 시험 중단 조건은 유지한다.
