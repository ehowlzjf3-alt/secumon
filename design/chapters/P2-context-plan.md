# P2-03 — 컨텍스트 수명과 compact

2026-09-05 · 구현 계획 · 실제 모델 선행 조건 유지

이번 챕터는 “컨텍스트에서 내려도 다시 판단할 수 있는가?”를 확인한다. P2-02의 정본·근거 수명·권한·기억·파일을 재사용한다. 정본을 줄이는 기능과 모델에 보낼 입력을 줄이는 기능은 분리한다. 매번 별도 요약 모델을 호출하지 않고 검증 가능한 규칙으로 시작한다.

## 구현 순서와 완료 기준

1. **보존 계약과 working set.** 최신 목표/정책·완료 조건, 가설/반증/판별 질문, 대기/wake/due·효과/전달 unknown, 실행 예산과 계획 frontier를 보호한다. 관련 없는 근거·완료된 시도·긴 본문·미사용 명세는 저장 위치를 확인한 뒤 참조하거나 내린다. 모든 과거 ID를 프롬프트에 다시 나열하지 않는다. 보존 필수 내용만으로 상한을 넘으면 잘라서 성공시키지 않고 입력 한계로 반환한다.
2. **선택 로딩과 재조회.** 실제 ModelCallOptions와 전송 packet 모두에 선택된 도구만 넣는다. 카탈로그와 근거/호출 조회로 빠진 항목을 다시 발견하며 정확한 ID/version/digest와 현재 권한을 확인한다. 도구/skill 사용 정보와 최소 유지 구간·상하 임계값으로 매 호출마다 퇴거/재로딩하는 진동을 줄인다. 신뢰된 지침의 필수 규칙과 버전을 유지하며 예시/긴 본문은 별도 취급한다. 권한 철회는 유지 유예보다 우선한다.
3. **내구성 있는 compact 전환.** ContextFrame/Manifest에 기반 state/goal/plan/event cursor·정책·수명·도구/지침 기준, 표현 방식/간단한 사유, 입력 비용과 퇴거·재로딩 관찰값을 남긴다. 원본 확인→후보 저장/검증→동일 기준 상태에서 head와 모델 호출 예약을 커밋한다. 오래된 후보를 최신 revision에 그대로 적용하지 않는다. 파생 frame의 유실/손상은 정본으로 재생성할 수 있도록 필수 원본 참조와 분리한다.
4. **실제 입력 구성과 비용.** 현재 구조화된 stateless proposal 방식은 유지한다. 호출의 task/inputDigest/attempt와 저장 결과를 대조해 완전한 쌍 또는 명시적인 저장 참조로 표현한다. provider chat history를 임의로 자르지 않는다. packet/선택 명세/직렬화 request bytes, 추정 tokens와 방법, 출력 예약·실제 보고 usage를 구분해 저장한다. LLM 없이 수행한 정리 비용과 재조회 호출도 기록한다.
5. **반복 교체와 장애 검증.** 두 업무군과 두 영속 상태 구현에서 적어도 5회 working-set 교체 뒤 작은 초기 단서와 반증을 다시 찾는다. 의무/unknown·현재 정책·완료 검증을 보존하고 큰 catalog의 실제 요청 크기 감소를 확인한다. 저장 실패·파생 frame 유실/손상·원본 누락·동시 목표/권한/근거 변경·재시작·버전 교체·재로딩 진동을 시험한다. 기존 전체 suite를 통과하고 실행·소스 hash·한계를 저장한다.

## 재사용과 경계

- ContextRecovery와 workspace의 원본 확인/동일 revision 커밋을 재사용한다. compact는 목표·근거·시도·예산을 새 진실로 덮어쓰지 않는다.
- 지연 조회는 카탈로그·호출 장부·근거/기억 서비스를 사용한다. P2-04의 광범위한 dedup/batch/cache 최적화를 이 챕터의 통과로 대신하지 않는다.
- 공개 채팅에 compact 사건을 말풍선으로 추가하지 않는다. 진단 명령/API와 저장 manifest에서 확인한다.
- 실제 모델/API·SIEM/EDR·Knox·컴퓨터 유즈는 실행하지 않는다. 공급자 요청 구성은 기존 로컬 transport fixture로 검증하고 실제 모델의 의미 보존/품질·usage 조건은 미충족으로 유지한다.
- 원본의 물리 삭제·전역 분산 fence·장기 성능·운영 도입은 이번 범위 밖이다. 전체 P0–P6 목표와 후속 작업은 유지한다.
