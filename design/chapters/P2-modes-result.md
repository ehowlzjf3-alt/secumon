## 모드가 실행을 바꾸는 방법

`Goal.mode`는 최초 요청의 일부로 보존한다. 현재 모드는 별도 `ExecutionControl`에 요청 모드·실행 전략·정책 버전·대기 변경·변경 이유와 revision으로 저장한다. 목표 revision을 바꾸지 않으므로 완료 task와 근거·저장 조회 checkpoint의 원출처가 유지된다.

| 요청 | 현재 로컬 정책 |
|---|---|
| auto | 직접 계획으로 시작한다. 검증한 계획의 범위나 반증/미완료 근거가 확장을 요구하면 조사 전략으로 바꾼다. work 총예산 안에서 실행한다. |
| fast | 직접 계획 범위를 제한한다. 도구 2회·모델 2회·추가 재계획 0회와 work 상한 중 더 좁은 절대 한도를 사용한다. 숨은 승격으로 제한을 우회하지 않는다. |
| deep | 조사 전략으로 시작한다. 이미 근거와 완료 조건이 충족되면 추가 추론 없이 종료한다. |

위 수치는 `local-v1` 합성 평가 정책이다. 실제 모델의 최적 기본값이나 처리 시간 개선을 주장하지 않는다. 기존 가설의 필수 검토는 fast에서도 보존하며, 새 가설 추가와 기존 가설 검토를 구분한다.

모드 명령은 owner·목표 revision·제어 revision·명령 중복을 확인한다. 실행 중인 도구/model이 있으면 다음 배정 경계까지 변경을 보관한다. 목표·근거·계획·사용/예약량·총기한·unknown 효과는 초기화하지 않는다. 적용 중 새로운 명령이 커밋되면 최신 상태를 다시 판정한다.

모델 입력의 의미 digest에는 현재 모드/전략/정책을 포함하고, 아직 적용하지 않은 대기 변경은 제외한다. 새 호출은 `semanticVersion: 2`, 과거 호출은 기존 형식을 사용해 예전 저장 응답도 정산할 수 있게 했다. ## 진전과 반복을 구분하는 방법

진전 장부는 검증된 새 원근거, 새로운 근거 조합에 대한 가설 평가, 충족한 기준과 해결한 의무를 안정적인 의미 키로 기록한다. task ID·계획 문구·revision·시각을 바꾸거나 저장 응답을 다시 채택해도 같은 정산을 중복 계산하지 않는다.

도구 카드·정확한 schema·지침 manifest/body를 처음 읽는 것은 준비 진전으로 별도 기록한다. 검색어·cursor·설명·표시용 길이를 바꿔 같은 자료를 다시 읽는 것은 새 진전이 아니다. 과거 호출과 근거를 다시 읽는 것도 새 근거를 만든 것으로 취급하지 않는다. 이 준비 기록은 권한이나 완료 조건을 추가하지 않는다.

결과 채택과 진전 갱신은 같은 상태 CAS에 저장한다. 장부 원본은 정본 저장소에 남기고 모델 컨텍스트와 재개 packet에는 네 개의 작은 집계만 넣는다. compact는 장부를 버리는 작업이 아니다. 모드 변경·조회·resume·재시작은 장부를 보존한다. 명시적인 목표 변경만 연속 무진전 epoch를 갱신하며, 과거 의미 키·실패 최초 시각·누적 비용은 남긴다. [진전과 준비 자료](/Users/seunghanee/Documents/secumon/runtime/src/application/work-progress.ts)

## 멈춤과 재시작

기본 로컬 정책은 연속 무진전 3회, 같은 의미의 실패 3회, 재시도 총기한 30초, backoff 100ms다. 실제 배치 전 평가가 필요한 값이다. 같은 호출을 새 task ID로 바꿔도 첫 실패 기한을 연장하지 않는다.

새 할당 전에 이 장부를 확인한다. 이미 받은 결과의 채택·lease 복구·unknown 효과 대조·검증된 완료·회신 대기는 기존 순서를 유지한다. 사용량을 모르는 모델 호출은 예약 토큰을 보존한다. backoff 때는 `retryWakeAt`을 저장하며 두 영속 저장소와 메모리 저장소의 runnable 조회는 해당 시각에 다시 실행 대상을 반환한다. 대기 동안 모델과 도구를 계속 부르지 않는다. [실행 판정](/Users/seunghanee/Documents/secumon/runtime/src/application/execution-decision.ts)

CLI의 최초 `--mode`와 별도 mode 명령을 연결했다. 상태 조회에는 현재 모드/전략, 대기 변경, 잔여·예약량, 재시도 시각과 미완료 이유를 보여준다. 조회 때문에 실행이나 자동 전략 변경을 수행하지 않는다. [CLI](/Users/seunghanee/Documents/secumon/runtime/src/presentation/cli.ts)

## 학습 질문

**왜 모드 변경이 목표 변경이면 안 되는가?** 같은 목표를 수행하는 전략 변경 때문이다. 목표 identity를 바꾸면 이미 받은 결과와 조회 checkpoint가 다른 업무 계약의 자료로 취급되어 재사용·정산을 깨뜨릴 수 있다.

**도구를 한 번 더 불렀으면 진전인가?** 새로 검증한 사실이나 필요한 도구/지침의 첫 발견은 진전일 수 있다. 같은 내용에 새 ID를 붙이는 것은 호출 비용만 증가시킨다. 진전과 업무 완료는 별도 판정이다.

**compact 뒤 재시도 기한은 어디에서 복구하는가?** 짧은 대화 요약이 아닌 정본 상태의 최초 실패·다음 실행 시각·총기한에서 복구한다. 모델에 모든 과거 실패 내용을 다시 넣을 필요는 없다.
