# C09 이력 조회 비용·사건 한도 결과

2026-09-09 · checkpoint400 · 기준선 `ab5c0761ed80936fce86b3497b19fe22da454294`.

같은 페이지에서 반복하던 업무 상태 조회를 줄이고, 사건 한도를 넘은 페이지를 받아들이지 않은 채 커서가 전진하던 문제를 수정했다. 전체 C09와 goal은 진행 중이다.

## 구현과 측정

`SessionOriginals.read`는 한 페이지에서 세 번 이상 등장하는 업무 상태만 재사용한다. 최대8개 업무·직렬화 UTF-8 4MiB이며 초과하면 기존 개별 조회를 사용한다. 재사용한 상태는 페이지 끝에 원 전체 상태를 다시 읽어 대조한다. 원문별 입력 영수증·권한·자료 존재 검사는 유지하고, 상태가 바뀌면 문맥 후보를 발행하지 않는다. 페이지가 끝나면 캐시를 폐기한다. 이 한도는 전체 프로세스 메모리 한도가 아니다.

이전 checkpoint399의 컴파일 파일 일치를 확인한 뒤 기준선을 측정했다. 같은 입력129개·문자열 크기128·문맥 한도262,144bytes로 수정 후 시험과 비교했다. 세션 접수는 실제 임시 SQLite, 업무 상태·자료는 메모리 저장소다.

| 동작 | 업무 상태 조회 전 → 후 | 업무 상태 반환 bytes 전 → 후 |
| --- | --- | --- |
| 문맥 조회 | 129 → 5 | 276,060 → 10,700 |
| 현재 문맥 재확인 | 129 → 5 | 276,060 → 10,700 |
| 문맥 검사 | 131 → 7 | 280,340 → 14,980 |
| 검사한 문맥 확정 | 262 → 14 | 560,680 → 29,960 |

원문 수·이력 페이지·이력 반환량·입력 영수증 조회 수는 그대로다. 로컬 시간 표본은 일관된 속도 향상을 입증하지 않는다. 저장소 호출·직렬화 반환량 감소를 물리 디스크 I/O나 모델 토큰 절감으로 해석하지 않는다. [원 측정](../../runtime/evidence/checkpoint400-measurements.json).

`MissionRuntime`은 같은 목표의512개 사건 한도를 넘으면 마지막으로 받아들인 커서·원문·읽기 확인을 보존하고 `closed/event_capacity`로 종료한다. 새 페이지를 저장·처리했다고 표시하지 않는다. 정확한 중복은 기존처럼 처리하고 ID가 같지만 내용이 바뀌면 거절한다. 511→512번째 새 사건은 정상 접수한다. 종료 후 같은 목표에서 자동 재개하는 기능까지 추가한 것은 아니다.

## 검증

신규9개·관련44개, 고유53개가 최종 코드에 대응해 통과했다. 첫 build1에서는49개 통과·4개 실패였다. 네 실패는 시험 준비 단계의 Buffer와 Uint8Array 자료형 비교 오류였고 제품 코드 수정 없이 바이트 내용 비교로 교정했다. build2에서 해당4개만 다시 실행해 모두 통과했다. 최종 build2의2,577개 컴파일 파일 중 해당 시험 JS·소스맵2개만 달라 나머지 결과를 재사용했다. 최초 실패 원로그도 보존한다.

- 이력 비용·상태 변경·권한 철회·입력 영수증·자료 존재·메모리 한도: 신규5개.
- SQLite/file-journal의 한도 초과·원자료 보존·재열기·중복/충돌·정확한 한도 도달: 신규4개. 511/512개 기록을 정상 저장 포트로 준비한 시험이며512회 실제 업무 실행 시험은 아니다. ACK 표식은 보존 확인용이고 실제 발급 검증은 기존 읽기 확인 회귀에 포함된다.
- compact 원문 경계·문맥 창·문맥 검사, mission 읽기 확인·이력·실행, 상주 담당 입구: 관련44개.
- build2·코어 타입 검사 exit0, 구조203개·위반0, 시험 후 소스·컴파일 대조 일치. 코어/구조 검사는 시험 비교문만 바뀐 build1 기록을 재사용했다.

## 남은 범위

원문 전체 검증은 이력 길이에 비례하며 원문·영수증 저장량도 계속 누적된다. 같은 목표의 용량 종료 이후 이어가기와 원자료·중복 근거를 보존하는 장기 보관/이관 처리가 다음 C09 잔여다. 전체 상태 대조는 관련 없는 동시 진행에도 보수적으로 재시도를 요구할 수 있다.

C05/C06 완주·기억 대화, C10 초기 복원·설치·현재 Linux/native Windows·실제 PostgreSQL, 최종 통합·사내 MCP/Knox/외부 A2A를 [남은 확인 목록](../REMAINING-ACCEPTANCE.md)에 유지한다. 이번에는 UI를 바꾸지 않았고 실제 브라우저·실환경 연결·전체 시험을 다시 실행하지 않았다. 실제 모델/API 시험 중단을 유지한다. 모든 빌드·시험은 종료됐다.
