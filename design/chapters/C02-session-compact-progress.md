# C02 반복 compact — 현재 등록 검증과 정리 완료

2026-09-07. [계획](C02-session-compact-plan.md)에 따라 지속 세션의 원문 보존과 반복 요약을 연결했다. **최종 Linux 전체 2,836/2,836, compact 46/46 통과와 전용 시험 프로세스 0개·SSH 종료를 확인했다. C03 개인 기억 흐름에 착수할 범위별 gate를 충족했다.** [최종 검증 근거](../../runtime/evidence/C02-compact-verification.json)와 [결과](C02-session-compact-result.md)를 기준으로 읽는다. C01/C02 전체나 전체 goal의 완료 기록은 아니다. 직전 원문 세션의 Linux 2,785개 검증은 이전 소스 기록으로 유지한다.

## 이번 연결

- 원문 대화는 그대로 두고, 앞부분 요약과 최근 원문을 합친 문맥 v2를 추가했다. 원문형 v1도 계속 검증·복구한다. 새 요약이 생겨도 이미 고정한 이전 입력을 최신 요약으로 다시 만들어 비교하지 않는다.
- 원문 목록은 제한된 페이지로 읽는다. 범위별 지문을 이어 계산하므로 입력 크기에 맞게 요약 구간을 줄일 때 같은 전체 원문을 매번 다시 읽지 않는다. 요약 사용 시 원출처 정책·원문·기존 모델 호출의 채택 상태를 확인한다.
- 사용자 원문은 접수 당시 내용 지문과 대조한다. 이력 본문, 접수 본문, 순서·업무·소유 범위가 다르면 새 정본으로 받아들이지 않는다.
- 구조화한 요약은 서술, 중요한 항목, 정확한 원문 인용을 가진다. 이전 중요 항목의 삭제를 거절하고, 변경에는 뒤의 원문 인용을 요구한다. 새 사용자 발언이 있는 구간에는 그 구간을 정확 인용한 중요 항목이 최소 하나 있어야 한다. 이 규칙이 모든 자연어 합의·반론을 빠짐없이 뽑았다는 증명은 아니며 실제 모델의 의미 보존 품질은 미검증이다.
- 기존 PlanningRuntime에서 planning과 session_compact 목적을 구분한다. 모델 호출 예약·사용량 정산·취소·unknown·저장 응답 재개를 공유하고, 요약을 가짜 업무 계획으로 제출하지 않는다. 소비 자원은 현재 활성 작업에 귀속된다.
- 요약 DB의 게시 기록과 작업 DB의 채택을 구분한다. 모델 호출이 accepted로 채택된 요약만 문맥에 사용한다. 게시 직후 취소 경합으로 남은 후보는 다음 문맥에서 채택된 요약을 대신하지 못한다. 물리적 게시와 논리적 사용 가능 상태를 하나의 DB transaction이라고 주장하지 않는다.
- 같은 범위의 재시도는 새 버전으로 보존하고, 더 과거의 범위는 최신 포인터를 돌리지 않고 별도 보존한다. 정책이 바뀌어 이전 요약을 쓸 수 없을 때도 원문을 작은 구간으로 다시 요약할 수 있다. 동일 범위의 미채택 후보를 건너뛰어 이전 채택 버전을 조회한다.
- CLI/Web은 일반 계획 실행과 compact 실행을 구분한다. 자동 compact는 최초 복구 전에 필요성을 확인하며, 조회·상태 표시에서는 모델을 호출하지 않는다. 유효한 문맥을 아직 만들 수 없으면 과거 checkpoint를 현재 것처럼 반환하지 않는다.

명시 합성 provider만 로컬 시험용으로 연결한다. 임의 자연어의 의미를 이해했다고 가장하지 않고 정해진 예제의 인용과 규칙으로 동작한다. 실제 모델/API·Knox·사내 서비스 시험은 중단 상태를 유지한다.

## 검증 이력과 최종 상태

build1에서 신규 46개 중 42개와 기존 세션·모델·워크플로 127개를 통과했다. 신규 4개 실패는 합성 실행기에 일반 모델용 token 추정을 적용한 연결과 자동 trigger 시험의 입력 부족을 확인해 수정했다. 예산을 확대하지 않고 합성 provider의 실제 bytes·최소 token 예약을 명시했다. build2 표면 9/9에서는 자동 compact→첫 도구→완료→같은 세션의 새 업무 문맥/독립 장부까지 실제 저장 checkpoint로 확인했다. 실제 planner.propose 또는 자연어 모델 품질의 증거는 아니다.

build2 소스 `cc3847d78e929914c9e37ddca46e45fa533eead0cda8dc5796ee3043d364afcb` / 빌드 `3b0b497497692014abb8854a398b96cd59c23a454fcaa13dfb444b1435de95f2` / 1,248파일의 첫 NAS 전체 결과는 **2,830/2,831·실패 1**이었다. compact 46/46은 이 시도에서도 통과했다. 원로그를 지우거나 최종 결과로 덮어쓰지 않았다. build2의 브라우저 관측과 합성 계측 1회도 별도 pin 근거로 보존하며 최종 소스 검증으로 옮겨 적지 않는다.

첫 NAS의 `agent_storage_owner_missing`은 오류 코드만 남아 정확한 throw 줄은 미확정이다. 이후 실제 SQLite/파일과 관측 경계 주입으로 동일 오류 경로를 고정 재현했고, 본체 부재 관측 뒤 경쟁 생성에 대한 한 번의 안전 재관찰을 추가했다. 기존 거절 경계를 유지한 수정 후 로컬 관련 43/43을 통과했다. [재현·수정 근거](../../runtime/evidence/C02-compact-owner-result.md)와 각 원로그/종료 상태는 별도로 남겼다.

최종 소스 `2193685e0a64d0f88e40113b2838afc03c8c24b8430d6a6c36847613b77e0967` / 빌드 `a8ffa413f7bef69302103f3f39bbf1738dfa74756d47d6435ff1404e0bb04d70` / 1,248파일에서 Linux 전체 **2,836/2,836**, compact **46/46**, build·core typecheck·계층 137개/위반 0·계층 CLI 경계·fixture 4시나리오/22검사가 통과했다. 최종 전체에서 실패·취소·skip·todo는 모두 0이다. 원로그 회수와 [프로세스 정리](../../runtime/evidence/C02-compact-linux-nas-20260907/cleanup.json)를 완료했고 SSH도 종료했다.

C03의 명시적 개인 기억 사용자 흐름에 진입할 구조 검증 조건은 충족했다. 실제 모델/API 실험 중단, 네이티브 Windows 미검증, 호스트 격리와 C02 잔여 인수 항목은 유지한다. C03 구현이나 C01/C02 전체·전체 goal 완료로 표시하지 않는다.
