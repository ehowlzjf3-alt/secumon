# C04 문맥 창 연결 — 구현 메모

문맥 창 단위의 구현·검증을 마쳤다. 같은 최종 소스에서 로컬 신규 71/71·관련 704/704, NAS Linux 전체 3,209/3,209가 통과했다. 아래는 구현 메모이며 최종 근거와 실패 이력은 [구현 결과](C04-context-window-result.md)를 따른다. 이전 C04 첫 흐름의 Linux 증거는 그대로 보존한다.

## 실행 흐름

다음 모델 호출이 필요한 경우, 현재 목표·가설·반론·의무·실행 상태·필수 도구와 현재 사용자 원문을 유지한 최소 입력을 먼저 측정한다. 선택된 기억과 이전 답변 초안도 이 측정에 포함한다. 최소 입력이 초과하면 과거 대화를 compact하는 호출을 만들지 않는다. 과거 대화 때문에 초과하면 기존 compact 호출로 넘기고, 전체 입력이 들어가면 기존 예방적 compact 기준을 유지한다.

다음 단계가 이미 정해진 도구 실행이나 답변 전달인 경우에는 새 모델 입력의 한도로 그 단계를 막지 않는다. 주 모델을 끄고 compact만 사용하는 배치는 WorkflowRuntime이 그 사실을 전달한다. 명시적 compact 요청의 기존 사용법은 유지한다.

## 문맥의 측정과 게시

읽기 전용 inspection은 세션 원문과 사용 가능한 요약을 검사하지만 head·frame·작업 상태를 게시하지 않는다. 미게시 자료를 정상 세션으로 보이게 만드는 가짜 head도 넣지 않는다. preview는 선택을 위한 추정이며, head를 실제 게시한 최종 요청을 다시 측정한 결과가 예약 여부를 결정한다.

기존 도구 선택기의 full/reference/omitted 표현을 그대로 사용한다. 실제 최소 구성이 들어간다고 확인했다면 근사적인 항목 비용 계산만으로 필수 입력 초과라고 판정하지 않는다. 과거 대화는 중간 항목을 잘라 반환하지 않는다.

PlanningRuntime은 최근 fits 준비 한 개만 메모리에 보관한다. 작업 전체 상태·모델 입력 설정·프롬프트 지문이 같을 때 준비 결과와 예방적 compact의 no-op 판단을 재사용한다. 소비·변경·compact 예약·오류 때 폐기하며 최종 게시에서 원문과 설정을 다시 확인한다. 다른 작업의 정상 요약 전진은 원문 전체 manifest가 같은 경우에만 일시적인 재준비로 처리한다.

## 호출과 자원

입력 한도, 입력 바이트 한도, 출력 예약, 입력과 출력의 총 창을 구분한다. 총 창을 등록했다면 입력 허용량은 입력 한도와 `총 창 - 출력 예약` 중 작은 값이다. 출력 예약을 몰래 줄이지 않으며 업무의 소비 예산과도 합치지 않는다.

compact는 한 번 읽은 완전한 원문 prefix 후보를 반으로 줄이며 최대 9개 후보를 로컬 측정한다. 실제 선택한 후보 하나만 기존 모델 장부에 예약한다. 잘못된 추정기 응답·권한·원문 오류는 용량 부족으로 바꾸지 않는다.

새 호출은 입력 설정 지문을 저장한다. 송신 전 설정이 바뀌면 기존 예약을 취소·반환하고 새로 준비한다. 이미 받은 응답은 한도 설정만 바뀌었다는 이유로 버리거나 재호출하지 않는다. 지문 없는 예전 호출은 고정된 원 입력을 현재 설정과 기존 예약 안에서 재측정하며, 예전 데이터 형식을 소급 변경하지 않는다.

## 검증 경계

신규 회귀는 한도 계산·추정기·설정 경합·무쓰기 검사·최소 입력 선택·정상 요약 경합·비모델 단계·compact 전용 배치와 두 저장 backend의 반복 자동 compact/답변/재시작을 포함한다. 시험 목록은 `runtime/evidence/C04-window-new-files.json`이다. 합성 UTF-8 단위와 규칙 제공자는 실제 모델 tokenizer나 요약 품질의 검증 근거가 아니다. 실제 모델/API 중단은 유지한다.
