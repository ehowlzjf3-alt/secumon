# C04 일반 요청의 복합 조사 — 인수 결과

2026-09-07 · Node v24.20.0에서 신규 **2/2**, 관련 **43/43**을 통과했다. [확정 기록](../../runtime/evidence/C04-complex-verification.json)은 로컬 인수 시험의 결과다. 이번에 추가한 것은 [통합 시험 파일](../../runtime/src/tests/complex-agent-turn.test.ts) 하나이며 제품 코어를 다시 구현하거나 변경하지 않았다.

사용자의 일반 원문을 실제 담당 디렉터리와 SQLite 저장소에 접수하고, 등록된 구조화 전송을 통해 기존 계획 검사·도구 실행·가설 재검토·답변·전달까지 연결했다. 복합 조사는 명시적인 `deep` 모드로 실행했다. 일반 업무의 `criteria` 빈 배열을 시험용 사실 조건으로 바꾸지 않았다. 모델의 자기 검토와 시험에서 별도로 확인하는 정답 기준도 구분했다.

## 실제로 확인한 흐름

| 흐름 | 관측과 결과 |
|---|---|
| 성공 | 초기 90일 자료 → 별도 자료의 30일 반증 → 재접속 → 개정 자료만 추가 조회 → 두 현행 자료의 30일 일치를 인용해 답변 → 전달 뒤 완료 |
| 판별 자료 실패 | 앞의 두 관측 → 개정 자료 읽기 실패 → 가설 충돌·실패 원본 보존 → 유효한 개정 자료를 요청하는 질문 1개 → `pending_obligation` 대기 |

성공 경로는 원본 조회 3회, 모델 5회, 계획 버전 2, 재계획 사용량 1이다. 실패 경로는 원본 조회 3회 중 성공 2회·실패 1회, 모델 4회, 계획 버전 2, 재계획 1에서 질문 대기로 끝났다. 실패를 지우거나 빈 계획으로 바꾸어 완료시키지 않았다.

이미 성공한 원본 조회는 다시 실행하지 않았다. 가설 평가만 갱신할 때에는 계획 버전과 재계획 사용량이 증가하지 않았고, 판별 작업을 추가할 때만 증가했다. 원본 결과 바이트, 현재 원문, 이전 시도 ID와 가설·계획·사용량은 재접속 뒤에도 유지됐다. 질문 대기 또는 완료 상태를 다시 열어 실행해도 모델·도구 호출과 전달은 늘지 않았다.

현재 답변 근거는 서로 다른 계보의 `doc-b`, `doc-a-amendment`이며 둘 다 30일이다. 구본의 90일 관측과 이를 대체하는 관계는 보존했다. 반론 문장을 별도 증거로 만들거나 같은 계보를 독립 출처로 중복 계산하지 않았다. 실제 저장된 각 모델 입력도 관측한 전송 입력과 대조했다.

## 검증과 범위

- `npm run build`의 최종 build4와 신규 new3·관련 related1이 같은 소스/빌드 지문으로 통과했다. 관련 5개 파일은 기존 모델 재계획, 일반 입력, 응답 완료, 일반 흐름, 등록 모델 재접속을 다룬다.
- 첫 빌드는 시험의 미사용 타입 import로 실패했다. 첫 신규 실행의 두 실패는 시험이 답변의 근거 배열을 `sort()`로 직접 변경한 점과 실패한 도구 시도를 성공 근거처럼 `adopted`로 기대한 점이었다. 시험만 교정하고 원로그를 보존했다. 이후 실패 원본 조회와 재접속 후 시도·가설 보존 검증도 보강했다.
- 이번 변경은 시험 추가이므로 직전 NAS 전체 검증을 반복하지 않았다. 앞선 등록 모델 소스의 Linux 3,253/3,253 결과는 역사적 근거다. 새 복합 인수는 다음 목표 변경 제품 연결 후의 Linux 필수 통합에 포함한다. 이번 인수를 Linux에서 실행했다고 표시하지 않는다.
- 실제 모델/API, 자유 문장의 가설·반론·요약·답변 품질, native Windows와 PostgreSQL은 미검증이다. 유한 전송이 고정 관측에 반응한 결과이며 실제 모델이 스스로 좋은 조사 전략을 만든다는 증거는 아니다.

다음은 [명시 목표 변경 계획](C04-goal-change-plan.md)이다. 기존 명령·영수증을 재사용하면서 재전송, 편집 중 후속 입력, 이전 목표 질문 대체를 확인하고 일반 CLI/Web에 연결한다. C04 전체와 전체 구현 goal은 진행 중이다.
