# 게시판 조회를 작업의 지속 입력으로 연결하기

2026-09-06 · v0.46 · 전체 2236/2236 · 관련 165/165 검증 완료 · P4-01 진행 중

## 이번에 연결한 동작

`core.board.read`로 읽은 글은 작업의 입력 장부에 남는다. 이후 모델 컨텍스트를 만들거나 이전 호출을 조회하고 작업을 재개할 때, 그 글·출처·현재 접근 권한을 다시 검사한다. 독립 근거를 추가하는 도구는 아니므로 게시판 조회만으로 사실 확인 조건이 충족되지 않는다.

예를 들어 A가 사내 비공개 기억을 참고해 공유 가능한 가설을 게시하고 B가 읽었다고 하자. B에게 전달되는 것은 A의 게시글과 허용된 인용 정보다. A의 비공개 기억 원문은 포함하지 않는다. 그렇지만 그 기억이 철회되면 B의 입력 역시 사용할 수 없게 된다. 이때 두 작업의 현재 권한을 확인하는 주체는 모델이 아니라 호스트의 `InputAuthority`다. 툴 인자에서 다른 사람의 권한을 지정할 수 없다.

## 검증기가 서로 다시 호출하지 않게 만드는 방법

공통 그래프의 노드는 업무 상태, 기억 입력 묶음, 게시판 조회 증명, 수집 checkpoint 검사다. 각 검사기는 자신이 맡은 자료를 확인하고 추가로 확인할 업무 참조를 반환한다. 하나의 큐가 그 참조를 끝까지 검사한 뒤 각 자료와 권한이 검사 도중 바뀌지 않았는지 확인한다.

`A → B → A`처럼 서로의 글을 참고하는 업무 관계는 유한한 큐에서 처리한다. 기억의 `derivedFrom`나 게시글 답글 자체의 순환은 별도의 잘못된 출처 관계로 거절한다. 같은 업무를 이미 보았다는 이유로 그 업무의 다른 입력을 검증 없이 통과시키지 않는다.

기억·게시판·수집의 내부 inspection은 자료 제공 API가 아니다. 원문 대신 추가 참조와 재확인 함수를 반환하며, 전체 그래프 검사를 거치기 전에는 그 입력을 사용 가능하다고 판단할 수 없다. 현재 효과 증명 경로의 기계적 검사는 재사용했고, 수집 checkpoint의 구조 검사와 전체 입력 검사는 분리했다.

## 입력의 수명과 컨텍스트

- 조회 증명에는 실제 호출·소비 업무·조회 조건·정확한 페이지·권한·데이터 세대를 묶어 저장한다. 모델과 공개 결과에서는 이 내부 참조를 제거한다.
- 뒤에 무관한 게시글이 추가되어도 이미 본 페이지는 유지한다. 기존 글의 철회, 출처 변경/삭제, 역할 비활성화, 현재 권한 상실, 증명 삭제는 사용을 막는다. 새 페이지를 조회하는 cursor는 현재 게시판 revision과 일치해야 한다.
- 소비 작업의 목표가 같은 범위에서 갱신되어도 과거 입력의 출처 책임은 남긴다. 이전 시도가 더 이상 채택 상태가 아니어도 참조는 유지한다. 관련 자료·근거·계획·가설을 격리한 후에만 현재 입력 장부에서 제거한다.
- 인용 없는 가설에도 작성 업무의 데이터 세대를 붙인다. 작성자의 파생 자료가 격리된 뒤 오래된 가설 문장만 계속 공유되는 일을 막는다.
- 조회 결과를 과거 호출 도구로 다시 읽거나 캐시를 재사용해도 원 입력 참조를 계승한다. compact는 그 참조를 지우는 절차가 아니다. 원본은 저장소에 남고 화면/모델에서 필요한 표현만 선택한다.

## 조립과 검증 범위

`composeRuntime`의 `board` 옵션에 게시판 repository, 현재 실행 주체, 호스트의 현재 권한 directory를 제공한다. 그러면 읽기 도구와 공통 입력 검증기가 등록된다. DB 구현은 domain/application에 들어가지 않는다. 두 주체가 같은 프로세스에 있어야 한다는 도메인 제약도 추가하지 않았다.

신규 34개 시험은 실제 로컬 runtime의 예약·호출·수신·채택을 사용한다. 문서/관측 두 업무군의 SQLite/파일 저널 상태 저장소에서 페이지·과거 호출·compact·재열기를 검증했다. 서로 참조하는 작업, 비공개 기억을 경유한 공유 글, 기억과 수집 증명이 섞인 참조, 조작된 페이지/다른 소비 업무, 취소 대기, 목표 갱신 후 출처 유지, 글·원본·증명·역할·권한 변경도 포함한다. 기억 저장소는 두 상태 저장소 시험 모두 SQLite다.

관련 165개는 신규 36개와 영향받는 게시판·입력 그래프·기억·수집 시험이다. 게시판 runtime 시험 34개 외에, 공통 검증기가 없는 기억 서비스에서 중첩된 일반 입력을 거절하는 회귀 2개를 추가했다. 공개 업무 화면의 정상 조회/입력 변경 차단도 확인했다.

첫 통합 시험에서는 성공 결과의 coverage가 공통 계약에 맞지 않아 채택이 거부됐고, 페이지 전체/부분 반환에 맞추어 수정했다. 빌드 중 발견한 테스트 필드 오류와 Zod refinement 스키마 조합 오류도 수정했다. 첫 전체 검증은 2234/2234 통과했다. 중첩 입력 보완 후 최종 전체 **2236/2236**, 관련 **165/165**, 실패/취소/skip/todo 0이며 빌드·코어 타입·계층 114/위반 0·fixture 4/22를 통과했다. 최종 전체 시험 시간은 313362.969541ms다. ## 남은 범위

이번 범위는 읽기 연결이다. 게시·요청·수락·답변의 runtime 도구, WorkState 의무, 상대 역할에게 예산을 할당하는 계약, 새 반증에 따른 두 runtime의 가설/재계획·완료 흐름은 이어서 구현한다. 게시판에 새 글이 도착했음을 자동 감지하는 구독/wake도 아직 추가하지 않았다.

게시판·기억·수집이 한 검증에 섞이는 사례는 시험했다. 컴퓨터 입력의 효과 증명까지 동일 게시판 사례에 함께 넣는 통합 시험은 별도로 남아 있다. 이번 새 시험의 재개는 저장소 재열기이며, 기존 전체 시험에 포함되는 프로세스 강제 종료 시험을 새 게시판 도구의 강제 종료 검증으로 세지 않았다.

출력 페이지는 20개 글/32KiB, 공통 검증 큐는 기본 256노드/1024참조/4MiB snapshot/10초 제한을 사용한다. snapshot byte 제한은 전체 원본 I/O 바이트 상한이나 저장소 간 원자적 snapshot을 뜻하지 않는다. 원문을 읽는 비용과 취소를 무시하는 저장소 I/O의 실제 종료는 별도 adapter 수준의 측정·제어 대상이다. 취소 시험은 원 응답이 오기 전에 도구 대기를 끝내는지 검증했다.

현재 도구 결과/시도는 일반 입력 참조를 최대 50개 보관한다. 상한에 도달하면 출처를 버리지 않고 새 결과 채택을 거절한다. 긴 임무에서 동일 관측 재사용과 입력 묶음·격리 단위를 개선하는 일은 후속 최적화다. 메모리 이름을 쓰는 일부 내부 오류/격리 이벤트는 공통 입력 경로에서도 재사용하고 있다.

실제 모델/API 시험은 취소된 상태를 유지한다. 사내 MCP·Knox·외부 A2A 상대와 운영 배포를 로컬 시험 성공으로 표시하지 않는다. P4-01과 전체 P0–P6는 진행 중이다.
