# C09 A2A 첫 로컬 인수 기록

## 구현·검증한 동작

독립 SQLite 담당 둘에서 일반 요청 → 실제 주턴 어댑터의 도구 계획 → A2A 접수 → 수신 담당의 명시 실행 → 발신 담당의 조회·답변을 연결했다. 접수 응답만 받은 시점에는 수신 모델 호출이 없고, 원격 작업 완료를 발신 담당의 독립 근거나 자기 목표 완료로 취급하지 않는다. 모델의 판단은 유한한 로컬 응답 대역이며 실제 모델 품질을 검증한 결과는 아니다.

- 같은 원 메시지의 재전달과 재시작은 원 접수·세션·작업을 재사용한다. 서로 다른 caller와 독립 담당의 저장소·원문·개인 기억은 섞이지 않는다.
- 전달된 추가 질문의 원 답변 명령은 재접속 뒤에도 이어진다. 취소된 대기 작업은 모델을 실행하지 않는다. 송신 뒤 응답 유실은 발신 측 미확정 효과로 보존하며 자동 재송신하지 않는다.
- 호스트 등록은 원 metadata·메서드를 포착하고 반환한 peer·도구·사건 source에도 종료와 권한 검사를 적용한다. custom get/cancel의 반환 task ID가 요청한 작업과 다르면 거절한다.
- JSON-RPC 전송은 늦은 fetch 응답과 body 읽기 중 취소·시간 만료·종료를 정리한다. 확인한 write ACK와 아직 확인하지 못한 원격 효과를 구분한다. 취소를 무시하는 외부 구현의 물리적 종료까지 보장한다는 뜻은 아니다.
- 등록된 A2A 도구의 채택된 결과는 협업 준비의 진전으로 기록한다. 같은 작업의 같은 상태·본문을 반복 조회하거나 생성 ID·시각·추적 metadata만 바꾸면 새 진전이 아니다. 실제로 다른 요청 task ID의 첫 조회는 별도 자원 관측으로 구분한다. get/cancel의 같은 상태는 하나의 진전으로 취급한다. 원 데이터 본문의 업무 값은 보존한다.

기본 무진전 한도3과 원 실행 자원 한도는 유지했다. 준비 진전은 Evidence를 생성하거나 완료 조건을 변경하지 않는다. 기존 예산 도구의 입력 스키마 변환을 공통 함수로 옮겨 그대로 재사용했고, 엄격한 입력 검사를 완화하지 않았다.

## 첫 실행에서 확인한 사실

- 신규 일반 입구5개·전송16개·등록9개를 준비했다. build1은 새 시험의 미사용 import 1개로 종료했고, 제거한 build2는 성공했다. build2의 sourceDigest는 `a308bc3797901820711a87a0bd3034ed1493634acb730b5fc5f272239748d36f`다.
- target1은 **30개 중18개 통과·12개 실패**, exit1이다. 일반 입구5개와 등록1개는 `invalid_tool_schema`로 막혔다. A2A의 JSON 데이터 입력이 만드는 scalar union을 기존 엄격한 Ajv 형태로 표현하지 않은 연결 문제다. C08 예산 도구에서 이미 사용하는 변환을 공통 함수로 옮겨 재사용한다.
- 전송4개는 취소 후 늦게 도착한 fetch 응답과 response body를 읽는 중의 abort/close/timeout을 제대로 끝내지 못했다. 주입 fetch/stream으로 유한하게 재현했고 실제 네트워크는 호출하지 않았다.
- 등록2개는 원 labels 배열을 나중에 바꾸면 이미 열린 도구의 권한 판단이 달라지는 문제와, 닫힌 등록이 반환했던 raw peer·mission source에서 새 호출을 시작할 수 있는 문제다. 원 등록 정보의 복사와 모든 공개 참조의 수명 검사·진행 호출 정리를 교정한다.

target2에서는 38개 중37개가 통과했다. 남은 실제 일반 루프가 send 성공→새 plan 다음에 `no_progress_limit`로 막혔다. A2A의 정상 요청이 기존 준비 진전에 연결되지 않은 문제여서 native 도구 표식과 의미 기반 진전 분류를 연결했다. 별도 build3 진단은 custom get/cancel의 다른 task ID를 2건 잘못 수락했으며 요청 ID 대조로 교정했다.

target3에서는 일반 입구5개와 등록10개가 모두 통과했다. 남은 진전 시험은 provider 변조를 `snapshotTool`이 먼저 정상 거절했는데 시험이 분류기까지 진입할 것을 예상해 실패했다. 기존 계약 거절을 명시적으로 검사하도록 시험만 교정했고 target4에서 통과했다. 실패 원로그와 수정 뒤 실행을 별도로 보존한다.

## 범위와 다음 행동

담당은 실제로 독립 SQLite 저장소를 열고, 등록된 구조화 모델 어댑터는 로컬 유한 응답을 받는다. fetch는 직렬화한 JSON을 실제 handler에 전달하지만 listener나 인증 서비스를 가동하지 않는다. 수신 내부 응답 보관의 destination은 `local`이며 호스트가 정한 발신 endpoint와 구분한다. 수신 metadata로 caller·권한·담당·세션을 선택하지 않는다.

이번 실행은 현재 구현된 text/data와 세 RPC의 로컬 경로에 한정된다. 다음은 C09 사건 원문·업무 재개, 상시 임무의 격리·중단 복구, 단독/협업 비교와 C10이다. C05 정책 재허용 뒤 전체 재개, C06 브라우저·기억 HTTP 지연도 남긴다. 실제 모델/API·외부 A2A 상호운용과 listener 인증·사내 MCP/Knox·PostgreSQL·현재 Linux/native Windows·운영 인수·최종 통합과 전체 goal은 미완료다.
