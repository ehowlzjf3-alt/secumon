# C10 복원과 외부 기록 대조 · checkpoint390

2026-09-08 · 착수 시 계획. 구현 및 로컬 검증 결과는 [checkpoint390 결과](C10-restore-reconciliation-result.md)에 기록했다. 실제 모델/API 시험 중단 유지.

## 개념과 확인한 공백

백업은 담당의 과거 기록이다. 백업 이후 외부 파일을 쓰거나 메시지를 보냈다면, 백업 복원이 그 동작을 취소하지 않는다. 복원본에서 사라진 실행 영수증은 기존 attempt 복구가 발견할 수 없다. 특히 복원된 pending 송신은 일반 outbox에서 다시 보낼 수 있다.

직전 goal 구현 단위 checkpoint389는 코드·기록을 바꾸고 로컬 검증 후 origin/main 158b82b까지 푸시한 progress다. 메인 프롬프트 질문에 대한 직전 응답은 소스 상태 확인이며 새 구현 완료로 세지 않는다. 이번 단위는 외부 실행 기록과 복원된 상태의 대조를 실제 일반 입구에 연결한다.

## 재사용과 변경

- 재사용: 백업 지문, 복원 완료 표식, 담당 신원 등록/rebind, maintenance lease, 파일 경계와 원자적 게시, 개별 attempt 및 컴퓨터 유즈의 read-only 복구.
- 수정: 새 복원마다 restorationId를 발급하고 중단 재개에서는 원 번호를 보존한다. 로컬/PG 백업은 과거 대조 완료 기록을 포함하지 않는다.
- 신규: 호스트가 등록한 읽기 전용 대조 source와 lifecycle restore-status / restore-reconcile. source는 복원본에 남은 attempt만이 아니라 담당의 외부 실행·송신·위임·자원 기록 전체 범위를 대조할 책임이 있다. 빈 attempt 목록을 무효과 증명으로 인정하는 source는 잘못된 등록이다.
- 일반 openAgentStores는 신원 검사 뒤, 저장소나 모델·도구·채널 연결을 열기 전에 해당 복원의 대조 완료 기록을 검사한다.

## 구체적인 처리

1. 기존 복원을 완료하고 필요하면 identity-rebind한다. 파일 복원 완료와 외부 대조 완료는 다른 상태다.
2. offline 관리 명령이 maintenance lease와 현재 신원 claim을 잡고 복원 표식·로컬 자료 지문을 고정한다.
3. 등록된 모든 source의 inspect 결과와 원문/영수증 참조를 받는다. 미확인 효과가 있으면 unresolved를 반환하며 재개 기록을 발급하지 않는다.
4. 모두 일치하면 verify로 각 source의 현재성을 다시 확인한다. 그동안 로컬 자료·복원 표식·신원이 바뀌지 않았을 때만 원자적으로 대조 완료 기록을 게시한다.
5. 완료 기록은 복원 고유 번호·백업 지문·표식 지문·신원 head와 묶인다. 새로운 백업/복원으로 복사되지 않는다. 일반 재시작에서는 작은 완료 기록만 읽는다.

source 등록은 신뢰 호스트 확장이다. 모델 답변·CLI JSON·사용자의 단순 확인만으로 완료를 발급하지 않는다. 원격 시스템의 진실은 코어가 추측할 수 없으며 실제 배치에서는 해당 시스템을 조회하는 source가 필요하다. 같은 source가 보고서의 자료 참조와 최신성을 검증한다. 실제 서비스의 조회 권한/범위는 연결 시 검증할 항목이다.

legacy 완료 표식에 복원 고유 번호가 없으면 새 완료 기록을 발급하지 않는다. 검증된 원백업을 현재 복원 명령으로 다시 복원해 번호를 발급한다. 기존 완료 표식을 임의 수정하지 않는다.

## 검증과 남는 범위

- 실제 로컬 외부 파일: 쓰기 전 백업 → 외부 쓰기 → 과거 백업 복원 → 대조 전 일반 입구 차단 → source가 사라진 기록 발견 → unresolved/재실행 없음.
- 외부 효과와 원 영수증이 포함된 백업: 복원 → 대조 → 일반 재개, 원문 보존·중복 효과 없음.
- 등록 누락, 미해결 결과, 현재성 변화, timeout, 다른 복원의 완료 기록 복사, 로컬 자료 변경, 실행 중 maintenance 거절, 반복 명령, 소스 함수 캡처.
- 관련 build/core/layer 검사와 선택 lifecycle/rebind/storage/entry 회귀. 실제 Linux/Windows/PG/Knox/model API 검증으로 과장하지 않는다.
- 오래된 백업에 없는 효과의 일반적인 원기록 가져오기/충돌 해결은 별도 후속이다. 이번에는 source가 불일치를 구체적으로 보고하고 일치한 복원을 재개하는 경로까지 완성한다. 임의 성공/무조건 재전송으로 불일치를 덮지 않는다.
