# C10 호환 배포본 전환과 담당 연속성 결과

2026-09-08 · checkpoint384 · 기준선 `5f7157da9fde4b8c642a93b5e3f5734d69f8b350`.

**실제 실행 코드가 다른 두 호환 시험 배포본 사이의 업데이트와 기존 업무 재개를 확인했다.** 설치·백업·pin/update 제품 함수와 CLI를 재사용했고 제품 코드는 수정하지 않았다. 새 통합 시험·실패 경계 시험·결과 기록을 추가했다. C10 전체나 운영 배포의 완료 판정은 아니다.

## 실제 실행 흐름

현재 빌드 전체와 의존성·CLI·UI/자료를 정상 bundle/install하여 A를 만들었다. 별도 후보 B에서 package/lock의 버전을 `0.1.0`→`0.1.1-fixture-update.2`로 바꾸고, 실제 컴파일된 시험 모델의 답변 형식에 `engine-update-v2` 표시를 추가했다. B도 정상 bundler와 installer로 작성했다. 두 release의 지문·실행 파일 SHA는 다르며 저장 형식 호환 선언은 같다. 원 저장소·설치 A와 release manifest를 임의로 고쳐 전환을 꾸미지 않았다. 실제 운영 release나 스키마 이행 시험은 아니다.

설치 A의 실제 CLI/probe로 담당을 초기화하고 check→첫 pin을 실행했다. 같은 세션에 실제 사용자 원문을 접수해 개인 기억을 명시 저장하고, 별도 조회 업무가 모델1회·도구1회로 원 자료를 채택한 직후 중단했다. 원 업무·근거·영수증·사용량을 직접 합성하지 않았다.

offline backup→B 호환 검사/명시 update→A 실행 거절→설치 B로 같은 담당 재열기를 실행했다. B 재열기에서는 기존 신원·원 업무·입력·세션 이력·개인 기억·호스트 등록·영수증·원문 bytes가 같았다. B의 실제 CLI에서 원 업무를 재개하자 새 코드의 표시와 원 자료의 “30일” 답변이 나왔다. 모델 호출은1→2회, 도구 호출은1→1회로 기존 조회를 재실행하지 않았고, 전달된 최종 답변은1개였다. 시험 모델의 토큰 사용량은0이며 실제 모델의 비용·응답 품질 증거로 사용하지 않는다.

별도 SQLite 담당과 file-journal+문서 개인 기억 담당은 공통 설치 A/B를 사용했다. offline 확인 누락, 실행 중 lease, 백업 누락·백업 이후 문서 변경·다른 담당 백업, 실제 저장 schema999, 설치 후 실행 파일 변경을 거절했다. 현재 자료의 새 백업으로 A→B→A를 명시 전환하며 pin 이력을 잇고, 백업 이후 추가한 문서와 현재 자료를 유지했다. 엔진 되돌리기와 원경로 자료 복원은 별도 시험으로 확인했다.

## 다음 구현과 남은 인수

다음은 [계획](C10-version-transition-plan.md)에 기록한 **전역 입구의 담당별 고정 엔진 선택과 공통 확장 호환 검사**다. 현재 전역 npm bin은 해당 설치 CLI를 직접 실행한다. 설치 B의 명시 명령 실행을 자동 버전 선택의 완료로 계산하지 않는다. 확장의 provider/model/tool/wire 버전과 엔진 API 호환 버전은 각각의 의미를 유지하며, 기동과 check/pin/update 전에 같은 호환 검사를 연결한다.
