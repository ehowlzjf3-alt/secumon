# 전체 구현 우선, 이후 순차 검증·수정

2026-09-08 사용자 합의. 기존의 작은 단위마다 상세 회귀·플랫폼 검증까지 마친 뒤 이동하던 절차를 이 문서가 대체한다. 전체 C01~C10 기능 범위는 유지한다.

## 구현 순서

**C06 → C07 → C08 → C09 → C10의 기능 구현을 먼저 마친다.** 2026-09-08 사용자의 최종 순서 지정이며 이전 C07 우선 제안을 대체한다.

1. C06 대화·설치·배치: CLI/Web/Knox 공통 표시, 접수/질문/진행/결과, 재접속·취소, 최소 설치와 담당별 업무 설정을 연결한다.
2. C07 게시판·아카이브: 선택 활성화, 경험 질문/답변, 응답 의무, 알림, 저장 공급자 연결. 조회 자료를 개인 장기기억에 자동 등록하지 않는다.
3. C08 동료·임시 역할·독립 반론·자원: 동일 범용 엔진을 재사용하고 반론을 후속 증거 수집과 계획 수정으로 연결한다. 배정·반환·정산은 지속 세션의 수명과 구분한다.
4. C09 A2A·사건 재개·상시 임무: 사건을 기다렸다 재개하며 중복 처리와 무진전 대화를 제어한다.
5. C10 설치·버전 이행·운영 복원: 패키지, 버전 고정·호환·업데이트, 자료 보존과 복원 경로를 연결한다. 시범·실제 배포는 해당 검증 이후 단계다.

기존 C01~C05와 기존 CLI/Web 등의 구현·계약을 재사용한다. 현재 구현을 실제로 막는 선행 기능만 보완하고 본 순서로 돌아온다. C01~C05의 남은 기능도 기존 목록에 유지하며 완료로 처리하지 않는다. 챕터의 depends_on은 필요한 계약의 관계이며 선행 챕터 모든 시험 통과를 요구하는 대기 조건이 아니다. Knox 등의 외부 접속 대기로 독립 구현을 멈추지 않는다.

검증 항목은 [C06~C10 별도 검증 계획](C06-C10-verification-plan.md)에 둔다. 기능 구현과 검증 판정을 따로 기록하며 상세 검증을 매 구현 단위의 완료 조건으로 끼워 넣지 않는다.

## 구현 단계의 확인 범위

- 작은 구현 계획과 실제 사용자 경로를 기준으로 코드를 연결한다. 인터페이스나 프롬프트만 작성한 상태를 기능 구현 완료로 표시하지 않는다.
- 빌드·타입 오류 등 다음 구현을 막는 문제를 확인하고 수정한다. 상세 회귀, 장애 주입, 운영체제별 시험, 반복 전체 시험은 후속 검증 단계에 모은다.
- 관측된 결함과 미검증 항목을 간단히 남긴다. 기존 검증 자료와 작성된 시험을 재사용하며 같은 설명·사본·증거 문서를 불필요하게 늘리지 않는다.
- 각 기능의 구현 상태와 검증 상태를 별도로 기록한다. 계획 개정만으로 기존 챕터를 완료로 바꾸지 않는다.

## 전체 기능 연결 후 검증·수정 순서

C01 담당 식별·저장 경계 → C02 지속 문맥·compact → C03 개인 기억·이력 → C04 추론 루프 → C05 도구·메모리·스킬·컴퓨터 유즈 → C06 대화 입구 → C07 게시판·아카이브 → C08 협업·반론·자원 → C09 사건 재개·상시 임무 → C10 설치·업데이트·복원 순서로 점검한다.

각 단계는 핵심 사용자 경로와 필수 경계를 묶어 검증하고 발견한 문제를 수정한다. 수정에 영향받은 범위만 다시 확인하며, 전체 회귀와 Linux/native Windows·저장 공급자 통합 검증은 의미 있는 통합 지점에 모은다. C05의 보관·정산 후속 시험 후보도 이때 재사용한다.

실제 모델/API 시험 중단은 유지한다. 사내 MCP·Knox·운영 환경처럼 외부 조건이 필요한 결과는 실제 검증 전까지 미검증으로 남긴다. 구현·대역 시험·실제 연동·배포 완료를 구분하며 미검증 사항을 숨겨 전체 goal을 완료 처리하지 않는다.

## 전환 시점의 저장 상태

- C05 페이지 응답 보관·사용량 정산 A/B: 제품 통합, 로컬 신규 54/54·관련 113/113, 빌드·코어 타입·아키텍처 검사 통과. [확정 결과](C05-mcp-collections-custody-AB-result.md). 이 결과는 macOS 해당 소스의 기록이며 앞선 Linux 결과를 새 변경의 검증으로 쓰지 않는다.
- C05 C: 실제 강제 종료와 프로필 종료 시험 후보는 별도 staging에 동결했다. 제품 미통합·미실행이다. 일반 CLI/HTTP 보관 후속 인수와 최종 통합/Linux 검증도 남아 있다.
- 전환 전 소스·빌드 설정·관련 진행 문서·C 시험 후보의 [복원용 압축본](../../runtime/evidence/checkpoint351-implementation-baseline.tar.gz)을 저장했다. 설치 의존성과 실행 데이터 전체를 담은 배포 백업은 아니다.
- 전환 시점의 다음 구현은 C06이었다. 현재는 [C06~C10 구현 결과](C06-C10-implementation-result.md)의 지원 범위를 연결하고 통합 빌드를 통과했다. 상세 검증은 여전히 별도 목록에 있으며 C01~C05의 선행 미구현 사항과 외부 조건도 유지한다.
- 이어 checkpoint359에서 [PostgreSQL 신규 저장 연결과 Windows 경계 코드](C01-C03-storage-implementation.md)를 작성하고 통합 build3를 통과했다. 상세 DB/플랫폼 시험은 별도 목록이다. 기존 자료 이행·외부 DB 복원·Windows 소비자 연결은 구현 잔여로 유지한다.
