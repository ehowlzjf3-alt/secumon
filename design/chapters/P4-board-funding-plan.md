# P4 요청 수락과 에이전트의 자원 관리 연결

2026-09-06 · 역할 간 권한/정산 단위 다음 구현 계획

현재 사용자 요청은 구현을 이어가기 전에 수정 범위를 정리하는 것이다. [P4 수정 범위 정리](/Users/seunghanee/Documents/secumon/design/chapters/P4-design-reconciliation.md)를 우선하며, 아래 준비 단계의 모델 금지·항상 자식 작업 생성·단순화 후속 순서를 모든 협업의 확정 계약으로 일반화하지 않는다. 기존 구현과 검증 기록은 보존한다.

## 목표

에이전트가 잔량과 실제 진척을 보고 작업별 자원 배정·추가 요청·회수/재배정을 결정한다. 사용자가 매번 숫자를 입력하거나 정산할 필요가 없도록 하며, 런타임은 현재 권한과 실제 사용량에 따라 결정 내용을 집행한다. 이번 계획은 P4-01의 남은 항목이며 `P4-budget-authority-result.md`의 기반 구현을 재사용한다.

## 현재 코드에서 확인한 연결 지점

- `BudgetDelegationService`는 위임 참조를 확인해 새로운 자식 작업에 자원을 예약한다. 역할 간 권한 port와 실제 역할 runtime으로 연결하는 정산 라우터가 있다.
- `BoardCommands`의 수락 명령은 caller가 임의 작업 ID를 선택하지 못하게 하고, 실제 실행 중인 작업 ID를 `acceptedWorkId`로 사용한다. 수락 전에 그 작업이 질문을 읽은 관측 proof가 필요하다.
- 따라서 실행 권한이 아직 없는 준비 작업에 기존 수락 도구를 바로 호출하면 수락 자체가 막힌다. 다음 구현에서 요청 조회·질문 읽기·수락에 한정된 준비 권한을 명시하고 일반 모델/도구 실행과 구분해야 한다. 전체 실행 권한을 잠깐 열어 해결하지 않는다.
- 기존 위임은 배정량이 고정된 자식 생성과 종료 정산을 제공한다. 추가 배정/부분 회수는 별도의 영속 변경 절차가 필요하며 아직 구현된 것으로 보지 않는다.

## 구현 순서와 계약

1. host의 역할 프로필과 funding 규칙을 정의한다. 에이전트 입력은 게시판/요청/역할 프로필 참조·배정량·기한·사유로 제한한다. 주체·자료 정책·runtime 등록은 host가 결정한다. 수신 역할의 자료 정책을 지원하는 쪽의 정책으로 덮어쓰지 않는다.
2. 현재 게시판 요청, 양쪽 역할의 현재 권한, 요청·작업·목표 개정과 funding 규칙을 확인하는 adapter를 연결한다. 참조나 게시판 metadata 자체를 권한으로 인정하지 않는다. 거절·취소·만료·목표/정책 변경에 따라 새 실행을 막되, 정산과 이미 발생한 효과 복구는 계속할 수 있어야 한다.
3. 준비 단계에서 허용되는 작업을 실행 경계의 명시적 입력으로 전달한다. 권한 port에 작업 종류/도구/요청 binding을 전달하는 확장을 검토하고, caller가 목적 문자열만 바꿔 일반 실행을 허용받지 못하게 원래 계획·dispatch와 대조한다. 준비 단계에는 모델 호출을 허용하지 않고, 필요한 제한된 도구 실행도 장부에 반영한다.
4. 질문 관측→수락→실행 허용의 영속 전환을 연결한다. 수락이 저장됐지만 응답이 유실되면 같은 요청/작업/배정으로 복원한다. 수락 전에 취소되거나 다른 작업이 먼저 수락했다면 배정을 회수하며 미확정 호출은 보류한다.
5. 에이전트용 조회·배정·추가 요청·회수/재배정 도구를 연결한다. 조회에는 사용량/예약량/가용량·참조·상태만 제공하고 다른 역할의 원문이나 내부 작업 상태 전체를 반환하지 않는다. 기존 장부의 전체 사용량을 현재 상태로 조회하고, 오래된 가용량으로 요청하더라도 집행 시 다시 검사한다.
6. 추가 배정은 부모 잔량을 먼저 예약한 뒤 자식 한도를 올린다. 회수는 자식의 신규 예약을 먼저 제한하고 진행 중/미확정 호출과 자식의 하위 배정량을 확인한 뒤 반환한다. 두 저장소 간 원자적 트랜잭션을 가정하지 않고 명령 ID·개정·영수증으로 중간 상태를 복구한다. 같은 역할 내 다른 작업으로 옮기는 경우에도 동일한 절차를 적용한다.
7. 잔량이나 진척의 의미 있는 변화가 발생할 때 planner에 정보를 제공한다. 매 도구 호출마다 별도 모델을 호출해 정산하지 않는다. 일반 사용량 기록과 종료 정산은 실행 경로에서 자동 처리한다. 부족하면 허용 범위 안에서 재배정·재계획하고, 불가능하면 상태를 보존해 대기한다. 한도 도달을 목표 완료로 표시하지 않는다.
8. 사용자의 복잡성 지적에 따라 게시판은 참여자가 같은 글을 읽는 공유 공간으로 단순화한다. 원문 권한은 역할 저장소에서 유지하고, 일반 게시마다 사람 승인·가공 단계를 강제하지 않는다. 공유 범위 밖의 내용은 게시 전에 처리하며 읽을 수 없는 최종 답변을 정상 게시한 뒤 확인을 기다리지 않는다. 정보 자체의 엄격한 비공개/공개 승인 절차는 선택 배치로 둔다. 다음 구현의 기준은 P4-shared-board-simplification.md다.

## 검증 기준

- 두 업무군×두 저장소에서 요청 발견→배정→질문 읽기→수락→근거 수집→답변→확인→정산/반환을 실제 도구 경로로 실행한다.
- 고정 planner가 잔량을 조회하고 배정을 선택하는 흐름, 실제 진척에 따라 추가 배정을 요청하거나 남은 몫을 다른 작업에 재배정하는 흐름을 검증한다. 사용자 중간 입력 없이 완료하되 실제 모델의 판단 품질과 구분한다.
- 준비 단계의 임의 도구/모델·다른 요청 사용, 권한/규칙 개정 중 변경, 부족한 잔량·동시 배정, 추가 배정/회수 중 응답 유실, 취소/만료/재시작·compact를 검증한다.
- 준비·수락·최종 답변의 의무와 자원 정산 의무를 구분한다. 정산 성공만으로 미완료 답변이나 근거 부족을 해소하지 않는다.
- P4-01 완료는 이후 공정한 역할 실행/대기/재개와 전체 가설·반증·재계획 평가까지 확인한 뒤 판단한다. 실제 모델/API 및 사내 연결은 현재 중단/미실행 조건을 유지한다.
