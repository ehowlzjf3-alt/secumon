# C06 대화·설치 연결 구현

2026-09-08. 전체 기능 구현 우선 정책을 적용한다. 기존 CLI/Web의 지속 세션, 발신함, 접수·질문·최종 결과 표시와 상세 보기, 업무별 설정을 재사용한다. 제품을 다시 만들지 않는다.

- 재사용: `AgentTurnService`, `SessionService`, `OutboxDispatcher`, `LocalChannel`, CLI/Web 입구와 담당 초기화.
- 수정: 초기 저장 방식 선택 전달, 설치 패키지 포함 파일, Web의 최신성 오류/재접속 안내, 로컬 대화 저장소의 확인된 외부 전달 기록.
- 신규: Knox 전송 등록과 라우팅, 동일 범용 세션/업무에 연결하는 메신저 입구. 사내 MCP의 도구명·인증·응답 형식은 호스트 어댑터가 매핑하며 여기서 추측하지 않는다.

Knox 연결은 수신자·담당·대화를 신뢰된 호스트가 매핑한다. 사용자 메시지에서 실행 모듈이나 수신자를 선택하지 않는다. 지시를 영속 접수하고 접수 안내를 전달한 뒤 별도 실행 함수로 업무를 진행할 수 있게 한다. 상태 조회와 취소는 실행 완료를 기다리지 않는다. 발신함이 이미 구분하는 접수/질문/결과/실패만 전송하며 도구 호출은 개별 메시지로 만들지 않는다.

실제 전송 확인 뒤 기존 담당 대화 저장소에 응답을 기록한다. 확인되지 않은 전송은 성공으로 바꾸지 않고, 공급자의 멱등성(같은 요청을 반복해도 한 번만 전달하는 성질)·조회 능력에 따라 기존 발신함이 재개한다. 별도 대화 DB나 정산 장부를 만들지 않는다.

구현 중 빌드/타입 확인만 수행한다. 채널 중복 전달·알림·취소·재개·설치·격리 시험은 [별도 검증 계획](C06-C10-verification-plan.md#c06)에 남긴다. 기존 C05 시험을 반복하지 않는다. Knox 실제 접속과 모델/API 시험은 수행하지 않는다.

추가로 일반 chat의 pause/cancel/명시 resume를 기존 영속 명령에 연결하고 중복 입력의 자동 재실행을 막았다. 구현 결과와 빌드 기록은 C06-implementation-result.md에 저장했다. 상세 인수는 별도 검증 단계다.
