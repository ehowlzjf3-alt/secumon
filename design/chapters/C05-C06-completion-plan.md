# C05/C06 완주·개인기억 대화 · checkpoint402

2026-09-09. 기준 `f93305d` / checkpoint401. 직전 상태 설명은 코드·검증 진척이 아니었다. 이번 단위는 남은 확인 목록의 C05/C06 네 흐름을 다룬다. 전체 C01–C10 목표와 C10·실환경 잔여는 유지한다.

## 재사용과 변경

- C05는 기존 수집 원문·영수증, 차단 복구, `readResume` 후속 작업, 공개 CLI 재개를 재사용한다. 신뢰된 호스트가 기존 업무 권한만 복구한 뒤 사용자가 명시 재개하여 원래 목표를 완료하는 실제 CLI 흐름을 SQLite/file-journal에서 확인한다. 상태 조회나 단순 재접속이 실행을 재개하지 않으며 같은 요청 재전달은 수집·정산·대답을 중복하지 않아야 한다.
- C06은 개인기억 저장·선택 허가를 외부 쓰기 도구 허가와 분리한다. 호스트와 사용자 actor에 선택적 기억 권한을 연결하고 미지정은 기존 권한 동작을 유지한다. 외부 쓰기 도구를 등록하지 않은 두 담당에서 공개 HTTP 저장·선택·후속 업무를 확인한다. 명시 기억 거절과 외부 쓰기 비허용도 유지한다.
- C06의 문서형 기억 지연은 같은 로컬 HTTP 시나리오로 변경 전후를 측정한다. 기준 빌드에서 실행 요청 약24.6초, 기억 저장소 조회2,064회, 해당 조회의 포함 시간 약22.3초였다. SQLite 기억 담당은 약4.1초였다. 한 번의 합성 업무 측정이며 실제 모델 호출·성능 보장이 아니다. `KnowledgeService.get`에서 결과를 버리는 사전 자료화를 제거하되, 안정된 전체 자료를 확인하는 세 번의 snapshot·현재 권한·원출처·마지막 검증을 유지한다. 전체 요청에 검증 성공을 캐시하지 않는다.
- 실제 브라우저에서 기억 조회·저장/선택·다음 작업·접수와 결과의 표시를 확인한다. 로컬 SQLite/file-journal 및 고정 모델 응답을 사용하며 실제 Knox·모델 품질을 대신하지 않는다.

## 검증과 종료 조건

네 흐름의 성공/실패 근거를 기록하고 발견한 실제 결함만 수정한다. 변경한 기능의 관련 회귀, 빌드·코어 타입·구조 검사를 실행한다. 통과한 같은 코드의 시험을 다시 돌리지 않는다. 변경 전 계측은 원 checkpoint401 컴파일 파일 전체를 manifest와 대조했고 후속 빌드 전에 종료했다. 변경 전후 HTTP 시간과 논리 호출 수를 별도로 기록하며 메서드 포함 시간을 더해 물리 I/O나 SLA로 해석하지 않는다.
