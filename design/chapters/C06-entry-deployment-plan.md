# C06 대화 입구·설치·담당 배치 인수

2026-09-08 · checkpoint376. 이전 단위는 `591e311`의 제품 수정·로컬 검증·문서화와 원격 main 일치 확인으로 진행했다. 전체 goal은 미완료이며 실제 모델/API 시험 중단을 유지한다.

이번 단위는 새 대화 엔진을 만드는 일이 아니다. 기존 `openAgentKnox`의 접수/실행 분리, `KnoxChannel`과 내구성 outbox, 담당 디렉터리별 profile/stores와 설치 패키지를 사용자 입구에서 연결해 확인한다. 실제 Knox·사내 MCP·사용자 전역 설치에는 접근하지 않는다.

- Knox: 현재 등록 모델·문서 도구 fixture를 재사용한다. 로컬 send/lookup으로 접수 안내1회와 실행 전 모델0, 명시 실행의 결과, 중복 접수·재접속, unknown 전달의 조회/확인, 사용자·담당·대화·세션 격리, 목표/제어 버전과 실행 수명을 확인한다. 일반 outbox 행렬은 복제하지 않는다.
- 설치: 현재 패키지를 임시 경로에 pack/install하고 포함된 bin·fixture·Web 자산을 실제 소비한다. 기존 의존성을 사용해 네트워크 없는 격리 설치를 구성하고 제거/재설치 뒤 담당 ID·세션·기억의 보존을 확인한다. 설치 대상과 담당 자료 경로는 분리한다.
- 배치: 두 업무의 목적·설정·도구·선택 스킬을 담당 폴더에서 구성하고 협업을 끈다. 공개 입구의 대화·기억·업무가 섞이지 않는지 확인하며 이미 있는 저장소 단위 행렬을 다시 만들지 않는다.

새 시험은 기존 계약을 통과시키기 위해 범위를 줄이지 않는다. 연결 누락을 발견하면 근거와 변경 이유를 기록하고 해당 제품 경로를 고친다. 소스를 동결해 빌드한 뒤 새 직접 입구와 변경에 관련된 기존 시험만 실행한다. 명시된 V06 전체 UI/플랫폼 인수, 현재 Linux/native Windows와 최종 통합, 실제 메신저/모델 품질은 실행한 로컬 범위와 구분해 남긴다.

결과·실패·소스 지문·미실행 항목은 `runtime/evidence/checkpoint376.json`과 결과 문서에 저장한다. 단위가 끝나면 코드·문서·증거를 함께 커밋/푸시하고 C07 게시판·아카이브로 이어간다.

## 공개 입구에서 확인할 수정 지점

정적 검토에서 `run()`이 업무 binding 검사 전에 세션의 pending 입력 전체를 적용하는 순서를 확인했다. 자기 세션에 미적용 pause가 있을 때 다른 대화의 업무를 요청하는 시험으로 거절 전 상태 변경을 확인한다. 수정 시 첫 await 전에 해당 업무 실행을 예약하고, 기존 업무 또는 해당 세션의 아직 생성되지 않은 pending work인지를 먼저 확인한다. 그 뒤 기존 세션 복구와 업무 검사를 수행하며 종료 시 예약을 해제한다. 미생성 pending work의 정상 복구와 동시 run 거절을 함께 유지한다.

`openAgentKnox`의 close는 현재 profile 종료를 직접 반환한다. 호스트 model close를 지연시킨 상태에서 새 입력/제어가 저장되는지 확인하고, facade에 종료 시작 표시를 동기 적용해 이후 호출을 거절한다. 이미 시작한 작업의 정산·자료 보존은 기존 profile 종료를 재사용한다.

같은 인증 사용자에게 명시적으로 같은 sessionId를 다른 대화 경로에 연결하면 기존 세션 이력을 이어 읽는 현재 계약을 유지한다. 이는 호스트가 지정한 명시 재연결이며 임의 다른 세션/담당의 이력을 허용하는 동작과 구분한다. 기존 업무의 status/run/control은 그 업무에 등록된 대화 binding을 계속 요구한다. 이 동작을 모든 대화 경로의 물리적 이력 분리로 설명하지 않는다.

오프라인 설치는 기존 `bundleAgentEngine/installAgentEngine`의 실제 제품 경로를 사용한다. 원 npm tarball에 없는 dependencies를 시험용으로 추가한 다른 패키지를 만들지 않는다. 원 npm pack 포함 파일 확인과 오프라인 bundle 실행 확인은 별도이며, 임시 호스트 launcher로 실행한 결과를 npm의 전역 bin 자동 등록·제거 성공으로 확대하지 않는다.

실행 중 원 npm 패키지의 잠긴 production 의존성이 기존 npm 캐시에 있음을 확인했다. 필요한 항목만 임시 캐시로 복사하여 원 tarball의 실제 npm 전역 설치·제거·재설치를 별도로 수행했다. 사용자 캐시와 전역 설치는 변경하지 않았다. 제품 bundle 경로의 반환 명령 실행과 구분한 [설치 결과](C06-installation-acceptance-result.md)를 따른다.

두 담당의 기억 선택은 업무 상태를 변경하므로 읽기 전용 work actor로는 허용되지 않는다. 첫 배치 시험은 읽기 전용을 유지하고, 기억 선택 시험만 현재 호스트 계약에 따른 권한을 명시한다. 이는 새로운 기억 전용 권한 체계를 설계한 것이 아니다. 허용 도구 목록에는 담당 읽기 도구와 지침 읽기만 두며, 실제 쓰기 도구 실행이 발생하지 않는지 함께 확인한다.
