# C01 작업 파일의 디렉터리·잠금·동기화 연결

2026-09-07 · POSIX 작업공간 연결 구현·실제 Linux 검증 완료 · C01 전체는 진행 중

작업 중간 파일을 보관하는 `FileWorkspaceStore`를 공통 파일 어댑터의 디렉터리 참조에 연결했다. 참조는 경로 문자열만 기억하는 대신, 처음 확인한 실제 폴더가 계속 같은 폴더인지 확인하는 값이다. 담당별 설정·기억·대화 저장소와 작업 중간 파일 저장소는 서로 다른 책임이며, 이번 변경은 작업 파일에 해당한다.

## 달라진 동작

| 상황 | 이번 동작 |
| --- | --- |
| 전에 확인한 작업 폴더가 사라짐 | 빈 대체 폴더를 다시 만들지 않고 실패한다. 기존 위치에서 빼 둔 원본은 건드리지 않는다. |
| 작업 도중 잠금 폴더나 상위 폴더가 바뀜 | 성공을 반환하지 않으며 새로 나타난 잠금을 삭제하지 않는다. |
| 정상 호출을 연속 실행 | 각 호출이 새 잠금을 만들고 자기 잠금만 해제한다. 이전 잠금의 식별자를 다음 호출에 강요하지 않는다. |
| 파일 저장 후 동기화 실패 | 성공을 반환하지 않지만 게시한 파일을 지워 실패를 숨기지 않는다. 기존 내용의 재조회·동일 요청 판정은 유지한다. |
| 주작업과 해제가 모두 실패 | 기존 주작업 오류 코드와 원인(`cause`), 해제 오류(`cleanupError`)를 함께 전달한다. 하나만 실패하면 원오류 객체를 그대로 전달한다. |
| 해제 직후 다음 호출이 새 잠금을 만듦 | 그 잠금에 간섭하지 않는다. 마지막 동기화가 실패해도 다음 주체의 잠금은 보존한다. |
| Windows 등 미구현 호스트 | 폴더를 만들기 전에 명확히 거절한다. 이 거절 시험은 Windows 지원 구현·실행 검증이 아니다. |

생성자는 root → parent, 성공 작업은 files → attempt → work → root → parent, 해제 후에는 attempt 순서로 동기화한다. 여기서 sync는 운영체제에 저장 내용을 반영하도록 요청하는 단계다. 각 경계에서 참조를 재검사하고 해제 후 성공 응답 직전에도 폴더들을 확인한다. 처음 잠금을 관찰하는 데 실패하면 소유권을 확정할 수 없으므로 그 잠금을 보존한다. 해제된 lock 자체는 다시 검사하지 않는다.

## 실제 중단 시험이 뜻하는 것

자식 프로세스를 잠금 생성 후, 후보 파일 fsync 후, 최종 hardlink 게시 후에 실제 `SIGKILL`로 종료했다. 다시 열었을 때 원본 바이트·권한·파일 식별과 남은 잠금을 보존하고 `workspace_busy`로 거절하는 것을 확인했다. 이는 **중단 흔적 보존과 안전한 거절**의 검증이다. 잠금 소유 영수증, 자동 stale-lock 복구, 전원 차단 복구 기능을 구현했다는 뜻이 아니다. 잠금 복구는 C10 후속에 남아 있다.

POSIX 참조는 열린 디렉터리 핸들을 고정하지 않고 경로를 다시 확인하는 방식이다. mkdir와 첫 관찰 사이, 검사와 rmdir 사이 교체를 원자적으로 막지는 못한다. `removeAttempt`의 여러 파일 삭제도 하나의 원자 트랜잭션이 아니다. EIO와 일부 경합 시점은 격리된 시험 프로세스에서 주입했으며 정상 sync·폴더 이동·파일 게시·SIGKILL은 실제 OS 작업이다.
