# 공통 입력 검증 그래프

2026-09-06 · P4-01의 게시판 지속 입력 연결을 위한 기반 작업

## 문제와 선택

현재 업무 W가 기억 M을 읽고, M이 다른 업무 X의 자료를 인용할 수 있다. X가 다시 W의 자료를 참고했다면 업무 사이의 참조는 순환할 수 있다. 이때 재귀 함수끼리 호출하면 끝없이 따라갈 수 있고, 이미 방문했다는 이유로 검사에 성공 처리하면 중간 자료의 철회나 권한 변경을 놓칠 수 있다.

각 출처를 제공자와 내부 key로 식별하는 공통 큐를 사용한다. 조회한 node는 현재 버전·추가 참조·스냅샷 바이트 수·만료 시각·마지막 유효성 확인 함수를 제공한다. 같은 node를 다시 참조하면 스냅샷 읽기는 반복하지 않지만 모든 버전 기대를 검사한다. 큐를 모두 읽은 뒤 업무별 의미 규칙을 검사하고, 각 출처와 권한을 다시 확인한다.

참조 순환을 읽을 수 있다는 사실은 논리적으로 순환한 주장을 근거로 인정한다는 뜻이 아니다. 기억의 `derivedFrom` 순환은 계속 거절하며, 원 출처·등급·현재 자료·검토 상태도 기존 업무 규칙으로 검사한다. 이 그래프는 독립 근거를 만들거나 목표 완료를 결정하지 않는다.

## 구현과 통과 기준

1. 공통 `InputValidationGraph`를 DB/모델/SDK 의존 없이 구현한다. reader는 읽기 전용 내부 adapter이며 새 참조를 반환한다. callback과 제공자 이름은 등록 때 고정하고 중복 제공자를 거절한다.
2. 호출마다 독립된 큐·스냅샷·기대 버전·취소 상태를 가진다. diamond, 순환, 나중에 도착한 버전 충돌, 중첩 조회 중 원본/권한 변경, 검증 중 만료를 검사한다.
3. 노드·참조·스냅샷 바이트·시간의 상한을 적용한다. 취소나 시간 초과는 기다리는 호출을 끝내고 신호를 reader에 전달한다. 늦은 거절이 처리되지 않은 Promise 오류로 새어 나오지 않도록 한다.
4. 실제 `KnowledgeService`의 지속 입력 검증을 이 그래프에 연결한다. 기존의 256개 논리 항목 제한과 원 출처/권한 규칙을 유지한다. 입력 의존성이 없는 경로에 추가 조회를 넣지 않는다.
5. 기억 도구의 AbortSignal을 검증 그래프까지 전달한다. 자료 조회가 대기 중일 때 취소하면 도구가 cancelled로 종료되고, 늦게 반환한 자료를 채택하지 않는지 실제 도구 wrapper로 확인한다.
6. 그래프 단독 시험과 기억 저장·도구·runtime·게시판을 함께 검증하고 repository의 `npm run verify`를 실행한다. 결과와 실패 원인·남은 연결을 저장한다.

## 범위와 다음 단계

이번 단위는 공통 그래프와 실제 기억 입력 경로다. 게시판 조회를 도구로 등록하고 읽은 페이지를 지속 입력으로 보관하는 작업은 아직 남아 있다. 이를 연결할 때 현재 주체·업무에 맞는 reader를 제공하고, 여러 주체의 기억 검증에 필요한 내부 권한 계약을 명시한다. tool 출력에 이 내부 참조/검증 오류를 노출하지 않는다.

후속 연결에서는 효과 증명과 수집 증명도 고려한다. 현재 일부 `current` 검증기가 다시 기억 입력 검증을 호출하므로, 이를 그대로 게시판/기억 node 사이에 연결하면 검증기끼리 재귀할 수 있다. 추가 참조를 반환하는 reader와 호출별 검증 문맥으로 연결해야 하며, 전역 visited 플래그나 무조건 성공하는 재진입 예외를 두지 않는다. 현 단계가 이런 복합 경로 전체를 검증했다는 뜻은 아니다.

상한의 바이트 수는 reader가 보고한 스냅샷과 내부 참조를 기준으로 한다. adapter의 전체 네트워크 전송량이나 모든 guard I/O를 측정하는 계량기가 아니다. 취소 신호를 무시하는 I/O 자체를 강제로 종료하지도 못한다. 각 transport의 취소·연결 종료·응답 크기 제한과 함께 사용한다.
