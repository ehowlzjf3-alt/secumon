## 이번 결과로 만들 행동

같은 담당과 지속 세션을 유지하면서 관측을 쉬는 동작, 개별 업무를 쉬거나 취소하는 동작, 업무의 목표를 바꾸는 동작을 구분한다. 담당 종료는 호스트 실행 수명을 끝내는 별도 동작이다. 관측 제어 때문에 세션을 지우거나 접수된 업무를 새로 만들지 않는다.

| 구분 | 이번 연결 방향 |
| --- | --- |
| 담당 종료 | 기존 driver·호스트·저장소 종료 수명을 재사용한다. 관측 일시정지나 업무 완료의 별칭으로 쓰지 않는다. |
| 관측 일시정지/재개 | resident driver와 호스트 API의 `pause`/`resume`으로 제어한다. 원 커서·대기 사건·접수 이력을 유지한다. |
| 개별 업무 일시정지/재개 | 기존 코어 명령을 사용한다. 일시정지 중 원 사건과 대기 실행을 보존하고 명시 재개와 연결한다. |
| 개별 업무 취소 | 기존 취소 명령과 임무의 종료 메타데이터·원 체크포인트를 맞춘다. 실제 완료 영수증이 있는 경우와 구분한다. |
| 목표 변경 | 원 접수 영수증으로 사건이 어느 업무에 속했는지 확인한다. 변경된 업무는 resident의 자동 사건 실행과 분리하여 명시적으로 재개한다. |

## 구현 순서와 소유

1. root가 resident driver의 관측 `pause`/`resume`, 호스트 노출, 원 접수 영수증을 사용하는 사건 귀속 확인을 연결한다. 사건 재전달을 목표 변경 업무의 새 접수·자동 재실행으로 처리하지 않는다.
2. 별도 작성자가 `MissionRuntime`에서 취소·목표 변경 후 종료 메타데이터와 원 체크포인트의 정합성을 연결한다. 일시정지에서는 원 사건·대기 상태를 유지하고 명시 재개를 지원한다. 기존 실제 완료 복구의 증명 검사는 유지한다.
3. 기존 코어 명령·세션·개인 기억·상태/원문 저장 포트를 재사용한다. 새로운 DB나 제어용 대화 기억을 만들지 않는다. 제어 업무와 사건 업무의 수명·목표·사용량 분리는 유지한다.
4. 작성자 동결 후 root가 신규 로컬 인수와 직접 영향 회귀를 실행한다. 실제로 관측한 실패만 필요한 범위에서 수정하고, 실패 원로그와 최종 결과를 구분한다. 이 문서 담당자는 소스·빌드·시험·Git을 변경하지 않는다.

## 이번 최소 인수

- 실제 로컬 프로필과 SQLite에서 관측 pause→재개, 개별 업무 pause→명시 재개, 취소, 목표 변경의 흐름을 연결한다. 모델과 원천 응답은 호출 횟수를 관측할 수 있는 결정적인 로컬 callback으로 제한한다.
- 늦은 관측·같은 사건 재전달·접수와 제어의 경합에서 원 업무를 보존하고 새 접수나 실행이 중복되지 않는지 확인한다. 이미 접수된 사실을 소급 삭제하지 않는다.
- 목표 변경 전 읽기 확인이나 완료 기록을 변경된 목표의 증명으로 사용하지 않는다. 취소·일시정지를 실제 완료로 표시하지 않는다.
- 원 사건·커서·접수 영수증·세션·대기 의무·사용량과 다른 임무의 기록을 보존한다. 일시정지·대기 자체에서 새 모델 추론이 발생하지 않는지 확인한다.
- 기존 완료 복구와 직접 변경한 resident/mission 경로만 관련 회귀로 확인한다. checkpoint381/382/383의 모든 과거 시험을 현재 전체 재검증으로 다시 합산하지 않는다.

실제 프로세스 강제 종료와 예외 주입, fake clock과 실제 시간 대기는 구분하여 기록한다. 이번에는 SIGKILL 시험을 실행하지 않았으며 기존 시험도 반복하지 않았다. 최종 API·반환 상태와 로컬 경합/재개 인수는 사용법·결과에 기록했다.
