# C05 호스트 읽기 도구·실행 권한 연결 결과

2026-09-07 · **구현과 macOS·NAS Linux 검증 완료.** C05 전체와 C01–C10 전체 목표는 미완료다. 실제 모델/API 시험 중단을 유지한다.

담당마다 도구·권한·새 업무 한도를 등록해 같은 일반 CLI/Web 실행 흐름을 사용할 수 있게 했다. 여기서 호스트는 에이전트를 시작하는 프로그램이다. 리드–워커 조직이나 별도 에이전트 본체를 추가한 것이 아니다.

## 구현한 것과 재사용한 것

- [호스트 도구 계약](../../runtime/src/presentation/host-tools.ts): `HostToolRegistration.open`이 검증된 담당 ID·위치·scope를 받고 읽기 도구, 정책, 한도, 종료 함수를 반환한다. 메타데이터와 콜백을 고정하며 잘못된 계약·쓰기 도구·내장 이름 차용·중복을 거절한다. 빈 목록은 유효하고, 명시 등록 실패를 합성 도구로 대체하지 않는다.
- [일반 프로필](../../runtime/src/presentation/agent-turn-profile.ts): 도구 등록과 모델 등록을 분리했다. 기존 C01 담당 저장소·세션·기억·CLI/Web을 재사용하며, 한 담당 종료가 다른 담당의 자원을 닫지 않게 소유 수명을 유지한다. 호스트 정책이 허용하지 않은 도구를 자동 추가하지 않으며 스킬 off 정책을 유지한다.
- [실행 권한](../../runtime/src/application/execution-authority.ts): 전체 사용자 권한·담당 scope·disclosure·종료 신호를 프로필 수명에 묶었다. 실행 직전과 비동기 출처 확인 뒤 모델·도구·전송·복원에서 현재 권한을 다시 검사한다. 제한 actor를 실행 권한 없이 넘기는 기존 경로는 계속 거절한다.
- [기존 실행기의 사용량 처리](../../runtime/src/application/execution-runtime.ts): 현재 라벨 정책이 좁아져 본문을 사용할 수 없더라도, 원 dispatch에서 유효했던 동일 호출의 측정값은 기존 결과 영수증과 attempt에 보존한다. 새로운 장부를 만들지 않았다. 잘못된 원본문·사용량·귀속이나 재사용을 새 호출로 신뢰하지 않는다.

늦은 모델 응답은 현재 권한을 잃으면 본문 대신 오류 영수증과 알려진 사용량을 저장한다. 읽기 도구는 현재 권한에서 채택할 수 없지만, 아직 실패로 확정되지 않은 결과는 새 유효 권한으로 재개할 때 원 목표·정책·출처를 다시 검증해 사용할 수 있다. 이미 실패로 확정된 시도를 다시 여는 것과 구분한다.

## 확인한 동작

실제 C01 SQLite와 파일 journal 담당, 별도 CLI 프로세스, localhost HTTP를 사용했다. 모델과 외부 자료는 결정적 로컬 대역이다.

| 인수 | 로컬 결과 |
|---|---|
| 담당별 서로 다른 읽기 자료 | 같은 모델·사용자도 소스·세션·근거를 섞지 않고 각 담당의 답변을 만든다. |
| 일반 CLI/Web | 접수 → 등록 도구 → 결과 저장 → 근거 답변, 재접속과 중복 호출 방지를 확인했다. HTTP로 도구·권한을 주입하는 입력은 거절한다. |
| 좁아진 권한으로 재접속 | 이전 업무의 넓은 정책을 덮어쓰지 않고 실행을 거절한다. 기존 사용량·한도·마감을 초기화하지 않는다. |
| 종료·실패 | 초기화 중 오류와 복수 정리 오류를 보존하고, 각 소유 종료 함수를 한 번 실행한다. |
| 취소·정책 경합 | 모델/도구 호출 전 검사, 응답 게시 중 변경, 늦은 응답의 사용량, 중복 정산·잘못된 귀속을 검증했다. |
| 기존 경로 | 모델 등록·합성 경로, 세션/compact, 목표 변경, 결과 재사용·검증을 포함한 관련 회귀를 통과했다. |

- 신규 5개 시험 파일 **54/54**, 관련 32개 시험 파일 **356/356**, 실패·취소 0.

최종 로컬 소스 지문은 `da1b2da2fb712caf48753afac5dc3d78822fd636d324455a080a7c8c2eebbdf4`, 빌드 지문은 `61e8cf8b24b4230e9899af6106b5c1e17f1d89b1667c63b685574a0289414b4e`이며 빌드 파일은 1,650개다. 지문은 같은 소스/산출물인지 대조하기 위한 값이다.

첫 신규 실행은 42개 중 41통과·1취소였다. 도구 계약이 `execute`를 고정한 뒤 시험이 콜백을 교체하여 신호가 오지 않았다. 콜백을 등록 전에 설치하도록 시험을 수정했으며 [첫 원로그](../../runtime/evidence/C05-host-new1.log)를 보존한다. 제품 동작을 시험에 맞춰 완화하지 않았다. 별도 검토에서 찾은 라벨 축소 시 사용량 유실은 제품 수정과 새 경계 시험 12개로 확인했다.

같은 소스를 NAS Linux/Node24에서 신규 **54/54**, 관련 **356/356**, 전체 **3,338/3,338**으로 검증했다. build·신규·관련·core·계층·CLI 구조·전체·fixtures의 필수 8단계가 모두 종료 코드 0이고 실패·취소는 0이다. native exec56905는 2026-09-07T10:33:02.838Z에 종료했다. 원로그와 결과 9개를 회수·해시 대조했으며, 관측 가능한 전용 프로세스 0·SSH 종료·private 제어 폴더 정리를 확인했다. 접근할 수 없는 같은 UID peer 2개의 범위는 미확정이며 시스템 전체 프로세스 부재로 확대하지 않는다. 시스템 Node18과 기존 자료는 유지했다. ## 확인하지 못한 것과 다음 작업

이 결과는 신뢰된 호스트 코드의 읽기 도구 조립과 실행 계약 검증이다. 임의 호스트 코드의 OS 격리, AbortSignal과 DB commit의 원자성, 직접 profile.close와 동시 실행의 완전한 drain을 새로 보장하지 않는다. 정상 CLI는 업무 처리가 끝난 뒤 종료하고 Web은 서버의 drain 뒤 프로필을 닫는다.

일반 Tool 계약을 위반한 결과는 기존 `invalid_tool_result`로 정규화된다. 모든 잘못된 원본문이 그대로 영속 보관된다고 주장하지 않는다. MCP의 원 응답 보관·증명은 기존 별도 어댑터 책임이다.

실제 모델의 판단 품질·usage·취소·tokenizer, 실제 사내 MCP/Knox, native Windows, PostgreSQL, 운영 배포는 미검증 또는 후속 구현 항목이다. 다음은 [기존 MCP의 일반 입구 연결 계획](C05-mcp-host-plan.md)이다. [호스트 연결 후속 검토](C05-after-host-review.md)와 [문맥 조회 비용 검토](C05-context-cost-review.md)에 따라 현재 보관 포트를 연결하고 측정한 중복 조회를 개선한다. 쓰기·스킬/메모리 선택·컴퓨터 유즈·효율 비교도 C05 전체 범위에 남는다.
