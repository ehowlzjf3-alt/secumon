# 이력 비용 개선과 사건 한도 상태 읽기

2026-09-09 · checkpoint400.

일반 문맥 조회와 compact에는 별도 설정 없이 개선이 적용된다. 오래된 대화나 개인기억을 삭제하지 않으며, 다른 업무·담당의 기억을 합치지 않는다. 저장 방식과 무관한 기존 포트를 사용한다.

`session_source_changed`는 문맥을 만드는 동안 재사용한 원 업무 상태가 바뀌었다는 뜻이다. 원자료를 다시 읽어 새 문맥을 구성해야 한다. 캐시 값이나 저장 버전 번호만으로 기존 문맥을 유효하다고 처리하지 않는다.

업무 관측의 `closed`와 `reason: event_capacity`는 사건 한도에 도달했다는 뜻이다. 목표 완료나 새 페이지 접수 성공이 아니다. `readEvents`의 커서는 마지막으로 받아들인 위치이며, 기존 사건과 읽기 확인은 보존된다. 같은 목표에서 같은 규칙을 다시 등록하거나 조회해도 자동으로 재개하지 않는다. 한도 이후 이어가기와 보관 이관은 남은 구현 사항이다.

장시간 실행하는 담당의 신원·세션 수명과 개별 업무 관측의 사건 한도를 구분해야 한다. 이 변경은 담당의 컨텍스트를 버리고 새 담당을 만드는 동작을 추가하지 않는다.
