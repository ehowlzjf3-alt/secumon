# P4 게시판 요청의 자원 배정과 수락 준비

2026-09-06 · 신규 44개 통과 · 전체 native 검증 진행 중

## 개념과 구현

자료를 조사할 역할은 요청을 수락하기 전에 무엇을 맡는지 확인할 수 있어야 한다. 이번 단위는 배정된 자식 작업에 질문 읽기·요청 상태 조회·수락만 허용하고, 수락이 저장된 다음 일반 도구와 모델 호출을 허용하는 경계를 구현한다. 자원 배정 자체는 조사 실행이나 목표 완료를 뜻하지 않는다.

`BoardFunding`은 host가 보관한 역할 프로필과 현재 게시판 요청을 기존 `BudgetDelegationService`에 연결한다. 프로필에는 역할의 자료 정책·목표·최대 자원이 있으며, 호출자는 프로필 참조·개정·요청·배정량만 지정한다. 반환값은 작업과 배정 ID다. 지원 역할에게 조사 역할의 원문·정책·목표 전체를 반환하지 않는다. 이 단위의 배정은 host API이며 에이전트용 도구 연결은 후속 작업이다.

현재 권한은 양쪽 주체·역할·게시 권한·게시판/질문 등급·목표 내용 digest·프로필 개정·요청 기한으로 확인한다. 준비 작업의 기한은 요청의 절대 마감과 일치해야 한다. 동일 요청은 프로필을 바꿔도 중복 배정할 수 없다. 실제 계획·예약·dispatch·도구 재인가·모델 실행에서 현재 권한을 다시 검사한다.

준비 권한은 해당 게시판의 질문 entity 읽기, 정확한 요청 조회, 정확한 요청 수락에만 적용한다. 다른 요청·게시판·entity, 게시판 전체 조회, 일반 도구, 게시, 모델 호출은 허용하지 않는다. 수락 준비에도 실행한 도구 수와 사용량을 기록한다. 제안된 계획은 검증 전에 복제·파싱하며, 임의 목적 문자열로 실행 권한을 바꾸지 않는다.

## 비공개 정보와 협업 상태

요청 metadata는 공유 게시판과 질문의 등급을 따른다. 조사 역할이 비공개 자료를 읽을 권한이 있다는 이유만으로 요청자에게 자기 요청의 상태를 숨기지 않는다. 질문 자체가 비공개이면 요청 metadata도 볼 수 없다.

자유 서술 게시물은 작성 역할의 자료 등급을 유지한다. 비공개 역할의 답변을 요청자가 읽을 수 없으면 확인도 할 수 없으며, 이를 목표 완료로 처리하지 않는다. 수락 이후 자원 배정의 유효성은 수락 역할의 현재 원본 접근 권한으로 확인한다. 요청자의 답변 접근 거절만으로 작업의 배정이 철회되지는 않는다.

공개 자료만 처리한 역할의 전체 완료 흐름과 비공개 역할의 원문 격리를 따로 검증한다. 이 검증은 현재 코드의 경계 확인이다. 사용자가 읽을 수 없는 글과 승인 가공 절차의 복잡성을 지적했으므로, 이 동작을 기본 UX로 채택하지 않는다. 다음 구현에서는 **게시판 참여자 모두가 글을 읽는 공유 흐름과 별도 원문 권한**으로 단순화한다. 정보 자체의 강한 격리/공개 승인은 선택 배치로 둔다. ## 검증과 복구

SQLite와 파일 저널, 문서와 관측 두 업무군, 실제 로컬 실행 경로와 고정 planner 대역을 사용한다. 실제 모델/API나 사내 서비스는 호출하지 않는다.

- 공개 자료 역할: 요청→배정→질문 조회→수락→대역 모델 계획→원본 수집→근거 답변→요청자 확인→자원 정산/반환. compact/restore와 저장소 재열기를 포함한다.
- 거절 경계: 준비 권한을 벗어난 동작, 프로필/주체 권한 철회, 다른 목표·정책 입력, 외부 주체, 비공개 질문과 답변, 요청 기한보다 짧은 배정.
- 복구: 수락 저장 후 응답 유실에서 동일 요청/배정/의무 복원, 중복 배정 거절, 취소나 경쟁 수락 시 미사용 반환. 원래 실패 응답을 성공으로 덮어쓰지 않으며 수락 복구와 계획 채택을 구분한다.
- 프로필 조회 중 개정 변경이 발생하면 오래된 준비 권한을 거절한다.

초기 정상 경로 4개는 합성 프로필의 짧은 기한 때문에 실패했다. 기한을 맞춘 후 부모의 자원 상태 갱신 전에 기준 개정을 읽는 helper를 수정했다. 첫 관련 실행은 202/206으로 비공개 답변 확인 4개가 거절됐으며, 게시물의 자료 등급을 낮추지 않고 시험의 공개 자료/비공개 자료 계약을 구분했다. 최종 actor 조회 중 프로필 변경 두 사례는 수정 전 실패했고 마지막 프로필 재확인으로 보완했다. build7의 미사용 시험 변수 오류는 제거했다. 최종 수치와 sourceDigest는 전체 native 검증 이후 기록한다.
