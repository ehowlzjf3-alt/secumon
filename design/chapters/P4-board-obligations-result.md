# P4-01 협업 요청과 작업 의무

2026-09-06 · v0.48 · 전체 2306/2306 · 관련 167/167 통과

요청자가 질문을 게시하고 동료에게 요청하면, 요청자의 작업에는 응답을 기다리는 의무가 남는다. 동료가 수락하면 동료 작업에는 답변을 작성할 의무가 생긴다. 답변을 게시한 뒤에도 요청자가 읽고 확인하기 전까지 양쪽 의무는 완료되지 않는다. 전체 목표는 별도의 근거·완료 기준으로 판정한다.

## 구현

`core.board.requests.offer`, `accept`, `answer`, `confirm`, `decline`, `cancel`을 일반 도구 catalog, 예약, 실행, 결과 검증과 효과 복구에 연결했다. 주체·작업·명령 ID는 host와 원래 dispatch에서 결정한다. 수락 시 질문의 기조회 여부를, 확인 시 질문과 답변의 기조회 여부를 검사한다. 답변은 수락한 작업이 작성한 인용 근거가 있는 글이어야 한다.

게시판과 WorkState가 같은 트랜잭션을 공유한다고 가정하지 않는다. 작업은 자신에게 적용된 offer/accept 영수증으로 `Obligation.source`를 만들고, 현재 요청 상태를 조회해 갱신한다. 저장 직후 결과나 의무 기록을 잃어도 영수증 복구 뒤 한 번만 반영한다. 원래 결과를 새 결과로 바꾸거나 상대 작업을 현재 주체의 권한으로 수정하지 않는다.

| 요청 상태 | 요청자 | 수락한 동료 |
|---|---|---|
| offered | 응답 대기 | 의무 없음 |
| accepted | 응답 대기 | 답변 작성 가능 |
| answered | 답변 확인 가능, 아직 미완료 | 요청자 확인 대기 |
| satisfied | 충족 | 충족 |
| cancelled / declined | 면제, 충족과 구분 | 수락한 경우 면제 |
| expired / needs_review | 미완료 상태로 재검토 | 미완료 상태로 재검토 |

`actionable` 의무는 필요한 실행을 허용하고 완료를 막는다. `waiting` 의무는 모델을 반복 호출하지 않고 기다린다. 명시된 계획의 취소·거절 도구는 host가 정한 `resumeToolIds`로 제한해 대기 중 실행할 수 있다. 일반 사용자 wait/resolve는 출처나 이 실행 허용 목록을 위조하거나 협업 의무를 임의 충족시키지 못한다.

협업 상태 검사는 실행·모델·compact·복구·최종 응답의 판단 경계에 연결했다. 원본 자료 검사에는 협업 의무를 재귀적으로 넣지 않았다. 따라서 A의 질문과 B의 답변이 서로의 자료를 참조할 때도 원본 유효성과 현재 협업 의무를 각자의 역할로 확인한다. 협업 의무는 사람에게 보낼 질문 목록에 섞지 않는다.

수락·답변·확인이 새로 관측되면 단계별 고정 키로 진척을 기록한다. 같은 요청 상태를 반복 조회하거나 예전 상태가 다시 나타나는 것만으로 진척 점수가 늘지 않는다. 이는 협업 과정의 진척이며 독립 근거나 목표 충족으로 계산하지 않는다.

첫 시험은 합성 authority fixture가 전용 관리 필드를 잘못 전달하여 거절됐다. 계약에 맞게 변환한 뒤 정상 흐름이 통과했다. 이후 협업 단계가 진척 장부에 기록되지 않아 후속 작업이 막히는 문제를 수정했다. 답변 철회는 저장에 적용되더라도 그 답변을 참조한 자료의 유효성을 잃게 할 수 있으며, 결과 채택/후속 문맥은 별도로 거절된다. 요청자의 이전 충족 의무 역시 재검토 대상으로 돌아간다.

전체 병렬 검증에서 파일 저널 협업 사례의 지연이 관련 시험보다 크게 늘었다. 사례 시간에는 fixture 준비, 원본/권한 검사, compact/reopen도 포함된다. 최종 실행 기록에 관련/전체의 사례별 시간을 남기며 운영 처리량이나 모델 응답 시간으로 해석하지 않는다. 반복 원본 검사와 동일 실행 내부 조회 비용은 후속 성능 평가 항목이다.

## 다음 범위

현재 시험은 요청 ID와 명령의 예상 게시판 revision을 로컬 테스트 실행기가 전달한다. 신규 요청 발견, 현재 revision 조회, 게시판 변경 이벤트와 cursor, 누락 이벤트 재조회, 중복 wake, 상시 임무 스케줄링은 다음 단위다. 두 runtime의 자율 가설·반증·재계획 및 역할 간 예산은 아직 별도 검증이 필요하다. 실제 모델/API 시험은 사용자가 중단했으며 사내 서비스·Knox·외부 A2A·운영 배포는 실행하지 않았다.

원래 Python 구현과의 동작 대조는 하지 않았다. 새 요구사항과 정상·실패·재개 조건으로 판정했다.
