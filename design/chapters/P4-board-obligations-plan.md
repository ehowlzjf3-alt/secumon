# P4-01 다음 소단위: 협업 요청과 작업 의무

2026-09-06 · 요청 도구/의무 로컬 검증 완료 · 요청 발견/이벤트 재개는 후속 단위

게시·철회와 원래 명령의 저장 효과 대조 다음에는 동료에게 일을 요청하고 응답을 기다리는 상태를 연결한다. 특정 보안 업무를 코어에 넣지 않고 문서 검토와 합성 관측 두 업무에 같은 계약을 적용한다.

## 배울 개념과 목표

요청을 보냈다는 사실과 상대가 수락한 사실은 다르다. 답변이 도착해도 요청자가 요구한 결과와 현재 근거를 확인해야 해당 의무를 충족시킬 수 있다. 전체 업무의 완료 판단은 그 뒤에 남는다.

현재 BoardService에는 offered/accepted/answered/satisfied/declined/cancelled가 있고, 현재 자료·기한·목표 변경에 따른 needs_review/expired 조회가 있다. 이를 기존 도구 catalog와 WorkState 의무에 연결한다. 설명 문장만으로 의무를 완료 처리하는 경로를 두지 않는다.

## 순서

1. 요청·수락·답변·확인·거절/취소를 runtime 도구로 연결한다. 주체와 대상 작업의 권한은 host에서 확인하고, 현재 작성·기조회 글만 참조한다. 게시·철회에서 도입한 명령 식별자, 저장 영수증과 미실행 종료 기록을 확장한다.
2. 별도 저장소 사이에 분산 트랜잭션을 전제하지 않는다. 게시판의 확정된 요청 상태로부터 각 작업이 자신의 의무를 멱등하게 반영한다. 다른 주체의 WorkState를 현재 역할의 권한으로 직접 수정하지 않는다. 어떤 요청/목표/게시판 revision에서 의무가 생겼는지 추적한다.
3. 먼저 요청자와 수신자 각각의 실제 runtime 경로를 검증한다. 요청 저장 뒤 의무 기록 전에 중단한 경우, 수락 저장 뒤 재개, 답변 도착 전후 취소와 기한 변경에서 양쪽 상태를 확인한다.
4. 현재 workflow의 대기/이벤트 재개와 연결한다. 안정적인 이벤트 ID와 cursor로 중복 전달을 무해하게 처리하고, 재시작 시 누락분을 조회한다. 단순 대기는 모델 호출 반복을 만들지 않는다.
5. 두 업무군에서 질문→수락→근거 있는 답변→요청자 확인을 실행한다. 반증으로 기존 가설/계획이 달라지는 전체 흐름과 역할 간 예산은 별도 완료 기준을 유지한다.

## 통과 기준

- 수락하지 않은 요청에 답변 의무가 임의 생성되지 않는다. 답변 도착만으로 요청자의 확인 의무나 전체 목표가 완료되지 않는다.
- 요청/답변 철회, 현재 역할 비활성화, 원본 근거 유실, 기한 경과, 목표 변경은 이미 저장된 이력과 현재 유효성을 구분하여 반영한다.
- 같은 이벤트·명령 재처리, 두 저장소 중 하나만 저장된 경우, 프로세스 재개가 중복 요청이나 중복 의무를 만들지 않는다.
- 응답 대기 중 호출 수가 증가하지 않으며 예산 사용은 실제 도구 실행 장부에 남는다. 역할 간 예산 위임은 명시 계약을 구현하기 전까지 자동으로 허용하지 않는다.
- SQLite/파일 저널, 정상/실패/재개를 실행하고 결과를 저장한다. 실제 모델/API·사내 MCP·Knox·외부 A2A·운영 배포는 이 단위의 로컬 성공과 구별한다.

## 이번 구현의 구체화

- `core.board.requests.offer/accept/answer/confirm/decline/cancel` 여섯 도구를 같은 영속 명령 영수증에 연결한다. 호출자가 주체·작업 ID·명령 ID를 주입할 수 없다. 수락은 질문을 읽은 뒤, 확인은 답변을 읽은 뒤 수행한다.
- `Obligation.source`는 제공자·게시판·요청·역할·원래 목표 revision·적용 시도 ID를 보존한다. 적용된 offer/accept 영수증에서만 작업 자신의 의무를 복원한다.
- `mode=actionable`은 답변 작성이나 확인을 위해 실행이 필요한 의무다. `waiting`은 상대를 기다린다. 대기 중에도 host가 지정한 취소/거절 도구만 명시된 계획에서 실행할 수 있다. 일반 사용자 wait/resolve로 이 설정을 만들거나 해소할 수 없다.
- 현재 협업 상태를 검증하는 경로와 원본 자료의 유효성을 검증하는 경로를 분리한다. 두 작업이 서로 질문/답변을 인용해도 완료 의무 검사가 원본 자료 검사에 재귀적으로 들어가지 않는다.
- 원래 Python과의 동작 비교는 시행하지 않는다. 새 요구사항의 정상·실패·재개 결과만 확인한다.

## 이후 다룰 항목

요청/의무 연결 후 사건 기반 상시 임무, 역할 간 예산, 두 runtime의 반증·가설·재계획 전체 흐름을 진행한다. 오래된 효과 영수증과 도구 기록을 컨텍스트에서 효율적으로 조회하는 방식은 원본 참조와 미해결 효과를 보존한다는 조건으로 개선한다. Python 원본 비교는 선행 절차가 아니다.
