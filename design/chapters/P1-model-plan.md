# P1-06 — 모델 호출과 가설·계획 변경

2026-09-05 · 구현 전 작성한 계획 · [로컬 구현 결과](/Users/seunghanee/Documents/secumon/design/chapters/P1-model-result.md) 저장, 실제 모델 시험은 미실행 유지

이번 단위는 기존 planner 포트를 실행 루프에 연결한다. 모델은 상태/권한/근거를 직접 수정하지 않고 계획과 가설 평가를 제안한다. 실제 provider 연결 정보가 없으므로 provider 중립 구조화 응답 adapter와 주입한 로컬 transport를 사용하고, 실제 모델 품질/호환성 완료를 주장하지 않는다.

1. 모델 호출의 ID·provider/model/revision·목적지·입력 artifact/digest·기반 상태·예산 예약·실행/수신/수락·사용량 상태를 저장한다. 호출 의도와 예산을 먼저 커밋하고 같은 시도를 다시 발송하지 않는다.
2. 입력에는 현재 허용된 근거와 목표/계획/가설/의무, 선택 도구 명세를 넣는다. 원본 파일을 자동 열지 않는다. 모델 목적지와 도구/정보 등급 권한을 호출 직전에 재검사한다. 소규모 입력 상한을 적용하고 초과분을 조용히 버리지 않는다. 본격적인 context 수명/compact는 P1-07/P2-03에서 이어 구현한다.
3. 실제 usage는 예약과 구분한다. 누락/취소/timeout으로 사용량을 모르면 미계측 호출과 예약을 남기고 추가 모델 호출을 차단한다. 입력 추정은 실제 토큰 수나 비용 상한의 증명이 아니며 보고 usage가 예산을 넘으면 다음 호출을 허용하지 않는다. adapter는 숨은 재시도/출력 수정 호출을 하지 않는다.
4. 응답은 엄격한 schema로 검사하고 잘림/거부/오류를 계획으로 실행하지 않는다. 사용량 정산은 계획 수락 여부와 분리한다. 입력 당시 의미 상태의 digest를 현재 상태와 비교하고 장부/전달 등 업무 판단과 무관한 revision 증가만 허용한다. 목표·정책·근거·의무·시도·계획 변경이나 취소 뒤의 응답은 수락하지 않는다.
5. 가설의 질문·주장·예측·반증 조건·판단 이유와 근거 상태를 검사한다. 현재 근거는 완료 판정과 같은 supersession/ACL 규칙을 따른다. 기존 지지/반증을 조용히 삭제하거나 같은 가설 ID의 의미를 바꾸지 않는다. 현재성에서 벗어난 참조는 이전 사건에 남기고 새 평가에서 제외할 수 있다.
6. 활성 가설이 있으면 새 근거 집합이 이전 평가 이후 바뀌었는지 감지해 검토를 요청한다. 초기 정책은 보수적으로 재검토하며 관련성에 따른 정밀 최소화는 후속 효율 평가 대상이다. 같은 작업 그래프를 유지하는 평가는 plan revision/replan 비용을 올리지 않는다. 작업 변경은 기존 ID/근거/완료 시도를 보존한 새 계획으로 검사한다.
7. 단순 조회는 기존 유효 계획을 계속하고 가설/별도 critic을 강제하지 않는다. 실제 실행 루프와 두 업무군의 대역 시험에서 정상 완료, 늦은 반증/계획 유지·변경, 무효 출력, 예산, 취소/목표·권한 변경, 중복/동시성, 저장 후 재시작을 확인한다.

P1-06은 실제 모델 시험까지 포함하므로 로컬 구현/대역 검증이 끝나도 작업 전체 상태는 in_progress로 유지한다. 이전 API 키 탐색/시험은 재개하지 않는다. 독립 구성요소를 구현할 수 있는 동안 전체 목표를 축소하거나 차단으로 표시하지 않는다.
