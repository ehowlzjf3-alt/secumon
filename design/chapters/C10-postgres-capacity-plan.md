# PostgreSQL 전달 용량 최종 확인 계획

2026-09-09 · checkpoint407 · 기준 ad472ce4965be98ce027449347a768c9ffd8eeae. 직전 단위는 복구 검사·결과 기록·원격 push를 완료한 progress다.

기존 V10-07의 전체 전달 64MiB 초과 처리 한 묶음만 확인한다. 새 private case와 독립 DB에서 최소 업무·세션·개인기억을 준비하고, 유효한 pending 입력 224개를 기존 저장 API로 받는다. 입력마다 한글 100,000자면 텍스트만 67,200,000바이트로 64MiB를 넘는다. 입력을 실행하거나 정산하지 않는다.

실제 PostgreSQL 백업이 `postgres_transfer_limit`으로 거절되고 최종 manifest가 없으며 부분 페이지·복사 자료가 보존되는지 확인한다. DB 원행의 정렬된 지문과 세션 입력의 원문·pending 상태를 전후 대조하고 관리 잠금 해제도 확인한다. 초과 자료에 성공하는 가짜 export를 만들지 않는다.

checkpoint406의 성공한 이행/복구/엔진 흐름·전체 회귀는 재실행하지 않는다. 새 DB 준비에 필요한 최소 정상 이행은 시험 준비로 구분한다. 제품 소스와 build는 그대로 쓰고, 실행기와 소스 지문을 확인한다. 실패가 있으면 원 로그·자료를 보존하고 실제 원인을 교정한다.

결과 기록·Git push 뒤 현재 환경에서 가능한 검증을 마감한다. Windows·운영 PG 역할/TLS·사내 MCP/Knox/A2A·실제 앱·운영 규모/복구 목표·선택 시범 운영은 외부 조건 인수로 남긴다. 실제 모델/API 시험 중단을 유지하며 전체 goal 완료로 표시하지 않는다.
