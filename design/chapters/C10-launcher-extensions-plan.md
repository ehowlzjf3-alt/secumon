# C10 전역 실행기와 확장 호환 연결

2026-09-08 · checkpoint385 · 기준선 `242d0b15994688336c86bbff628863564e9a4104`.

직전 단위는 실제 설치 버전 전환의 검증 결과를 저장하고 원격 main과 일치시킨 progress다. 같은 시험을 이유 없이 반복하지 않는다. 이번 시작 시 작업 트리는 깨끗했고 실행 중인 이전 빌드·시험은 없다.

전역 명령은 공통 엔진을 선택하는 입구다. 담당 폴더에는 사용할 엔진의 pin만 두고, 실행 가능한 설치 위치는 호스트의 별도 등록표로 확인한다. 미등록·없어진·변경된 설치본을 다른 버전으로 대체하거나 자동 다운로드하지 않는다. 기존 신규 담당 설정, 설치/백업/호환 검사/업데이트를 재사용한다.

1. 기존 bin 경로를 유지하면서 일반 명령을 담당의 pin에 맞는 검증된 설치본으로 연결한다. 담당 경로는 현재 디렉터리 또는 `--directory`를 따른다. 관리 명령·도움말·설치 버전 표시는 현재 실행기를 사용하여 잘못된 pin에서도 복구할 수 있다. 하위 실행은 shell 없이 argv/stdin/stdout/stderr와 종료·중단 상태를 유지한다.
2. 호스트 설치 등록표는 담당 데이터와 분리한다. 검증된 release 지문·실제 설치 경로·디렉터리 객체를 기록한다. CLI의 정상 설치 뒤 등록하며, 기존 설치는 지문을 명시한 `lifecycle register`로 등록한다. pin 자체는 임의 경로 실행 권한이 아니다.
3. 모델/도구/선택 기능 등록에 공통 엔진 API·필수 기능 선언을 캡처하고, 선택된 등록만 저장소나 콜백을 열기 전에 검사한다. 선언된 비호환은 거절한다. 기존 미선언을 허위 호환으로 승격하지 않고 미검증으로 보고하며, 호스트가 미선언도 거절하는 정책을 선택할 수 있게 한다. 이 검사를 lifecycle check/pin/update에서도 공유한다.
4. 원 입력·세션·기억·진행 업무를 보유한 담당을 전역 A 입구에서 지정 B로 재개하고 B의 실제 코드가 실행되는지 확인한다. 미등록/변조/신원 불일치/다른 담당/원자료 보존과 선택 확장의 비호환·비활성·변경 검사를 포함한다. root만 소스 동결 후 빌드·대상 회귀·코어/계층 검사를 실행하며 살아 있는 시험 중 dist를 교체하지 않는다.
5. 결과·실패 원로그·미실행 항목·다음 행동을 저장하고 단위 완료 시 커밋/푸시/원격 일치를 확인한다. 실제 모델/API, 사내 서비스, 외부 게시/배포는 실행하지 않는다. macOS 로컬 결과를 현재 Linux/native Windows 또는 운영 호환 완료로 표시하지 않는다.

C10 저장 형식 이행·compact 이후 버전 전환·미확정 외부 효과, C09 잔여·C05 재허용 완주·C06 기억 HTTP/브라우저·실제 PostgreSQL·플랫폼·최종 통합은 계속 남아 있다. 전체 goal은 미완료다.
