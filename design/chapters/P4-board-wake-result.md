# P4-01 요청 발견과 사건 기반 재개

2026-09-06 · v0.49 · 로컬 검증 완료

담당 역할은 요청 목록에서 요청 ID·질문 참조·현재 게시판 revision을 발견하고, 자신의 작업에 저장된 알림을 바탕으로 계획을 갱신한다. 요청을 읽거나 알림을 받았다는 사실로 목표를 완료하지 않는다. 새 요구사항과 완료 기준으로 검증하며 원래 Python 코드 비교는 수행하지 않았다.

## 학습 포인트

사건은 “다시 확인할 때가 됐다”는 신호다. 영수증은 처리 위치가 저장됐다는 증명이고, 현재 요청 상태는 다음에 해야 할 일을 정한다. 실제 자료와 완료 조건은 별도로 검사한다. 이 구분 때문에 같은 사건을 다시 받아도 중복 실행하지 않고, 사건의 문구가 잘못됐거나 오래됐다고 해서 그대로 행동하지 않는다.

각 작업은 자신이 처리한 위치와 아직 검토할 요청 참조를 함께 저장한다. 도구 호출 결과를 잃거나 프로세스가 종료돼도 이 기록으로 이어간다. 기존 구독이 없는 작업에 역할만 보고 새 목표를 임의 생성하는 기능은 이번 범위에 포함하지 않았다.

## 구현

- `core.board.requests.read`는 현재 역할이 참여하는 요청의 메타데이터를 반환한다. 본문과 원자료는 기존 게시판 읽기로 조회한다. 관측 artifact·원래 dispatch·관측 영수증·현재 공개 권한을 확인하며, 정상적인 수락/답변 후에도 과거 관측은 보존된다.
- 실행기가 붙인 기존 자료 출처는 원래 dispatch에서 보유한 것만 허용한다. 요청의 변하는 상태를 영구적인 자료 출처 의존성으로 추가하지 않는다. 메타데이터 조회는 새로운 독립 근거를 만들지 않는다.
- 게시판 revision에 대응하는 변경 조회 port를 추가했다. SQLite에서는 변경·명령 영수증·이벤트가 함께 commit된다. 파일 저장소는 검증한 원래 저널의 상태 전이로부터 같은 이벤트를 도출한다. 기존 파일 저널 형식은 유지한다.
- 작업의 구독과 알림은 같은 체크포인트에 저장한다. 알림에는 본문 없이 제공자·자원·요청 참조가 들어간다. host의 `boardWatch.register/refresh/close`가 현재 역할·조직 권한의 교집합으로 처리하며 다른 주체의 작업은 수정하지 않는다.
- 중복 알림은 같은 참조로 합친다. 이벤트가 많이 쌓이거나 SQLite에 과거 이벤트가 없으면 현재 요청 목록을 끝까지 확인한 뒤 위치를 전진시킨다. 이미 기록한 이벤트 구간의 누락은 오류로 처리한다.
- 새 요청은 계획 재검토를 요구하며, 이미 예약한 모델 문맥도 무효화한다. 조회만으로 알림을 해소하지 않고 수락·거절·취소·만료 등 현재 요청 상태를 확인한다. 받아들인 요청의 응답 의무는 별도로 유지한다.
- compact/재개에 알림과 구독을 보존하고 누락·변조·증명 부재를 거절한다. 목표 변경·자료 세대 변경·취소·완료는 이전 구독을 닫는다. 일시정지는 처리 위치를 보존한다.
- 알림 처리 자체는 모델·도구·메신저 전송을 호출하지 않는다. 사람에게 보여줄 질문 목록에도 내부 협업 알림을 넣지 않는다. 웹/CLI는 기존 공통 작업 상태 및 완료 검증을 사용한다.

## 한도와 복구

작업당 구독 16개, 알림 512개, 이벤트 페이지 32개/64KiB, 요청 페이지 20개/32KiB와 최대 13페이지, 경합 재시도 8회로 제한한다. 한 번의 refresh에 10초의 협력적 시간 한도를 적용해 I/O 경계와 commit 직전에 확인한다. 하위 adapter가 응답하지 않는 경우의 강제 중단은 adapter의 책임이며 이 시간 검사가 중단 가능한 I/O를 대신하지 않는다.

기록 없는 과거 구간은 명시적으로 현재 상태를 재조회한다. 단일 이벤트와 최종 cursor까지 UTF-8 바이트 크기를 계산한다. 처리 중 권한 철회·시간 초과·불완전한 목록 조회는 처리 위치를 성공한 것처럼 전진시키지 않는다. 여러 구독을 순서대로 처리하다 뒤에서 실패하면 앞서 확정된 구독의 체크포인트는 보존된다.

## 검증

전체 **2354/2354**, 관련 **48/48**, 신규 **48개** 통과. 실패/취소/skip/todo 0. 빌드·코어 타입·계층 121/위반 0·fixture 4/22 통과. 전체 시험 시간 369908.69325ms. [실행 기록](/Users/seunghanee/Documents/secumon/runtime/evidence/P4-board-wake-local-verification.json).

문서 검토와 합성 관측, SQLite와 파일 저널의 네 조합에서 실제 도구 실행 경로로 요청을 발견하고 수락·답변·확인했다. 요청 ID와 명령용 revision은 조회 출력으로 전달한다. 고정된 시험 계획에 따라 두 역할 합계 도구 14회·모델 0회이며 독립 근거는 원래 두 개를 유지한다. 이것은 모델의 자율 추론 성능 측정이 아니다.

추가 시험은 중복/누락 알림, 체크포인트 저장 후 응답 유실, 실제 worker SIGKILL 후 이벤트/영수증 보존, compact/reopen, 조회 결과 변조/증명 유실, 비참여 역할, 조회 직후 권한 철회, 시간 초과, 만료, 목표/자료/일시정지/종료 수명, 반복 조회의 진척 중복 방지, 새 요청 도착 후 모델 호출 전 차단을 다룬다. 실제 종료 시험 두 개와 reopen·응답 유실 모의 시험은 구분해 기록한다.

첫 관련 실행은 수락 후 조회 네 사례에서 실패했다. 런타임이 상속한 출처를 조회 검증기가 모두 거절한 원인을 수정했다. 최초 타입 빌드의 시험 API 인자 오류도 로그에 보존했다. 실패 기록을 삭제하거나 통과 기록으로 바꾸지 않았다.

## 남은 범위

이번 결과는 host가 호출하는 영속 조회·재개 경로다. 여러 역할을 상시 실행하는 공정한 dispatcher, 작업 종료 후 역할에 새 임무를 만드는 정책, 역할 간 예산, 두 runtime의 자율 가설·반증·재계획은 후속 범위다. 실제 모델/API 시험은 사용자 요청에 따라 중단 상태이며 사내 MCP·Knox·운영 배포를 실행하지 않았다.
