# P3-02 두 번째 단위: 로컬 Web 작업실

2026-09-06 · 개념 → 작은 계획 → 구현 → 정상/실패/복구 검증 → 결과 저장

첫 단위의 공통 조회와 CLI를 재사용해 실제 브라우저에서 접수·현재 질문/답변·상세·명시 제어를 사용할 수 있게 한다. 합성 자료 두 업무군과 질문 시나리오만 실행한다. 실제 모델/API·MCP·Knox 연결은 이 단위에 포함하지 않는다.

## 배울 개념

작업의 수명과 화면 연결의 수명은 다르다. 화면을 열거나 다시 연결하는 행위는 저장된 작업을 조회하며 실행을 재개하지 않는다. 접수 영수증, 현재 진행, 근거를 통과한 결과와 주 채널의 전달 상태도 구별한다. 기본 대화에는 접수·현재 질문/결과와 한 개 진행 표시만 두고 상세/진단을 접는다.

커서는 불투명한 투영 식별자다. 같은 상태 revision에서도 근거가 철회될 수 있으므로 최신성은 revision 숫자만으로 판단하지 않는다. 서버는 매 조회에서 공개 권한과 현재 근거를 확인하고, 클라이언트는 선택·세션·요청 세대를 확인해 늦은 응답이 현재 화면을 복원하지 못하게 한다.

## 구현 경계와 순서

1. LocalWorkbench와 strict Web DTO: 신뢰된 synthetic learner·등록된 web 대화를 고정한다. 목록도 WorkView를 거친다. 명시 접수/연결/실행/중지/재개/취소/목표/모드/질문 확인은 기존 코어 상태·영수증·revision 검사를 재사용한다. 같은 요청 ID의 다른 내용은 충돌이며 실행 응답 유실은 재실행 허가가 아니다.
2. Node HTTP 바깥 adapter: 127.0.0.1, 정확한 Host/Origin, 일회 fragment 연결 토큰, 인스턴스별 HttpOnly SameSite 쿠키와 CSRF, 32 KiB strict JSON, 자산 allowlist, 안전한 고정 오류를 사용한다. 읽기 API는 실행 기능을 호출하지 않는다.
3. SSE: 공개 conversation view만 2초 간격으로 직렬 조회한다. 서버 전체 4연결, 연결 수명 60초, 세션 수명 1시간, 불필요한 queue 없이 disconnect/만료/권한 거절/shutdown에서 정리한다. 변경 요청 동시 상한 12, 실행 중 업무 상한 4는 별도로 둔다. SSE 조회마다 세션을 재확인한다.
4. 브라우저: 새 작업 접수 후 명시 실행, 질문 확인, 목표 완료 조건/모드 편집, 연결 복원, 접힌 상세/진단을 구현한다. text node로 렌더링하며 입력 draft·초점·읽는 위치를 유지하고 좁은 화면을 지원한다. 합성 자료/모델 미연결과 로컬 전달의 의미를 화면에 밝힌다.
5. 두 저장소 controller 회귀, 독립 HTTP/session/SSE 시험, CLI/Web 같은 업무, 실제 브라우저 320/390px·키보드·초점·재접속을 검증한다. 정상/실패/복구 결과를 실제 실행 여부와 함께 기록한다.

브라우저를 닫아도 취소 명령은 생기지 않는다. 프로세스 종료 뒤에는 저장 상태를 새 명시 실행으로 재개하며 상주 worker를 구현했다고 표현하지 않는다. HTTP 실행 요청이 살아 있는 동안 중지/취소 요청은 별도 처리한다. 화면 조회 결과의 카드 수 제한은 저장소 I/O 제한과 다르므로 polling 비용도 관측하고 남은 제한을 기록한다.

## 산출물과 완료 기준

- 새 local-workbench/web-contracts, HTTP 진입점, HTML/CSS/TS 화면, 의미 있는 controller/transport/UI 상태 시험.
- 같은 업무 재접속 시 중복 실행/메시지 없음, 현재 권한 거절 시 과거 결과 제거, stale 편집은 자동 재전송하지 않고 draft 보존.
- 최종 build/verify와 실제 브라우저 관측을 별도 분모로 저장. 이전 검증·원본 1,973파일·dependency lock 보존.
- [독립 검토](P3-web-review.md)의 수용 행렬로 확인하고 결과/제약/다음 단위를 새 결과 문서와 WORKLOG에 남긴다. 전체 P0–P6 목표와 실제 연결 선행 조건은 유지한다.
