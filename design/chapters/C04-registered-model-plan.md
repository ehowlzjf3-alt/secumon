# C04 등록 모델과 일반 요청 입구 연결 — 구현 계획

2026-09-07 · 문맥 창 단위의 [확정 증거](../../runtime/evidence/C04-window-linux-nas-20260907/verification.json)를 기준으로 채택해 실행한 계획이다. macOS 신규 44/44·관련 245/245와 NAS Linux 전체 3,253/3,253·8단계를 통과했고 [결과](C04-registered-model-result.md)에 교정·한계·후속 범위를 기록했다. 실제 모델/API 시험 중단을 유지한다.

에이전트 담당 폴더에는 **사용할 모델의 등록 이름**만 둔다. 실행 프로그램인 **호스트**가 그 이름에 해당하는 모델 연결 객체를 만들고, 기존 에이전트의 요청·도구·compact·답변 흐름에 넣는다. 모델을 바꾸려고 본체의 세션·기억·실행 코드를 고칠 필요가 없도록 한다. 등록 이름이 권한이나 도구 사용 승인을 뜻하지는 않는다.

## 이번 결정

- C01의 기존 `model: null | {profile: string}`과 설정 v1/v2를 유지한다. 이름은 호스트 등록표의 정확한 키로만 찾는다. 파일 경로·URL·모듈 이름으로 해석하지 않는다.
- 명시적인 `synthetic` 선택은 그대로 둔다. `registered` 선택은 C01에 저장한 등록 이름을 사용하며 없는 이름은 모델 호출·업무 접수 전에 거절한다. 기본 외부 모델이나 합성 요약으로 대체하지 않는다.
- 최초 제공 예제는 `local-contract-v1`이라는 고정 로컬 전송 대역이다. 구조화 요청·응답을 실제 어댑터에 통과시키되 네트워크를 호출하지 않는다. 사내 호스트는 같은 공개 함수에 자신이 관리하는 transport를 정적으로 주입할 수 있다. 임의 코드 경로를 받는 플러그인 로더는 만들지 않는다.
- 등록 factory에는 담당 ID·목적·skills mode만 전달한다. 원문·저장소·권한 객체를 전달하지 않는다. 모델 구성·한도·정리 함수만 반환한다. 기본 local 권한과 도구 배치는 별도 조립 책임으로 유지한다.
- 첫 단위의 주 턴과 compact는 동일 모델 신원·목적지·능력값·호출 한도를 사용한다. 추정 설정 지문에 두 요청 포장의 버전을 모두 반영한다. 목적별 모델 라우팅은 이 단위에서 코어를 확장할 이유가 아니다.
- 기존 SessionCompactInput/Candidate를 쓰는 얇은 구조화 compact 어댑터를 추가한다. `policyDigest`는 권한이 아니며 실제 호출은 기존 PlanningRuntime의 권한·현재성·예약 검사를 거친다. 어댑터가 원문을 읽거나 요약을 직접 게시하지 않는다.
- CLI와 Web은 같은 호스트 등록표와 `openAgentTurnProfile` 조립을 사용한다. HTTP 본문은 모델·권한·코드 경로를 받지 않는다. 표시 정보는 합성 규칙 실행과 등록된 transport 구성을 구분하고 실제 연결 시험으로 표현하지 않는다.

구체 타입과 입력·응답 경계는 [등록 계약 검토](C04-registered-model-contract-review.md), [구조화 compact 검토](C04-structured-compact-contract-review.md)를 따른다. 구현 중 확인된 필수 차이는 이 문서에 기록한다.

## 구현 순서와 재사용

| 순서 | 변경 | 재사용할 부분 |
|---|---|---|
| A | 고정 지시문·candidate schema·응답과 usage 정규화를 가진 구조화 compact 어댑터 | 기존 구조화 모델 설정/응답 helper, SessionCompactCalls, SessionCompactor, 호출 장부 |
| B | 호스트 등록 타입·프로필 이름 조회·주 턴/compact 조립·생성/종료 수명·고정 로컬 예제 | StructuredAgentTurnAdapter, C01 프로필/저장소, 기존 명시 synthetic 분기 |
| C | compose의 선택적 입력/출력 예약 설정, CLI/Web 공통 등록 선택, 비밀 없는 모델 표시 | 기존 model-input-budget/profile, AgentTurnService, WorkflowRuntime, Workbench와 outbox |
| D | 등록된 로컬 전송으로 읽기→자동 compact→답변→재시작 후 다음 입력 검증 | 기존 실제 임시 담당 저장소와 세션 helper, 기존 창·현재성·출처 회귀 |

모델 설정 한도는 `composeRuntime`에서 일반 planning과 compact 전용 runtime 양쪽의 기존 생성자에 전달한다. 생략 시 기존 기본값을 유지하고 출력 예약을 자동 축소하지 않는다. 저장 데이터 의미 버전이나 작업 자원 장부는 바꾸지 않는다.

등록 오류·DB 열기 실패·후속 조립 실패에서 이미 연 모델과 저장소를 모두 정리한다. 한 정리 실패로 다른 정리를 건너뛰거나 최초 오류를 없애지 않는다. 임의 요청 actor의 제한을 제거해 실행 권한으로 바꾸는 기능도 넣지 않는다.

첫 흐름 검증에서 작은 문맥 창이 근거를 생략하면 기존 유한 합성 규칙이 재조회하지 못하는 점을 확인했다. 등록 예제의 `registered-1` 구현에 현재 적용된 고정 read 요청·근거 생략·허용된 `core.evidence.get` 계약을 모두 만족할 때 기존 근거 조회를 제안하는 규칙을 추가했다. 핵심 선택기나 원문 저장 방식을 바꾸지 않고, 원본 자료를 다시 수집하지 않는다. 일반 모델의 판단 능력으로 표현하지 않으며 읽기→자동 compact→저장 근거 재조회→답변의 원래 검증 범위를 유지한다.

## 필요한 검증

1. 등록 없음/잘못된 계약은 호출 전에 거절하고, C01 v1/v2 및 명시 synthetic 동작을 보존한다.
2. 구조화 compact의 추정과 실제 요청이 일치하며 지시문·schema 비용을 포함한다. 잘못된 도구 옵션·과대 입력은 송신하지 않는다.
3. 잘린 JSON·거절·모델 신원 불일치·응답 크기·usage null/누락/부분 값을 구분한다. 이미 발생한 사용량을 0으로 바꾸거나 자동 재호출하지 않는다.
4. 같은 등록 프로필에서 CLI 또는 HTTP 접수→호스트의 읽기 도구→구조화 compact→답변을 확인한다. 원문·현재 입력·반론/미해결 항목·개인 기억 경계를 보존하고 같은 세션으로 재개한다.
5. 예약 후 등록/템플릿 변경은 기존 입력 지문 검사로 막고, 이미 받은 응답은 원 호출·영수증으로 재개한다. status/history/GET은 모델 호출을 시작하지 않는다.
6. 변경된 조립·전송·표시 경계의 집중 시험과 관련 회귀, 타입·계층 검사, 고정 최종 소스의 필수 통합 검증 결과를 기록한다. 끝난 문맥 창 검증은 별도 역사 증거로 보존하며 이유 없이 재실행하지 않는다.

합성 전송의 통과는 연결·수명·출처 검증이다. 실제 모델의 판단·요약 품질·tokenizer 정확도, Windows native, PostgreSQL, Knox/사내 MCP는 완료로 표시하지 않는다. C04의 일반 입구를 통한 복합 반증/부분 재계획과 명시 목표 변경도 별도 잔여다. 이번 한 단위 이후 C04 잔여를 다시 좁혀 진행한다.
