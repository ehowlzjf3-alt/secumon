# C06 Web 알림과 작업 선택

현재 구현을 확인했다. `work_view_knowledge_changed`가 HTTP 403이어도 원인은 기억·출처의 현재성 검사 실패인데, 브라우저는 상태 코드만 보고 권한 오류로 표시한다. 조회 실패로 카드를 지운 뒤 목록은 ‘아직 업무가 없습니다’라고 안내하며, 기억 재선택/해제 후 업무 조회가 성공해도 이전 오류 알림을 정리하지 않는다. 페이지 재접속 시 선택 ID를 복원하는 코드도 없다.

최소 구현 계획:

- 알려진 원문/기억 현재성 오류 코드를 접근 오류와 구분한다. 확인할 수 없는 이전 본문은 계속 숨기고, 선택 업무 ID와 개인 기억 관리 동선을 유지한다. 서버가 세부 사유를 생략한 SSE unavailable은 기존 view API로 재확인한다.
- 업무 조회에 연결된 오류·연결 알림은 새 유효 snapshot을 받은 경우만 지운다. 명령 결과 알림과 기존 검토 의무는 임의로 해제하지 않는다. 기억 선택의 관리 조회가 실패하면 오래된 선택 기준으로 변경하지 못하게 한다.
- 같은 브라우저 탭·담당·지속 대화에 한해 선택 ID만 보관한다. 재접속 때 읽기 요청으로 다시 확인하며 본문/권한/CSRF/명령은 저장하거나 자동 재실행하지 않는다.

소유 범위는 `runtime/src/presentation/web/{client.ts,personal-memory.ts,view-state.ts,styles.css,index.html}`이다. 공통 API/코어 변경과 새 대규모 시험은 하지 않는다. Root가 최종 빌드를 담당하며, 상세 검증은 C06–C10 기능 구현 이후에 수행한다.

후속 검증은 기존 `web-view-state.test.ts`, `personal-memory-presentation.test.ts`, `web-server.test.ts`를 활용한다. 현재성 403과 접근 403의 문구 차이, stale 선택 해제/재선택 후 알림과 새 snapshot, 선택 전환 중 늦은 memory 응답, 같은 대화 재접속의 선택 복원, 다른 담당/대화와 만료 인증의 본문 비노출, SSE의 포괄 unavailable 후 재조회 및 보호된 이전 본문 비복원을 확인한다. 현재 통과 결과를 주장하지 않는다.

구현을 저장했다. 현재성 코드 판별, 해당 오류의 개인 기억 확인 버튼, 빈 목록과 조회 불가 상태의 문구 구분, 성공한 snapshot에 연결된 알림 정리, 선택 관리 조회의 순서 보호와 최신 basis 재조회, sessionStorage의 담당·대화별 선택 ID 및 브라우저 뒤로 가기 복원을 연결했다. `styles.css`는 기존 버튼 스타일로 충분해 수정하지 않았다. 공통 API/코어와 검토 의무 상태는 그대로다. 브라우저 저장을 사용할 수 없으면 현재 화면 선택만 유지하며, 다른 origin/탭/담당·대화로 선택 ID를 옮기지 않는다. 빌드·시험·브라우저 관측은 이 작업에서 실행하지 않았다.
