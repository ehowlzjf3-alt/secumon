# C10 초기 복원·보존 이력·설치 결과

2026-09-09 · checkpoint403 · 기준선 `3c6f86f29ae9b3e62171fb8468e552e3fbfa4c7a`

로컬의 명명된 설치·복원 인수와 관련 회귀 **69개**, NAS Linux의 해당 인수 **24개가 최종 코드에 대응해 통과**했다. 플랫폼 간 중복 실행을 합쳐 고유93개라고 세지 않는다. 전체 C10나 goal 완료 선언이 아니다.

초기 복원은 operation intent(복원 실행을 식별하는 기록), 원본 접근 차단 표식, 복원 시작 nonce(이번 복원을 구별하는 값)를 고정 경로 게시 전에 준비한다. 기존 native no-replace 이동으로 완성된 디렉터리만 게시한다. POSIX에서 원래 표식의 두 파일명이 남은 경우 기록된 동일 파일·바이트만 확인해 게시를 마친다. 임의의 기존 `.apply`나 복원 대상은 자동 채택하지 않으며, 게시 전 남은 임시 디렉터리는 보존한다. 공개된 정확한 복원 시작 디렉터리와 nonce는 재사용하고, 부분 복사본은 기존 보존·복구 절차를 따른다. 복원 완료와 후속 저장소 대사는 분리돼 있다.

초기 중단5개는 실제 파일 게시 경계의 callback/file-hook 예외 시험이다. 이번 단위의 실제 SIGKILL·전원 손실 시험으로 표현하지 않는다. 관련 기존 apply8개를 함께 확인했다. 무관한 디렉터리와 바이트는 같지만 다른 파일 객체의 거절을 포함한다.

보존 이력은 SQLite/file-journal에서 실제 로컬 전체 백업 → 원본 디렉터리 보존 → 복원 → 기존 담당 신원 재연결 → 실제 저장 파일 대사 → 다시 열기를 거친다. 현재 참조 목록에서 빠진 과거 명령·사건의 원영수증과 원문을 검증하고, 과거 명령 재사용·같은 사건 재전달·본문 충돌을 확인했다. 기존512개 사건 해시는 명시적인 시험 준비이며 새32개만 실제 접수했다. 544건 처리나 운영 용량 시험으로 세지 않는다. 재전달은 새 실행·모델·송신·중복 정산을 만들지 않는다.

설치는 macOS/Linux에서도 고정 native 파일을 필수로 검사한다. 후보 release의 일반 조회는 코드 실행 없이 파일 목록·원문을 검증한다. 명시 준비·설치·등록 때에는 기대 digest 확인 후 새 Node 자식 프로세스로 OS/CPU와 파일 API4·디렉터리 이동 API1을 검사한다. 검사 전후 바이트와 해시를 확인하며 이전 로딩 캐시를 재사용하지 않는다. 실제 패키지·오프라인 bundle에 포함된 파일과 설치본의 native 로딩을 검증한다.

검증 기록:

- 로컬 build1의69개 중66개 통과·3개 실패 원 로그를 보존했다. 기존 호환성 기대값에 `sessionCompact:null`이 빠져 있었고, 새 이력 fixture는 백업이 원래 제외하는 SQLite 공유메모리 파일을 비교했다. 실제 백업 뒤 이동 전 원본 상태를 기준으로 하고 정확한3개 `-shm` 경로만 맞췄다. DB·WAL·영수증·원문 검사를 유지했다.
- build2는 호환성1개 통과, 이력2개가 Buffer/Uint8Array 타입 차이로 실패했다. 바이트 비교를 같은 표현으로 맞춘 build3에서 이력2개가 통과했다. 최초66개+교정1개+이력2개를 재사용하며 반복 실행을 더하지 않은 고유69개다.
- 최종 컴파일2610개 중 build1 대비 시험 JS/소스맵6개만 달랐고 제품 컴파일 파일은 동일하다. 코어 타입·구조204개/위반0 결과를 재사용한다. 최종 source와 build 지문은 `checkpoint403-build3-pin.json`에 있다.
- NAS Linux x64는 별도 Node24.20.0과 격리 Rust1.93.1을 사용한다. Cargo 소스15개·잠금파일을 전후 대조했고 기존 캐시만으로 native 빌드·실제 로드/API 검사를 통과했다. 시스템 Node18과 이전 시험 자료는 유지했다. 초기 vendor 실패는 캐시에 없는 다른 플랫폼 의존성 때문이며, Linux 대상 빌드에 추가 다운로드는 필요 없었다.
- Linux build1/2도 로컬의 해당 소스·2610개 컴파일 지문과 일치한다. 초기24개 중21개 통과, 같은 이력 fixture2개와 설치 캐시1개가 실패했다. 이력 교정2개는 통과했다. 기본 사용자 캐시에 tarball이 없었고, 기존 별도 캐시에는 잠금 tarball18개만 있어 다음 시도는 package metadata 부재로 실패했다. 로컬에서 현재 lock의 공개 tarball18개·manifest18개만 선별하고 인증/쿠키 등 metadata를 제외한 새 캐시를 전송·대조한 뒤 설치1개가 통과했다. 네트워크 재다운로드와 이미 통과한 Linux21개 재실행은 없었다.

로컬/NAS 시험 후 소스·컴파일 지문이 모두 일치한다. 모든 관리한 빌드·시험은 종료됐고 NAS 격리 디렉터리를 작업 경로로 가진 프로세스0개를 확인했다. 전용 SSH 연결도 종료했다. NAS 시험 자료는 다음 통합 확인을 위해 격리 디렉터리에 보존하며 운영 배포로 표시하지 않는다.

로컬 소규모 백업은 SQLite42항목/569,284bytes와 file-journal58항목/458,147bytes다. 백업/복원은 각각 약202/194ms, 250/253ms였다. NAS 같은 자료는 약17/18ms, 14/39ms다. 원영수증·자료9건과 새32개 사건을 사용한 한 번씩의 합성 측정이다. 디스크 물리 I/O·실서비스 지연·운영 용량 보장은 아니다.

남은 최종 통합은 원자료·세션·기억·실행 기록 연결, 이미 구현된 기억 선택 만료/오류/재선택 UI 복구와 문서형 기억 약23.7초 지연이다. 선택 배치의 보관/누적 용량·복원 목표, 실제 PostgreSQL 이행·복원, native Windows 및 사내 MCP·Knox·외부 A2A는 별도 실제 환경 인수로 남는다. 실제 모델/API 시험 중단은 유지한다. 기존4GiB/파일1GiB/10만 항목 백업 한도와 PG 전달64MiB 한도를 변경하지 않았다.
