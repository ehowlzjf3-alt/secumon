# C05 개인 기억 원문 조회 재사용

2026-09-08 · checkpoint375 진행 중. 메인 프롬프트에 대한 직전 답변은 읽기 확인만 수행한 대화였으며 구현 진전으로 세지 않는다. 기준선 측정과 아래 변경으로 작업을 재개한다.

개인 기억은 원문 대화의 사본을 별도 사실로 만들지 않고 해당 담당·사용자의 발언을 참조한다. 읽는 중 원문이나 접근 조건이 바뀔 수 있으므로 이력 대조와 마지막 재확인은 필요하다. 같은 검사 안에서 이미 가져온 입력 기록과 업무를 한 번 더 읽는 부분만 줄인다.

1. 기존 전달 관측 스크립트를 새 파일로 복사하고 현재 build/source 확인과 임시 등록표를 적용했다. 과거 계측 파일은 보존했다. 변경 전 원문 검사4회, `state.get`12회·`session.input`12회·`session.history`4회를 확인했다. 실제 API·모델·도구 호출은0이다.
2. 사용자 이력/입력 기록 일치와 출처 정책 검사를 순수 함수로 공유한다. 일반 대화 조회는 기존 조회·pending·artifact 검사를 유지한다. 개인 기억의 한 검사에서만 최초 자료를 공유하고 새 이력 조회·마지막 업무/전체 입력 기록 비교를 유지한다. 호출 사이 캐시나 저장소 전용 기능을 추가하지 않는다.
3. 기존 기억·대화·compact 경계 시험과 새 결정적 경합 시험을 실행한다. 같은 관측 스크립트로 변경 후 호출 수와 논리 반환 바이트를 비교한다. 모델 토큰·실제 디스크 I/O·처리속도 개선으로 확대하지 않는다.
4. 병렬로 C03 복구 R04/R07와 C05 collection custody-only 일반 입구의 기존 검증 공백을 확인한다. 각 작업의 코드·시험·잔여를 구분해 기록한다. 모든 소스 작성이 멈춘 후 통합 빌드를 한 번 수행한다.

최종 결과·실행 지문은 검증 후 별도 기록한다. 현재 결과는 계획/변경 전 관측이며 C05 전체와 전체 goal 완료가 아니다.
