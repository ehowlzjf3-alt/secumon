# C02 지속 세션 첫 흐름 — 진행 상태

2026-09-07 · 첫 연결 단위의 Linux 검증·회수 완료 · 다음은 증분 문맥과 반복 compact

같은 담당·사용자의 세션에서 X 업무를 마친 뒤 프로그램을 다시 열어 Y를 요청하면, 실제 사용자 원문과 전달된 응답을 Y의 문맥으로 이어가는 경로를 구현하고 검증했다. 목표·근거·계획·실행 기록·자원 장부는 각 업무에 남는다. 현재 표면은 합성 예제로 동작하며 실제 모델 API를 호출하지 않는다.

자세한 설명과 검증 범위는 [구현 결과](C02-persistent-session-result.md), 착수 기준은 [첫 구현 계획](C02-persistent-session-plan.md)에 정리했다. 이 문서는 진행 상태를 확인하는 짧은 기록으로 유지한다.

## 구현한 연결

- C01 프로필의 담당 ID와 저장소 소유 검사를 재사용하고 `.secumon/channel.sqlite`에 세션 정보·입력 접수함·이력 참조·문맥 버전을 구분해 저장했다. 개인 장기기억은 별도다.
- 원문 접수 → 기존 작업 생성/명령 → 적용 확정 → 응답 전달을 공통 `SessionService`에 연결했다. 서로 다른 작업·대화 저장소는 기존 처리 영수증으로 중단 후 연결을 복구한다.
- 사용자 원문과 실제 응답 정본을 유지한다. 응답 본문을 세션 저장소에 다시 복제하지 않으며 로컬 응답 저장과 이력 참조는 같은 transaction으로 기록한다.
- 적용한 입력 기준을 작업·모델 입력·저장 프레임·복구·늦은 결과 검증에 포함했다. 새 입력은 기존 계획과 장부를 보존하면서 계획 재검토를 요구한다.
- 세션 head의 버전 검사와 과거 고정 범위 보존을 연결했다. 과거 X 문맥을 뒤늦게 만들어도 최신 Y의 head나 새 입력 위치를 되돌리지 않는다.
- 설치형 `secumon-agent work`와 담당용 Web을 같은 저장소·접수 경로에 연결했다. 원문, 이력, 새 세션, 추가 지시를 지원한다. 다른 담당·사용자·선택 세션의 업무는 섞지 않는다.
- Web 접속 쿠키/CSRF와 영속 대화를 분리했다. 접힌 기록 영역을 열 때만 이력을 읽는다. C01 세션 간 `attach`는 아직 거절하며 기존 비세션 경로는 유지한다.

## 다음 구현과 남은 조건

첫 단위의 문맥 한도는 최대 256개 이력·직렬화한 문맥 본문 64KiB다. 넘으면 서비스가 거절하고 원문은 보존한다. 반복 compact나 자동 의미 요약은 아직 구현하지 않았다. 현재 Web에서는 일부 용량 오류가 일반 실패로 표시될 수 있으므로 후속 compact에서 사람이 이해할 수 있는 안내도 연결해야 한다.

다음 작업은 [C02 세션 compact 계획](C02-session-compact-plan.md)의 증분 문맥·핵심 합의와 미완료 항목을 보존하는 반복 compact, compact 중 새 지시·취소·중단·재시작 검증이다. 이번 원문 이력·입력 기준·head 검사를 재사용한다.

개인 기억 선별과 파일·문서·PostgreSQL 어댑터는 C03, 범용 프롬프트·실제 모델은 C04, 마지막 업무 자동 선택·기술 용어 정리·Knox/전체 UX는 C06에 남는다. Windows native 설치·파일 경계·실제 실행과 호스트 임의 코드 격리는 C01 잔여다. **C01 전체·C02 전체·전체 goal은 아직 완료로 표시하지 않는다.**
