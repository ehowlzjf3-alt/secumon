# C07 게시판·아카이브 일반 입구 연결

2026-09-08. C06~C10 구현 우선 방침에 따른 실제 연결 단위다. C06의 구현/빌드 기록을 재사용하며 상세 시험은 반복하지 않는다.

게시판은 에이전트끼리 경험을 묻고 답하는 공간이다. 아카이브는 성공/실패 사례·대화·기존 시스템 자료를 조회하고 필요할 때 명시 등록하는 공급자다. 둘은 담당별 개인 장기기억이나 대화 이력의 자동 복사본이 아니다.

1. 기존 config.features.board/archive의 기본 false를 사용한다. 기능이 꺼져 있으면 등록 공급자를 열거나 도구를 추가하지 않는다. 켰는데 등록이 없으면 설정 오류로 설명한다.
2. 게시판은 기존 BoardRepository/BoardService/BoardCommands/BoardWatch 및 core 도구·의무·입력·결과 검사를 그대로 재사용한다. 호스트 등록을 일반 profile에 전달하고 명시 도구 허용 목록/쓰기 권한만 합친다. 공유 게시판 scope와 개인 담당의 저장 공간은 구분한다.
3. 아카이브는 기존 KnowledgeRecord가 업무 Evidence/세션 원문을 요구한다는 제약을 확인했다. 외부 문서에 가짜 업무 근거를 만들지 않도록 공급자 인터페이스를 둔다. 조회 전용/조회·등록 능력, 안정된 ID·출처 버전·경로, 중복 명령·정정·삭제를 표현한다. 재사용 가능한 파일 게시 primitive를 사용하고 기존 기억 엔진을 다시 만들지 않는다.
4. 모델 도구, CLI/Web/Knox는 같은 profile 조립을 사용한다. 아카이브 조회는 검증된 Evidence가 아닌 참조 자료로 반환한다. 에이전트의 명시 등록·정정·삭제 도구와 저장 확인을 연결하며 관리 API만 있는 상태를 모델 기능 완료로 기록하지 않는다.
5. 등록 리소스는 호스트가 소유권을 정하고 profile 종료에서 실행 정리를 거쳐 한 번 닫는다. profile 개설 실패도 기존 종료 경로로 정리한다.

이번에는 실제 제품 연결과 빌드/타입 확인을 수행한다. 비활성 기본값, 공유 권한, 읽기 전용 공급자, 직접 답변, 출처 버전/중복 명령, 재개·삭제, 실제 외부 공급자 연결은 별도 검증 목록에 유지한다. 최종 연결에 남은 부분은 구현 상태와 분리해 기록한다.
