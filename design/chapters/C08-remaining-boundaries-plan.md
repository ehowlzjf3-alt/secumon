# C08 분리 원장·접수 중단 잔여 인수

2026-09-08 · checkpoint379. 앞선 단위는 실제 C08 교정·선택199개와 관련47개의 소스별 검증·문서 저장·원격 main 일치 확인으로 진행했다. 현재 기준선은 `3d75c03`이며 [앞선 결과](C08-ordered-verification-result.md)의 통과 묶음은 이유 없이 반복하지 않는다. 전체 goal은 미완료다.

담당 세션은 살아 있고 개별 작업의 배정만 끝나야 한다. 따라서 반환은 기존 grant와 실제 사용량을 정산하는 일이며, 재배정은 정산 이후 원 후원자 한도 안에서 의도적으로 새 grant를 만드는 별도 판단이다. 반면 compact/reopen과 동료 접수 복구는 새 목표·grant·수신 작업으로 바꾸지 않고 원 기록을 이어야 한다.

- 반환·재배정: 실제 서로 다른 SQLite 담당에서 모델이 명시 반환을 선택하고 런타임이 진행 중 호출·미사용량을 정산한다. 중복 명령과 재접속은 원 반환 영수증·배정·사용량을 보존한다. 후원자가 재사용 가능한 자원 안에서 새 업무에 배정하며 상주 세션과 개인 기억을 닫거나 합치지 않는다.
- 활성 배정 compact: 실행 전 또는 진행 중인 grant를 유지한 상태에서 실제 ContextCompiler의 compact를 수행하고 담당을 다시 연다. 후원자·수신자의 목표, 원문, 원한도·deadline·주소·의무·영수증·사용량을 비교한다. compact 자체의 실제 비용은 별도로 정산되므로 전체 budget 숫자를 무조건 같은 것으로 단언하지 않는다.
- 동료 접수 중단: 수신 접수 성공과 발신 ticket 영수증 사이에 중단을 배치한다. 재개는 최초 request와 수신 input/작업/세션/ticket/예산을 재사용하고 추가 작업·답변을 만들지 않아야 한다. 실제 프로세스 중단과 주입한 오류는 구분해 기록한다.

고정 소스의 새 시험을 먼저 실행하고 실제 실패가 확인된 경우에 제품을 최소 교정한다. 기본 무진전3·문맥 창·하드 한도를 통과용으로 늘리지 않는다. 빌드·실행 handle과 결과는 `runtime/evidence/checkpoint379.json`에 저장한다. C09 준비 문서는 기존 시험·실제 일반 입구의 공백을 별도 조사하며 아직 실행한 것으로 표시하지 않는다.

압축 인수는 두 동작을 구별한다. 실제 세션 요약은 등록된 compact 어댑터와 `requestCompact → execute → adopt`로 게시하고, 다음 모델 입력에서 그 요약을 사용했는지 확인한다. `ContextCompiler.prepare(forceCompact: true)`는 작업 문맥 frame을 저장하지만 기준 head를 채택하지 않는다. 따라서 이 호출만 한 부분은 저장 frame·원장 보존 확인으로 기록하며 자동 압축 채택·복구 성공으로 확대하지 않는다. 기준 head를 시험이 직접 바꾸지 않는다.

사내 서비스·Knox·외부 A2A·실제 모델/API를 호출하지 않는다. 현재 Linux/native Windows·PostgreSQL·운영 품질은 로컬 SQLite/결정적 모델 검증으로 완료 처리하지 않는다. 끝난 단위는 코드·문서·증거·다음 행동을 함께 커밋하고 푸시한다.
