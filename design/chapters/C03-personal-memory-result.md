# C03 개인 장기기억: 명시 등록·회상·정정·잊기

2026-09-07 · 이번 사용자 흐름 구현 및 로컬·Linux 회귀 검증 완료 · C03 전체/전체 goal 미완료

개인 기억을 **지정한 발언에서 저장 → 같은 담당·사용자의 새 대화에서 검색 → 이번 업무에 사용할 기억 선택 → 정정하거나 잊기**로 연결했다. CLI/Web과 `core.memory.get/search`가 기존 KnowledgeService를 사용한다. 검색한 내용이 자동으로 현재 문맥이나 개인 기억에 들어가지는 않는다.

## 지금 구현한 동작

- **서로 다른 네 가지 저장 용도:** 원문 대화·요약은 대화 저장소, 목표·계획·자원·선택 참조는 실행 상태, 개인 기억은 memory SQLite, 큰 입력 프레임은 artifact 파일에 둔다. 같은 담당의 새 대화는 필요한 개인 기억만 선택하여 읽는다. 옛 대화 전체를 복사하지 않는다.
- **조직·담당·사용자 범위:** 개인 정본, 명령 receipt, 검색 색인, 캐시·의존성에 같은 범위를 적용한다. 기본은 담당별 SQLite이며 명시 등록한 공유 DB에서도 동일한 id가 다른 담당·사용자와 충돌하거나 보이지 않는다. 파일 자체의 OS 접근 격리는 별도 조건이다.
- **사용자 원문 출처:** 적용 완료된 사용자 입력의 receipt·대화 이력·정확한 문구·현재 권한을 확인한다. 사용자 발언을 외부 사실이 검증된 Evidence로 승격하지 않는다. 기존 Evidence JSON/해시는 변경하지 않는다.
- **실제 문맥:** 선택한 기억의 현재 버전과 출처를 검증해 ContextPacket과 저장 ContextFrame에 조합한다. 선택 상태에는 본문 대신 참조와 의존성을 둔다. 모델 호출·계획 채택·도구/결과 사용·복구의 현재성 검사에도 포함한다.
- **정정·잊기:** 정정은 새 사용자 원문을 적용한 뒤 버전을 올린다. 옛 기억으로 이미 준비한 입력과 지연 응답은 그대로 채택하지 못한다. 잊기는 활성 본문·인용을 비우고 재조회/검색/재사용을 막는다. 과거 원문 대화와 백업까지 물리 삭제했다는 뜻은 아니다.
- **중단과 정산:** 입력 적용과 기억 명령 ID를 구분한다. 응답 유실 뒤 같은 명령은 중복 저장하지 않는다. 사용한 모델 자원이나 미확정 외부 효과는 기억 변경을 이유로 지우지 않는다. 구버전 저장 이행은 한 트랜잭션이며 기존 JSON·receipt 값을 유지한다.

기억은 기본 5개·합산 8 KiB까지 명시 선택한다. 초과를 조용히 잘라내지 않는다. 데이터/권한 변경으로 낡은 파생 사본을 정리하더라도 별도 사용자 원문은 그대로 검증한다. 같은 업무가 자신의 원문에서 만든 기억을 읽는 순환 막힘을 피하면서 실제 접근 철회는 계속 차단한다.

## 검토 의무 수정

첫 관련 시험을 통과한 뒤 별도 검토에서 개인 기억 선택이 기존 업무 기억의 검토 의무까지 면제하는 결함을 발견했다. clear/recall 두 경로를 실제 실패로 재현하고, 이번 선택에서 새로 생긴 의무만 처리하도록 수정했다. 기존 의무와 완료 차단은 유지한다.

앞서 이미 생성된 검토는 기존 `runtime.command(..., {kind:'resolve', obligationId, reason})`로 이유를 제공해 해결한다. 에이전트·호스트가 쓰는 기존 명령이며 새 사람 승인 단계를 추가한 것이 아니다. 그 뒤에도 개인 기억 변경에 따른 계획 재검토는 별도로 필요하다. 원인별 검토 의무를 더 정밀하게 자동 해결하는 것은 후속 개선이다.

## 호출 비용과 화면에서 남은 점

단회 합성 자료에서 105 B짜리 개인 기억 한 개가 포함된 실제 packet은 3,547 B였다. 준비 과정에 state.get 256회, knowledge.get 69회, session.input 228회, history 75회가 관측됐다. 약92 ms는 이 개발 환경의 단일 관측이며 운영 지연이나 물리 디스크 읽기 횟수가 아니다. 반복 현재성 검증의 중첩을 줄일 여지가 있다.

같은 서비스의 동일 검색은 후보 조회1회에서0회로 줄었지만 원문·정본 검사는 유지했다. CLI/Web은 요청마다 좁은 권한의 서비스를 생성하므로 이 결과를 요청 간 공유 캐시 효과로 주장하지 않는다. 후속 C05는 검증 범위 안의 중복 읽기 제거와 마지막 소비 시 재검증을 함께 다룬다.

Web 관리 작업은 채팅 말풍선을 추가하지 않았다. 정정/잊기 직후 옛 선택이 유효하지 않으면 업무가 일시 조회 불가이고, 별도 기억 영역에서 최신 버전 선택/해제로 복구된다. 현재 화면은 이를 일반 권한 오류·빈 업무 목록처럼 표시하고 복구 뒤도 오류 문구가 남아 새로고침해야 사라진다. 업무 데이터가 삭제된 것은 아니며 C06에서 오류 원인·복구 상태 표시를 바로잡아야 한다. 재접속 시 선택 업무 자동 복원과 긴 내부 ID 표시도 남아 있다.
