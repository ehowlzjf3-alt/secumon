첫 단계는 [게시판 저장·권한·출처 결과](/Users/seunghanee/Documents/secumon/design/chapters/P4-board-foundation-result.md)에서 검증했다. 신규 43개, 관련 86/86, 전체 2,160/2,160 통과. 아래 두 번째 단계는 남아 있으며 P4-01 전체 완료가 아니다.

직전 챕터는 전체 2,117개 시험과 저장 응답 복원을 검증한 진전이다. 현재 작업 목록의 다음 항목은 P4-01이다. 새 코어의 현재 저장·권한·근거 계약을 사용하며 원래 시큐몬과의 동작 비교는 하지 않는다.

## 개념과 완료 결과

에이전트 ID는 실행 프로세스와 독립된 역할이다. 같은 역할이 재시작해도 같은 개인 관측과 담당 범위를 사용한다. 게시판은 검토 중인 관찰·가설·질문·반증·결정을 공유하는 공간이며 게시된 의견 자체는 새 Evidence나 조직의 확정 지식이 아니다. 개인 기억은 기존 KnowledgeService를 사용한다.

게시물은 작성 역할·업무·목표 개정·공유 대상·원 출처를 보존한다. 동료의 인용은 원 출처를 계승하며 독립 출처를 증가시키지 않는다. 원 근거가 정정·철회되거나 현재 권한이 없어지면 해당 게시물과 파생 인용은 현재 판단에서 제외한다. 본문은 설명이며 권한·라우팅·완료 규칙을 바꾸는 명령으로 실행하지 않는다.

질문을 올리는 것과 특정 동료가 책임을 수락하는 것은 구분한다. 요청·수락·응답 제출·요청자 확인·거절·취소와 기한을 저장한다. 응답이 왔다는 사실은 목표 완료와 다르다. 대화/요청 상한과 명시적 대기 관계로 반복·교착을 제어한다.

## 구현 순서

1. **협업 저장과 서비스:** 별도 저장 포트 뒤에 게시판 aggregate를 둔다. 주입한 인증 주체와 저장된 역할 권한을 교차 확인한다. 역할·entity는 호스트가 구성하며, entity는 조직/범위/유효기간을 포함한 명시 ID로 참조한다. 게시물·인용·질문 상태·멱등 명령과 CAS를 SQLite와 파일 저장으로 검증한다. 두 업무군·두 역할의 로컬 흐름, 공개하지 않은 개인 기억, 중복 출처·반증·철회·권한·재시작을 확인한다.
2. **런타임 연결:** 도구 목록의 선택 호출, 게시판 조회 의존성의 재검증, 기존 작업 의무·부모/자식 예산·제어 루프와 연결한다. 게시판 변화와 반증이 compact/reopen 이후에도 재조회·가설/계획 갱신으로 이어지고, 미해결 요청이 완료로 잘못 처리되지 않는지 확인한다. 도구용 조회는 범위/크기를 제한하고 출처별 coverage를 포함한다. 근거가 아직 없는 초기 가설도 명시적인 초안으로 표현하되 근거로 자동 승격하지 않는다. 기존 runtime의 동작을 복제하는 별도 에이전트 엔진을 만들지 않는다.

첫 단계만으로 P4-01 전체를 완료 처리하지 않는다. A2A 외부 프로토콜은 P4-02, 구독/상시 wake는 P4-03, 실제 모델의 협업 품질·비용 비교는 별도 평가로 남긴다. 기존 API 시험 취소를 유지한다.

## 검증 기준

- 같은 원본을 두 역할이 인용해도 독립 출처는 하나이며, 다른 값의 원 근거는 충돌로 남는다.
- 공개된 글을 근거 없이 확정 사실로 승격하지 않는다. 개인 기억·다른 조직·비회원·권한이 철회된 주체에게 내용을 노출하지 않는다.
- 수정/철회·원본 누락·만료와 역할 비활성화를 현재 조회에서 확인한다. 파생 인용도 함께 제외한다.
- 질문 게시와 수락을 분리하며 지정 상대만 수락/응답하고 요청자만 답을 확인한다. 만료·취소·대기 순환·메시지/요청 한도를 검사한다.
- 저장소 재열기·중복 명령·동시 CAS·저장 후 응답 유실에서 게시물과 의무를 중복 생성하지 않는다.
- 두 번째 단계까지 실제 runtime 실행/compact/reopen으로 연결한 후 P4-01 로컬 완료를 판단한다. 관련 시험과 native verify 결과, 아직 검증하지 않은 범위를 저장한다.
