# P2-05 모드·예산·무진전과 실행 평가

2026-09-05 · 착수 기준 v0.25 / 934개 로컬 시험

이전 단위는 증분 checkpoint와 조회 공유를 구현하고 동일 기준선 비용/의미 대조·검증·학습 기록을 남겼으므로 진전이다. 전체 P0–P6 목표를 유지하며 이번 챕터를 아래 순서로 구현한다. 실제 모델/API/사내 서비스 호출 중단도 유지한다.

## 현재 확인한 문제

Goal.mode는 저장되지만 실행 범위를 바꾸지 않는다. 모델/도구 예약·사용량과 work 전체 기한, 완료 검증·대기·취소·저장 응답 재개는 이미 있다. 모드를 바꾸려고 goal command를 사용하면 목표 revision과 재사용/checkpoint 원출처가 바뀐다. 별도 실행 제어가 필요하다.

무진전 장부는 없어서 같은 내용을 다른 task ID나 계획 문구로 반복하면 전체 예산까지 계속할 수 있다. 현재 fixture baseline은 checkpoint의 정적 기대 판정이며, 실제 누적 실행의 완료율이나 지연을 검증하는 harness는 별도로 만들어야 한다.

## 구현 순서와 완료 조건

1. **요청 모드와 실행 전략.** Goal.mode를 초기값으로 읽고 별도 revisioned ExecutionControl에 현재 요청 모드·정책·실제 전략·전환 이유를 저장한다. 기존 제어 루프를 사용하며 fast는 짧은 계획 구간/선택 탐색을 제한하고 auto는 검증된 계획 범위·반증·필수 미완료의 확장 필요에 따라 전환한다. deep도 이미 충분한 결과가 있으면 종료한다. 숫자 정책은 버전과 함께 저장한 로컬 평가용 값이며 실제 모델의 최적 기본값으로 주장하지 않는다.
2. **안전한 변경과 예산.** 별도 mode 명령에 owner/goal/control revision·idempotency를 적용한다. 실행 중 변경은 다음 안전한 배정 경계로 예약하고, 현재 실행의 결과/unknown 의무와 비용은 정산한다. 목표·근거·완료 task·checkpoint·사용량·총기한은 초기화하지 않는다. 명시된 work 상한과 mode 상한 중 더 좁은 값이 실제 새 예약을 제한한다. snapshot/CLI에 현재 모드·대기 변경·잔여/예약·미완료 사유를 보여주되 자동 전환마다 새 메시지를 내보내지 않는다.
3. **영속 진전·재시도.** 검증된 새 근거·반증·판별 평가·의무 변화와 단순 revision/문구/복사/replay를 구분한다. 결과/model 응답 정산과 진전 갱신을 같은 CAS에 저장한다. 새 실행에만 no-progress/failure/backoff gate를 적용하고 기존 결과 채택·복구·unknown 의무·완료 검사는 유지한다. 같은 의미의 호출을 새 task ID로 바꿔도 재시도 총기한이 늘지 않게 한다. 상태 조회·대기·compact·모드 변경은 무진전/기한을 초기화하지 않는다.
4. **부모/자식 예산 계약.** 부모의 예약/사용/미확정액과 자식에게 위임한 상한을 별도 원장으로 연결한다. 미확정 사용량을 가용 예산으로 되돌리지 않고 재시작·중복 정산·취소·부모 한도 하향을 시험한다. 저장소의 work 단위 CAS와 여러 work 사이 원자성을 구분하며 실제 자식 실행의 새 model/tool 예약 경계에 연결한다. 순수 계산 helper만으로 이 조건을 완료 표시하지 않는다.
5. **고정 실행 평가.** 같은 두 업무군·두 영속 backend에서 auto/fast/deep, 늦은 반증, 권한/자료 결손, 오류 반복, 다음 날 회신, 실행 중 변경/취소, 저장 응답 replay를 실행한다. 평가 manifest에 입력/기준/코드/정책/도구·지침·planner 버전과 실행 종류를 고정한다. scripted fresh 실행과 저장 artifact/receipt replay를 구분하고 replay는 실제 도구/model/sink 진입 0을 확인한다. 완료율/잘못된 완료·고유 조회/재조회·시도/채택·예약/사용/unknown·첫 유용 응답과 검증 완료 지연을 구분한다.

각 단위는 실제 경로에 연결한 뒤 의미 있는 정상·실패·경합·종료/재개 시험으로 검증한다. 이 전체 범위가 끝나야 P2-05 로컬 계약을 검증 완료로 표시하며, 실제 모델 품질/비용/운용 지연을 요구하는 선행 조건과 작업 전체 상태는 별도로 유지한다.

## 첫 구현 단위

첫 단위는 실행 제어 계약·mode 변경·공통 예약/계획 경계 연결과 영속 진전/재시도 기반이다. 모드와 목표/자료 identity를 분리하고 현재 모델/도구 호출을 폐기하지 않으면서 다음 배정을 제어하는 경계를 먼저 확인한다. 부모/자식 예산의 실제 위임 경계와 전체 실행 평가는 같은 챕터의 후속 필수 단위로 남기며 생략하지 않는다.

핵심 회귀는 fast의 숨은 승격/거짓 완료 거부, auto의 근거 있는 확장, deep의 조기 완료, 상태 조회의 호출·상태 변경 0, mode 변경 후 완료 task/원출처 재사용·영속 조회 재개 보존, late reply 정산, 반복된 같은 결과/새 ID/compact로 무진전 우회 불가, 대기/backoff 동안 새 호출 0이다. 기존 934개 의미/원본/비용 비교 조건을 별도로 유지한다.

## 학습 질문

모드를 바꿨는데 왜 목표 revision을 바꾸면 안 되는가? 같은 증거를 새 ID로 다시 가져온 것은 진전인가? 빠르게에서 깊게로 바꿨다고 남은 예산이 처음으로 돌아가면 어떤 일이 생기는가? 다음 날까지 기다리는 동안 모델이 계속 호출될 이유가 있는가? 각 질문을 코드의 저장 상태와 실행 기록으로 확인한다.

## 구현 중 확인한 구체 정책

- auto는 사용자가 요청한 work 총예산을 사용한다. fast의 도구 2회·모델 2회·추가 재계획 0회 같은 절대 상한은 명시적인 fast에만 적용한다. 오류나 대기만으로 auto를 승격하지 않는다. 이 값은 버전 있는 로컬 시험 정책이며 실제 모델의 최적값을 뜻하지 않는다.
- 검증된 새 도구 카드·정확한 schema·지침 manifest/body의 첫 로드는 준비 진전으로 기록한다. 같은 내용의 검색어·cursor·ID 변경과 과거 호출/근거 재조회는 새 진전이 아니다. 준비 진전은 완료 조건을 충족하는 근거로 사용하지 않는다.
- 진전/실패의 중복 방지 원장은 정본 상태에 보존하고 모델 context와 재개 packet에는 작은 집계만 넣는다. 모드·compact·resume은 원장을 초기화하지 않는다.
- 모델 의미 digest는 새 형식에 현재 모드/전략/정책을 포함하되 예약된 모드 변경은 제외한다. 예전 저장 호출의 digest 형식도 구분해 진행 중인 응답을 보호한다.
