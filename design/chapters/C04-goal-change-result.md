# C04 같은 업무의 명시 목표 변경 — 결과

2026-09-07 · 같은 업무의 목표 변경을 일반 CLI/Web에 연결하고 검증했다. macOS Node24 변경 범위 **57/57**·관련 **249/249**, NAS Linux Node24 전체 **3,284/3,284**와 필수 8단계를 같은 소스로 통과했다. 원 로그 9개 회수와 전용 시험 프로세스 감사·SSH 종료까지 확인했다. C04 전체와 전체 제품 구현의 완료는 아니며 실제 모델/API 시험은 중단 상태다.

사용자는 같은 담당·대화·업무에서 목표를 명시적으로 바꿀 수 있다. 예를 들어 자료를 읽은 업무를 문장 작성으로 바꾸어도 이전 원문과 근거를 버리고 새 업무를 만들지 않는다. 추가 설명은 `followup`, 새 업무는 `ask`, 기존 목표 교체는 `goal`로 구분한다. 모델이 자연어를 해석해 목표를 임의로 교체하는 기능은 아니다.

## 연결한 동작

- **원문을 먼저 보존한다.** `AgentTurnService.changeGoal`이 기존 `SessionService.command`로 원문과 명령을 접수하고, 기존 업무 명령 경로에서 새 목표를 적용한다. 목표 버전은 1 증가한다. 담당·사용자·세션·업무 범위와 권한은 호스트가 검사하며, 요청자가 임의 정책이나 완료 조건을 주입하지 않는다.
- **같은 요청은 처음 저장한 기준으로 재개한다.** 같은 메시지 ID·원문·버전으로 재전송하면 처음 고정한 명령과 영수증을 재사용한다. 영수증은 접수·적용 여부를 확인하는 기록이다. 현재 모드나 최신 입력으로 명령을 다시 만들지 않는다. 접수 후 또는 업무 적용 후 중단도 기존 복구 경로를 사용한다. 같은 ID의 다른 내용은 충돌이다.
- **새 입력과 경합하면 덮어쓰지 않는다.** 목표·제어 버전과 마지막 적용 입력의 ID·순번·내용 지문, 정책 지문을 저장 직전 다시 비교한다. 편집 중 후속 입력이나 실행 방침이 바뀌면 변경을 거절한다. 이미 수신한 원문과 거절 사유는 남는다.
- **옛 결과와 새 목표를 구분한다.** 이전 답변·도구 시도·근거·대화 기록은 이력으로 보존한다. 새 답변은 현재 목표와 입력, 원문·근거·모델 응답의 현재성 검사를 통과해야 한다. 이전 목표의 계획은 새 답변의 필수 작업으로 검사하지 않지만 실행 중인 시도와 효과 확인·정산 의무는 별도로 계속 검사한다.
- **이전 목표의 모델 질문만 대체한다.** 원 모델 호출과 목표 버전을 확인한 질문 의무만 새 목표에 의해 대체되었다고 기록한다. 질문 원문은 남으며 다른 자료 수집·게시판·자원 정산 의무를 일괄 면제하지 않는다.

완료된 업무는 새 목표로 다시 준비 상태가 될 수 있다. 취소·실패한 업무를 임의로 되살리지는 않는다. 기존 실행 루프, 모델·도구 취소, 예약 반환, 실제 사용량 정산과 결과 전달 검사를 재사용한다.

## 원문·컴팩트·한도

컴팩트는 작업 문맥을 요약해 줄이는 과정이다. 목표 변경 원문이 요약 구간에 들어가 현재 원문 구간에서 빠져도, `agentTurnRequestCurrent`는 저장된 접수 기록과 `SessionOriginals`의 원문을 조회한다. 적용된 `goal` 명령인지, 이전·새 목표 버전과 원문·범위·응답 요구가 맞는지 확인한다. 일반 후속 입력이나 거절된 명령을 새 목표의 원문으로 인정하지 않는다. 이를 재접속 뒤 답변까지 잇는 시험이 이번 로컬·Linux 변경 범위와 Linux 전체 통합에서 통과했다.

목표 변경은 **원래 자원 한도, 이미 쓴 사용량, 마감 시간**을 초기화하지 않는다. 현재 `fast`의 모델 호출 상한 2회는 같은 업무 전체의 상한이다. 자료 읽기에 계획·답변 2회를 사용했다면 목표를 바꾸어도 빠른 모드의 추가 호출은 차단된다. 명시적으로 `auto`로 바꾸면 실행 방식의 상한은 바뀌지만 원래 업무에 남은 자원만 사용할 수 있다.

build3의 좁은 합성 진단에서는 SQLite와 파일 저널 모두 호출 수가 `2 → 2(차단) → 3(auto 완료)`였고, 원래 한도와 마감이 유지됐다. 문장 교정 후 직접 설명은 `fast`에서 `1 → 2`로 완료됐다. 이는 유한 합성 요청의 실행·정산 관측이며 실제 모델 품질 검증이나 새 시험 묶음의 통과를 뜻하지 않는다. [진단 원기록](../../runtime/evidence/C04-goal-cli-fast-diagnosis.json)

## CLI와 Web

| 항목 | CLI | Web |
|---|---|---|
| 목표 변경 | `chat goal`에 업무·메시지 ID, 목표·제어 버전, 원문을 전달 | 일반 요청의 목표 편집 화면에서 변경 원문을 접수 |
| 입력 기준 | 최초 명령 접수 시 현재 적용 입력을 고정 | 편집 시작 시 조회한 입력 기준을 제출해 편집 중 변경을 감지 |
| 실행 | 처음 생성된 요청은 접수 안내 후 새 목표 버전으로 실행 | 접수 안내 후 별도의 ‘실행’을 유지하며 접수 자체로 모델을 호출하지 않음 |
| 재전송 | `created: false`, 새 실행 없이 현재 상태 표시. 필요하면 명시 `resume` | 같은 요청 ID·원문으로 재전송. 접수와 실행 ID의 충돌도 영속 기록으로 거절 |
| 모드 | 생략하면 최초 접수 당시 모드를 유지 | 편집 기준의 현재 또는 대기 중 모드를 고정 |

Web의 `run`과 `request-goal`은 같은 업무 영수증 ID를 저장 버전 비교(CAS)로 고정한다. CAS는 예상한 저장 상태가 여전히 같을 때만 반영하는 검사다. 동시에 다른 명령이 같은 ID를 사용하면 하나만 차지한다. 목표 변경 원문을 포함한 의도를 먼저 업무 이벤트에 저장하므로 세션 접수 전 중단도 같은 요청으로 복구한다. 기존 세션 영수증만 있는 과거 형식의 재전송도 보존한다.

CLI 명령과 상태의 두 버전 번호는 [사용 설명](C04-goal-change-cli-usage.md)을 따른다. 실제 localhost HTTP와 화면 상태 함수 시험은 통과했다. 실제 브라우저 조작은 Mac 잠금으로 실행하지 못했고, 임시 합성 서버·담당을 종료·삭제했다. [브라우저 시도 기록](../../runtime/evidence/C04-goal-browser-attempt.json). HTTP 결과를 화면 렌더링 검증으로 표시하지 않는다.

[new1](../../runtime/evidence/C04-goal-new1.log), [new2](../../runtime/evidence/C04-goal-new2.log), [new3](../../runtime/evidence/C04-goal-new3.log)의 실패 로그는 당시 결과로 보존한다. new3에서는 코어·Web 회귀가 통과했고 CLI 3개와 컴팩트 시험 1개가 실패했다. 교정 뒤 build4/new4 57/57·related1 249/249·코어 타입·계층 158파일/위반0이 통과했다. 같은 소스를 NAS에서 빌드하고 변경 범위 57/57·관련 249/249·전체 3,284/3,284, 코어 타입·계층·CLI fixture·시나리오 판정을 통과했다. 첫 실패 기록은 이 성공으로 덮어쓰지 않았다.

필수 인수는 [목표 변경 계획](C04-goal-change-plan.md)에 따른다. 회귀 파일은 [입력·복구](../../runtime/src/tests/agent-goal-change.test.ts), [CLI](../../runtime/src/tests/agent-goal-change-cli.test.ts), [컴팩트](../../runtime/src/tests/agent-goal-change-compact.test.ts), [HTTP](../../runtime/src/tests/agent-turn-web.test.ts), [화면 상태](../../runtime/src/tests/web-view-state.test.ts)에 있다. 앞선 등록 모델의 Linux 3,253개 통과는 과거 소스의 근거이며 이번 변경의 Linux 통과가 아니다. [복합 조사 로컬 결과](C04-complex-turn-result.md)의 새 인수도 이번 Linux 변경 범위와 전체 시험에 포함했다. 복합 조사 자체의 이전 소스·증거는 그대로 보존한다.

실제 모델의 자유 문장 이해·요약·목표 변경 후 답변 품질, native Windows, PostgreSQL, 사내 인증·도구·Knox 연결은 이번 로컬 연결로 검증되지 않는다. C04 전체와 전체 구현 goal의 완료를 선언하지 않는다.
