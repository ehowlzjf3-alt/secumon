# 최종 로컬 통합 확인 결과

2026-09-09 · checkpoint404 · 기준 커밋 `d4144a31b418bb0113d22de416b279272dc60b31`

남았던 세 로컬 흐름을 확인했다. 원자료·세션·개인기억·실행 결과의 연결, 기억 선택 오류 후 실제 웹 화면 복구, 문서형 기억 조회의 반복 비용 개선이다. 관련 macOS 시험 61개와 동일 HTTP 흐름 계측 1개가 통과했고, NAS Linux에서는 파일 접근 변경에 관련된 17개가 통과했다. 플랫폼 사이 중복을 더해 고유 79개로 세지 않는다. 전체 시험은 다시 실행하지 않았다.

## 변경과 재사용

제품 변경은 `document-knowledge-owner.ts`의 디렉터리 참조 재사용이다. 인스턴스당 최대 64개를 보관하며, 매번 현재 scope·경로·접근 권한·파일 객체 동일성을 확인한다. 생성은 기존 게시·동기화 경로를 사용한다. 미존재 결과는 보관하지 않고, 교체된 디렉터리는 자동 채택하지 않는다. 종료하면 참조를 비운다. Windows에서는 기존 scope가 소유한 handle과 native 확인을 그대로 사용한다. Windows 실제 실행 증거는 이번에 추가하지 않았다.

원문 내용이나 검증 성공을 요청 사이에서 재사용하지 않는다. 기존 전체 snapshot 3회·동일 벡터 2회와 출처·권한 확인을 유지한다. 기록 연결과 웹 복구 기능은 기존 구현을 재사용했고, 새 제품 흐름을 만들지 않았다.

## 원문부터 결과까지

새 `agent-final-record-links.test.ts`는 SQLite 상태+문서 기억, 파일 저널 상태+SQLite 기억에서 같은 HTTP 업무 흐름을 실행한다. 최초 사용자 입력과 접수 영수증 → 개인기억의 원문 출처 → 후속 업무의 명시 선택 → 저장된 모델 입력/응답 → 도구 원결과와 채택 → 최종 답변·전달·세션 기록의 실제 바이트·해시·식별자를 대조했다.

profile을 닫고 다시 열어 원문·영수증·답변을 재조회했다. 완료 요청의 재전달은 모든 기록을 보존했고 추가 모델·도구 호출은 0이었다. 개인기억은 도구가 수집한 독립 근거로 승격되지 않으며, 다른 담당의 기억은 모델 입력에 포함되지 않았다. 이 시험의 모델은 고정 합성 제공자이며 실제 모델/API 품질 증거가 아니다.

## 기존 웹 화면의 복구

실제 내장 브라우저와 loopback HTTP 서버에서 다음을 확인했다.

| 행동 | 실제 관측 |
| --- | --- |
| 다른 정상 연결에서 선택된 기억의 버전 변경 | `기억·원문 재확인 필요` 안내와 실행 버튼 비활성화. 빈 업무나 권한 오류로 표시하지 않음 |
| 최신 버전 검색 후 `이번 업무에 사용` | 버전 2를 선택하고 같은 업무의 실행 대기 화면 복원 |
| 다시 버전 변경 후 `이번 업무 선택 해제` | 오류 해제, 선택 목록 비움, 장기기억 버전 3 유지 |
| 서버 측 실제 제한 actor로 조회 | `work_view_denied`와 현재 연결의 권한 오류 표시 |
| 정상 actor 복원 후 새로고침 | 같은 업무와 실행 제어 복원 |
| 같은 origin에서 HTTP 서버 재개, 같은 탭에서 새 문서 로그인 | 업무를 다시 누르지 않아도 저장된 선택 업무 복원. 상태 revision 6 유지 |

화면 시험 전체에서 사용자 원문 1개가 유지됐고 모델·도구·예산 사용은 0이었다. HTTP 서버 재개를 OS 프로세스 장애나 전원 손실 복구로 해석하지 않는다. profile 종료·재개는 별도 기록 연결 시험에서 확인했다. 기존 정상 저장·완주 화면은 checkpoint402 결과를 재사용한다.

초기 stdin이 닫힌 fixture 실행은 바로 종료되어 인수에 사용하지 않았다. 실제 화면은 PTY로 유지한 fixture에서 확인했다. 첫 축약 텍스트 선택자가 일치하지 않아 화면에 표시된 복구 버튼으로 패널을 열었다. 같은 문서의 fragment 이동만으로는 로그인 초기화가 다시 실행되지 않아, 같은 탭에서 `about:blank`를 거쳐 새 로그인 문서를 로드했다. 중간 화면까지 DOM 기록에 보존했다. 인증 token은 증거 파일에 저장하지 않았다.

## 비용 측정

같은 기존 HTTP 업무 흐름을 같은 계측기로 실행했다. 대상은 모델 3회·도구 단계가 포함된 합성 업무의 로컬 처리 시간이며, 단순 검색 1회의 시간이 아니다.

| 구성 | 변경 전 | 변경 후 | 디렉터리 검사 호출 |
| --- | ---: | ---: | ---: |
| SQLite 상태 + 문서 개인기억 | 23.132초 | 13.317초 | 6,601,410 → 3,568,230 |
| 파일 저널 상태 + SQLite 개인기억 | 4.069초 | 4.026초 | 121,052 → 121,052 |

문서 구성에서 관측 시간은 약 42.4%, 디렉터리 검사 호출은 약 45.9% 줄었다. 문서 저장소 조회 1,845회, 파일 데이터 read 81,180회, 읽은 10,811,700bytes와 다른 논리 호출 수는 같았다. 새 디렉터리 시험은 재사용 시에도 같은 원문 읽기량, 현재 권한 변경, 같은 경로의 다른 객체 거절, 생성·미존재·종료 처리를 확인했다.

이는 한 번씩의 로컬 계측이다. inclusive 메서드 시간은 서로 더하지 않으며, 호출 수는 물리 디스크 I/O가 아니다. 13.3초의 남은 비용과 파일 저널의 누적 원문 검증 비용은 그대로 공개한다. 운영 응답 시간·동시 사용자·장기 보관량 목표 충족을 주장하지 않는다.

## 전체 요구와 남은 항목

[요구 대조](final-integration-audit.md)에서 C01–C10의 기존 명명된 로컬 인수를 현재 구현과 후속 결과에 연결했다. 이 범위에서 추가 로컬 미구현·미실행 사례를 찾지 못했다. 과거 각 빌드의 시험 수를 현재 소스 전체의 검증 수로 합산하지 않았다.

native Windows, 실제 PostgreSQL 이행·복원, 사내 MCP/Knox/외부 A2A와 비계측 사내 앱의 컴퓨터 유즈, 선택한 운영 규모·보관·복원 목표는 [남은 확인 목록](../REMAINING-ACCEPTANCE.md)에 유지한다. 실제 모델/API 시험은 사용자의 중단 결정을 유지한다. 이번 로컬 단위 완료를 전체 goal이나 실운영 준비 완료로 표시하지 않는다.
