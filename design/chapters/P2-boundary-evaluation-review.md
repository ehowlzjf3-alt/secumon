# P2-06 정보 경계 비교와 회귀 검토

2026-09-06 · 독립 설계 검토 · 합성 계약의 제안이며 구현/실행 결과 아님

[정보 경계 대안](/Users/seunghanee/Documents/secumon/design/05-data-boundary-options.md)의 A(외부 리드와 공개 게이트), B(전체 내부), C(내부 관리자와 제한 자문)를 같은 업무 계약으로 비교한다. 이번 검토는 실제 모델·서비스·키에 접근하지 않았고 제품 코드나 빌드를 변경하지 않았다. 전체 P2-06의 조직 배치 정책 결정은 합성 회귀와 별도 완료 조건이다.

## 1. 현재 재사용할 경계와 남은 차이

[Policy](/Users/seunghanee/Documents/secumon/runtime/src/domain/model.ts:33)는 주체/조직, 허용 labels, tools, destinations, 쓰기 여부를 가진다. 현재 [모델 예약과 진입](/Users/seunghanee/Documents/secumon/runtime/src/application/planning-runtime.ts), [원본과 과거 호출 접근](/Users/seunghanee/Documents/secumon/runtime/src/application/work-resources.ts), [전달 직전 검사](/Users/seunghanee/Documents/secumon/runtime/src/application/outbox.ts)를 재사용한다. 단순히 labels와 destinations가 각각 허용 목록에 있다는 것만으로는 특정 등급을 특정 목적지로 보낼 권한을 뜻하지 않는다.

[구조화 planner](/Users/seunghanee/Documents/secumon/runtime/src/infrastructure/structured-planner.ts)는 고정 지침과 strict proposal 계약을 사용하고 packet/options를 복사·동결한다. 기존 시험은 지침 포함과 수정 거절을 확인한다. 이것이 LLM의 지침 준수를 증명하지는 않는다. 하위 자료가 만든 제안도 최종 plan validator·tool broker·목적지 게이트의 같은 권한 검사에 들어가야 한다.

[컨텍스트 구성](/Users/seunghanee/Documents/secumon/runtime/src/application/context-packet.ts)은 work의 읽기 정책으로 원문 사실·참조·과거 입력/결과를 포함한다. 이를 외부 모델 전송 권한으로 확대해서는 안 된다. 사람은 내부 원문을 읽을 수 있어도 대화 모델·메신저 서버·로그 목적지가 그 원문을 받을 수 있는지는 각각 결정한다. `local` 문자열은 프로세스·네트워크 격리의 증거가 아니다.

## 2. 합성 비교에서 주장할 것

| 비교 항목 | 이번에 검증 가능한 사실 | 실제 모델/배치 없이는 주장할 수 없는 것 |
| --- | --- | --- |
| 정보 가용성 | 허용 사실/관계/원본 참조가 각 역할 입력에 남았는지, 필요한 정보가 누락되면 보류하는지 | 같은 실제 판단 정확도, 반증 발견률, 자유언어 의미 보존 |
| 경계 통과 | 최종 요청/전달에서 금지된 합성 값과 필드가 없는지, 금지 경로의 transport 진입이 0인지 | 임의 자연어·이미지에서 완벽한 비밀 제거, 실제 네트워크 우회 차단 |
| 호출 효율 | 내부 분석/외부 자문/재질의/게이트 거절 각각의 실제 대역 진입 수와 직렬화 bytes | 모델별 실제 토큰·금액·운영 지연 우열 |
| 재개 | 저장된 공개 내역/정책·출처 버전/unknown이 재시작·compact 후 유지되는지 | 조직 전체 배치의 원자적 정책 철회 |
| 누적 공개 | 같은 사건/주체/목적지의 공개 집합과 명시한 조합 금지·상한을 지키는지 | 측정하지 않은 추론 경로나 재식별 가능성이 0이라는 보장 |

세 대안에 같은 원본, 현재 권한, 공개 규칙, 필요한 사실의 독립 oracle을 고정한다. A/B/C라는 이름을 보고 scorer가 성공을 주거나 planner가 예상 답을 읽어서는 안 된다. A/C의 정보 부족으로 내부 재질의 또는 보류가 발생하면 이를 정보 부족으로 보고한다. scripted resolver가 정답을 제공한 결과는 계약상 완료이지 모델 정확도 측정이 아니다. 공개를 전부 차단하여 누출 0을 얻은 사례는 허용된 과제를 완료한 사례와 분리한다.

A는 외부 리드가 공개 view와 제한된 내부 질문 계약만 받고 원문 읽기 capability를 받지 않아야 한다. B는 내부 리드가 주체 권한에 맞는 원문을 받을 수 있지만 외부/타 주체 전달에는 같은 공개 게이트가 필요하다. C의 외부 자문은 원문과 실행 capability를 받지 않으며, 자문 응답은 내부 관리자가 검토할 자료다. 외부 자문의 주장 자체로 근거·권한·사용자 승인·완료를 생성하지 않는다.

## 3. 필수 회귀 행렬

두 기존 업무군(문서 비교/관측 검토)을 유지한다. 모든 축의 기계적 전수 조합보다 실제 출구와 재개 경계를 충족하는 coverage 표가 우선이다. 서로 다른 저장소를 지원한다고 표시하려면 SQLite/파일 저널 각각에서 실제 저장·reopen을 관측한다. 순수 함수 결과만 비교한 경우에는 이를 영속 실행 평가로 표시하지 않는다.

| 경계 | 합성 입력/변경 | 필요한 단언 |
| --- | --- | --- |
| 정상 공개 | 공개 허용 사실과 제한 원본을 함께 제공 | A/C에는 허용한 주장·관계·사건 범위 가명만, B의 허용 내부 원문 유지. 업무 필수 사실 누락도 독립 검사 |
| 전체 전송 표면 | 원문, summary, 검색 제목/미리보기/locator, tool schema/description/output/error, guidance, compact, artifact metadata, 이미지 대체문/bytes, 채널 text/attachment, 로그에 각기 다른 합성 표식 | 최종 직렬화 outbound에서 금지 값/필드 0. 검사하지 않은 표면을 보장 범위에서 제외 |
| 주체와 목적지 분리 | 같은 문서: 내부 사용자 허용, 외부 대화 모델 금지; 같은 역할명인 타 주체/타 조직 | 역할명으로 권한 상속 없음. 모델과 사람 각각의 정책 검사. 금지 transport 진입 0 |
| 출처와 공개 규칙 결합 | 요청 payload가 등급/출처/공개 완료 표식을 임의 변경; 원본 교체/삭제; 허용 필드를 모르는 경우 | canonical 원본·규칙 버전으로 검사. 요청의 자기 선언으로 공개 승인 없음. 미정/불명은 보류 |
| 전송 직전 변경 | 원본 read 또는 공개 준비 후 권한·목적지·공개 규칙 변경 | 실제 I/O barrier 이후 fresh 검사를 수행하고 금지 진입 0. 오래된 캐시/저장 요청은 허가서가 아님 |
| 재시도·폴백 | 첫 전송 실패/unknown 뒤 다른 목적지 또는 같은 요청 재전송 | 새 목적지에 별도 판단. unknown 공개 내역을 지우지 않음. 반복 예산/공개량 초기화 없음 |
| 지시 승격 | 도구/A2A/검색/지침 본문이 goal/policy/사용자 승인·system 역할로 해석되기를 요청 | authenticated command 필드 불변, 별도 data 출처 보존. strict proposal의 금지 구조 거절. 허용 형태의 잘못된 실행 제안도 broker/validator로 거절 |
| 자문/파생 결과 | 자문이 추가 원문/권한 또는 증거 없는 완료를 제안; 제한 자료 summary를 public이라고 자체 표시 | 자동 권한 변경·원본 전송·근거 생성 없음. 파생 출처/등급을 유지하고 명시적 공개 규칙만 적용 |
| 공개 누적 | 각 요청은 허용이나 두 필드 조합은 금지인 fixture, task ID/대화 ID 변경과 compact/reopen | 정책에 정한 집계 scope에서 결합 검사. 단일 payload만 검사하여 누적 노출을 놓치지 않음 |
| 감사와 거절 | 게이트 거절과 예외 자체에 합성 비밀 포함 | 외부/일반 로그는 정해진 code와 opaque 참조만. 제한 내부 감사 저장과 사용자 표시의 목적지 분리 |

합성 표식의 부재만으로 통과시키지 않는다. destination별 strict 스키마/허용 필드, 원본 참조·주체·revision, 실제 adapter 진입, 필요한 허용 정보의 존재를 함께 검사한다. 빈 출력도 표식 검사에는 통과하므로 정상 공개 대조군이 필수다. 잘못된 게이트 대역을 주입했을 때 독립 scorer가 의도대로 실패하는 부정 대조를 포함한다.

프롬프트 지시 승격의 합성 검증은 구조적 권한 불변과 제안 검증의 강제에 한정한다. 모델이 부적절한 문장에 전혀 영향받지 않는다는 의미적 저항성은 미검증으로 남긴다. 내부 원문을 모델에 준 경우 그 응답도 입력 출처의 경계를 따르는 것이 기본이다. 요약이라고 해서 자동으로 공개 자료가 되지 않는다.

## 4. 기록과 최종 판정

기존 [실행 평가](/Users/seunghanee/Documents/secumon/runtime/src/domain/execution-evaluation.ts)의 fixture/code/build/config/environment pin과 독립 scorer 방식을 재사용하되 공개 규칙 버전, 목적지별 모델 배치, 대상 주체, 출처 버전, 공개 내역 scope와 한도를 추가로 고정한다. 최종 전송 요청의 bytes/hash와 gate 판단 이유를 기록하고, 일반 결과물에는 합성 표식 외 실제 원문을 남기지 않는다.

통과 수/전체 예정 수/실행 수/미실행 수, 정상 허용 중 성공 수, 금지 요청 중 차단 수, 허용 요청 오거절 수, 잘못된 완료 수를 따로 보고한다. 호출 수는 내부/외부/게이트·재질의로 분리하며 bytes와 fake usage, 실측 wall time과 합성 시간을 구분한다. 개인정보 재식별·조직 보존 정책·실제 endpoint 제한·실제 모델 의미 정확도는 별도 미검증 항목이다.

학습 결론은 **읽기 권한, 파생물의 출처, 전송 권한, 명령 권한은 서로 다르다**는 것이다. 이번 구현의 완료는 검증한 로컬 계약 범위로 기록하고 A/B/C 채택과 조직의 실제 분류·주체·모델 목적지·보존 정책 결정은 사용자의 선택에 남긴다.
