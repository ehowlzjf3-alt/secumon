# C07 게시판·아카이브 로컬 인수 계획

2026-09-08 · checkpoint377. 이전 checkpoint376은 `69f84d5`의 코드·로컬 인수16개·문서·원격 main 일치 확인으로 진행했다. 전체 goal은 미완료이며 실제 모델/API 시험 중단을 유지한다.

게시판은 담당 사이의 질문·답변과 명시 요청을 연결하고, 아카이브는 기존 사례와 원문을 찾는 선택 공급자다. 둘을 읽었다는 이유로 개인 장기기억이나 독립 근거를 자동 생성하지 않는다. 각 담당의 세션·업무·기억 저장소는 유지하며 공유 원문은 호스트가 명시 등록한 출처에서만 확인한다.

- 기존 게시판 저장·원문·명시 요청·알림 시험을 현재 배포되지 않은 로컬 빌드에서 재사용한다. 자원 후원은 C08 범위에 둔다.
- 호스트 등록: 두 기능 off의 일반 CLI 연속 대화, on+미등록 오류, 허용 도구·쓰기 권한·공급자 능력, 담당 신원과 등록 수명을 확인한다.
- 독립 담당: 서로 다른 디렉터리·DB·scope에 같은 게시판만 연결해 일반 입력과 관측한 ID로 질문·답변을 진행한다. 명시 요청의 수락·답변·요청자 확인을 선택 답글과 구분하고 기억 비복사를 확인한다.
- 아카이브: 검색 카드→명시 원문 조회, 조회 전용/등록 가능한 공급자, 동일 명령과 다른 내용의 충돌, 버전·정정·삭제를 확인한다. 불명 쓰기는 원 영수증 조회로만 확인하며 mutate를 재전송하지 않는다.
- 출처 등록: 중복 해제와 같은 ID 재등록, 조회 중 등록 철회가 다른 담당의 출처를 선택하거나 철회된 응답을 채택하게 하지 않는지 확인한다.

먼저 기존 코드와 시험을 읽고 빈 연결만 추가한다. 정적 의심은 실행 증거를 확보한 뒤 교정하며, 소스를 동결해 빌드하고 변경에 관련된 선택 시험을 수행한다. 공유 build 산출물 사용 중에는 재빌드하지 않는다. 실제 모델의 반론 품질·사내 게시판/아카이브·PostgreSQL·현재 Linux/native Windows·검색 규모 성능은 로컬 계약 검증으로 완료 처리하지 않는다.

실패 원로그·소스 지문·결과·다음 행동은 `runtime/evidence/checkpoint377.json`과 C07 결과 문서에 저장한다. 완료 단위는 코드·문서·증거를 함께 커밋하고 origin에 푸시한다. 현재 기준과 기존 공백은 [C07 준비](C07-ordered-verification-preparation.md)를 따른다.

## 실행 중 확인한 연결 공백과 교정 범위

기존 공유 DB 시험에서 다른 담당의 업무를 읽을 때 명시 등록한 그 담당의 출처 검사기를 선택해야 했다. 출처 등록 해제는 여러 번 호출해도 후속 같은 ID 등록을 지우지 않아야 하고, 조회 도중 해제한 출처의 늦은 응답도 거절해야 한다. 별도 디렉터리·DB 일반 입구 시험으로 공유 DB fixture의 한계를 보완한다.

build3에서는 아카이브 검색·게시판 읽기·게시가 성공해도 다음 실행 전에 기본 무진전 한도에 도달했다. 새 조회로 얻은 카드·원문·토론과 실제 적용한 게시 명령을 진행 기록에 연결한다. 런타임이 채택한 실제 등록 도구의 결과만 사용하며 프롬프트나 출력 문자열만으로 권한을 부여하지 않는다. 이 진행 기록은 근거·기억 등록이나 목표 완료가 아니다.

기본 무진전 한도 3은 유지한다. 검색어·페이지 순서·관측 시각·task/attempt/result ID·동일 내용의 새 게시물 ID만 바뀌어도 동일 내용을 다시 진전으로 세지 않는 회귀를 추가한다. 실행 영수증이 불명·미적용인 쓰기와 재사용/거절한 결과에는 새 진전이 없다. 일반 성공 흐름과 의미 없는 반복의 유한 중단을 함께 검증한다.

명시 요청 왕복에서는 필요한 다음 명령의 변경 번호만 얻으려는 재조회도 확인했다. 게시 명령의 성공 결과에 검증된 원 영수증의 적용 revision을 함께 제공하여 즉시 이어지는 명령이 이를 사용하게 한다. 다른 쓰기 이후의 최신 head라는 뜻은 아니며, 다음 명령은 여전히 현재 권한·본문 조회 증명·expectedRevision을 검사한다. 도구 명세와 버전은 유지하고 revision이 없는 기존 저장 출력도 정확한 원형일 때 검증한다. 잘못된 revision이나 추가 필드를 허용하지 않는다.
