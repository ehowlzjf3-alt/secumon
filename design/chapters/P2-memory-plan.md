# P2-02 — 기억·근거의 수명과 조회

2026-09-05 · 구현 계획 · 실제 모델 선행 조건 유지

이번 챕터의 질문은 “다시 찾은 내용이 지금도 허용되고 유효한가?”이다. 업무 상태, 원본 근거, 개인/공유 기억, 검색 색인과 작업 파일을 같은 것으로 취급하지 않는다. P1의 직접 조회·호출 이력·상태 커밋·재개 패킷과 P2-01의 영속 adapter를 재사용한다.

## 단계와 완료 기준

1. **근거 수명과 전파.** 현재 근거의 출처 의존성과 대체 관계를 함께 판정한다. 부모 철회·정정·접근 제거가 자식 요약에 전파되고, 정정본이 안 보인다고 옛 근거가 다시 살아나지 않아야 한다. 공식 수명 변경은 인증된 업무 소유자 맥락, 예상 수명 버전, 명령 ID, 변경 사유를 받아 원자적으로 저장한다. 정정은 새 근거 ID를 사용한다. 단순 철회는 역사 검토를 허용할 수 있고, 삭제/접근 금지는 과거 결과·파생 입력까지 차단한다. 비동기 읽기와 늦은 도구/모델 응답도 현재 상태를 재검사한다.
2. **개인/공유 기억과 조회.** 경험·사실·절차 후보의 작성자, namespace, 검토/공유 상태, 출처 버전, 적용 범위와 만료를 보존한다. 개인 기록을 자동으로 조직 사실로 승격하지 않는다. 직접 ID 조회와 범위/시각/유형·한국어/영어 키워드 검색을 제공하며 검색 결과를 새 관측으로 자동 수락하지 않는다. 원출처 정정/삭제/철회가 파생 기억과 관련 의무의 무효화로 이어져야 한다.
3. **색인과 조회 캐시.** 정본과 색인의 revision/cursor를 분리한다. 신규 기록은 색인 전에 직접 읽을 수 있고 검색의 지연/실패/부분성을 표시한다. 색인·캐시에 남은 카드도 반환 전에 현재 접근/출처 유효성을 검사한다. 재생성·중복 갱신 후 삭제된 내용이 부활하지 않아야 한다. 선택적인 의미 검색·reranker는 이 챕터의 lexical 기준선 이후 필요를 측정해 결정한다.
4. **작업 파일 체크포인트.** work/attempt별 격리된 작업 파일에 소유권·한도·경로 검증을 적용한다. 중요 미완료 파일을 versioned artifact와 업무 참조로 저장하고 새 인스턴스에서 복원한다. 활성 lease·미확정 효과·미승격 파일을 나이만 보고 삭제하지 않는다. ContextRecovery의 파생 packet과 파일 checkpoint를 구분한다.
5. **통합 검증과 기록.** 두 업무군과 두 영속 상태 구현에서 현재 근거·기억·검색·늦은 응답·준비 답변·재개의 관련 경계를 확인한다. 정상/권한 간 차단, 조회 중 변경, 중복/충돌, 프로세스 재개, 신선도·검색 회수 사례를 시험한다. 적용 명령·소스 hash·관찰값·미실행 항목을 새 결과 기록으로 보존한다.

## 구현에서 지킬 경계

- 범용 domain/application은 저장소 SDK에 의존하지 않는다. 작은 업무 의미의 포트와 바깥 영속/파일 adapter를 사용한다. 원자적 상태 변경에는 이미 있는 StateRepository를 재사용한다.
- 수명 정본은 지연되는 색인이나 TTL 캐시보다 우선한다. 권한 없는 제목·요약·개수는 먼저 반환하지 않는다. 주체/공유 검토 권한은 trusted 호출 맥락에서 받고 모델이 고른 ID를 인증으로 사용하지 않는다.
- 삭제된 원본의 복사본이 ToolResult.output, 모델 입력·응답, 가설·계획, 준비 답변에 있을 수 있다. 추적할 수 없는 과거 복사본은 보수적으로 제한하고, 이후에는 명시 출처 참조로 의존성을 기록한다. 이미 발송된 답변은 회수된 것으로 표시하지 않고 전달/대조 의무를 보존한다.
- 내용 접근 차단, 현재 view의 정리, 물리 바이트 제거, 사건/영수증/백업의 보존은 별개다. 현재 SQLite와 파일 저널은 과거 전체 상태를 보존하므로 논리 삭제를 물리 purge 완료로 표시하지 않는다. 물리 제거가 남아 있으면 그 상태를 기록하고 P6 보존/복원 검증으로 이어간다. 원본부터 지워 취소·수명 변경 commit까지 실패시키는 순서를 피한다.
- 원본·기억 조회의 신선도는 관측/기록 시각과 출처 버전으로 표현한다. 점수나 재조회 횟수를 진실성으로 해석하지 않는다.

## 독립 검토에서 확인한 기존 문제

현재 accessibleEvidence는 파생 근거의 부모 철회를 따라가지 않고, 가시적인 대체 근거만으로 구버전을 제외한다. WorkResources는 artifact 읽기 이후 최신 권한 재검사가 없다. core.evidence.get/core.calls.get의 반환 본문이 다시 호출 결과에 저장되지만 원래 근거 의존 관계는 잃는다. ContextRecovery와 commitWithArtifacts는 모든 과거 artifact의 존재를 요구한다. 이 경로를 수명 계약과 함께 수정하고 회귀 시험으로 확인한다.

P2-02 전체 범위를 위 단계로 유지한다. 한 단계의 통과를 개인/공유 기억·검색·작업 파일 전체 완료로 세지 않는다. 실제 모델·SIEM/EDR·Knox·컴퓨터 유즈, 운영 보존/백업 검증은 별도 조건이며 중단한 키/모델 시험은 재개하지 않는다.
