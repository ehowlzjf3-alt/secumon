# C10 설치·복원 인수 마무리

2026-09-09 · checkpoint403 진행 중 · 기준선 `3c6f86f29ae9b3e62171fb8468e552e3fbfa4c7a`

현재 남은 큰 묶음은 **C10 → 최종 통합·실환경**이다. 이번 단위는 기존 설치·복원 경로를 유지하며 다음 세 인수 흐름과 실제 발견한 결함에 한정한다. 이미 통과한 전체 시험이나 새로운 가정만의 경계 사례를 반복하지 않는다.

1. **초기 복원 중단:** 고정 복원 경로를 게시하기 전에 증명이 함께 준비되도록 한다. 초기 `.apply`, 원본 접근 차단 표식, 복원 대상 디렉터리의 게시 중단에서 원자료를 보존하며 명시 재개한다. 관계없는 기존 경로는 자동 채택하지 않는다. 기존 완료 후 저장소 대사는 유지한다.
2. **보존 이력 백업·복원:** SQLite/file-journal에서 원영수증과 현재 참조에서 빠진 이력을 실제 로컬 백업·복원·신원 재연결·저장소 대사 후 재조회·재전달한다. 기존 544건 검증을 반복하지 않고 명시한 legacy512개 준비와 새32개 처리로 구간 연결을 재사용한다. 파일 수·bytes와 단계별 시간을 기록하되 운영 용량 검증으로 확대 해석하지 않는다.
3. **설치 구성:** 네이티브 모듈이 macOS/Linux에서도 설치 묶음에 포함되고 실제 OS/CPU에서 로딩되는지 확인한다. 일반 후보 조회는 코드 실행 없이 검사한다. 명시 준비·설치·등록에서는 대상 digest 검증 뒤 고정된 별도 Node 프로세스로 실제 API를 확인한다.

작성 상태: 보존 이력과 설치 항목은 소스·시험 코드 작성 후 동결했고 초기 복원은 시험 작성 중이다. **checkpoint403 빌드·시험은 아직 실행하지 않았다.** 세 작성자가 동결한 뒤 루트가 빌드·코어 타입·구조 검사와 새/영향받는 시험을 실행한다. 실패는 원 로그를 보존하고 영향받는 사례만 다시 확인한다.

실제 Linux 확인은 기존에 허가받은 NAS의 새 격리 디렉터리에서 수행한다. 시스템 Node18과 이전 시험 자료를 유지하고 확인된 별도 Node24.20.0을 사용한다. Linux용 Rust1.93.1 도구 구성요소는 공식 배포 checksum을 대조한 후 새 시험 디렉터리에만 설치했다. 다음은 잠금파일의 캐시된 의존성·현 소스 전달, Linux 네이티브 빌드, 현 소스 대조와 위 인수 흐름 실행이다. 인증정보는 산출물에 저장하지 않는다.

현재 미검증: checkpoint403의 실행 결과 전체, 네이티브 Windows, 실제 PostgreSQL, 사내 MCP·Knox·외부 A2A, 운영 보관/용량/복원 목표. 실제 모델/API 시험 중단을 유지한다. 문서형 기억 약23.7초와 최종 배치 응답 시간 인수는 다음 통합 묶음에 남는다. 이 계획이나 시험 코드 작성은 통과 또는 전체 goal 완료를 의미하지 않는다.
