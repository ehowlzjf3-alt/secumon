# C09 사건 수신·상시 담당·협업 비교 인수

2026-09-08 · checkpoint381. 시작 기준선은 `c8ffdfc7f5a03fab80adb8463409a60ee52e8821`이며 작업 트리는 깨끗했다. 직전 단위는 A2A 실행 연결 교정·소스별 로컬 검증·문서·푸시와 원격 일치 확인으로 진행했다. 전체 goal은 계속 미완료다.

상시 담당은 사건이 없을 때 모델을 계속 호출하는 방식이 아니다. 사건 원천을 확인하고, 새 사건이 오면 같은 담당의 지속 세션에 새 업무로 접수한다. 세션의 대화 문맥은 이어가되 목표·계획·근거·사용량은 사건 업무별로 구분한다.

- 기존 `MissionRuntime`, `ResidentMissions`, 호스트 등록, SQLite 세션 접수·명령 영수증·artifact 저장을 재사용한다. 이미 끝난 A2A 왕복이나 C08 원장을 다시 만들지 않는다.
- 독립 작성자는 사건 원천/호스트 등록, 한 업무의 대기·재개, 기존 oracle을 이용한 협업 비용 집계를 각각 제한된 핵심 사례로 확인한다. root는 실제 일반 프로필의 사건 A/B, 담당별 저장소·대화 분리, 재접속·중복·질문 대기·종료와 복구를 연결한다.
- 원문 저장→사건 접수→제어 체크포인트→실행 결과를 구분한다. 빈 관측/같은 사건의 재전달은 새 모델 호출을 만들지 않고, 원문 충돌·현재 권한 상실·미확정 효과는 새 업무 생성이나 자동 재송신으로 우회하지 않는다.
- 필요한 의미 진전과 현재 권한은 기존 실행 루프에서 확인한다. 기본 무진전 한도나 실행 자원을 시험 통과 목적으로 높이지 않는다. 사건 조회와 상대의 답변은 독립 근거나 개인 장기 기억으로 자동 승격하지 않는다.
- 작성자 동결 후 Node v24.20.0으로 빌드하고 신규 시험부터 실행한다. 실제 실패의 경계를 교정하고 직접 영향 회귀만 추가한다. source/build 지문과 terminal exit, 실패 원로그·수정 뒤 결과·미실행 항목을 체크포인트에 저장한다. 빌드 중 dist 시험을 실행하지 않는다.

실제 모델/API 중단을 유지한다. 로컬 유한 모델·관측 callback·가짜 시계와 실제 로컬 저장소의 결과를 사내 모델 품질·외부 source/A2A·운영 성능으로 확대하지 않는다. 긴 대기·실제 프로세스 중단과 예외 주입은 구분해서 보고한다. 사건 임무의 후속 경계와 C10, 기존 C05/C06 및 플랫폼·최종 통합 인수는 구현/검증 상태에 맞춰 남긴다.

## 이번 단위 뒤의 최소 인수

1. 같은 문제·mode·고정 판정 기준으로 실제 독립 프로필의 단독/협업 각1회 실행을 비교한다. 기존 peer-deployment-entry-fixture를 재사용하고 onStep의 원 상태/전달 기록과 모든 참여 업무의 최종 로컬 사용량을 모은다. 일반 접수의 responseRequirement·빈 criteria와 기존 평가기의 completion_criteria_missing 관계는 **정적 검토 후보**다. 실제 paired 실행으로 확인하며 저장 상태를 시험 뒤 수정해 맞추지 않는다.
2. 같은 업무의 게시판/임무 동시 등록에서 각각의 알림·커서·철회가 다른 원천을 덮지 않는지 확인한다. 기존 board/resident fixture를 재사용한다. 별도 provider 시험만으로 결합을 통과 처리하지 않는다.
3. C10은 기존 설치/번들 시험을 다시 만드는 대신 check→최초 pin→offline backup→같은 release의 다른 설치 경로 update→동일 담당/세션/기억 재열기와 오래된 backup/expectedPrevious 충돌을 인수한다. 실제 registry 게시·버전 간 이전·플랫폼 배포와 구분한다.
