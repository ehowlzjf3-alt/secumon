직전 C10 단위는 코드·증거·문서를 원격과 일치시켜 완료했다. 이번에는 [남은 인수 목록](../REMAINING-ACCEPTANCE.md)의 로컬 세 항목을 진행한다. C01–C10 전체 목표와 외부 환경 인수를 유지하며 이미 통과한 전체 시험을 반복하지 않는다.

1. **원자료·세션·기억·실행 기록 연결:** C05/C06 완주와 C09 지속 문맥, C10 원자료 복원의 기존 결과·fixture를 먼저 확인한다. 기존에 직접 확인한 연결은 재사용하고 남은 연결만 하나의 사용자 흐름에서 확인한다. 기억은 개인별로 분리하며 독립적인 검증 근거로 자동 승격하지 않는다.
2. **기억 선택 실패 후 회복:** 구현된 선택 만료·권한 오류·빈 업무 구분, 재선택/해제 뒤 오류 정리, 재접속 뒤 선택 업무 복원을 실제 HTTP와 내장 브라우저에서 확인한다. 정상 저장·완주 시험 전체를 다시 만들지 않는다. 발견한 제품 결함이 있을 때 해당 경로만 수정한다.
3. **문서형 기억 지연:** 같은 기존 HTTP 기억 fixture와 계측기를 사용해 현재 소스 기준선을 한 번 측정한다. 저장소/원자료 검증의 실제 반복 비용을 좁혀 개선한다. 첫 원문 확인·현재 권한·최종 일관성 검사를 생략하거나 다른 요청에 검증 성공을 무조건 재사용하지 않는다. 변경 전후 같은 흐름의 호출 수·지연과 영향받는 회귀로 확인한다.

독립된 코드 읽기/fixture 준비는 병행한다. root가 소스 작성 동결 후 빌드·코어 타입·구조 검사와 필요한 시험을 실행한다. 실행 중 컴파일 산출물을 바꾸지 않으며, 바뀌지 않은 부분의 유효한 결과는 재사용한다. 실패 원 로그와 교정 이유, 확인된 사실과 미검증 항목을 보존한다.
