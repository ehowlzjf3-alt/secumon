# P2-04 — 다음 호출이 필요한지 검증하고 실행 비용 줄이기

2026-09-05 · 전체 챕터 구현 계획 · P2-03의 521개 로컬 시험 기준선

모델에 보내는 입력을 줄인 다음에는 실제 도구 실행과 내부 조회를 구분해 줄인다. 성공한 과거 결과를 현재 관측으로 둔갑시키지 않으며, 복사본의 원출처 검사·미확정 쓰기·같은 revision의 저장 계약을 재사용한다. 실제 모델/API/사내 MCP 시험 중단과 P0–P6 전체 목표를 유지한다.

## 구현 순서

1. **재사용·비용 계약.** 기본 재사용 금지. 검토된 read 도구만 고정 버전 또는 TTL을 선언한다. task는 명시적으로 새 관측을 요구할 수 있다. 키는 업무/목표 의미·tenant/principal·정책·범위·정확한 계약 digest·입력과 결합한다. 원 관측/근거 ID·artifact와 소비한 attempt를 연결하고 논리 시도, 실제 구현 호출, adapter 보고 transport/내부 연산/이미지/대기 비용을 구분한다. 미보고 비용은 unknown이다.
2. **저장 결과 재사용.** 현재 원본·호출 영수증·권한·근거 수명·기억 출처를 다시 확인하고 유효한 완전 read 결과만 채택한다. partial/error/denied/expired/unknown/write 결과는 일반 hit가 아니다. 원래 관측시각과 독립 출처를 유지한다. 결과를 소비자 attempt에 연결하는 새 기록은 기존 dispatch/receive/adopt 경로를 따르며 새 물리 관측을 만들지 않는다. 프로세스 재시작 뒤에도 같은 원본을 찾는다.
3. **진행 실행 합류.** 기존 동일 work/attempt의 실행에 복수 caller가 합류할 수 있게 한다. caller의 취소/대기는 자신만 분리하며 원 실행 owner/lease/업무 기한을 연장하지 않는다. 프로세스 메모리는 대기 가속 수단이고 정본은 저장된 시도·영수증이다. 다른 프로세스의 실행 완료를 확인할 수 없으면 확인 가능한 대기 상태를 돌려준다. 업무 간 전역 exactly-once를 work CAS로 주장하지 않는다.
4. **묶음·페이지·증분.** 단일 active read attempt 안에서 검토된 adapter의 좁은 batch/page 계약을 사용한다. 항목 ID/입력 digest·상태·coverage·not-run과 전체 집합을 대조한다. cursor는 query/정책/도구/원출처 snapshot과 결합하고, 저장된 page 결과와 cursor 진행을 함께 채택한다. 일부 실패·빈 페이지·반복 cursor·중복/누락 항목·상한/기한을 검사한다. 재시도는 미완료 항목과 명시 cursor에서만 이어지며 자동 무제한 retry를 넣지 않는다.
5. **카탈로그·지침 수명.** 제공자 목록의 모든 페이지·동일 revision·중복·schema를 검증한 뒤 snapshot을 교체한다. 중간 실패는 이전 목록을 지우지 않으며 완전한 빈 목록과 장애를 구분한다. 검색 cursor를 질의/현재 정책/snapshot에 묶고 byte/항목 예산을 둔다. 이미 선택한 도구의 계약을 실행 직전에 다시 대조하며, 지침의 원본 재사용과 현재 applicability/방법 선택은 분리한다.
6. **내부 조회·통합 평가.** 변경되지 않은 schema/파싱/dispatch 정보를 재사용하는 지점을 측정한다. 원본의 무결성을 확인하는 실제 비용까지 기록하며 get을 exists로 바꾼 것을 I/O 절감으로 주장하지 않는다. 두 업무군과 SQLite/FileJournal에서 cold/warm·동일 입력·새 버전·TTL·재시작·권한/출처 변경·부분 실패·취소를 비교하고, 기존 전체 suite와 정적 보존 검증 뒤 학습/결과를 저장한다.

## 실행 경계와 검증 증거

- 기존 toolCalls 예산은 논리 실행 시도 한도를 유지한다. 별도 실행 기록으로 invoke/reuse/join과 실제 구현 호출·보고된 transport 등을 구분해 원 실행 비용을 소비자에게 다시 더하지 않는다.
- cache·registry 교체·외부 실행은 transact의 재시도 edit 안에서 수행하지 않는다. 후보를 준비한 뒤 동일 기준에서 커밋하고 반환/실행 직전의 권한·원본 검사를 유지한다.
- 한 업무의 단일 active attempt를 무작정 풀지 않는다. 독립 task 병렬 scheduler와 업무 간 shared execution은 공유 소유권/예산 계약이 필요한 별도 확장이다. 이번 batch는 내부 항목 상태를 노출하는 adapter 계약으로 검증한다.
- TTL은 도구가 보고한 관측의 의미와 구분한다. 캐시 유효기간을 새 사실의 관측 시각으로 쓰지 않는다. 새 관측 요구에는 cache를 사용하지 않는다.
- 원본 없는 과거 hit, 다른 권한의 검색 없음, 일부 실패한 목록의 삭제, 오래된 schema 실행, caller 취소의 다른 실행 전파를 실패로 검증한다.
- 모델 판단 품질·실제 MCP 구현/성능·Knox/컴퓨터 유즈 동작을 합성 실행으로 완료 처리하지 않는다. 내부/이미지/대기 비용 필드와 합성 adapter 계측은 구현하되 실제 운용 값은 미검증으로 남긴다.

각 소단위는 구현/시험/기록으로 연결하지만, 이 여섯 단계와 선행 실제 모델 조건을 충족하기 전에는 P2-04 전체 완료로 표시하지 않는다.
