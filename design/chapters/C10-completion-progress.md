# C10 확인 진행 기록

2026-09-09 · checkpoint403 · 최종 결과 저장

**최종 상태:** 로컬69개·NAS Linux24개의 명명된 인수/관련 시험이 최종 코드에 대응해 통과했다. 추가 수정은 시험 기대값/byte 비교와 시험 준비에 한정됐고 build1 이후 제품 컴파일 파일은 동일하다. 모든 관리 실행과 전용 SSH 연결을 종료했다. [최종 결과](C10-completion-result.md)를 우선한다. 아래는 진행 중 관측을 남긴 기록이다.

큰 잔여는 C10와 최종 통합·실환경의 두 묶음이다. 구현·시험 코드 작성과 실행 통과를 구분한다.

- 초기 복원5개, 보존 이력2개, 설치 native4개 및 영향을 받는 기존 설치·복원 시험을 준비했다. 소스 작성자는 모두 동결했다.
- 로컬 build1·코어 타입 exit0, 구조204개·위반0. 소스 digest `d78ab34c489dda6ed2ec751f4f696ed47ca426cae7fc5c039545452fec248560`, 컴파일2610개. 원 manifest와 소스 목록을 `runtime/evidence/checkpoint403-*`에 저장했다.
- `C10-completion-target1.log`의 관련11개 시험 파일 실행이 진행 중이다. 초기 호환성의 기존 기대값에서 `sessionCompact:null`이 빠진 실패1개를 관측했다. 해당 반환 필드는 기존 구현(`158b82b`)에도 존재한다. 현재 배치 완료 후 시험 기대값만 고치고 해당 실패를 다시 확인할 예정이며, 아직 고치거나 통과 처리하지 않았다.
- NAS Linux: 시스템 Node18과 과거 시험 디렉터리를 유지한다. 새 격리 디렉터리에 현 소스·의존성을 전달했고 전송 archive SHA256을 확인했다. Linux Rust1.93.1 오프라인 native 빌드 exit0, 추가 crate 다운로드0이다. 실제 native 로딩과 TS 빌드/시험 결과는 별도 확인 중이다.
- 로컬 `cargo vendor --locked --offline`은 전체 플랫폼 의존성 중 캐시에 없는 bumpalo 때문에 exit101이었다. 원 실패 로그를 보존했다. 이후 기존 registry 캐시로 Linux 대상만 오프라인 빌드했으므로 재다운로드를 확대하지 않았다.

진행 중인 실행은 종료 결과를 확인한 뒤 다음 빌드를 한다. 최종 소스와 컴파일 원문을 대조하고 유효한 기존 통과 결과를 재사용한다. 현재 관측은 제품 운영 인수나 전체 goal 완료가 아니다. Windows·실제 PostgreSQL·사내 연결 및 문서형 기억 지연은 잔여로 유지한다.
