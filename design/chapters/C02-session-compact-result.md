# C02 반복 compact 결과 — 현재 소스의 등록 검증 통과

2026-09-07. **최종 Linux 전체 2,836/2,836, compact 관련 46/46이 통과했다. 전용 시험 프로세스 0개와 SSH 종료를 확인했으며, C03 개인 기억의 명시적 사용자 흐름에 착수할 범위별 gate를 충족했다.** [최종 검증 근거](../../runtime/evidence/C02-compact-verification.json)는 현재 소스/빌드·등록 시험의 결과이며 C01/C02 전체나 전체 goal의 완료 판정은 아니다.

대화가 길어지면 앞부분을 요약하고 최근 입력은 원문으로 붙여 계속 작업하는 경로를 구현했다. 작업 X의 완료가 세션 초기화 조건이 되지 않는다. 세 번의 compact와 재시작, 응답 저장·요약 게시 직후 프로세스 강제 종료를 실제 로컬 저장소에서 확인했다. 최초 NAS 실패와 고정 재현·수정의 근거는 아래에 별도로 보존한다.

## 사용자가 경험하는 동작

같은 담당·사용자의 같은 대화에서 X가 끝난 뒤 Y를 시작하면, Y는 앞선 대화와 자신의 목표를 함께 읽는다. 문맥이 커지면 실행 조정자가 compact 호출을 먼저 진행한다. 요약 후보를 검증·채택한 뒤 도구 실행을 이어가며, 현재 사용자 발언은 원문으로 유지한다. 다음 업무 Z는 자신의 계획·근거·자원 장부를 새로 갖고, 대화 요약과 최근 발언을 이어받는다.

CLI의 `work compact`와 Web의 ‘대화 문맥 정리’도 같은 경로를 사용한다. 상태 조회만으로 모델을 호출하지 않는다. Web은 정리 상태를 별도 영역에 표시하며 후보·호출마다 대화 말풍선을 추가하지 않는다. 정리에 실패해도 원문을 보존하고, 유효한 문맥을 만들 수 없는 경우 명시적인 용량·복구 상태를 반환한다.

현재 CLI/Web 실행은 명시적으로 선택한 합성 규칙 provider만 지원한다. 임의의 자연어를 요약하는 실제 모델 연결과 의미 품질 검증은 이번 결과에 포함하지 않는다. 외부 모델/API 시험 중단을 유지했다.

## 저장과 검증의 경계

| 개념 | 의미와 동작 |
| --- | --- |
| 원문 이력 | 사용자 접수 원문·적용 영수증·실제 전달된 응답. compact가 삭제하거나 덮어쓰지 않는다. |
| 적용 입력 `basis` | 해당 작업이 실제로 적용한 입력 ID·순서·내용 지문. 요약 끝과 별도로 유지한다. |
| 앞부분 요약 `summary` | 어느 순서까지 요약했는지, 짧은 서술, 중요한 항목과 정확한 원문 인용을 가진 파생 자료. |
| 최근 원문 `tail` | 요약 끝 다음부터 현재 적용 입력까지의 원문. 현재 사용자 입력은 반드시 여기 남는다. |
| 문맥 `head` | 원문형 v1 또는 요약+최근 원문형 v2로 조합한 입력의 버전. 요약 head와 다른 개념이다. |
| 게시 영수증 | 요약 저장소에 같은 호출의 결과를 게시했는지 확인하는 기록. 모델 호출의 채택 완료와 구분한다. |

새 요약을 사용할 때 원문 접수 지문, 출처 권한·모델 목적지·원본 파일 존재, 생성한 모델 호출의 채택 상태를 확인한다. 요약이 존재한다는 이유만으로 사용하지 않는다. 저장된 후보가 현재 출처와 맞지 않으면 이전 유효 요약 또는 허용 원문으로 복구한다.

새 입력 artifact를 만들 때는 최신 유효 요약을 선택한다. 이미 실행 중인 입력은 그때 고정한 v1/v2 표현과 출처를 검증한다. 나중에 요약 head만 바뀌었다는 이유로 정상적인 기존 호출을 무효화하지 않는다.

기존 중요 항목의 삭제를 거절하고, 상태·내용 변경에는 뒤에 도착한 정확한 원문 인용을 요구한다. 사용자 발언이 있는 새 구간에는 해당 발언을 인용한 중요 항목이 최소 하나 필요하다. **이는 원문에서 모든 제약·반론을 빠짐없이 추출했다는 증명은 아니다.** 자유 서술의 의미 정확도와 올바른 상태 변경 판단에는 별도 모델 평가가 필요하다. 현재 업무의 완료 의무·검증 근거·미정산 외부 효과는 WorkState가 정본이며 대화 요약이 이를 새로 발급하지 않는다.

SQLite와 파일 저널은 업무 상태 저장 방식이다. 이번 요약·대화는 두 경우 모두 기존 channel SQLite에 저장한다. 개인 장기기억, 게시판, 아카이브로 자동 복제하지 않는다.

## 호출·정산·복구

`PlanningRuntime`의 예약 → 실행 → 응답 저장 → 사용량 정산 → 채택 수명을 재사용하고 `session_compact` 목적만 구별했다. 요약을 업무 계획으로 위장하지 않으며 compiler 내부에서 숨겨진 모델 호출을 만들지 않는다. 현재 활성 업무가 비용을 부담하고, 완료된 이전 업무의 장부는 바뀌지 않는다.

모델 응답을 저장한 뒤 중단되면 같은 응답에서 검증을 재개한다. 요약 게시 직후 작업 상태 채택 전에 중단되면 게시 영수증을 확인해 채택을 마친다. 두 저장소를 하나의 transaction으로 가정하지 않는다. 입력 변경·취소가 먼저 적용되면 늦은 후보를 최신 지시에 대한 성공으로 채택하지 않고 소비한 사용량은 보존한다.

기본 세션 문맥 한도는 64KiB/256항목, 최근 원문은 8항목, 요약 입력은 최대 48KiB/64항목, 요약 본문은 최대 8KiB다. 80% 수준에서 준비하고 60% 목표를 사용하지만 이는 초기 정책이다. 실제 요청 bytes·공급자 추정 tokens·출력 예약도 기존 모델 수명에서 검사한다. 보호 항목 자체가 한도를 넘으면 무한히 줄이거나 삭제하지 않고 용량 상태로 멈춘다. 모든 모델에 최적인 값으로 검증된 것은 아니다.

## 남은 범위

수정본 Linux 전체 검증과 원로그 회수·정리는 끝났다. 실제 모델/API 실험은 중단 상태이며 의미 품질은 미검증이다. 네이티브 Windows 실행, 호스트 실행 격리, 전원 장애 내구성, 장기 운영량에서의 비용 검증도 별도 미완료 항목이다. C02의 다른 설계 인수 항목과 C01/C02 전체, C01~C10 goal은 완료로 표시하지 않는다.

다음 사용자 가치 단위는 [C03의 명시적 기억 등록 → 같은 담당의 새 대화에서 선택적 회상 → 정정·잊기](C03-personal-memory-plan.md)다. 이 범위에 필요한 C02 구조 검증 gate는 충족했으며 C03 구현 자체는 아직 진행하지 않았다. 대화 원문·세션 요약·개인 장기기억을 구분하고, 담당/사용자 논리 범위를 조회·참조·캐시에 연결한다. 기존 기억 서비스와 기본 SQLite를 재사용하며 문서 파일/PostgreSQL 지원은 후속 범위로 유지한다.
