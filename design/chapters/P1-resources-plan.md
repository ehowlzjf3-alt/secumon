# P1-04 — 도구·호출 장부·근거·지침

2026-09-05 · 구현·로컬 검증 완료 · 계획과 실제 범위는 [학습·결과 기록](/Users/seunghanee/Documents/secumon/design/chapters/P1-resources-result.md) 참고

목표는 도구의 발견과 실행, 이미 얻은 결과의 재조회, 업무 지침의 선택을 하나의 범용 실행 계약에 연결하는 것이다. P1-03의 계획 검증·시도/예산·결과 저장·근거 수락을 재사용한다.

## 구현 순서와 완료 기준

1. 작은 도구 카탈로그: provider로 구분한 ID/버전, 엄격한 manifest, 변경 불가능한 등록 snapshot, 권한 필터 후 제한된 lexical 검색, 정확한 ID/버전으로 명세 선택. 검색 결과 카드에는 schema 전체를 포함하지 않는다. 중복 등록·오용 버전·명세 변조·권한 밖 목록 노출을 검사한다.
2. Broker: runtime의 실제 호출을 공통 집행 경로로 연결한다. 저장된 실행 시도·현재 목표/정책·입력 digest·owner를 재확인한 뒤 등록된 tool을 호출한다. 도구가 직접 상태/권한을 고치는 API를 받지 않게 한다.
3. 호출 장부와 근거 조회: 현재 work의 invocation 카드·저장 결과·특정 evidence를 제한된 크기로 읽는다. 출처/관측 시각·범위·부분 결과·당시 수락 여부와 현재 유효성을 구분한다. 과거 결과 재조회는 새 관측/독립 근거를 만들지 않는다.
4. 방법론·지침: 단순 조회/근거 비교/가설 조사/회신 대기의 작은 방법 선택 규칙과 공통 지침 하나를 제공한다. 선택된 지침의 정확한 버전·hash·적용 조건·선택 이유를 결과와 artifact로 기록한다. 본문은 선택 후에만 읽고, 지침을 읽었다고 권한이나 완료가 생기지 않게 한다.
5. 합성 전체 경로: 두 업무군에서 지침 선택 → 필요한 도구 실행 → 근거/호출 ID 조회를 실행한다. SQLite 재시작 뒤 같은 결과/지침 참조를 읽으며 외부 도구를 다시 호출하지 않는지 확인한다.

조회 도구는 기존 task/attempt/예산·결과 계약을 거친다. CLI 내부의 단순 상태 조회는 모델 호출 없이 application reader를 사용할 수 있다. 선택 본문·schema·결과의 크기는 명시 상한으로 제한하고, 초과를 빈 결과나 전체 성공으로 숨기지 않는다.

P2-04에서 자동 읽기 캐시·신선도 정책·in-flight 합류·batch/증분·큰 카탈로그 갱신/효율을 구현한다. 이번에는 보존된 결과와 현재 관측을 혼동하지 않는 조회·장부 기반을 완성한다. P2의 자동 재사용 성능을 이번 통과로 대체하지 않는다.

원본 Python 도구는 수정하지 않는다. 기존 registry의 중복 거부·정확 선택·제한 검색, read_extract의 원본 위치 보존 원칙을 TypeScript 계약에 재사용한다. 실제 MCP/모델/Knox/컴퓨터 유즈는 연결하지 않는다.
