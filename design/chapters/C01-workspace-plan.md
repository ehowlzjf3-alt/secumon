## 개념과 이번 단위

담당 ID는 디렉터리의 위치가 바뀌어도 같은 에이전트임을 식별하는 값이다. 최초 설정은 이 ID와 기본 저장 위치를 준비한다. 이것만으로 모델이 대화하거나 여러 작업의 문맥을 이어가는 것은 아니며, 그 연결은 C02 이후에 수행한다.

기존 로컬 CLI는 합성 예제용 프로필이다. 이를 일반 담당인 것처럼 이름만 바꾸지 않고, 새 공통 명령의 담당 탐색/초기화/진단 경로를 추가한다. 기존 합성 CLI와 시험은 계속 유지한다.

## 재사용·수정·신규

- 재사용: TypeScript/Node 빌드, Zod 경계 검사, SQLite 상태/기억 저장소, 파일 원본/작업 저장소, 원자적 파일 생성의 기존 방식.
- 수정: 패키지의 명령 진입점 등록, 실제 담당 구성에 필요한 기존 저장 어댑터 조합(후속 단위에서 연결).
- 신규: 담당 설정/ID 계약, 현재 디렉터리 탐색, 원자적 최초 등록·명시 복구, 상태 안내, 담당 영역 쓰기 경계, 이동/복제 구분.

## 진행 순서

1. 담당 identity/config의 최소 계약과 실제 파일 기반 초기화·상태 조회를 구현한다. SQLite 기본/파일 영역·선택 기능 비활성·모델 미설정을 명시한다.
2. `secumon-agent` 명령의 첫 실행/setup/status/repair/version을 연결한다. 기존 설정을 덮어쓰지 않으며 잘못된 입력/버전/소유 정보는 먼저 판별한다.
3. 실제 임시 디렉터리와 별도 프로세스로 신규·재호출·동시 생성·중단 후 복구·설정 누락·기존 파일 보존·이동·복제·엔진/다른 담당 쓰기 차단을 확인한다.
4. 기존 저장 어댑터를 담당 경로/주체에 연결하고 관련 회귀와 필수 통합 검증을 수행한다. 디렉터리 등록만 통과하면 C01 전체 완료로 처리하지 않는다.

## 경계와 검증

설정 파일의 ID, `.secumon/identity.json`, 초기화 완료 기록의 담당 ID는 일치해야 한다. 파일 생성은 덮어쓰기 없는 원자 게시와 디렉터리 동기화를 사용한다. 손상/모호한 기존 기록에 새 ID를 자동 발급하지 않는다. 심볼릭 링크·경로 탈출·다른 담당/엔진 영역은 담당용 파일 경로로 허용하지 않는다.

일반 파일 접근 제한과 임의 셸/동일 OS 사용자까지의 강한 격리는 다르다. 현재 제공하는 담당용 도구/저장 경계의 보장 범위만 기록하고 임의 코드 실행을 안전하다고 주장하지 않는다. 외부 효과나 실제 API 호출 없이 로컬 파일/프로세스 시험을 수행한다.

현재는 첫 작은 구현 단위를 시작한다. 완료 기록에는 실제 구현/로컬 검증과 C01에서 남은 연결을 따로 남긴다.
