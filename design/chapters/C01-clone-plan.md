# C01 다음 단위 — 새 담당으로 복제

2026-09-07 · 구현에 사용한 계획 · [구현/검증 결과](/Users/seunghanee/Documents/secumon/design/chapters/C01-clone-result.md) 별도 기록

## 사용자가 보게 될 동작

디렉터리를 이동하면 같은 담당 ID와 기록을 유지한다. 명시적인 clone 명령은 기존 담당의 설정과 스킬을 바탕으로 **새 ID를 가진 별도 담당**을 만든다. 기본 복사 대상은 검증된 config와 skills의 일반 파일이다. 대화·개인 기억·진행 작업·산출물·workspace·자격증명 저장소는 새 담당의 빈 영역으로 시작한다. 원본 담당은 바꾸지 않는다.

후보 명령은 `secumon-agent clone --directory 원본 --destination 대상`이며, 대상 디렉터리가 이미 있으면 덮어쓰지 않고 거절한다. 이름은 명시 옵션 또는 대상 디렉터리 이름을 사용하고 모델 profile 이름은 참조만 복사한다. 기록을 옮기는 별도 기능은 C03/C10의 이행·복원 계약으로 다룬다.

## 중요한 중단 처리

현재 `initialize(target)`를 먼저 완료한 뒤 스킬을 복사하면, 도중에 멈췄을 때 불완전한 clone이 이미 ready로 보일 수 있다. 또한 현재 일반 init/repair는 setup 완료 표식이 없는 identity/config를 정상 초기화로 이어서 완료할 수 있다. 복제 중인 담당을 이 경로로 잘못 완성하지 않게 해야 한다.

초기화와 clone이 공통으로 사용하는 원자적인 작업 표식을 먼저 확보한다. 표식에는 작업 종류와 ID·대상 담당 ID를 넣고, clone에는 원본 담당과 복사 목록의 해시를 연결한다. 같은 일반 초기화는 기존 동작처럼 하나의 ID로 합류한다. clone과 다른 작업의 충돌은 기존 파일을 보존하고 거절한다. 게시 함수의 EEXIST 처리를 성공으로 가정하지 않고 실제 게시된 표식의 종류·ID·옵션을 다시 읽는다. 복사와 검증이 끝난 뒤 완료 표식을 마지막에 게시하고 기존 저장소 조합으로 빈 DB를 준비한다.

미완료 clone의 일반 init/repair는 전용 재개 절차로 안내한다. 명시 재개는 같은 대상 ID를 유지하고 이미 복사한 파일은 해시가 맞을 때 재사용한다. 원본 변경·대상 파일 충돌·모호한 표식을 자동 덮어쓰기나 새로운 ID로 감추지 않는다. 완료 뒤의 정상 스킬 편집을 막기 위해 복사 시점 해시를 영구 불변 규칙으로 사용하지 않는다.

## 구현 순서와 재사용

1. clone 입력·결과 및 초기화 작업 표식 계약을 추가한다. 이전에 정상 초기화된 담당과 새 불완전 작업을 구분한다.
2. 일반 init과 clone의 공통 선점·부분 복구 흐름을 연결한다. 최초 등록의 기존 ID/설정 보존을 유지한다.
3. config/skills의 복사 목록·크기·해시를 검증한다. 링크와 경로 탈출을 거절하고 실제 복사는 OS 파일 경계를 이용한다.
4. 미완료 표시·명시 재개·최종 완료와 CLI를 연결한다. Zod 계약, 경로 경계, 기존 원자 게시, openAgentStores를 재사용한다.
5. Linux 실제 시험과 Windows 경로/권한 어댑터 검증을 구분해 실행한다. 지원하지 않는 플랫폼의 저장 보장을 가정하지 않는다.

## 기존 초기화와의 호환 확인

- 기존 v1 setup 완료 담당은 표식 추가나 재작성 없이 연다. identity/config만 남은 부분 초기화도 기존 ID를 보존한다.
- clone 작업 표식은 identity/config보다 먼저 게시한다. inspect/init/repair와 중첩 담당 검사는 표식만 남은 경우도 구분하며 일반 초기화가 완료하지 못하게 한다. CLI에는 일반 repair와 clone 재개를 구분하는 상태가 필요하다.
- 완료 기록은 작업 ID·담당 ID·복사 목록 해시와 연결한다. 명시 재개만 기존 대상 경로를 허용한다. 작업 표식은 프로세스 잠금과 같지 않다.
- 이전 엔진은 새 작업 표식을 모르므로 미완료 clone을 일반 init으로 완료할 수 있다. identity 게시 전 이전 엔진이 거절하는 버전 표식이나 명시적인 실행 버전 제한을 결정한다. 현재 read의 schemaVersion=1 직접 검사도 함께 검토한다.
- config/skills 복사 완료와 DB 준비 성공은 별개다. DB 준비가 실패해도 같은 담당을 다시 열며 원본 재복사나 새 ID 발급으로 덮지 않는다.

## 통과 기준

- 이동의 ID 유지와 clone의 새 ID·빈 저장소 분리를 확인한다.
- 설정·스킬 내용 보존, 원본 불변, 대화/기억/작업 미복사를 확인한다.
- 기존 대상·같은 경로·중첩 담당·엔진 영역·링크를 거절한다.
- 복사 전·중·완료 표식 직전 실제 프로세스 중단 뒤 incomplete로 남고 일반 init이 우회하지 못한다.
- clone끼리 및 init/clone의 동시 실행은 한 작업만 진행한다.
- 재개 시 원본 변경·대상 충돌을 보존하고 오류를 낸다.
- 완료 후 스킬 편집과 정상 재호출이 가능하다.

수동으로 전체 디렉터리를 복사해 동일 ID가 두 곳에 생기는 문제는 이 명령만으로 해결되지 않는다. 호스트의 담당 등록·실행 소유권 검증과 이동 감지는 별도 남은 경계다. 이 문서는 clone 구현이나 C01 완료 증거가 아니다.

## 이번 구현의 구체적인 저장 순서

`setup-operation.json`은 일반 init과 clone을 구분하는 영속 작업 표식이다. 일반 init은 같은 표식의 ID에 합류하고, 기존 정상 v1 담당은 다시 쓰지 않는다. clone은 새 대상 디렉터리를 배타적으로 만들고 표식을 먼저 게시한다. 이후 `setup.json` v2를 가드로 게시하여 이전 v1 엔진의 정상 재호출을 거절한다. identity/config와 skills를 복사·검증한 다음 `clone-complete.json`을 마지막에 게시한다. v2 담당을 이전 엔진으로 열지 않는 버전 호환 계약이며, 서로 다른 엔진 버전의 동시 관리 실행 조정은 C06에서 연결한다.

중단된 clone의 일반 init/repair는 명시 재개로 안내한다. 완료 후 DB 준비 실패는 복사 재실행과 구분하며 같은 담당을 다시 열어 저장소 준비만 수행한다. 복사 완료 뒤 스킬/설정 수정은 허용하고 최초 복사 해시를 영구 불변 규칙으로 사용하지 않는다.

스킬 복사는 512개 파일/디렉터리, 개별 파일 4 MiB, 전체 32 MiB, 깊이 16 및 작업 표식 512 KiB 한도에서 전체 목록을 확인한다. 초과 시 자동 누락하지 않고 명시 오류를 낸다. 원본 링크·특수파일과 예약 임시파일명은 거절한다. 타깃의 내부 원자 게시 임시파일은 안전한 파일임을 확인한 경우 별도 512개/32 MiB 한도에서 보존하며 실제 스킬 목록과 구분한다. 이 한도는 LLM 자원 할당 예산이 아니라 파일 복사 시 메모리/디스크 사용을 제한하는 호스트 설정값이다.

기존 POSIX 파일 읽기/원자 게시를 공통 helper로 추출하여 재사용한다. Windows ACL/핸들 경계는 후속 구현이며 이 코드의 정적 호환만으로 native Windows 지원을 주장하지 않는다.
