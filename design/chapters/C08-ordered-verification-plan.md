# C08 동료·반론·자원 로컬 인수 계획

2026-09-08 · checkpoint378. 이전 goal 단위는 C07 교정·선택261개와 관련89개 검증·문서 저장·원격 main 일치 확인으로 진행했다. 기준선은 `c6a5225`이며 전체 goal은 미완료다. [준비 문서](C08-ordered-verification-preparation.md)와 [V08-01~06](C06-C10-verification-plan.md#c08)을 따른다.

동료 상담과 자원 위임은 다른 기능이다. 상주 담당은 세션을 이어가며 자기 자원으로 상담할 수 있고, 명시 배정한 임시 업무만 후원자의 한도와 분리 원장으로 정산한다. 반론 응답은 검토 대상·대안·근거 유무·판별 질문을 제공하지만 호출자의 독립 근거나 완료 판정이 아니다.

- 기존 budget 계산·runtime·실제 로컬 프로세스 중단 시험을 현재 확정 dist에서 재사용한다. 같은 DB 시험을 새 분리 원장 인수로 세지 않는다.
- 명시 원장 등록의 정확한 tenant/principal/scope/work 주소, 동시 조회와 등록 철회/교체, 원장 전용 작업과 원문 비공개 경계를 확인한다.
- peer 서비스의 원 request/ticket/reply·중복·재개, 대상 version과 모델/참조 현재성, 호스트 off/등록/종료 경계를 확인한다.
- 서로 다른 SQLite 담당의 일반 profile 입력으로 양방향 consult, 상주/임시 세션 수명, 반론→재평가→필요한 자기 관측, peer/local 전달을 확인한다.
- 모델이 선택한 자원 도구를 실제 분리 원장에 연결해 status/allocate/run/request/increase/return/revoke/reconcile 중 필요한 인수 흐름을 확인한다. 배정 승인과 실행 승인은 분리하며 unknown 사용량·효과를 임의로 반환하지 않는다.

제품 수정은 실행 가능한 결함 증거를 얻은 뒤 최소 범위로 한다. 새 fixture는 기존 서비스 계약을 따르고 공개 packet의 현재 상태·관측을 사용한다. context 창과 무진전 한도를 시험 통과용으로 늘리지 않는다. 빌드 소스를 동결하고 현재 dist 사용 중에는 재빌드하지 않는다.

실행·실패·판정·소스 지문·다음 행동은 `runtime/evidence/checkpoint378.json`과 결과 문서에 저장한다. 실제 모델/API 시험 중단을 유지하며 사내 서비스·외부 peer·PostgreSQL·현재 Linux/native Windows와 운영 품질은 이 로컬 대역 검증으로 완료 처리하지 않는다. 완료 단위는 코드·문서·증거를 함께 커밋·푸시하고 원격 일치를 확인한다.

## 일반 입구 실행 뒤 추가한 교정 범위

target2~4에서 원장 주소, 최초 동료 세션, 도구 스키마/성공 응답 계약, 자원 준비 진전 누락을 실제로 확인했다. 각각 원로그를 보존하고 해당 경계만 교정한다.

자원 실행 승인은 배정 승인과 별개로 매 시도 확인한다. `core.budget.run`의 `budget_authority_denied`만 제한 재시도 가능한 오류로 분류하여, 모델이 처음 제안한 동일 task의 maxAttempts 범위에서 기존 runtime의 backoff를 따른다. 명시 resume나 승인 변경으로 진전 카운터를 지우지 않고, 하드 한도·도구 정책·기타 오류는 이 예외에 포함하지 않는다. 승인된 뒤 같은 grant와 task로 이어지며 새 planner 호출이 필요하지 않은지, 계속 거절되면 원래 시도 횟수와 무진전 한도로 멈추고 수신자 호출·배정 자원은 유지되는지 함께 확인한다.
