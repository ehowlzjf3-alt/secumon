# C09 프로세스 간 관측 제어 전달 결과

2026-09-09 · checkpoint398 · 기준선 `c0a14e9b401aa2426b8975cbecc5c9a85143fce7`.

**다른 프로세스에서 저장한 제어가 대기 중인 resident·mission 관측에 전달되도록 연결했다.** 같은 담당의 실제 CLI 자식 프로세스로 pause·resume·stop을 전달했고, 부모가 원천 응답을 기다리는 동안 중단 신호를 받는 것을 확인했다. 제어 명령의 단일 원자적 저장과 원 영수증 계약은 유지한다.

## 구현

기존 StateRepository에 선택 `revisionHint`를 추가했다. memory는 저장 projection, SQLite/PostgreSQL은 기존 revision 컬럼, 파일은 기존 디렉터리 검사와 발행 기록명을 사용한다. 파일 hint는 검증된 head나 원문 캐시를 갱신하지 않으며 DB 구조와 별도 알림 쓰기를 추가하지 않았다.

공통 `observePendingPoll`은 실제 source.poll 대기 중에만 기본250ms 주기로 변경 후보를 확인한다. 후보가 달라지거나 마지막 정식 검사 후5초가 지나면 현재 권한·전체 상태를 다시 확인한다. 같은 버전이나 파일명만으로 원문 무결성을 보증하지 않는다. 포트를 제공하지 않는 저장소는 정식 검사로 동작한다.

이 검사로 최초 관측 기준이 달라졌음을 확인하면 그 호출의 취소 신호만 전달한다. 빠른 pause→resume 뒤 최종 상태가 active여도 과거 조회는 중단한다. 새 조회는 새 기준을 사용하며 이전 명령의 재전달은 이를 멈추지 않는다. hint 자체로 제어 적용·권한·목표 완료를 확정하지 않는다.

검사는 한 관측 안에서 중첩하지 않고 종료 후 다음 타이머를 남기지 않는다. 늦은 저장소 응답과 source 결과는 끝난 관측이나 이후 관측을 변경하지 않는다. source·저장소 오류를 성공이나 완료로 바꾸지 않는다. 기존 일반 mission은 감지 중단을 원천 조회 실패 횟수 증가로 기록하지 않는다.

## 검증

**동일한 최종 build1에서 신규23개·기존55개, 고유78개가 모두 통과했다.** 실패·취소·건너뜀0이고 재실행하지 않았다.

| 실행 | 통과 | 범위 |
| --- | --- | --- |
| target1 | 15 | 저장소 hint7개, 공통 helper8개: 범위·원문·타이머·직렬화·취소·오류·늦은 결과 |
| process1 | 8 | 실제 CLI resident6개와 일반 mission 명령 프로세스2개; SQLite/file-journal |
| resident1 | 26 | 기존 입구·제어·원천 중단·응답 불명 회복·안정된 명령 재전달 |
| mission1 | 29 | 기존 등록·실행·제어·원천 중단·명령 회복 |

실제 CLI가 종료된 뒤 부모가 저장 변화를 처음 읽도록 감지 조회를 gate한 시험에서도, pause와 resume 두 원 명령을 보존하며 과거 poll만 중단했다. 잘못된 사용자 대화·담당 선택은 거절했고 다른 세션·담당의 조회는 계속 대기했다. 모델·도구 호출0을 확인하는 CLI worker와 원 대화·영수증·자료·예산 보존 단언을 재사용했다.

한 로컬 실행에서 일반 resident pause/stop·격리 제어의 중단 신호는 CLI 종료 기준 약-31.8~213.7ms에 관찰됐다. 음수는 CLI 종료 전에 이미 신호를 받았다는 뜻이다. 일반 mission의 명령 응답 이후 중단 확인은 SQLite 약136.2ms, 파일 약227.4ms였다. 이 값은 소수의 관찰값이며 최대 지연 보장이나 운영 부하 평가가 아니다. gate 시험은 감지 검사를 풀어준 이후의 응답을 별도로 기록했다.

파일 hint6회는 원 기록 읽기0회·원문 해시0bytes, 헤더 읽기12회·메타데이터 확인60회였다. 파일명 열거 비용은 남는다. 같은 파일명 아래 원문을 바꾸면 hint는 그대로일 수 있지만 뒤의 정식 get은 변조를 거절했다. Node 읽기·애플리케이션 해시 계측이며 물리 디스크 I/O나 모델 토큰 계측이 아니다.

build1/core1 exit0, 구조203개/위반0이며 시험 전후 소스·컴파일2,559개 대조가 일치했다. 제품·시험 변경 후 추가 빌드나 시험 반복은 없었다. PostgreSQL은 기존 등록·maintenance 검사와 바인딩된 SQL을 기록 전송으로 확인했으며 실제 서버 연결은 실행하지 않았다.

## 잔여와 한계

이 기능은 활성 resident/mission 원천 조회를 대상으로 한다. 다른 모델·도구 실행 전체를 위한 프로세스 간 취소 버스를 구현한 것은 아니다. 취소에 협조하지 않는 원 source나 이미 시작된 저장소 읽기는 나중에 끝날 수 있으며 원천을 연 호스트의 종료·drain 책임을 유지한다. 기본 감지 간격에 실제 저장소·이벤트 루프 지연이 더해진다.

다음은 **C09 브라우저 미확정 제어 요청의 새로고침 뒤 복원과 실제 화면 조작 검증**이다. 전체 세션 컨텍스트 비용, 동일 목표의 장기 사건 중복 확인·용량·보관, C05 원 수집 완료의 권한 재허용, C06 기억 HTTP·권한·지연·브라우저, C10 초기 복원 중단·현재 Linux/native Windows·실제 PG·네이티브 설치·운영/최종통합을 유지한다.

실제 모델/API 시험은 사용자 중단을 유지했다. 이번에는 macOS arm64의 실제 임시 저장소·로컬 프로세스와 결정적 대역을 사용했다. 사내 MCP/Knox·외부 A2A·배포, 네이티브 Windows/Linux 실행과 실제 브라우저 렌더링은 미실행이다. **전체 C09와 goal은 진행 중**이다.
