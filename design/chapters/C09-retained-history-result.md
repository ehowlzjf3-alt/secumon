# C09 보존 이력과 계속 실행 결과

2026-09-09 · checkpoint401 · 기준선 `b9fa88d5acf051bc34e69d300b4b5a7f3003cc7a`.

현재 관측 상태의 참조 누적을 줄이고, 같은 업무에서512개를 넘는 사건을 원기록과 연결해 이어 받도록 구현했다. 과거 원문은 원영수증으로 조회하며 새로고침·재전달·재시작 때문에 원자료를 삭제하거나 사건을 다시 실행하지 않는다.

## 구현

mission/resident의 새 저장은 검증한 직전 checkpoint 참조만 현재 목록에서 교체한다. 다른 현재 구조가 쓰는 참조, 일반 도구 결과와 근거 자료는 남긴다. 과거 checkpoint 파일·사건·영수증은 그대로 보존한다. 기존 배치에 이미 누적된 참조를 일괄 삭제하는 기능은 추가하지 않았다.

과거 제어 재전달은 정확한 원 명령 영수증에서 자료 참조를 얻어 현재 권한·세션·삭제 세대·원 해시를 확인한다. 일반 현재 상태 조회는 현재 참조가 없을 때 과거 기록으로 우회하지 않는다.

업무 mission의 `seen`은 최대512개짜리 구간이다. 다음 페이지가 이 한도를 넘으면 직전 확정 checkpoint의 명령 ID·발행 revision을 작은 `seenHistory` 연결에 담고 새 구간을 시작한다. 과거 ID는 이 연결을 따라 원문을 대조한다. 연결은 같은 업무·담당·목표·삭제 세대·규칙에서만 유효하고 revision이 감소해야 한다. 누락·차단·충돌을 새 사건으로 처리하지 않는다.

기존 `event_capacity` 종료에는 명시적 `continueAfterCapacity` 호스트 API를 추가했다. 마지막 수락 위치·읽기 확인·기존 제한을 보존하며, 일반 `register` 재전달이나 취소·완료·다른 종료 사유가 자동으로 재개되지는 않는다. 새 정상 구간 교체는512개 한도만으로 종료되지 않는다.

## 측정과 검증

수정 전 checkpoint400의 컴파일 파일 일치를 확인한 기준선과 비교했다. 실제 임시 SQLite/file-journal에서 같은7회 빈 관측을 수행했다.

| 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 현재 관측 자료 참조 | 22개 | 1개 |
| 보존한 checkpoint 원객체 | 22개 | 22개 |
| 마지막 관측의 자료 존재 검사 호출 | 66회 | 6회 |
| 마지막/최대 저장 요청 직렬화 크기 | 10,167bytes | 최대4,938bytes |

원문 저장량이 사라진 것이 아니다. 논리적인 자료 읽기·직렬화 반환량 측정이며 물리 디스크 I/O, 전체 지연 또는 모델 토큰 측정으로 확대하지 않는다. [원 측정](../../runtime/evidence/checkpoint401-measurements.json).

고유75개가 최종 코드에 대응해 통과했다: 신규8개·변경된 기존 경계4개·관련 회귀63개. 최초 target1은10/12, 회귀48/48, resident 제어15/15였다. 새 시험 설정 두 곳을 교정한 build2에서는 과거 자료 경계2개가 통과했고, 동일 원문 반복 읽기가 기본 무진전 제한에 걸린 나머지 시험은 별도 진단 후 유한한 시험용 허용치32를 초기 설정해 build3에서 통과했다. 제품 기본 제한은 바꾸지 않았다.

최종544건 시험은32개씩17페이지를 실제 저장·조회하고 같은 업무에서 실제 로컬 도구17회와 응답 대기를 연결했다. 재시작 후 가장 오래된32개를 중복 처리하고 같은 ID의 변경된 본문은 거절했다. 마지막 checkpoint는3,921bytes, 현재 seen32개와 이전 구간 연결1개다. 실제 모델 호출은0이다. 반복 읽기는 생산적인 추론544건이나 완료된 업무544건을 뜻하지 않으며 무진전 집계를 초기화하지 않았다.

build1부터 build3까지 제품 컴파일 파일은 같다. 달라진 것은 한 시험의 JS·소스맵2개뿐이다. 그 파일 밖72개 결과와 build2의 변경되지 않은 두 사례를 재사용했고 build3에서는 남은544건 사례1개만 실행했다. 최초 실패와 진단 원로그를 보존한다. build3·코어 타입 exit0, 구조204개·위반0, 시험 후2,586개 컴파일 파일과 소스 대조가 일치한다.

## 다음 작업과 보관 제한

다음 로컬 흐름은 **C05 권한 재허용 후 원자료로 완주 → C06 개인기억 대화**다. C09의 물리 보관·이관 인수는 완료로 처리하지 않고 C10에 명시적으로 넘긴다. 로컬 백업은 현재 참조 목록만이 아닌 전체 파일 트리를 복사하며, PostgreSQL 이전은 원 사건·상태 영수증·세션 inbox를 포함하는 기존 경로를 재사용한다.

C10에서는 이번 보존 이력이 실제 백업/복원·이전 후에도 조회·재전달되는지 확인하고, 선택한 배치의 용량과 복원 시간도 측정해야 한다. 현재 로컬 백업의 총4GiB·파일1GiB·10만 항목, PG 전달의 총64MiB 제한을 무제한 보관으로 설명하지 않는다. 이는 로컬 확인도 포함하는 잔여이며 전부 외부 환경 대기로 분류하지 않는다.

file-journal의 전체 원기록 재검증과 디스크 누적, 운영 보관 기간·용량은 남는다. 별도 cold archive·자동 삭제를 추가하지 않았다. 현재 Linux/native Windows·실제 PostgreSQL·사내 MCP/Knox/외부 A2A·운영 인수와 실제 모델 품질은 이번에 검증하지 않았다. 전체 C09와 goal은 진행 중이고 모든 빌드·시험은 종료됐다.
