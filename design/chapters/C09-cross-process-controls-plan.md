# C09 프로세스 간 관측 제어 전달 계획

직전 checkpoint397은 안정된 resident 제어 명령과 CLI/Web 입구 구현, 고유62개 로컬 검증, 커밋·푸시·원격 일치까지 마친 progress다. 이번 시작 때 같은 커밋과 깨끗한 작업 트리를 확인했다.

## 개념과 구현 범위

현재 취소 신호 등록은 한 프로세스 안에서만 공유된다. 다른 CLI 프로세스에서 관측을 일시정지해도 원 저장 상태는 바뀌지만 대기 중 source callback은 응답하거나 기존 제한시간에 도달하기 전까지 살아 있다. 제어 명령의 단일 원자적 저장 계약을 재사용하고, 대기 중인 관측 프로세스가 저장 상태의 변화를 확인하도록 연결한다.

1. StateRepository에 선택적 `revisionHint(workId)`를 추가한다. SQLite/PostgreSQL은 기존 revision 컬럼, memory는 저장 projection, 파일은 기존 보안 경계 안의 발행 기록명을 이용한다. 새 DB 구조나 별도 명령 발행을 추가하지 않는다. hint는 변화 후보일 뿐 권한·원문·제어 완료의 증거가 아니다.
2. 공통 관측 helper를 통해 실제 source.poll이 미완료일 때만 기본250ms 주기로 감지한다. 검사는 중첩하지 않고 다음 검사는 이전 검사 종료 후 예약한다. 후보가 바뀌면 기존 authorize의 현재 권한과 전체 상태 비교로 그 관측의 기준이 유효한지 확인한다. 다른 프로세스에서 pause→resume이 빠르게 지나가도 과거 조회의 기준은 달라졌으므로 과거 조회를 중단한다.
3. 같은 파일명이나 같은 버전만으로 원문 무결성을 보증하지 않는다. 기본5초마다 정식 현재 상태 검사를 수행한다. 정식 검사가 실패하면 그 조회를 중단하고 실제 오류를 유지한다. 감지용 조회 실패도 성공/제어 완료로 바꾸지 않는다.
4. resident 관측과 기존 mission 관측의 공통 대기 경로에 연결한다. 그 호출만의 취소 신호를 사용하고 이전 명령으로 이후 시작한 다른 조회를 취소하지 않는다. 소스가 취소에 협조하지 않으면 원 callback의 종료·drain은 기존 소유 호스트가 담당한다. 모델 호출·게시판 업무·새 작업 실행을 추가하지 않는다.
5. 실제 SQLite/file-journal와 CLI 자식 프로세스에서 대기 중 제어, 원 기록 보존, 재개 후 이전 요청 재전달, 다른 담당/대화 격리를 확인한다. hint의 메타데이터 비용과 정식 원문 검사를 구분한다. PostgreSQL은 가능한 기록 전송 시험과 실제 서버 시험 여부를 명시한다.

## 검증과 잔여

코어 helper의 타이머 정리·중첩 방지·원 오류·늦은 source 결과, adapter의 범위/재열기/변조, 실제 다른 프로세스 제어와 관련 기존 관측 회귀를 확인한다. 변경에 맞는 빌드·코어·구조 검사와 최종 소스 대조를 저장하며 통과한 관련 시험을 이유 없이 반복하지 않는다.

250ms는 감지 예약 간격이며 하드 실시간 지연 보장이 아니다. 저장소·이벤트 루프 지연에 따른 실제 관측 시간을 별도 기록한다. 현재 Linux/native Windows·실제 PG·사내 MCP/Knox·외부 A2A·배포/최종통합, 브라우저 pending 재로드·전체 세션 비용·장기 보관과 C05/C06/C10 잔여를 유지한다. 실제 모델/API 시험은 사용자 중단을 유지한다. 이 단위 완료를 C09/전체 goal 완료로 표시하지 않는다.
