# C09 동일 문제 비교·게시판/임무 결합 결과

2026-09-08 · checkpoint382 · 이번 로컬 단위 검증 완료. 기준선은 `b2684ffaab48953409bf6325b25ff55ddb52b7e2`이다. C09 전체와 전체 goal은 미완료다. [계획](C09-integrated-trials-plan.md)과 [실행 기록](../../runtime/evidence/checkpoint382.json)을 함께 유지한다.

이번 비교는 같은 질문과 원문을 실제 독립 SQLite 담당으로 실행한다. 단독 담당 1개, 협업 담당과 동료 각 1개를 사용하고, 각 담당의 원 상태·원 호출·원 답변과 사용량을 수집한다. 동료 답변은 검토 의견으로 전달되고, 최종 담당이 자신의 자료 조회 도구로 원 근거를 확인한다. 일반 질문 입구를 사용하며 실행 후 목표 조건을 바꾸지 않는다.

## 첫 실행에서 확인한 문제

- build1과 core1은 exit0, 구조 검사196개/위반0이다. 신규9개 시험은3개 통과·6개 실패, exit1이다. 실패 원문과 당시 빌드 지문을 보존했다.
- 게시판과 임무의 알림을 같은 업무에 등록하면 `BoardWatch.current`가 전체 알림과 게시판만 고른 알림을 비교해 정상 상태를 거절했다. 보드 내부 검사는 보드 자료로, 마지막 동시 변경 검사는 원 전체 스냅샷으로 비교하도록 수정했다. 다른 제공자의 커서나 알림만 바뀐 낡은 스냅샷도 계속 거절한다.
- 실제 단독 실행은 완료됐지만 협업은 동료 응답 수신 뒤 원문 조회를 계획한 지점에서 기본 무진전 한도3에 걸렸다. 기존 코드가 정상 peer 응답을 새 준비 정보로 세지 않았다. 한도나 질문을 바꾸지 않고 현재 native 도구의 검증·채택된 응답을 진전에 연결했다. 같은 내용을 반복 수신하거나 도구 설명만 복사해도 진전이 늘지 않는다.
- 기존 평가기는 근거 조건이 있는 조사 업무만 가정해서 일반 답변 목표의 `criteria: []`를 거절했다. 명시적인 고정 답변 oracle과 수집한 원 답변 관측을 선택적으로 추가했다. oracle는 이 시험에서 미리 정한 정답이며, 모델의 자체 점검이나 런타임의 완료 선언을 정답으로 삼지 않는다. 필요한 독립 원문·사실·반대 근거 검사는 유지한다.
- 첫 결합 실행의 `resume_effect_proof_changed`는 원 로그에 보존했다. 이후 build3·4·5에서는 재현되지 않았고 별도 효과 증명 코드는 수정하지 않았다. 이후 단계에서 나온 차단은 아래의 시험 모델 분기 오류로 확인했다.

추가 코드 검토에서 새 응답 관측을 기존 평가 재생기의 엄격한 입력 형식에도 연결해야 함을 확인했다. 저장한 답변 텍스트와 원 산출물 바이트의 일치를 재생 때 확인하도록 연결했다. 읽을 수 있는 파생 자료의 추가 인용은 허용하되, 독립 원문 요구를 대신하거나 철회·누락·순환 부모를 통과시키지 않는다. 실제 저장된 오답은 실패한 평가로 재생되며, 내용을 바꾸거나 자체 점검 결과만으로 정답으로 만들지 않는다.

## 확인된 비교·평가 결과

build2는 선택 필드의 `undefined` 허용 타입 연결에서 실패했고, 타입 교정 뒤 build3은 exit0이다. build3에서 응답 평가8개·응답 재생2개·peer 진전4개·실제 독립 담당 비교1개, 신규15개가 통과했다. 기존 평가·재생·동료 실행·진전의 직접 회귀94개도94/94, core2 exit0·구조198개/위반0이다. 게시판 결합2개는 이 소스에서 실패해 아래처럼 시험 fixture를 교정했다.

[같은 문제의 비교 원기록](../../runtime/evidence/C09-integrated-trial2/collaboration-profile-originals-cJImEa/comparison.json)은 다음과 같다. 협업 수치는 호출자와 동료의 실제 로컬 원장 합계다.

| 로컬 대역 실행 | 단독 | 협업 |
|---|---:|---:|
| 참여 업무 | 1 | 2 |
| 도구 호출 | 1 | 2 |
| 모델 호출 | 2 | 4 |
| 기록된 토큰 사용량 | 560 | 1120 |

| 실제 경과 시간 | 418.449041ms | 1014.377667ms |

동일 원문·질문·정답과 직접 원문 조회 각1회, 최종 전달 각1회를 확인했다. 협업 응답을 먼저 수신한 다음 호출자가 자기 자료 조회를 수행했고, peer 의견은 근거로 승격되지 않았다. 모든 업무의 무진전 한도는3으로 유지했다. 중복 원장을 넣어도 협업의2개 업무 사용량을 다시 더하지 않고, 동료 원장이 빠지면 비용 비교 불가로 표시했다.

이 한 문제에서는 협업의 추가 성공 이득이 없었고 비용만 늘었다. 서로 다른 난도·모순·실패 복구 사례와 실제 모델을 비교하기 전에는 협업의 일반적인 우열을 주장하지 않는다. 과거 근거 중심 oracle를 적용한 동일 원 상태는 계속 `completion_criteria_missing`으로 거절된다. 일반 답변 평가를 지원하기 위해 실제 업무의 조건이나 완료 상태를 나중에 가공하지 않았다.

## 결합 시험과 최종 소스

게시글 본문에는 실제 질문 접두어가 있었지만 첫 시험 기대값은 자료 본문만 가정했다. 원 게시글 전체와 비교하도록 교정한 build4에서 게시판/임무의 독립 원문·영수증 검사, 한쪽 읽기 확인과 철회, 다른 알림 보존·재열기가 통과했다. 같은 공통 fixture를 사용하는 기존 게시판 입구4개도 통과했다.

두 번째 시험은 사건 목록→사건 원문→게시판→자기 자료→게시 후, 앞선 목록이 제한된 도구 관측 문맥에서 빠지자 이미 남아 있는 사건 원문을 무시하고 목록 조회를 반복했다. 시험용 모델이 현재 문맥의 사건 원문과 그 안의 rule을 먼저 사용하도록 분기를 교정했다. 숨겨진 모델 기억이나 캐시는 추가하지 않았다. build5에서 도구5회·로컬 대역 모델6회·기록 토큰1680·재계획4회, 기본 무진전 한도3으로 답변과 완료에 도달했다. 인용 답글, 사건 원문·커서·읽기 확인, 종료 체크포인트와 점유 해제, 재열기 후 보존을 함께 확인했다.

## 범위와 다음 작업

실제 모델/API 중단을 유지했다. 이번 모델과 자료 원천은 결정적인 로컬 시험 대역이다. 실제 SQLite/파일 저장과 일반 프로필·도구 실행을 거치지만, 측정된 시간·사용량을 실제 모델의 품질이나 운영 비용으로 일반화하지 않는다. 메인 프롬프트는 구현되고 실행에 연결되어 있으나 실제 모델 판단 품질은 미검증이다.

다중 임무 rule의 종료 정리와 업무 완료 직후 종료 체크포인트 게시 전 중단 복구는 남아 있다. 이어 C10의 서로 다른 유효 릴리스를 사용한 실제 버전 전환·백업·기존 신원/세션/기억 재열기를 검증한다. 같은 릴리스의 설치 경로만 바꾸는 것은 업데이트 인수가 아니다. C05/C06 잔여 인수, 현재 Linux/native Windows, 실제 사내 서비스·Knox·A2A·PostgreSQL과 최종 통합 인수도 미완료다.
