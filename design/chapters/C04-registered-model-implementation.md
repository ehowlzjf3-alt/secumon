# C04 등록 모델 연결 — 구현 메모

2026-09-07 · Node24 build2·신규 44/44·관련 재실행 245/245 및 NAS Linux 전체 3,253/3,253·8단계를 같은 소스로 통과했다. [검증 결과](C04-registered-model-result.md)와 [확정 증거](../../runtime/evidence/C04-registered-linux-nas-20260907/verification.json)를 기준으로 한다. 첫 신규 시험의 두 실패는 교정했고, 관련 회귀에서 한 번 발생한 기존 동시 초기화 오류는 원인 미확정으로 기록했다. 이전 문맥 창의 Linux 3,209개 통과는 이전 소스의 결과다.

호스트가 제공한 등록표에서 C01 `model.profile` 이름을 조회한다. 모델 생성 함수에는 담당 ID·목적·skills mode만 넘긴다. 반환된 모델의 프롬프트·신원·능력·compact 메서드 쌍·호출 한도를 검사하고, 메타데이터와 함수 참조를 고정한다. 호스트 callback 내부까지 실행 격리한 것은 아니므로 호스트가 구현 버전을 관리해야 한다.

`StructuredSessionCompactAdapter`는 기존 SessionCompactCandidate schema를 포함한 고정 지시문으로 요청을 포장하고, 기존 구조화 모델 응답·usage를 해석한다. 읽은 원문·후보 검증·게시·회수·정산은 기존 코어 책임이다. 고정 지시문과 schema가 바뀌면 입력 추정 설정 지문도 바뀐다.

`StructuredAgentModel`은 주 턴과 compact 어댑터를 같은 신원·목적지·능력으로 묶는다. 두 하위 입력 추정 등록과 주 턴 프롬프트 지문을 합친 값으로 송신 전 현재성을 확인한다. 새 호출 장부나 별도 요약 루프는 만들지 않았다.

CLI `runAgentTurnCli(args, host)`와 Web `openAgentWeb(args, host)`는 같은 프로필 조립을 사용한다. 명시 `--provider registered`는 담당 설정의 이름을 쓰며, HTTP 요청은 이름·권한·코드 경로를 바꿀 수 없다. 기본 `local-contract-v1`은 기존 합성 규칙을 구조화 전송·파서에 통과시키는 로컬 예제다. 사내 transport의 실제 접속 시험을 수행한 것은 아니다.

입력 바이트 상한과 출력 예약은 `composeRuntime`의 선택적 설정으로 일반 planning과 compact 전용 경로에 전달한다. 기존 기본값·업무 예산·원문/개인 기억 저장 형식을 유지한다. 모델 미등록, compact 미제공, 설정 부적합을 다른 제공자로 대체하지 않는다.

생성과 종료 실패를 검토하며 기존 `openAgentStores`가 여러 close 오류 중 첫 번째만 전달하고 open 실패의 cleanup 오류를 버리는 점을 발견했다. 이번 모델·저장소 수명 연결에서 오류가 사라지지 않도록 한정 수정했다. 실제 저장소를 닫은 후 오류를 주입하는 회귀로 나머지 자원도 닫는지 확인할 예정이다. 이 추가는 저장 방식이나 이관 구조를 바꾸지 않는다.

현재 일반 배치의 기본 정책·사용자·도구는 기존 local 구성이다. 등록 모델 이름이 동적으로 권한을 확대하지 않게 했다. 별도 호스트 정책·도구 배치 구성과 실제 사내 MCP 연결은 후속 C05/C06 범위이며 이 연결만으로 운영 배치를 완료했다고 표시하지 않는다.
