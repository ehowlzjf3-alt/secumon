# P0 — 대표 업무, 계약, 구현 선택

2026-09-05 · 진행 중 · 전체 목표의 첫 챕터

## 이번에 배우고 구현할 것

도구 실행 성공과 목표 완료를 구분한다. 공개 문서를 본뜬 합성 문서 비교와 합성 관측 검토에 같은 목표/근거/완료 계약을 적용한다. 실제 내부 자료와 API는 사용하지 않는다.

| 작업 | 구체적인 산출물 | 완료 증거 |
|---|---|---|
| P0-01 | 두 업무군의 단순/복잡 시나리오, 반증/자료 부족/대기/오류/취소와 측정 기준 | 공통 형식으로 읽은 fixture 검증 및 기대 판정 검사 |
| P0-02 | 목표·근거·가설·계획·작업 결과·예산·정책·상태·저장/모델/도구 포트 | 타입/실행 시 입력 검증, revision·부분 결과·저장 경계 계약 검사 |
| P0-03 | TypeScript 제품 경로, 지원 runtime, 첫 영속 구현과 실행 방식 ADR | 격리된 저장소의 대기→종료→재개, 충돌/중복 커밋 적합성 실험 |
| P0-04 | 첫 도구/지침 재사용 판단, 외부 MCP/Knox/컴퓨터 유즈 확인 목록 | 원본 선언/계약 근거와 확인/미확인·대역 대응 표 |

구현은 `runtime/`에 둔다. 원본/아카이브/이전 실험은 변경하지 않는다. domain은 업무 규칙, application은 포트/실행 시 입력 검증·유스케이스, infrastructure는 저장소/모델/도구 구현, presentation은 CLI/Web 경계로 시작한다. 사용자 지시로 제공된 현재 Workflow Rules와 전체 구현 요청을 따른다. 상위 폴더의 이전 승인/자동 분할 규칙을 근거로 반복 승인을 요청하거나 기존 자료를 옮기지 않는다.

기술 비교 기준은 TypeScript + 지원 중인 Node.js LTS, 작은 자체 상태 루프, SQLite 첫 adapter다. 정확한 버전과 선택 이유는 공식 자료 및 실제 적합성 시험 후 ADR로 확정한다. SQLite/SQL은 저장 포트 밖에 둔다. 완전한 외부 workflow 엔진은 대기/복구 의미를 비교하고 초기 운영비와 이중 상태 관리 비용을 함께 평가한다.

P0의 모델 대역과 판정 fixture는 추론 품질의 증거가 아니다. 중단된 API 시험은 재개하지 않는다. 실제 모델/사내 MCP/Knox 명세가 필요한 검증은 별도 외부 의존성으로 남기며 대역 통과로 완료 처리하지 않는다.

각 작업 끝에 실행 명령/환경·결과·남은 한계를 기록하고 작업 목록을 갱신한다. 이 문서의 계획 자체는 구현 완료 증거가 아니다.
