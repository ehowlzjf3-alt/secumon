# P4 역할 간 자원 배정 권한과 정산 라우팅

## 개념과 결과

자원을 지원하는 역할과 자료를 읽는 역할은 같지 않을 수 있다. 부모는 사용할 수 있는 몫을 배정하고 소비량을 정산하지만, 그 사실만으로 자식의 원문을 읽을 수 있게 되지는 않는다. 이번 구현은 이 경계를 기존 예산 장부에 연결한다.

기존 같은 주체의 하위 작업은 정책을 축소하는 경로를 유지한다. 다른 역할에는 host가 확인하는 위임 참조가 필요하다. 참조는 제공자·업무 참조·규칙 개정·자식 목표 개정을 포함하며, 현재 확인에는 부모/자식 작업·주체·정책·범위·배정량·기한을 전달한다. 같은 참조에 grant 두 개를 만드는 것은 새 명령 ID나 규칙 개정을 이용하더라도 거절한다.

배정 허용과 실행 허용은 구별한다. host는 요청 수락 준비를 위해 몫을 예약하면서 실제 모델/도구 실행은 아직 허용하지 않을 수 있다. 허용 여부는 계획·예약·실행 진입 및 도구의 재인가 경로에서 확인한다. 권한 조회가 멈추면 남은 기한과 최대 10초 안에 거절하고 취소 신호를 전달한다.

정산은 host의 `BudgetRuntimeRouter`가 자식 주체에 등록된 runtime으로 전달한다. 하위 작업이 다시 위임한 경우도 같은 경로를 사용한다. 등록은 host 구성 기능이며 에이전트의 도구 입력으로 세션을 선택하지 않는다. 모델에 공개할 배정 조회 도구는 다음 단위에서 별도로 연결한다.

## 상태와 복구

- 배정 후에는 전액을 예약한다. 자식의 사용량을 여러 번 조회해도 예약액과 사용량을 이중으로 더하지 않는다.
- 종료·취소·명시 권한 철회가 발생하면 새 실행을 차단하고 진행 중 호출을 중단시킨다. 사용량/효과가 불명확하면 예약액을 유지한다.
- 실제 사용량과 종료가 확인돼야 미사용 예약을 반환한다. 사용량이 늦게 도착해도 같은 실행 기록으로 한 번만 반영하고, 취소된 모델의 계획은 채택하지 않는다.
- 권한 reader의 일시 장애는 철회와 구분한다. 기존 예약과 활성 연결을 유지한 채 실행을 막으며, reader가 복구되면 새 grant 없이 재개한다.
- 역할 runtime이나 효과 증명이 없으면 예약액을 성급히 반환하지 않는다. 최종 증명 조회 중 자식 상태가 바뀌면 정산을 다시 확인한다.
- compact는 모델 문맥을 줄인다. 권한 참조와 장부의 정본은 작업 저장소에 남으며, 재시작 후에도 사용량을 초기화하지 않는다.

## 다음 구현

현재 제공하는 것은 host 권한 port와 역할별 runtime 라우터다. 실제 게시판 funding 정책 adapter, 요청 수락을 통한 실행 허용 전환, 에이전트가 조회·배정·추가 요청·회수/재배정을 결정하는 도구는 아직 연결하지 않았다. 따라서 P4-01과 전체 목표는 진행 중이다.

다음에는 위임된 작업을 누가 준비하고 누가 수락하는지 명확히 연결한다. 수락 준비는 host의 제한된 절차로 처리하고, 수락 이전의 임의 모델/도구 실행은 막는다. 에이전트는 준비된 역할 프로필과 잔량을 보고 배정량을 결정하며, 런타임은 같은 장부·영수증·자료 경계를 집행한다. 추가 배정/회수는 사용 중 예약량을 건드리지 않는 절차로 구현한다.
