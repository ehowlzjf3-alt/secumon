# C10 설치 버전 전환과 담당 연속성

2026-09-08 · checkpoint384 · 기준선 `5f7157da9fde4b8c642a93b5e3f5734d69f8b350`. 시작 시 main 작업 트리는 깨끗했다. 직전 C09 단위는 최종 소스34개 통과·결과 저장·커밋/원격 일치로 진행했다. 전체 goal은 미완료다.

설치된 엔진은 교체할 수 있지만 담당 디렉터리의 ID·설정·세션·개인 기억·업무 원기록은 같은 자료로 이어져야 한다. 버전 pin은 담당이 사용할 배포본의 지문을 고정하는 기록이다. 자료 백업은 별개이며, 업데이트가 과거 업무를 다시 실행하거나 DB를 초기화해서는 안 된다.

1. 기존 `bundleAgentEngine`, `installAgentEngine`, `checkAgentLifecycle`, `pinAgentEngine`, `backupAgent`와 실제 설치 CLI/probe를 재사용한다. package를 설치/재설치했던 기존 시험을 실제 다른 release 전환의 인수로 대체하지 않는다.
2. 실제 런타임·의존성·CLI를 포함한 서로 다른 유효 호환 시험 release를 정상 bundler로 만든다. `release.json`만 바꾸거나 같은 release의 설치 경로만 옮기는 no-op을 업데이트 통과로 세지 않는다. 호환 코드 전환과 스키마 이행·실제 운영 release는 구분한다.
3. 첫 엔진으로 담당 설정·기억·지속 세션·미완료 업무를 만들고 원 입력/영수증/사용량/자료를 기록한다. check→첫 pin→offline backup→다른 release update→두 번째 설치 엔진으로 같은 담당/세션/기억 재열기→원 업무 resume을 실행한다. 이전 엔진의 실행 거절과 새 엔진의 실제 실행, 현재 pin/이전 pin/백업 지문을 확인한다.
4. 현재 pin 불일치, 오래되거나 다른 담당의 백업, 실행 중 유지보수, 지원하지 않는 저장 버전/변경된 배포 파일을 직접 검토하고 필요한 실패·원자료 보존 시험을 추가한다. 기존 시험과 겹치는 검증은 반복 구현하지 않는다. 현재 소스가 요구를 만족하면 제품을 억지로 바꾸지 않는다.
5. root가 작성자 동결 후 Node v24.20.0으로 빌드·신규 대상 시험·발견된 실패 교정·직접 영향 회귀와 코어/구조 검사를 수행한다. 시험이 살아 있는 동안 dist를 재빌드하지 않는다. 실행 핸들·실패 원로그·소스 지문을 checkpoint에 저장한다.
6. 결과·현재 계획·백로그·다음 행동을 갱신하고 완료 단위를 origin/main에 커밋·푸시하여 원격 일치를 확인한다. C10 전체/최종 운영 인수는 구현·실행 증거가 뒷받침하는 범위로만 판정한다.

실제 모델/API 중단을 유지하며 사내 서비스·외부 A2A·PostgreSQL·registry 게시·운영 배포는 하지 않는다. macOS는 개발/로컬 환경이며 이번 결과를 현재 Linux/native Windows로 확대하지 않는다. C09 잔여·C05 정책 재허용 완주·C06 기억 HTTP/권한/브라우저·플랫폼·최종 통합은 보존한다.

## 이어서 구현할 확장 호환 경계

읽기 검토에서 V10-01의 확장 호환은 아직 공통 계약이 없음을 확인했다. 이는 범위에서 제외할 기능이 아니라 C10 후속 구현이다. 현재 config는 모델 등록 이름·기능 선택·PG 등록 ID를 가지며 확장 파일을 로드하지 않는다. 호스트가 `AgentExecutionHost`의 등록 객체를 직접 주입한다. 담당 ID 등록표를 확장 등록표로 바꾸지 않는다.

공통 엔진 API 버전/필수 기능 선언을 각 호스트 등록의 고정된 정보에 포함하고 `EngineReleaseSchema.compatibility`의 지원 범위와 대조하는 검증을 기동 전과 lifecycle check/pin/update에서 공유한다. 기동은 선택 등록을 캡처한 후 저장소나 확장 콜백을 열기 전에 검사한다. 꺼진 기능은 열지 않는다. 모델 revision·도구 version·MCP protocol·A2A 1.0·peer schemaVersion·Knox send/lookup 능력은 각각 기존 의미를 유지한다. 이미 있는 등록 복사·권한·입출력 검증·부분 정리 로직을 재사용하고 새 플러그인 로더를 만들 필요는 없다. 현재 저장소 호환 확인만으로 확장까지 호환된다고 표시하지 않는다.

## 이어서 연결할 전역 실행기의 버전 선택

[설치/버전 계획](installation-and-versioning.md)은 공통 전역 명령에서 담당별 고정 엔진을 선택하는 흐름을 요구한다. 현재 npm bin은 해당 설치의 `agent-cli.js`를 직접 실행하고, 다른 엔진으로 고정된 담당은 실행 호환 검사에서 거절한다. pin에 기록된 다른 엔진을 전역 입구가 자동 선택해 실행하는 연결은 아직 없다. 이번 설치 B의 명시 CLI 실행을 전역 자동 선택의 완료로 계산하지 않는다. 기존 배포 지문·담당 pin·원 경로/권한 검사를 재사용해 이 연결을 C10 후속으로 구현하며, 실제 API·자동 다운로드를 추가하지 않는다.
