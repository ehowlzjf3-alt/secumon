# P1-07 — 상태 기반 재개와 첫 전체 실행 흐름

2026-09-05 · 로컬 구현 계획 · 실제 모델 선행 검증은 별도 유지

이번 질문은 “대화 창과 프로세스가 사라진 뒤 무엇으로 이어가는가?”이다. 목표·기준·가설/반증·작업 그래프·호출 장부·대기 의무는 저장 상태가 기준이다. 재개 패킷은 그 상태에서 다시 만든 입력이며, 과거 패킷이 최신 목표나 권한을 덮어쓰지 않는다.

## 구현 범위와 순서

1. 모델 ContextPacket 생성을 공통 함수로 분리하고 현재 예산·기한·작업 시도를 포함한다. 현재 근거와 가설이 인용하는 허용된 과거 근거를 보존한다. 원문은 artifact 참조로 남긴다.
2. ContextRecovery는 workId/호출자 확인 후 state → events/outbox → state의 revision을 대조한다. 순서가 맞는 사건 cursor와 원본 참조를 확인하고, 내부 실행용 ResumePacket을 파생 artifact로 저장한다. 패킷 저장 자체는 업무 revision/호출 예산을 바꾸지 않는다.
3. 이전 패킷은 엄격한 형식·내용·현재 상태·도구 명세 digest와 비교한다. 같으면 재사용하고 오래됨/손상/누락이면 현재 상태로 재생성한다. 파생 패킷 유실과 원본 유실을 구분한다. 원본이 없으면 복구 오류와 참조를 반환하고 실행을 시작하지 않는다. 패킷에는 메시지/원문 본문을 복사하지 않는다.
4. WorkflowRuntime은 접수 안내, planning 또는 명시 계획 execution, 결과 준비, outbox 전달, 완료 판정을 연결한다. 명시적 workId로 제한된 step만 진행하고 대기/unknown에서 반환한다. CLI는 이 공통 실행 경로를 사용하되 기본 합성 명시 계획을 유지한다.
5. 두 업무군의 접수→결과와 실제 별도 프로세스 강제 종료→재시작 시험을 추가한다. 실행 전, 원천 응답 후 수신 저장 전, 수신 저장 후 수락/답변 전, 수신 채널 저장 후 전달 확인 전을 구분한다. 쓰기 효과/모델 비용을 잃은 경우 unknown을 유지하고 중복 발송·허위 완료를 막는다.

재사용: 기존 StateRepository/ArtifactStore/CAS, ExecutionRuntime/PlanningRuntime, validator, ConversationService, OutboxDispatcher, SQLite/로컬 채널과 합성 fixture. 안쪽 계층은 DB·파일·채널 SDK를 참조하지 않는다.

## 완료 기준과 한계

- 대화를 전달하지 않은 재시작에서 목표·반증·의무·원본/호출 참조를 복원한다. 이전 패킷으로 목표 변경·취소·권한 철회를 되돌릴 수 없다.
- 파생 패킷 크기 초과를 명시적으로 거부한다. 중요한 항목을 조용히 잘라내지 않는다. 저장/복원 검사 중 revision이 바뀌면 제한된 재검사를 한다.
- 저장한 응답의 수락/전달 재개는 원천 도구/모델을 다시 호출하지 않는다. 수신 저장 전 읽기 응답 유실은 기존 재시도 계약을, 쓰기 효과 불명은 기존 대조 의무를 따른다.
- 같은 이벤트/outbox revision만을 반복 진전으로 보지 않고, unknown 전달은 한 번의 제한된 flush 이후 반환한다.
- 새 packet은 내부 실행용이다. 제한된 리드/외부 역할에 공개하는 view는 P2-06에서 별도 검증한다. 현재 모델 packet도 기존 정책 경계를 유지한다.
- 검토 후 범위를 구체화했다. P1 workflow는 전체 권한의 소유자 역할만 실행하며 명시 제한을 가진 actor는 거부한다. 호출자 상한을 dispatch까지 고정하는 후속 계약 없이 제한 실행을 지원한다고 표시하지 않는다.
- 자동 상주 worker/전체 runnable 검색, 고급 compact·미사용 도구 퇴거·조직 기억·GC·백업 복원은 후속 범위다. 기존 원본 유실 시 일반 commit이 거부되는 제약을 숨기지 않는다.
- 실제 provider transport·모델 추론 품질·사내 MCP/Knox·컴퓨터 유즈는 실행하지 않는다. P1-06/P1-07 전체 작업 완료는 이 실제 검증을 대역 시험으로 대체하지 않는다.

검증: Node 24.20.0의 기존 npm run verify, 새 복구/통합 실패 시험, 원본 1,973파일 불변·문서 링크·JSON·작업 상태 일관성 확인. 결과·실패·선택 근거·소스 hash는 별도 결과 문서와 evidence에 저장한다.
