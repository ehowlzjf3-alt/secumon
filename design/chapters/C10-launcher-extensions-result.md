# C10 전역 실행기·확장 호환 결과

2026-09-08 · checkpoint385 · 기준선 `242d0b15994688336c86bbff628863564e9a4104`.

**같은 전역 명령이 담당별로 고정한 설치 엔진을 선택하고, 선택 확장의 엔진 API 호환을 검사하도록 연결했다.** 기존 설치·배포 지문·pin 이력·저장·업무 실행 코드는 재사용했다. [사용법](C10-launcher-extensions-usage.md) · [계획](C10-launcher-extensions-plan.md).

## 달라진 동작

- 전역 bin 경로를 유지하고 담당 경로와 pin을 읽는다. 현재 실행기 외의 설치본은 호스트의 별도 등록표에서 경로·배포 지문·디렉터리 객체를 확인한 뒤 실행한다. 같은 내용의 다른 폴더 등록을 빌려 쓰거나, 미등록·분실·변조된 설치를 다른 버전으로 대체하지 않는다.
- `lifecycle install`은 정상 설치 뒤 등록도 수행한다. 이미 설치했거나 등록만 실패한 경우 `lifecycle register`로 동일 설치를 등록한다. pin이나 담당 config 자체는 임의 코드 경로의 실행 권한이 아니다. 관리 명령은 현재 입구에서 계속 사용할 수 있다.
- 네 CLI가 같은 옵션 명세를 사용하므로 원문에 들어 있는 옵션 모양의 문자열을 담당 경로로 오인하지 않는다. 선택한 자식 엔진은 shell 없이 argv·작업 디렉터리·표준 입출력을 이어받는다. 부모에 도착한 종료 신호를 전달하고 자식의 실제 종료를 기다린다.
- 모델·도구·Knox·게시판·아카이브·동료·A2A·임무·자원·선택된 PG 등록에 공통 `engineApi` 선언을 추가했다. 선택 등록만 캡처하여 저장소/콜백 기동 전에 검사한다. 미선언은 `unverified`, 호스트 엄격 정책에서는 거절이다. 선언한 API/필수 기능의 비호환은 항상 거절한다. 선언 검사와 실제 서비스/모델 품질은 별개다.
- 같은 검사를 로컬/PG check·pin·update에 연결했다. 호스트가 확장 목록을 제공하지 않은 셸 lifecycle은 목록을 검사했다고 표시하지 않는다. CLI JSON과 Web/Knox 호스트 반환 정보에 결과가 있고 `chat status`는 미검증 상태를 표시한다. 새 Web 관리 화면이나 Knox 반복 알림은 만들지 않았다.

읽기 검토에서 등록표를 너무 일찍 닫는 문제, 사라진 디렉터리의 `null` 재검사 누락, signal 전달 오류 뒤 살아 있는 자식 수명 관리가 끊기는 문제를 찾아 보완했다. 등록표는 배포 검증 이후 다시 읽으며, 실제 release 읽기 중 등록 원문을 바꾸는 재현 시험에서 거절을 확인했다. 동일 OS 계정이 검사와 실행 사이에 파일을 바꾸는 모든 경우를 원자적으로 막는 샌드박스라고 주장하지 않는다.

## 남은 작업

다음은 [고정 전달 형식과 compact된 세션의 버전 전환](C10-launch-envelope-plan.md)이다. 그 뒤 신규 setup 완료 전에 최초 pin을 고정하는 경로와 npm/개발 설치의 검증 release 준비를 구현한다. 기존 무핀 담당을 신규로 오인하거나 `offline:true`를 내부에서 꾸며내지 않는다.

현재 이전 입구가 모르는 CLI 옵션은 원 parser가 거절하며 자동 최초 pin은 아직 없다. 저장 schema 이행·미확정 외부 효과, C09 취소/목표 변경/일시정지·저널 응답 불명·이력 비용, C05 재허용 완주, C06 기억 HTTP/권한/브라우저, 이번 소스의 Linux/native Windows·실제 PG/사내 연동·패키지 효율·운영 배포·최종 통합은 미완료다. 실제 모델/API 중단을 유지한다. C10과 전체 goal은 완료되지 않았다.
