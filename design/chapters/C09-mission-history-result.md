# C09 현재 규칙과 사건 이력 결과

## 구현 결과

새 목표에서 같은 규칙 ID를 다시 등록할 수 있다. 현재 목록에서 과거 목표의 닫힌 mission 규칙 자리를 반환하며, 원문·사건·checkpoint·영수증은 보존한다. 새 목표는 새 커서·빈 관측/중복 확인 목록·점유 없음으로 시작한다. 현재 목표의 동일 ID 재시도는 그대로 반환하고 내용 변경은 충돌로 거절한다. 현재 목표에서 닫힌 규칙을 자동 재개하지 않고 다른 provider의 규칙도 정리하지 않는다.

목표 변경의 저장된 상태를 이용하므로 과거 source를 제거한 배치에서도 새 source 규칙을 등록할 수 있다. 원 checkpoint 본문은 당시의 active 상태를 보존할 수 있으며, 이후 원 goal 명령 영수증에 종료가 기록된다. 과거 본문을 현재 상태로 덮어쓰지 않는다. refresh의 종료 복구는 기존 증명 검사를 유지한다.

StateRepository에 원문 페이지 조회를 추가하고 memory/SQLite/file-journal/PostgreSQL에 연결했다. 상태 번호 범위, 사건 순번, 종류, 최대 128개를 지정한다. 제어 확인은 checkpoint 발행 뒤부터 현재 기준 상태까지의 user_command만 페이지당 32개 읽는다. 완료 복구는 최신 완료 뒤의 최대 16개 종료 기록을 원 완료 영수증에 순서대로 적용하여 현재 상태와 대조한다.

동일 증명 안의 발행 영수증 중복 조회를 제거했다. 저장 직전에는 새로 읽으며, 그 사이 제어 영수증이 달라진 경우 저장을 거절하는 시험을 유지했다. 저장소 포트 전달·읽기 전용 평가·자원 소유자 조회 거부 경로에도 새 메서드를 연결했다. 원문 접근 권한이나 파일 저널의 전체 원파일 검사를 완화하지 않았다.

## 조회량 측정

- 185개 사건의 원문 전체 반환량은 513,942 bytes였다. 동일 구간을 검증하는 두 번의 제어 증명은 합계 6페이지/132개/27,522 bytes를 반환했다. 발행 영수증은 두 독립 증명에서 합계 2회 읽었다. 과거·다른 종류의 본문을 읽기 결과에 포함하지 않는다.
- 별도 파일 저장소 시험의 96개 사건 전체 반환은 410,032 bytes, 마지막 2개 페이지는 8,548 bytes였다. 두 방식 모두 원기록 12개를 읽고 422,489 bytes를 해시했다. 범위 밖의 오래된 원기록이 바뀌면 페이지 조회도 거절했다.
- 앞의 임무 파일 시험 전체 연산에서 원기록 읽기 90회/해시 7,632,300 bytes를 측정했다. 페이지 반환량·중복 영수증 감소와 전체 저장소 I/O 비용은 다르다. 수치는 Node 조회/해시 계측이며 실제 물리 디스크 I/O나 LLM 토큰 사용량이 아니다. SQL도 반환 본문 수를 제한하며 드문 종류를 찾는 모든 행 검사량이 상수라고 주장하지 않는다.

## 미완료와 다음 작업
