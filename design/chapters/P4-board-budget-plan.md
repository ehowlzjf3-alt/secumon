# P4 역할 간 실행 자원 배정·반환·정산과 요청 수락 조건

2026-09-06 · 역할 간 권한/정산 로컬 검증 완료 · 게시판 수락/에이전트 배정 연결 진행 중

사용자는 예산이 턴 수를 뜻하는지 확인한 뒤 배정·반환·정산도 필요하다고 짚었다. 역할 간 자원 관리를 선택적 후속으로 미뤘던 판단을 정정하고 P4-01의 구현 범위로 유지한다. 여기서 예산은 모델/도구 호출 수·토큰·재계획 등의 실행 자원 한도다. 대화 한 턴 안에서도 모델과 도구를 여러 번 호출하므로 사용자 채팅 턴 수와 같지 않다. 금액 환산은 제공자별 선택 기능이며 필수 코어 계약이 아니다.

사용자가 작업마다 숫자를 입력할 필요는 없다. 사용자의 추가 지시에 따라 배정·추가 배정·회수 판단도 에이전트가 담당한다. 리드/planner는 업무 난이도·우선순위·남은 자원·실제 진척을 보고 작업별 몫을 정하고, 작업 에이전트는 잔량과 추가 필요량을 보고한다. 부족하면 전체 허용량 안에서 다른 예약량을 안전하게 회수하거나 배정을 조정하고, 계획을 변경한다. 단일 에이전트도 같은 정책을 자기 하위 작업에 적용한다.

런타임은 배치 정책과 실행 모드의 기본 한도를 적용하고, 에이전트의 결정을 권한·잔량·기한·현재 실행 상태에 맞춰 검증·집행한다. 실제 사용량 기록·정산·중복 방지·종료 시 미사용 몫 반환은 런타임이 자동으로 처리한다. 에이전트가 숫자를 작성했다고 실제 사용량이나 영수증을 대체하지 않으며, 할당 권한만으로 전체 허용 한도나 자료 접근 권한이 확대되지 않는다. 기본 실행 한도·취소·무진전 제어와 기존 같은 주체의 부모/자식 장부를 재사용하고, 역할 간 권한과 요청 생명주기에 연결하는 부분을 구현한다. 역할 간 권한/정산 경계는 로컬 검증했다. 실제 게시판 수락과 에이전트 배정/재배정 도구 연결은 P4-board-funding-plan.md에 따라 이어간다.

## 의미와 동작 예시

- 배정: 부모의 사용 가능한 자원에서 자식 몫을 예약해 다른 작업이 중복 사용하지 못하게 한다.
- 정산: 실제 실행 기록과 사용량을 확인해 소비량을 반영한다. 사용량과 작업 성공 여부는 별개이며 실패한 호출에도 사용량이 발생할 수 있다.
- 반환: 더 이상 실행되지 않을 것이 확인된 미사용 예약량을 해제한다. 취소 요청이나 기한 경과만으로 실행 중인 호출의 몫을 반환하지 않는다.
- 대조·복구: 응답 유실, 실행 중 종료, 미확정 사용량은 보류 상태로 저장하고 재시작 후 확인한다. 같은 영수증의 재처리로 중복 차감·중복 반환이 발생하지 않아야 한다.

예를 들어 다른 소비가 없는 도구 호출 한도 100회에서 역할 A에 30회를 배정하면 새로 배정 가능한 몫은 70회다. A가 12회를 사용한 뒤 진행 중인 호출 없이 종료하면 소비 12회를 정산하고 미사용 18회를 반환해 가용량은 88회가 된다. 이 예시는 도구 호출 횟수라는 한 차원이며 토큰·모델 호출·재계획은 각 차원으로 관리한다. 배정·정산·반환은 의미상 구분하되 상태 반영은 원자적으로 하거나 멱등한 복구 절차로 처리한다.

시간은 별도로 다룬다. 마감 시각과 경과 시간은 더해서 나눠 갖거나 반환하는 자원이 아니며, 동시 실행 슬롯은 실행 중 점유하고 종료 확인 후 해제한다. 제공자 사용량이 누락되면 0으로 추정하지 않는다. 토큰은 예약 추정치와 실제 관측값을 구분하고 초과 사용이 확인되면 그대로 기록한 뒤 새 배정을 차단한다.

한도 도달은 목표 완료가 아니다. 상태·근거·미확정 호출을 보존하고 정책에 따라 대기·재개·재계획한다. 공정한 역할 실행기는 배정 가능한 작업을 선택하고, 다른 역할의 대기 때문에 특정 역할이 자원을 계속 점유하는 상황도 검증한다.

요청 발견과 재개가 가능해졌으므로, 요청을 받는 역할이 사용할 시간·모델·도구 예산을 수락 전에 확인한다. 상대에게 요청을 보낼 수 있다는 권한과 비용을 배정할 권한, 자료를 읽을 권한은 각각 확인한다. 기존 일반 예산 장부와 실행 경계 검사를 필요한 범위에서 재사용한다.

## 구현 순서

현재 구현 단위는 역할 간 배정의 권한 계약과 실행/정산 경계다. 영속 grant에 host가 확인하는 위임 참조를 묶고, 수락 준비 단계의 배정 허용과 실제 실행 허용을 구분한다. 자식 역할의 효과 증명 갱신/중단은 host가 해당 역할의 runtime으로 전달한다. 이 경계를 검증한 다음 게시판 요청 수락과 planner의 배정/재배정 도구를 연결한다. 첫 단위 통과를 전체 에이전트 자원 관리 완료로 표시하지 않는다.

1. 요청을 보낸 작업의 예산을 배정받는 경우와, 수신 역할이 자기 예산을 사용하는 경우를 구분한다. 이미 존재하는 parent/child 예산 port·영수증·정산 계약을 확인하고 같은 주체라는 가정이 있는 지점을 좁게 조사한다.
2. tenant·요청·부모/자식 작업·목표 개정·한도·기한에 묶인 수락 조건을 정의한다. host가 권한을 확인하며 역할이 다른 작업의 상태나 자료 정책을 직접 넓히지 않는다. 요청 메타데이터만으로 예산 사용 권한을 만들지 않는다.
3. 요청 수락과 예산 예약 사이의 부분 실패를 영수증으로 복구한다. 배정 미확정 상태에서 모델이나 도구를 실행하지 않고, 같은 요청의 중복 수락으로 배정액이 증가하지 않도록 한다.
4. 답변 완료·거절·취소·기한 경과·목표 변경·프로세스 종료 시 실제 사용량과 남은 예약액을 정산한다. 요청의 완료와 비용 정산의 완료를 별도로 검사한다.
5. planner의 배정·추가 요청·회수/재배정 판단을 잔량 및 실제 진척 조회와 연결한다. 잔량이 부족하면 자동 재배정 또는 재계획하고, 한도에 걸린 작업을 완료로 표시하지 않는다. 에이전트가 매 호출마다 예산 관리 도구를 호출하지 않도록 사용량 기록/종료 정산은 런타임의 기존 실행 경로에 연결한다.
6. 두 업무군과 두 저장소에서 예산 부족·동시 수락·수락 중 응답 유실·실행 중 취소·중복 정산·compact/reopen을 검증한다. 추가 배정 요청과 반환된 자원의 재배정도 사용자 개입 없는 고정 planner 흐름으로 검증한다. 모델과 사내 서비스는 로컬 대역을 사용한다.

## 완료 기준

- 권한 없는 배정과 다른 tenant/목표/요청에 대한 배정 재사용을 거절한다.
- 실제 호출이 예약 한도를 넘지 않고, 반환/정산은 중복 적용되지 않는다.
- 예산 회수가 불확실한 동안 새 지출을 막고, 이미 발생한 효과와 사용량 기록을 보존한다.
- 에이전트가 배정/재배정을 결정하고 런타임이 실제 장부를 집행한다. 정상적인 배정·정산·반환에는 사용자 입력이나 승인을 요구하지 않으며, 실제 모델 판단 품질과 고정 대역의 계약 검증을 구분한다.
- 사용자가 지시한 범용 코어·저장소 독립성·Python 없는 런타임을 유지한다.
- 전체 검증 및 실패 원인·한계·다음 단위를 파일에 기록한다. 원래 Python 코드와의 비교는 선행 조건이 아니다.

그 뒤에는 역할별 공정한 실행/재개 dispatcher와 제한된 로컬 planner 평가를 연결한다. 두 runtime의 가설·반증·재계획·완료를 평가한 뒤 실제 모델 검증 여부는 별도 사용자 지시를 따른다.
