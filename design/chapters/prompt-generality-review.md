**현재는 범용 에이전트의 공통 메인 턴 프롬프트가 구현되어 어댑터에 연결돼 있다.** [agent-turn-prompt.ts](/Users/seunghanee/Documents/secumon/runtime/src/infrastructure/agent-turn-prompt.ts)의 `createAgentTurnPrompt`가 공통 지침·담당 목적·스킬 모드·응답 schema를 구성한다. [StructuredAgentTurnAdapter](/Users/seunghanee/Documents/secumon/runtime/src/infrastructure/structured-agent-turn.ts)는 이를 생성하고 요청의 프롬프트·담당 신원을 대조한 뒤 호스트 전송 입력에 포함한다.

- 결과는 `answer`(직접 답변·작성), `question`(필요한 추가 질문), `plan`(허용된 도구 작업 제안) 중 하나다. 간단한 요청에 도구나 가설을 억지로 만들지 않는다.
- 이전 합의·정정·미해결 질문을 이어가되 이전 업무의 계획·결과를 현재 업무와 합치지 않는다. 세션 원문과 요약을 구분하며, 조사에는 가설·지지 근거·반증·대안 설명을 사용한다. `counterarguments`는 검토한 반론, `missing`은 미해결 사항이며 모델 자기검토는 독립 검증이나 완료 허가가 아니다.
- 제공된 도구 계약과 현재 식별자만 사용하고 필요할 때 발견·조회를 제안한다. 명시된 저장 완료 수집의 재개 제안 예외도 원 checkpoint·권한을 런타임이 다시 확인한다. 스킬은 `off`/`explicit`/`on-demand`를 따르며 방법론을 제공할 뿐 권한을 늘리지 않는다.
- 프롬프트는 행동 지침이다. 실행·계획 및 응답 채택·상태 변경·완료 판정·compact 적용은 [PlanningRuntime](/Users/seunghanee/Documents/secumon/runtime/src/application/planning-runtime.ts), [WorkflowRuntime](/Users/seunghanee/Documents/secumon/runtime/src/application/workflow-runtime.ts), [SessionCompactRuntime](/Users/seunghanee/Documents/secumon/runtime/src/application/session-compact-runtime.ts) 등 코드의 검사를 거친다.

이는 **구현·연결 상태**의 확인이다. 실제 모델의 범용 추론·반론·도구 선택·한국어 응답 품질은 검증하지 않았으며 모델/API 시험 중단을 유지한다. 아래 2026-09-06 본문은 당시 계획용 프롬프트만 확인했던 역사 기록으로 보존한다. 그때의 “전체 메인 프롬프트 미완성” 판단을 현재 구현 상태로 읽지 않는다.

## 결론

현재 계획용 프롬프트는 특정 보안 업무나 고정 리드–워커 조직을 요구하지 않는다. 사실·가설·반증·미확인 정보를 구분하고 단순 작업에 가설을 강제하지 않는 기반은 범용 목적에 맞는다. 다만 이것을 지속 대화형 범용 에이전트의 전체 메인 프롬프트가 완성·검증되었다는 의미로 설명하면 안 된다.

사용자는 설치와 운영 논의로 범위가 커진 상황에서 현재 프롬프트의 범용성과 품질을 질문했다. 이번 검토로 기능을 추가하거나 구현 보류를 해제하지 않는다. 설치·버전 관리 요구는 유지하되, 구현 재개 시 실제 한 담당의 대화·실행 품질 확인을 우선할 것을 권고한다.

## 구현 재개 시 정리할 프롬프트 경계

다음은 검토 권고다. 이미 모두 구현되었다는 뜻이 아니며, 각 항목을 별도 모델 호출이나 별도 상주 에이전트로 만들 필요도 없다.

1. **공통 행동 원칙**: 사용자의 의도 확인, 간단한 요청의 직접 처리, 필요한 계획·도구 사용, 결과 확인, 불확실성 표현, 불필요한 반복 억제. 특정 업무의 담당 이름이나 시스템 이름을 공통 본문에 고정하지 않는다.
2. **담당 설정**: 담당 디렉터리에서 목적·언어·업무 범위 등 허용된 설정을 읽는다. 보안 운영과 문서 작성 같은 차이는 여기서 표현하며 엔진 수정이 필요하지 않게 한다. 설정이 실행 권한을 자동 확대하지는 않는다.
3. **현재 세션과 작업 정보**: 이어지는 대화, 현재 목표, 미완료 작업, 근거와 반론, 관련 기억 참조를 선택해 제공한다. 작업 완료와 세션 종료를 구분하는 동작은 프롬프트 문구와 실제 세션 저장·복구가 함께 뒷받침해야 한다.
4. **필요한 방법·스킬·도구 명세**: 관련 항목만 읽고 미사용 명세는 활성 문맥에서 정리한다. 조회 자료와 과거 경험을 현재 사용자의 새 지시 또는 새 관측으로 오인하지 않게 한다.

계획 제안, 선택적 반론 검토, compact에 필요한 보존 판단, 기억 선별, 사용자 응답은 서로 다른 결과물을 요구할 수 있다. 모든 규칙과 전체 도구 목록을 하나의 거대한 메인 프롬프트에 넣거나 모든 요청마다 각 단계를 호출하는 방식은 기본값으로 삼지 않는다.

## 구체적인 점검 사항

- 현재 계획용 지침의 “목표를 변경하지 말라”는 계획 제안자가 임의로 완료 기준을 바꾸지 못하게 하는 책임 경계다. 이를 전체 대화 프롬프트에 그대로 확대하여 사용자의 정당한 목표 수정까지 막으면 안 된다.
- 같은 본문에 “도구를 실행하지 말라”와 “discovery 도구를 사용하라”가 있다. 실행기가 도구를 실행하고 계획기는 발견 작업을 제안한다는 뜻을 더 명료하게 표현할 여지가 있다. 실제 모델 혼동을 재현한 결함은 아니다.
- 전체 JSON schema가 계획 요청에 포함된다. 입력 크기와 소형·사내 모델의 출력 준수 비용은 실제 선택 모델로 평가해야 한다. 현재 소스만으로 성능 저하나 호환 성공을 단정하지 않는다.
- 현재 지침은 근거 확인 중심이다. 정보 조회뿐 아니라 글 작성·편집, 여러 단계의 자료 변환, 도구를 이용한 산출물 작성, 후속 대화에서도 목적에 맞는 결과를 만드는지 확인해야 범용성을 주장할 수 있다. 모든 과제를 조사 업무처럼 처리하지 않는다.
- 독립 반론 역할, 이전 작업에서 이어지는 대화, 기억 조회/등록의 선별, 사용자에게 보이는 간결한 응답은 기존 설계 기록과 맞춰 정리할 남은 부분이다. 프롬프트를 추가하는 것만으로 실행 경로나 상태 연결이 구현되지는 않는다.

## 검증 상태

이번에는 소스와 기존 시험의 내용을 읽었다. 코드·HTML 변경, 새로운 시험 실행, 모델/API 연결은 하지 않았다. 중단된 모델 연결 시험을 재개하지 않으며, 기존 합성 시험 통과를 실제 모델의 판단 품질 증거로 바꾸지 않는다.

후속 품질 평가가 허용되면 단순 요청, 산출물 작성, 모순 근거, 도구 실패, 작업 간 대화 연속성, compact 이후 이어가기, 담당 간 기억 격리를 포함해 결과의 정확성·불필요한 호출·완료 판단·답변 가독성을 살핀다. 프롬프트의 문장이 존재하는지를 확인하는 시험과 실제 행동 품질 평가를 구분한다.
