# C01 공통 메타데이터 파일 경계 결과

2026-09-07 · 메타데이터 경계의 POSIX 범위 구현·검증 완료 · C01 전체 미완료

프로필 설정과 파일 저널 헤더가 사용하던 디렉터리 검사, 크기를 제한한 파일 읽기, 디렉터리 동기화를 같은 호스트 어댑터에 연결했다. OS 차이를 다룰 위치를 모으는 작업이며, 추론 코어와 저장 데이터 형식은 그대로다. Windows 구현은 후속 범위다.

## 구현 범위

| 위치 | 담당하는 일 |
| --- | --- |
| host-metadata-files.ts | 호스트 파일 계약, 오류 종류, 디렉터리 참조와 플랫폼 선택 |
| posix-metadata-files.ts | Linux/macOS의 UID·권한·파일 종류·정체성 검사, 제한 읽기와 sync |

디렉터리 참조는 해당 어댑터가 발급한 객체만 유효하다. 다른 어댑터의 참조나 복사·조작한 객체는 거절한다. 참조 내부에는 디렉터리의 파일시스템 식별 정보가 있고, 읽기 전후에 경로가 같은 디렉터리를 가리키는지 재확인한다. OS 핸들로 디렉터리를 계속 고정하는 구현은 아니다.

공개된 상위 디렉터리를 통과하는 것과 그 안의 파일을 읽을 수 있는 조건을 구분했다. 파일 자체의 소유·권한 검사는 따로 수행하며, 동기화 전용 참조로 파일을 읽을 수 없다. 파일 크기, 읽기 전후 정체성과 메타데이터, 정상적인 임시 하드링크 쌍을 확인한다. 열린 파일과 목록 열거 자원은 예외가 나도 정리한다.

프로필과 저널의 임시 파일 이름·링크 허용 규칙은 각각의 모듈에 남겼다. 게시 순서, 저널 commit/복구, SQLite 소유 확인은 공통 읽기 함수로 옮기지 않았다. 기존 소비자 계측 외에 어댑터의 디렉터리 검사 등 I/O 진단을 추가했다. 재확인 호출이 늘었으므로 성능이 개선됐다고 주장하지 않는다.

## 확인한 문제와 변경

- 동시 CLI 초기화 시험이 한 차례 실패했다. 실패 원 로그는 보존했다. 별도 순서 고정 진단에서는 최초 조회와 디렉터리 목록 조회 사이에 다른 프로세스가 설정을 완성하면 정상 자료를 소유 불명 데이터로 오인했다. 그 경우에만 메타데이터를 한 번 다시 읽도록 수정했다. 최초 실패와 동일 원인이라고 단정하지 않는다.
- 다른 플랫폼에서 standalone journal 생성자가 플랫폼 확인 전에 디렉터리를 만들 수 있었다. 프로필 생성·게시와 저널 생성 모두 미지원 플랫폼을 먼저 거절하도록 했다. 플랫폼 값을 바꾼 시험은 분기 검증이며 실제 Windows 검증은 아니다.
- 파일을 연 이후 마지막 조회에서 파일이 사라진 오류와, 파일을 처음 열 때의 거절을 프로필 래퍼에서 구분해 기존 오류 의미를 보존했다.
