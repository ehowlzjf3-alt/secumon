# C05 호스트 도구 연결 다음 검토

2026-09-07 · 현재 소스를 읽고 정리한 후속 검토다. 호스트 연결은 구현·검증 중이며 아래 후속 기능을 완료한 기록이 아니다. C05 전체 범위와 실제 모델/API 시험 중단을 유지한다.

현재 일반 입구는 담당별 `Tool[]`, 정책, 새 업무 한도를 받을 수 있다. 이것으로 모델·실행기·대화·기억을 다시 조립하는 필요는 줄었지만, 사내 MCP를 곧바로 연결했다고 볼 수는 없다.

## 다음 연결: 기존 MCP 어댑터를 같은 담당에서 사용

[기존 MCP 읽기 어댑터](../../runtime/src/infrastructure/mcp-read-tools.ts)는 원 응답과 호출 의도를 담당의 상태·산출물 저장소에 기록하고 결과를 다시 검증한다. `createMcpReadTool`과 `createMcpProviderSource`는 `state`, `artifacts`, `digester`, `clock`을 받는다. [현재 호스트 도구 context](../../runtime/src/presentation/host-tools.ts)는 담당 ID·위치·scope만 제공한다. 따라서 새 호스트 factory에서 기존 MCP 어댑터를 쓰려면 이 보관·검증 포트를 연결하는 작은 조립 단계가 필요하다. 별도 DB를 열거나 두 번째 세션·호출 장부를 만들지 않는다.

다음 구현 전에 검토할 선택은 본체가 검증한 담당의 포트를 받는 전용 MCP 조립 helper 또는 선택적 도구 조립 callback이다. 일반 모델 factory에 저장소를 넘기지 않는다. 호스트는 신뢰된 실행 프로그램이고 모델이나 사용자 입력으로 등록 코드를 교체할 수 없다는 현재 경계를 유지한다. ID·정책·저장소의 소유자는 기존 C01 프로필이다.

기존 `McpStdioClient`, 읽기/페이지/대기 어댑터, `ProviderToolSource`와 `refreshProviderTools`를 재사용한다. 새 SDK·카탈로그·MCP 서버를 제품 안에 만들지 않는다. 로컬 시험 서버 프로세스에서 일반 요청 → 선택한 MCP 도구 → 원 응답 보관 → 근거 답변 → 재접속·중복 호출 방지를 연결한다. 새 연결·재시작으로 계약이 바뀌면 기존 snapshot/계약 검사가 감지하는지도 확인한다. 실제 사내 endpoint·인증·Knox는 별도 연동 검증으로 남긴다.

## 효율 개선은 측정한 병목부터

이전 C02/C03 기록은 작은 입력에서도 원문·기억 현재성 검사를 여러 번 반복하는 비용을 보여 주었다. [C03 비용 기록](C03-personal-memory-cost-notes.md), [문서 기억 비용 기록](C03-document-memory-cost-notes.md), [backlog의 C05 관측](../implementation-backlog.json)을 시작점으로 삼되 현재 소스로 같은 업무를 다시 측정한다.

개선 후보는 한 번의 검증 단계 안에서 동일 snapshot을 재사용하는 것이다. 서로 다른 실행 단계나 재접속 사이에 오래된 권한·출처를 재사용하는 TTL 캐시로 바꾸지 않는다. 실행 직전의 새 검증, 변경/삭제/정정 경합 거절, 실제 원문과 증거 보존은 같은 시험으로 비교한다.

측정 항목은 저장소 호출 수와 읽은 바이트, 선택한 도구/기억/스킬 명세의 크기, 실제 모델·도구 호출 수, 재시도·지연이다. 한 번의 합성 실행을 일반 성능이나 실제 모델 토큰 절감률로 표현하지 않는다. 변경 전후 동일 업무의 답변·근거·원문·정산 결과를 먼저 맞춘다.

## 범위에 계속 남는 것

쓰기 도구와 미확정 외부 효과, 기억/스킬 선택·해제·재로딩, 오래된 도구의 활성 문맥 정리, 구조화 API와 컴퓨터 유즈의 선택·행동 묶음·부분 성공 복원, Linux와 native Windows 검증은 C05 및 관련 챕터의 구현 범위다. 읽기 도구 첫 단위의 성공으로 이 항목들을 완료 처리하지 않는다. 다음 작은 단위의 확정 계획은 현재 검증 결과와 실제 포트 검토를 근거로 정한다.
